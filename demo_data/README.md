# Forge CRM 演示数据重建

## 重建顺序

1. 备份数据库。最近一次备份为 `/private/tmp/forge-crm-before-full-demo-rebuild-20261006.dump`。
2. 执行 Prisma 迁移，确保数据库约束与当前编码规则一致。
3. 初始化并核对组织、法人、岗位、员工、账号及其关联。
4. 导入物料分类字典。
5. 导入 001 产品和 004 物料。跳过临时编码及其 BOM；名称必须唯一、包含关键配置且不超过 30 个字符。
6. 重建 BOM，所有产品、组件和替代料必须引用启用的物料产品。
7. 清理旧客户、商机、报价、销售订单、入库、库存流水、库存余额、销售出库，以及引用旧业务对象的助手会话、活动、协作、建议和待办数据。
8. 按当前编码规则和业务状态重新生成数据。
9. 同步编码计数器，执行 `005演示数据一致性检查.sql` 并保存报告。

## 编码规则

| 对象 | 格式 |
|---|---|
| 客户 | `C` + 7 位流水 |
| 员工 | `1` + 6 位流水 |
| 商机 | `OP` + `yyyyMMdd` + 5 位日流水 |
| 报价 | `QT` + `yyyyMMdd` + 5 位日流水 |
| 销售订单 | `SO` + `yyyyMMdd` + 5 位日流水 |
| 入库单 | `IB` + `yyyyMMdd` + 5 位日流水 |
| 销售出库 | `OB` + `yyyyMMdd` + 5 位日流水 |
| 物料产品 | 物料大类 + `.` + 物料中类 + `.` + 7 位流水 |

## 执行与恢复

在仓库根目录执行：

```bash
pnpm --filter @forge-crm/server db:migrate:deploy
node --import ./packages/server/node_modules/tsx/dist/loader.mjs demo_data/004全量演示数据重建.ts
```

恢复备份时，从 `.env` 读取连接地址并去除 Prisma 专用的 `schema` 查询参数，再使用 `pg_restore --clean --if-exists --no-owner`。重建脚本会校验 514 条规范物料和 24 个规范 BOM 是否存在；不满足时停止，不继续清理。
