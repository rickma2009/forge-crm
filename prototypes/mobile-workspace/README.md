# 移动工作台交互原型

2026-10-11 · 隔离原型 · L2针对性验证。用于体验[移动设计方案](../../docs/design/mobile-workspace/solution.md)与[详细需求](../../.specify/requirements/mobile-workspace/requirement.md)。授权见[本轮输入](../../.specify/sources/20261011-mobile-prototype/source.md)。

## 打开与启动

正式项目工具条的 **CRM 工作台** 下拉框提供 **移动端原型** 入口，选择后在新页面打开；当前系统仍保持 CRM 工作台，默认值不变。入口连接独立的5176原型服务，需先启动下述服务。

演示地址：**http://127.0.0.1:5176/**。默认进入免密码演示登录，选择处理人或只读用户后进入工作台。桌面显示手机预览与场景导航；窄屏自动显示全屏手机布局。

```bash
bash prototypes/mobile-workspace/start.sh
bash prototypes/mobile-workspace/stop.sh
```

启动/停止脚本只管理本原型5176服务，检查PID所属命令，不停止正式5173/3000或其他原型。依赖复用现有web包的Vite、React及Tabler图标，不新增安装。

```bash
pnpm --dir prototypes/mobile-workspace build
pnpm --dir prototypes/mobile-workspace test
```

原型只绑定本机127.0.0.1；手机不能直接访问电脑的localhost。真实手机网络/HTTPS部署是下一阶段工作，本轮可用浏览器窄屏预览；没有擅自暴露开发服务到局域网/公网。

## 推荐演示顺序

1. **审批闭环**：右侧场景01→查看单据/附件→同意并填意见→确认。当前任务变已同意，待审批数量24→23，来源模拟销售订单变已审核；已办不可重复执行。
2. **普通邮件**：场景02→回复→交期模板→改正文→发送→确认。回复变已发送，任务仍处理中；再点完成并填说明，待处理数量减少。
3. **质量客诉**：场景03→先点完成尝试，缺少质量记录/回复将被拒绝→关联QA-DEMO-001→回复并确认发送→填写结论完成。
4. **暂挂与分派**：普通邮件→更多→暂挂并说明→恢复→备注/关注/分派。暂挂只改此任务；分派后任务离开“我的”待办。
5. **发送未知结果**：右侧或“我的→演示环境”选择发送超时→回复并确认→显示待核实、发送不可重试→邮件详情核实模拟已发出，不重复发信。切换正常模式后继续其他动作。
6. **弱网与只读**：模拟网络中断后提交备注，提示未保存；恢复网络重试。我的切只读后审批/邮件处理隐藏或禁用。
7. **库存联动**：场景06→筛选成品仓→查询→点物料→只显示选中仓库维度；库存事务保留行号入口。数值仅用于查询视觉演示，不是建立了新的库存账。
8. **消息/P1**：场景09点未读消息查看对应任务；客户跟进、舆情关闭需结论，采购基础审核不使库存过账。

## 验证与已知边界

验证证据见[原型验收](verification.md)。模型测试覆盖数量、审批一次性、质量完成要求、暂挂恢复、通知与任务分离、未知发送保护、只读/版本保护和审核不入库。

原型可复用现有图标语义；布局沿用移动设计的字号与触控建议，没有修改PC公共样式。独立React/CSS保持“原型→依赖”方向，正式代码不导入原型。库存事务、流程节点、附件为示意，不读取生产数据；表单只模拟关键校验，不构成正式权限/并发/财务保证。

未实现P2扫码、拍照上传、企业IM/SSO、PWA安装、离线写入和完整生产接口；没有对应可点击假入口。跨端同步演示体现为本原型单据/待办状态联动，不声称已经同步真实PC。文件本轮保存在统一原型目录，未创建Git提交/分支或宣称用户已批准设计。
