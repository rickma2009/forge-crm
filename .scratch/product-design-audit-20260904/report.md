# 企业管理系统 UI 模板资产审查（2026-09-04）

## 结论

当前 `interaction-pattern-lab` 已经具备“验证场”的正确骨架，但还不是可供新项目直接采用的 UI 模板库。登记册共有 27 个页面，其中 22 个仍是 `description-only`；颜色、排版、间距、基础组件和页面模板目前只有入口与候选说明。客户列表、数据字典、列表视图、资源目录和概览提供了真实交互证据，但尚未被拆成可追溯的主题、组件与页面模板资产。

下一步不应横向一次性填满 22 个页面。建议用“数据字典”做首个资产闭环，把已有实现拆成：一个紧凑企业主题、八个基础组件、一个树形主从管理模板及其 EPM 交互映射；通过后再用客户列表验证第二个页面模板。

## 审查范围和用户目标

- 范围：基础规范、基础组件、页面模板、客户列表业务演示、数据字典及新增字典值弹窗。
- 目标：判断现有内容能否成为未来企业管理系统的可选模板，以及应怎样保存、验证和晋升。
- 证据：当前运行页面截图、Showcase Registry、CSS 令牌、切片 006/008 Spec、UID-001/002 参考萃取、方法论 08/09。

## 关键发现

### 已有优势

1. 应用壳层、服务端 RBAC、多页签和统一工具栏已把“模板运行环境”打通。
2. 客户列表与数据字典不是静态截图，已有真实数据、权限、异常和测试证据。
3. Registry 已显式区分 `interactive-slice` 与 `description-only`，不会把占位页冒充已实现资产。
4. 页面具备较好的语义骨架：导航、表格、对话框、字段标签和 `aria-live` 等已有基础。

### 高优先级缺口

1. **目录大于资产。** 27 个页面里只有 5 个是交互切片，22 个是说明占位；导航完整度不能代表模板成熟度。
2. **资产模型尚未落地。** 规划已提出 `UI-THEME-*`、`UI-COMP-*`、`UI-TPL-*`，但 `_methodology/ui-assets/`、Schema、索引和证据卡仍不存在。
3. **来源关系需要清理。** 多数基础规范、组件和模板页仍统一引用 `UID-001`，而 UID-001 已被标记为当前目标的反例/被替代候选；应为每类资产重新登记来源选择，不能沿用一个过期来源包。
4. **设计令牌有双事实源。** `index.css` 使用 `--ipl-*`，`showcase.css` 又声明 `--showcase-*`，并散落大量固定字号、颜色、间距和圆角。未来项目无法只替换一份主题配置。
5. **12px 不能直接晋升为通用默认。** 它是当前验证场已批准的“紧凑密度”项目决策，应作为 `compact` 档位；通用模板至少需要 `comfortable/compact` 两档，并验证 200% 缩放、中文可读性和高密度表格。
6. **实现尚未组件化。** 数据字典和客户页的大量 UI 仍集中在页面文件与 CSS 选择器中；缺少组件输入、状态、权限、可访问性、失败行为和视觉回归契约。
7. **弹窗键盘行为存在可观察缺口。** 新增字典值弹窗按 Escape 后仍保持打开；还需验证焦点圈闭、关闭后焦点返回、背景不可交互。
8. **规划文档状态滞后。** 产品规划仍写到切片 004 Architecture 阶段和“系统管理固定底部”，而项目状态已是切片 005—009 在验证场发布，且 UID-001 记录该布局已被用户取消。

## 建议的资产分层

| 层级 | 回答的问题 | 建议位置 | 当前内容 |
|---|---|---|---|
| 来源证据 | 从哪里学到、哪些不能带走 | `_methodology/reference-cases/ui-distillations/` | UID-001/002，需补新来源选择 |
| 验证场实现 | 在真实交互中是否工作 | `interaction-pattern-lab/` | 客户、字典、视图、壳层 |
| 正式 UI 资产 | 可复用的视觉/组件/结构契约是什么 | 规划中的 `_methodology/ui-assets/` | 尚未建立，需方法论变更审批 |
| 接入模板 | 新项目怎样开始采用 | `_methodology/templates/ui/` | 现有导航/记录工作区骨架，需扩展 |
| 交互语义 | 用户任务、状态、失败与权限边界是什么 | `_methodology/patterns/` + EPM 索引 | 已有分类，可建立 `relatedEpmIds` |
| 项目采用证据 | 哪个真实项目采用了什么 | 各项目 Spec/ADR/回归证据 | 尚不能由验证场自证 |

## 首个纵向资产切片建议

名称：`010-traceable-tree-detail-ui-asset-slice`

目标：以数据字典为验证案例，打通“源码令牌 → 组件实物 → 页面模板 → EPM 行为 → 接入说明 → 浏览器证据”的一条链路。

候选资产：

- `UI-THEME-001`：企业中性浅色主题；包含语义颜色和 `compact/comfortable` 密度档位。
- `UI-COMP-001`—`008`：按钮、字段/选择器、状态徽标、数据表格、树导航、工具栏、对话框、反馈提示。
- `UI-TPL-001`：树形主从管理页；左树、右侧对象头、描述列表、明细表、动作区和状态区均为具名槽位。
- EPM 映射：`EPM-PAGE-014`、`EPM-ACT-001/006/010/011/014/041`、`EPM-VIEW-005/010/011/013`、`EPM-STATE-001—007/009/011`，导入扩展关联 `EPM-PAGE-050/051`。

每张资产卡必须包括：用途、适用/不适用边界、令牌或属性、全部状态、权限钩子、键盘路径、失败行为、来源、代码位置、截图、接入步骤、验收清单、成熟度和下一证据。

## Gate 建议

- 当前切片 005—009 仍保持 `released-in-validation-lab`；本次审查不改变 Gate 或成熟度。
- 新的 UI 资产 Registry 与 `_methodology/ui-assets/` 会改变方法论资产架构，应先归档新的需求来源并完成影响评估，再通过相应 Specification/Architecture 评审。
- 验证场可提供 `implementation-verified` 和 `interaction-verified`；不能独自声明 `project-adopted`、`business-validated` 或通用模板 `released`。
- 数据字典弹窗可访问性修正属于切片 006 的行为增量，应有明确 Spec/Testcase，而不是只改 CSS/组件代码。

## 验证结果

- Showcase Registry：通过，27 个页面、22 个 capability。
- Web 测试：14 个测试文件、67 项测试通过。
- 浏览器观察：基础规范/组件/模板均为说明占位；客户列表和数据字典可运行；新增字典值弹窗 Escape 未关闭。
- 未验证：颜色对比度数值、屏幕阅读器、200%/400% 缩放、完整键盘焦点圈闭、移动端；不能据此声明 WCAG 合规。
