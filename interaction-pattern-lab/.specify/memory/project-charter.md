## 1. 业务问题与机会

企业管理系统中的导航、列表、详情、表单、审批、批量处理和异常反馈大量重复，但这些经验分散在方法论文档、模板、Demo、实际项目源码和个人认知中。后续原型设计仍可能重复讨论页面结构，或只复制视觉结果而遗漏权限、状态、失败行为与适用边界。

本项目被重新定义为不承载真实业务数据的交互模式验证场：通过探索与可运行切片验证交互假设，为 `_methodology/` 提供证据。它不是模板权威源，也不以发布独立产品为当前目标。

## 4. 范围

### In Scope

- 按页面、操作、展示、状态、特殊操作和组合场景分类浏览；
- 103 个分类项全部进入可检索目录，但不批量生成 pattern 或 Demo；
- 左侧模式导航与检索，右侧可点击原型预览；
- 模式说明、行为契约、适用/不适用边界、风险和验收清单；
- 原型交互的重置、状态切换和特殊效果演示；
- 现有双层导航和记录管理工作区作为首批种子案例；
- 新增“批量选择—批量分配—部分成功”验证切片；
- 参考系统、Open Design 案例和用户补充材料的证据化登记；
- Demo 实践结果向 `_methodology/` 回流。
- 每个新页面生成前登记具体来源、版本、保留项、排除项和冲突；
- 建立上方业务/资产菜单与底部系统管理分组的演示门户壳层；
- 使用 `admin` 与 `viewer` 的浏览器内模拟身份验证菜单、路由、只读和操作权限。
- 对被选为未来可直接采用的导航能力，建立菜单、页面操作、用户、角色、角色成员和角色权限六类逻辑数据，并由服务端按目标系统执行授权。

### Out of Scope

- 保存真实企业业务数据；
- 代替业务系统、低代码平台或生产级后台管理系统；
- 未经人工批准自动决定项目业务规则；
- 本阶段建设在线模式编辑器、多人协作或完整账户/权限管理后台；
- 表级、行级、字段级、组织级数据权限；
- 直接复制参考项目的业务字段、组织约束和遗留技术栈；
- 把 Open Design 或单一系统案例直接定义成普适最佳实践。

## 5. 关键约束与风险

- 需求：详细场景和优先级仍需持续补充；
- 事实源：方法论资产必须继续以 `_methodology/` 为唯一通用规范源；
- 数据：Demo 操作默认不持久化，资产定义仍需版本化；
- 技术：历史 React/Vite 方案只对切片 001 有效；新索引、投影和 Demo 扩展方案留待 Architecture Gate；
- 范围：若同时建设浏览器、编辑器、生成器和管理后台，容易失去最小闭环；
- 复用：截图只能补充视觉证据，不能替代源码、路由、样式和测试；
- 验证：一个案例有效不能证明跨行业或跨项目通用。

## 6. MVP 假设与停止条件

- 假设：使用者通过“左侧分类选择—右侧原型体验—查看总结”即可更快理解和评审交互模式；
- 首个新增闭环：查找批量操作分类项 → 体验当前页/全部结果选择 → 预检查 → 批量分配 → 查看部分成功结果 → 重置 Demo；
- 验证方式：真实浏览器任务、可访问性检查、使用者评审和模式资料完整性检查；
- 停止/转向条件：使用者只需要静态文档、交互 Demo 无法改善理解，或模式维护成本明显高于复用价值时，应缩减为静态案例索引。
