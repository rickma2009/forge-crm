# 切片 002 规格澄清

> 状态：resolved-for-specification-review
> 来源：`REQSRC-008`、批准业务基线及本轮一致性分析

## 已确认的规格决策

| ID | 问题 | 决策 |
|---|---|---|
| `Q-SPEC-201` | Demo 以哪个资产编号出现 | 使用项目级验证案例 `VAL-002`；以 `EPM-SPECIAL-002` 为主要发现入口，并通过 `coveredBy` 关联其他分类项，不新增 EPM 场景编号 |
| `Q-SPEC-202` | 分类项打开后的默认内容 | 默认显示说明；只有关联可运行 Demo 时才可选择“交互演示” |
| `Q-SPEC-203` | 批量对象使用什么业务语义 | 使用去业务化“工作项”和“负责人”，只演示交互，不定义真实企业分配规则 |
| `Q-SPEC-204` | 如何构造当前页与全结果差异 | 确定性查询结果必须超过一页，并明确显示当前页数、总结果数和已选范围 |
| `Q-SPEC-205` | 全结果选择是否默认 | 否；默认只选择当前页，升级为全部查询结果需要显式动作 |
| `Q-SPEC-206` | 查询改变后如何处理选择 | 清空选择并通过可访问状态消息说明原因 |
| `Q-SPEC-207` | 预检查拒绝原因 | 使用无权限、记录锁定、状态不兼容、负责人不可用中的确定性样例；每条显示一个可行动主原因 |
| `Q-SPEC-208` | 部分成功后保留什么 | 成功项显示新负责人；失败项保留失败原因并保持可选择，便于修正或重试 |
| `Q-SPEC-209` | 系统失败后保留什么 | 不改变任何记录；保留查询、选择和目标负责人，允许重试或重置 |
| `Q-SPEC-210` | 如何访问加载、空和失败状态 | 验证案例提供明确场景入口，不依赖不可预测网络或随机失败 |
| `Q-SPEC-211` | 场景契约是不是业务接口 | 不是；只约束初始状态、动作、可观察结果、失败代码与键盘路径 |
