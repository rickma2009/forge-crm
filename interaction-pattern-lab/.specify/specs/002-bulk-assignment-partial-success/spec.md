# 功能规格：批量分配与部分成功验证

> 功能编号：002
> 状态：specified-awaiting-specification-gate
> Spec Gate：pending

## 1. 目标与范围

- 关联业务目标：`BUS-001`、`BUS-002`、`BUS-004`；
- 目标：让产品/需求分析人员能从完整分类目录发现批量操作候选，理解其证据边界，并体验无歧义的选择范围、预检查、确认和部分成功反馈；
- In Scope：99 项目录展示要求、真实成熟度、无 Demo 状态、`VAL-002` 同步批量分配交互、确定性状态与键盘路径；
- Out of Scope：真实后端、服务端权限/事务、异步任务、导入文件、在线编辑、资产晋升、项目采用、部署和发布。

## 2. 用户故事

### US-201 查找并判断分类项

作为产品或需求分析人员，我希望检索全部企业交互分类项，并看到真实成熟度、覆盖关系和 Demo 可用性，以便判断哪些内容只是想法、哪些已有验证证据。

### US-202 体验批量分配

作为产品或需求分析人员，我希望体验当前页与全部查询结果两种选择范围，以及预检查、确认和部分成功，以便在项目 Spec 中准确描述批量操作。

### US-203 形成采用判断

作为模式评审者，我希望理解该 Demo 证明了什么、没有证明什么，并能恢复确定性初始状态，以便记录采用、调整或拒绝结论。

## 4. 业务规则与状态

### 4.1 选择范围状态

```text
未选择
  → 选择当前页 M 条
  → 显式升级为选择当前查询全部 N 条
  → 修改查询/筛选/排序
  → 选择被清除并返回未选择
```

- 当前页选择只包含当前可见页；翻页不隐式扩大范围；
- 全查询结果选择绑定当前查询快照，不等于数据库全部记录；
- 所有批量操作入口必须显示实际对象数量，不使用含糊的“全部”。

### 4.2 执行状态

```text
已选择
→ 选择负责人
→ 预检查中
→ 全部可执行 / 部分拒绝
→ 确认或取消
→ 执行中
→ 全部成功 / 部分成功 / 系统失败
```

- 预检查拒绝项不会进入本次执行；
- 部分成功必须分别显示成功、失败和未处理数量；
- 系统失败表示本次没有任何记录发生变化；
- Demo 中的权限、锁定和状态规则是演示样例，不代表真实服务端已实现。

## 6. 非功能需求

| ID | 维度 | 要求 | 验证方式 |
|---|---|---|---|
| `NFR-301` | 可访问性 | 目录、筛选、选择范围、确认、结果和重置具备键盘路径、可见焦点及可访问名称 | 自动化 + 浏览器检查 |
| `NFR-302` | 确定性 | 相同场景入口和动作序列产生相同可观察结果；重置恢复同一初始状态 | 场景契约测试 |
| `NFR-303` | 隔离性 | 不调用生产接口、不写真实业务数据或持久化 Demo 操作状态 | 网络与代码审查 |
| `NFR-304` | 可追溯性 | 每项可定位分类定义、成熟度、覆盖关系、来源和下一证据；`VAL-002` 可定位本切片 | 投影检查 + 人工抽查 |
| `NFR-305` | 可扩展性 | 目录允许无 Demo 分类项存在，案例数量不受“必须正好两个”限制 | 目录与注册契约测试 |

## 7. 边界与异常

| 场景 | 预期业务行为 |
|---|---|
| 资产投影缺少必填信息 | 明确失败并阻止把不完整状态展示为已验证；具体失败机制留给 Architecture Gate |
| Demo 加载失败 | 说明仍可访问，交互区域显示失败和重试，不影响目录 |
| 无查询结果 | 区分无数据与无筛选结果；后者保留条件并可清空 |
| 无选择直接执行 | 操作不可执行并解释先选择对象，不弹空确认框 |
| 负责人不可用 | 预检查拒绝受影响记录，不把失败伪装成成功 |
| 部分成功 | 成功项与失败项不混写，结果可复核 |
| 查询条件变化 | 清除旧选择，不猜测用户是否希望保留 |
| 刷新或重置 | 恢复预置状态，不恢复上次 Demo 操作数据 |
