# Feature Specification：导入—校验—执行

| 项目 | 内容 |
|---|---|
| Feature ID | `011-import-validation-execution` |
| 业务目标 | `BUS-017` |
| 来源 | `REQSRC-036`—`REQSRC-038` |
| 状态 | `specification-gate-draft-awaiting-approval` |

## 1. 目标与范围

本切片验证使用者能否准确区分“文件已接收、已解析、已校验、已确认、已执行”，在写入前理解影响范围，并从失败结果返回可修复输入。

范围包含中性资源记录、单文件 `.xlsx`、字段映射、分层校验、全量或授权部分执行、异步任务、错误下载和关联重试。范围不包含真实企业数据、生产级存储或队列、多格式 ETL、方法论资产晋升、部署与 Release。

## 2. 用户故事

- `US-1101`：作为业务操作员，我希望在执行前看到文件、映射、校验和预计影响范围，以免把上传成功误认为业务写入成功。
- `US-1102`：作为获授权的业务操作员，我希望在部分行错误时明确选择只执行通过项，并理解被排除范围与不可撤销边界。
- `US-1103`：作为数据维护者，我希望错误能定位到源行、源列和目标字段，以便指导修复后创建可追溯的新任务。
- `US-1104`：作为审核或支持人员，我希望只读查看任务阶段、操作者、策略、计数和来源任务，以便解释结果而不代替操作员执行。

## 3. 功能需求

### 文件与模板

- `REQ-1101`：用户必须先选择导入对象与模板版本，页面明确展示目标对象和模板要求。
- `REQ-1102`：首轮只接受单个 `.xlsx` 文件、单个数据工作表、最大 5 MiB 和最多 5,000 条数据行；文件加密、包含宏或存在多个数据工作表时拒绝进入映射。
- `REQ-1103`：文件接收成功只表示可开始解析，不得显示为导入或执行成功。

### 字段映射与预览

- `REQ-1104`：中性资源记录包含唯一编码、名称、分类、启用日期和数量；唯一编码与名称为必填目标字段。
- `REQ-1105`：系统按唯一表头自动匹配字段，允许人工调整和忽略可选来源列；一个目标字段不得被多个来源列同时映射。
- `REQ-1106`：全部必填目标字段必须完成唯一映射后才能校验；映射变化使旧校验结果失效并要求重新校验。
- `REQ-1107`：解析预览显示源行号、原始值和规范化建议；任何规范化都不得静默覆盖原始值。

### 校验与确认

- `REQ-1108`：校验结果区分文件级、字段级、行级和跨行错误，并分别统计通过、错误、警告和总行数。
- `REQ-1109`：缺少必填值、类型错误、未知分类、负数量、非法日期、文件内编码重复或与目标快照编码重复均为阻断错误。
- `REQ-1110`：首尾空格可安全规范化和未映射可选列为警告；警告不阻断，但必须在确认页单独展示。
- `REQ-1111`：错误项至少定位源行、源列或文件级原因，并提供稳定错误码、可行动原因和修复建议。
- `REQ-1112`：无错误时允许全量执行；存在错误时默认阻断，只有具备 `import.execute-valid-rows` 能力的用户可选择仅执行通过项。
- `REQ-1113`：执行确认必须展示目标、文件、模板版本、总数、通过/错误/警告数、执行策略和预计写入数；部分执行还必须二次确认排除范围与不可撤销说明。

### 任务、结果与恢复

- `REQ-1114`：确认后统一创建异步任务，状态限定为 `queued`、`running`、`succeeded`、`partially-succeeded`、`failed` 或 `cancelled`。
- `REQ-1115`：只有排队中的任务允许取消；运行中的取消请求必须解释不能撤销，不能伪装成功取消。
- `REQ-1116`：同一确认动作的重复触发不得产生不可区分的重复任务，界面返回并聚焦同一任务。
- `REQ-1117`：终态结果分别显示成功、失败、跳过和警告计数；各互斥行级计数与执行范围保持可解释的一致关系。
- `REQ-1118`：错误明细可查看并下载为与任务版本绑定的 `.xlsx`，至少包含任务 ID、源行、源列、目标字段、错误码、原值、原因和修复建议。
- `REQ-1119`：修复后重试必须创建新的关联任务并保留来源任务只读记录，不得原地覆盖历史结果。
- `REQ-1120`：Demo 在同一浏览器页签刷新后恢复已创建任务；显式重置或会话结束后不承诺恢复，并持续标记为本地确定性模拟。

## 4. 业务状态与不变量

```text
file-selected → parsed → mapped → validated → confirmation-ready
                                               ├─ full execution
                                               └─ authorized valid-rows-only
confirmation → queued → running → succeeded | partially-succeeded | failed
                    └─ cancelled
```

- 新文件、模板或映射变化会废止旧预览与校验结果；
- `queued` 之前没有业务执行任务；`running` 之后不能承诺撤销；
- 错误默认阻断，部分执行是显式能力而不是自动降级；
- 历史任务、校验快照和下载结果保持版本对应；
- Demo 反馈不得冒充生产持久化、生产队列或真实外部事务。

## 5. 验收标准

- `AC-1101`：错误格式、超限、加密、宏或多数据表文件被安全拒绝，并说明可行动原因；合规文件仅显示“已接收/待解析”。
- `AC-1102`：自动映射结果可复核和调整；重复目标映射或缺少必填映射时不能校验。
- `AC-1103`：解析预览保留源行和原始值，规范化建议可见；改变文件、模板或映射后旧校验结论失效。
- `AC-1104`：四类校验及首轮错误/警告规则产生稳定、可定位、可筛选的结果与准确计数。
- `AC-1105`：错误存在时普通操作员不能执行；授权操作员选择仅执行通过项时必须完成包含排除范围的二次确认。
- `AC-1106`：无错误全量确认和授权部分确认均显示目标、版本、策略和预计影响范围，取消确认不会创建任务。
- `AC-1107`：重复确认只产生或返回同一任务；任务按限定状态转换，只有 queued 能成功取消。
- `AC-1108`：成功、部分成功、失败和取消终态反馈互不混淆，行级计数与执行范围一致。
- `AC-1109`：错误查看与下载内容绑定任务版本，包含规定定位列；修复重试创建带来源关系的新任务且不改写旧任务。
- `AC-1110`：只读审核角色可查看任务与结果但不能确认、取消或重试；数据维护权限不自动授予业务执行权限。
- `AC-1111`：同页签刷新恢复本地任务，显式重置后恢复预置状态；页面始终披露模拟和会话边界。
- `AC-1112`：选择文件、修正映射、定位错误、确认、任务查看和下载入口可使用键盘完成，焦点与异步状态可感知。
- `AC-1113`：1440px 与 1024px 支持完整流程；窄屏支持查看、错误定位和轻量动作，并明确把复杂映射/确认引导至宽屏。
- `AC-1114`：场景使用合成数据且不访问生产服务、MCRM 或参考项目数据；执行 Specification 检查时不存在孤立 REQ/NFR、AC 或 TC。

## 6. 非功能需求

- `NFR-1101`：所有关键动作具备键盘路径、可见焦点和屏幕阅读器可感知的状态/错误反馈。
- `NFR-1102`：1440px、1024px 和 390px 三档均无关键文本不可恢复裁切；窄屏降级边界显式呈现。
- `NFR-1103`：5,000 行边界内的 Demo 校验和任务进度使用确定性数据，结果可重复，不伪造真实性能或吞吐承诺。
- `NFR-1104`：操作能力、只读边界和部分执行能力在入口、确认和结果层保持一致，不能只隐藏按钮而缺少行为拒绝。
- `NFR-1105`：来源、BUS、REQ/NFR、US、AC 与 TC 具有稳定可检查追溯；切片 002 的 Release 状态不被继承。
- `NFR-1106`：所有展示数据为合成数据；错误下载不得包含真实个人信息、凭据或来源项目专属字段。

## 7. 明确边界

本草案只请求批准可观察行为、规格阈值、验收标准与测试设计。它不选择解析库、状态管理、文件存储、任务调度、数据库、API 或部署方案，也不批准 Architecture、Plan、Tasks、实现、资产晋升或 Release。
