# 需求澄清：认证式企业导航壳层

> 状态：`specification-decisions-approved`
> 说明：下列答案已由 `REQSRC-015` 随 Specification Gate 批准；技术实现仍等待 Architecture Gate。

| ID | 问题 | 建议答案 | 依据 | 状态 |
|---|---|---|---|---|
| `Q-SPEC-301` | 首片采用哪组密度 | 默认采用来源复刻密度：展开宽度 220px、菜单项高度 34px；首片不提供密度切换，232px/36px 保留为后续比较变体 | 用户要求首片完整复刻结构、样式和字号；避免首片同时验证两套密度 | approved |
| `Q-SPEC-302` | 默认展开哪些菜单 | 登录后“概览”激活，主菜单分组默认折叠；“系统管理”默认展开。进入子页面时自动展开其祖先 | 与参考截图一致，并减少首屏视觉噪声 | approved |
| `Q-SPEC-303` | `viewer` 的精确权限 | 可访问全部上方资产说明页和“资源目录”；系统管理中只显示“资源目录”。资源目录为只读，导出/维护操作禁用；直接访问用户管理返回无权页 | 在最小范围内覆盖隐藏、拒绝、只读、禁用四类反例 | approved |
| `Q-SPEC-304` | 模拟登录如何反馈 | 登录页明示“仅用于前端交互演示，不是生产认证”；输入 `admin` 或 `viewer` 进入，空值和未知账号就地报错；不要求密码。退出、刷新或重置均回到身份选择页 | 不制造虚假密码安全感，保持确定性 | approved |
| `Q-SPEC-305` | 哪些子菜单是真实 Demo | “概览”展示壳层说明；“资源目录”承载权限验证面板；其余入口是可路由的说明页，明确标记“互动演示未接入”，不冒充完整功能 | 避免扩展成系统管理后台，同时保留完整菜单结构 | approved |
| `Q-SPEC-306` | 窗口高度不足时怎样滚动 | 品牌和搜索固定；主菜单使用主要滚动区；系统管理固定在底部且最多占导航可用高度的 45%，超出时在自身区域滚动 | 保持管理入口可发现，避免挤没主菜单 | approved |
| `Q-SPEC-307` | 折叠后怎样访问层级菜单 | 折叠宽度为 64px，保留图标和可访问名称；悬停/聚焦显示标签，激活分组时用临时浮层展示子项；搜索按钮打开临时搜索面板 | 折叠不应使键盘或层级入口不可用 | approved |
| `Q-SPEC-308` | 搜索与权限如何组合 | 搜索只在当前身份可见菜单中匹配名称和登记关键词；命中子项时保留祖先；隐藏菜单不得通过搜索暴露 | 权限过滤先于发现功能 | approved |

## 已确认的切片边界

- 可复用：业务/资产主区与底部管理区分层、统一菜单节点语义、确定性权限反例、语义化视觉令牌。
- 不可复用：来源品牌、业务菜单名称、组织 IAM、远程菜单接口、缓存键和旧技术遗留。
- Architecture Gate 已由 `REQSRC-016` 批准：会话 seam、Registry、图标适配、路由保护、测试工具和与现有 Lab 的集成边界按 `plan.md` 与 ADR-003 执行。
- Specification Gate 已批准；任何改变上述行为的实现发现都必须重新打开 Specification Gate。
