# 功能规格：模式目录与交互预览

> 功能编号：001-pattern-catalog-preview  
> 状态：approved  
> Business Gate：approved  
> Specification Gate：approved

## 1. 目标与范围

- 关联业务目标：`BUS-001`、`BUS-002`；
- 目标：让产品/需求分析人员在一个工作台内发现两个已验证模式、体验其声明交互并理解适用边界；
- In Scope：分类目录、关键词搜索、模式选择、两个种子案例、交互原型/模式说明页签、重置、状态与来源展示；
- Out of Scope：多方案比较、源码或配置复制、在线编辑、账户权限后台、业务数据保存、Open Design 自动生成、生产接口调用。

## 2. 用户故事

### US-001 查找模式

作为产品/需求分析人员，我希望通过分类和关键词找到已有模式，以便快速判断是否有可复用起点。

### US-002 体验模式

作为产品/需求分析人员，我希望直接操作模式案例并随时重置，以便理解主要交互而不产生真实业务副作用。

### US-003 理解与评审模式

作为产品、设计或前端人员，我希望看到模式的边界、行为、状态、来源和验证结果，以便在项目中作出采用、调整或拒绝决定。

## 3. 页面规格

### PAGE-001 企业交互模式工作台

**关联功能**：`FR-001`—`FR-005`  
**关联场景**：`EPM-PAGE-001`、`EPM-SCENE-001`

#### 页面目标

使用者在同一页面完成模式发现、原型体验、总结阅读和状态重置，不需要登录或进入内容编辑后台。

#### 页面结构

1. 左侧平台导航：采用企业双层导航壳层，品牌区、搜索、收起按钮、一级真实分类、二级模式页面和当前项反馈一体化；
2. 右侧顶部栏：展示当前资产分类、模式数量与“静态 Demo · 无业务写入”边界；
3. 右侧模式头：模式名称、分类编号、验证状态和重置操作；
4. 右侧主区：“交互原型 / 模式说明”两个页签；
5. 原型页签：展示当前模式的可点击案例；
6. 说明页签：展示用途、边界、行为、状态、风险、来源和验证结论。

#### 关键操作

| 操作 | 显示条件 | 执行结果 | 失败/恢复 |
|---|---|---|---|
| 搜索模式 | 始终可见 | 目录只保留名称、编号、分类或关键词命中的模式 | 无结果时显示原因和清空入口 |
| 展开/收起分类 | 导航展开或抽屉打开 | 显示或隐藏该一级分类下的二级模式 | 搜索时自动展示命中分类及子项 |
| 收起/展开导航 | 桌面视口 | 在 232px 完整导航和 64px 图标导航间切换；收起态以浮层访问子项 | 窄屏统一使用可关闭抽屉 |
| 选择模式 | 目录存在模式 | 当前项高亮，右侧加载该模式预置原型与说明 | 加载失败时说明仍可查看，并可重试原型 |
| 切换页签 | 已选择模式 | 在原型与说明之间切换，不改变方法论资产 | 页签内容失败时保留另一页签可用 |
| 重置 Demo | 当前模式存在交互案例 | 当前案例恢复预置状态 | 重置失败时显示原因并允许重新打开模式 |
| 操作案例 | 当前模式案例已加载 | 只改变当前案例的临时状态 | 不调用生产接口，不生成真实业务副作用 |

#### 页面状态

- 初始：按稳定目录顺序选择第一个种子模式并展示其原型；
- 搜索无结果：保留搜索词，提示没有匹配项并提供清空入口；
- 原型加载中：显示加载范围，目录和说明页签仍可用；
- 原型不可用：显示“说明已存在、交互案例暂不可用”，提供重试；
- 模式说明缺失：标记资产不完整，不使用通用占位总结伪装完整；
- 重置成功：恢复当前案例预置状态并给出页面内可感知反馈；
- 窄屏：目录、模式头和两个页签仍可依次访问，不要求桌面双栏同时可见。

## 4. 功能需求

### FR-001｜【新增】【P0】分类目录与关键词搜索

- 关联：`REQ-001`、`REQ-002`；
- 平台自身使用企业双层导航壳层：一级只展示实际存在的分类，二级展示模式页面；默认展开当前模式所属分类；
- 模式条目至少包含名称、分类编号和验证状态；导航支持一级展开/收起、整体收起/展开与当前项反馈；
- 搜索匹配模式名称、编号、分类和显式关键词，忽略首尾空白；
- 清空搜索后恢复完整首批目录；
- 无匹配项时不清除用户输入，并提供清空入口。

### FR-002｜【新增】【P0】模式选择与上下文切换

- 关联：`REQ-002`、`REQ-006`；
- 选择模式后，目录明确标识当前项，右侧原型和说明必须指向同一模式；
- 首批包含企业双层导航壳层和记录管理工作区；
- 切换到另一个模式时，离开的案例状态不保存；再次打开从预置状态开始；
- 当前模式可通过可分享地址定位，但案例内部输入和展开状态不进入分享地址。

### FR-003｜【新增】【P0】种子模式交互原型

- 关联：`REQ-003`、`REQ-004`、`REQ-006`；
- 导航壳层案例声明并演示：分组展开/收起、菜单搜索、导航折叠和当前项反馈；
- 记录管理案例声明并演示：查询、重置、打开新增、打开详情、页签切换与关闭；
- 案例使用虚构或去业务化样例，不调用生产接口；
- 案例只宣称真实可操作行为，未接通能力不得表现为可用操作。

### FR-004｜【新增】【P0】模式说明

- 关联：`REQ-005`、`REQ-009`；
- 每个模式显示：名称、分类编号、验证状态、解决的问题、适用边界、不适用边界、主要行为、关键状态、风险、来源与验证证据；
- 验证状态使用方法论规定的枚举，不显示“最佳实践”作为未经证据支持的状态；
- 说明内容与当前原型保持同一模式上下文；
- 来源不可定位或证据缺失时明确标记，不静默提升验证状态。

### FR-005｜【新增】【P0】重置与非持久化

- 关联：`REQ-004`；
- 每个可交互案例提供明确的重置入口；
- 重置、切换模式或重新打开工作台后恢复案例预置状态；
- 搜索词和当前模式可以作为当前浏览上下文存在，但不得把案例输入、模拟业务对象或特殊操作结果保存为业务数据；
- 所有危险或外部操作只演示界面反馈，不执行真实副作用。

## 5. 业务规则与状态

1. `_methodology/` 是模式定义、状态和来源的权威来源，Demo 不独立改变模式结论；
2. 首批只展示两个已有 `validated-once` 模式，不把其他 `idea` 列为可交互案例；
3. 模式切换必须同时更新原型、模式头和说明，禁止出现上下文错配；
4. 模式内部临时状态生命周期为“预置 → 交互 → 重置/切换/重新打开 → 预置”；
5. 浏览者没有在线修改或发布模式的入口；
6. 具体加载、路由和隔离机制属于 Architecture Gate，不在本 Spec 固定。

## 6. 验收标准

| ID | 关联需求 | Given | When | Then |
|---|---|---|---|---|
| `AC-001` | `REQ-001`、`REQ-006` | 首批模式资产可用 | 用户打开工作台 | 左侧按分类展示两个种子模式，且名称、编号和验证状态正确 |
| `AC-002` | `REQ-001`、`REQ-002` | 用户位于模式目录 | 输入名称、编号、分类或关键词 | 只显示匹配模式；无结果时保留输入并可一键清空 |
| `AC-003` | `REQ-002` | 两个模式均可选择 | 用户选择任一模式 | 目录高亮、模式头、原型和说明均切换到同一模式 |
| `AC-004` | `REQ-003`、`REQ-006` | 导航壳层案例已加载 | 用户执行声明的导航交互 | 展开、搜索、折叠和当前项反馈与模式说明一致 |
| `AC-005` | `REQ-003`、`REQ-006` | 记录管理案例已加载 | 用户执行声明的记录交互 | 查询、重置、新增、详情和页签行为与模式说明一致 |
| `AC-006` | `REQ-005`、`REQ-009` | 任一模式已选择 | 用户打开模式说明 | 必填总结、来源和验证状态完整显示，且没有无证据的最佳实践表述 |
| `AC-007` | `REQ-004` | 用户已改变案例临时状态 | 用户重置、切换后返回或重新打开 | 案例恢复预置状态，临时业务输入和操作结果没有被保留 |
| `AC-008` | `REQ-004` | 用户执行案例全部声明操作 | 检查浏览器网络和持久化结果 | 没有生产接口请求，也没有真实业务数据写入 |
| `AC-009` | `NFR-001` | 用户只使用键盘 | 浏览目录、选择模式、切换页签、操作主要案例并重置 | 焦点可见，操作可完成且具有可访问名称 |
| `AC-010` | `NFR-002` | 视口收窄 | 用户访问目录、原型和说明 | 三类内容仍能依次访问，不出现无法关闭的遮挡或不可恢复状态 |
| `AC-011` | `REQ-003`、`REQ-005` | 当前原型加载失败 | 用户查看当前模式 | 目录和说明保持可用，页面解释失败并提供重试入口 |
| `AC-012` | `REQ-001`、`REQ-006`、`NFR-001`、`NFR-002` | 用户打开平台导航 | 展开/收起一级分类、收起平台导航或在窄屏打开抽屉 | 一级与二级关系明确、当前项可识别，所有模式仍可访问且抽屉可关闭 |

## 7. 非功能需求

| ID | 维度 | 要求 | 验证方式 |
|---|---|---|---|
| `NFR-001` | 可访问性 | 核心路径支持键盘操作、可见焦点和可访问名称 | 自动检查与真实浏览器键盘验收 |
| `NFR-002` | 响应式 | 桌面优先；窄屏下目录、原型和说明仍可恢复访问 | 多视口浏览器验收 |
| `NFR-003` | 隔离性 | 案例不得请求生产服务或写真实业务数据 | 网络记录、配置和代码审查 |
| `NFR-004` | 可追溯性 | 两个模式均能定位分类、来源和真实验证状态 | 自动检查与人工核对 |
| `NFR-005` | 资产完整性 | 模式清单、原型和说明的上下文不能错配 | 自动化测试和浏览器验收 |

## 8. 边界与异常

| 场景 | 预期业务行为 |
|---|---|
| 搜索词仅包含空白 | 按空搜索处理，显示完整目录 |
| 搜索没有结果 | 保留搜索词，显示无结果与清空入口 |
| 当前原型加载失败 | 目录、模式头和说明仍可用，提供重试 |
| 当前说明缺少必填信息 | 标记资产不完整，不生成推测性文案 |
| 用户尝试危险或外部动作 | 只显示模拟反馈，不产生真实副作用 |
| 模式来源失效 | 标记来源待复核，不提升或伪造验证状态 |
| 窄屏打开目录或原型 | 所有区域均有明确进入和退出路径 |
