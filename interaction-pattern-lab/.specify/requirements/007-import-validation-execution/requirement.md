# 企业批量导入验证业务需求

> 版本：v1.0
>
> 状态：`business-gate-approved`
>
> 来源：`REQSRC-036`、`REQSRC-037`

## 1. 业务问题

企业管理软件的批量导入常把“文件已上传、格式已解析、数据已校验、业务已执行”混为一个成功状态。用户难以判断哪些记录会被写入、错误发生在哪一行、部分成功是否可接受，以及失败后应修复文件还是重试任务。

## 2. 目标

| ID | 目标 | 当前基线 | 成功方向 | 证据 |
|---|---|---|---|---|
| `BUS-017` | 建立可解释、可恢复的“导入—校验—执行”交互闭环 | 只有字典专项导入和同步批量操作案例，没有通用导入闭环 | 使用者能区分五个阶段、在执行前确认影响范围，并从错误结果回到可修复输入 | 自动测试、浏览器任务和至少两类角色观察 |

不预设效率提升比例；真实观察不足时保持 `baseline-pending`。

## 3. 目标角色

| 角色 | 核心任务 | 权限边界 |
|---|---|---|
| 业务操作员 | 选择模板/文件、检查自动映射、发起校验、确认执行并查看结果 | 只能操作获授权的数据类型，不能绕过校验直接写入 |
| 数据维护者 | 配置允许映射的字段、查看错误分类并指导修复 | 不因维护映射而自动获得业务数据写权限 |
| 审核/支持人员 | 查看任务范围、操作者、阶段、计数与失败原因 | 默认只读，不代替操作员确认部分执行 |

## 4. 建议主流程

```text
选择导入对象与模板
→ 选择文件并完成文件级预检查
→ 自动匹配字段，人工处理未匹配必填列
→ 解析为预览并执行字段/行/跨行校验
→ 展示通过、失败、警告和预计影响范围
→ 无错误则全量执行；有错误时默认阻断
→ 有显式权限的用户可选择“仅执行通过项”并二次确认
→ 创建异步任务，展示排队/运行/完成/部分成功/失败
→ 查看结果、下载错误明细、修复后建立新任务
```

## 5. 范围

### In Scope

- 中性合成记录的模板下载、文件选择和预检查；
- 自动字段匹配、必填列缺失和人工映射确认；
- 文件级、字段级、行级和跨行校验结果；
- 执行前影响范围和部分执行二次确认；
- 异步任务状态、确定性进度与终态结果；
- 成功、失败、跳过和警告计数；
- 可定位到源行与字段的错误明细和下载；
- 键盘操作、窄屏降级、空态、错误态和恢复路径；
- 来源、候选模式、Demo 与测试证据追溯。

### Out of Scope

- 连接生产系统、MCRM、`gf_scm` 或 `gscrm-sdd` 数据库；
- 通用 ETL 平台、定时调度、超大文件、实时流处理；
- 生产级病毒扫描、对象存储、消息队列或长期任务归档；
- 任意公式语言、脚本执行或用户自定义代码；
- 自动回滚已经提交到外部系统的业务事务；
- 资产晋升、独立包发布或外部部署。

## 6. 业务不变量

1. 上传、解析、校验和执行必须是不同状态，不得用单一“成功”覆盖。
2. 执行前必须展示目标对象、记录总数、通过/失败/警告数和执行策略。
3. 存在错误时默认禁止执行；“仅执行通过项”必须显式授权并二次确认。
4. 每条错误必须至少定位源行、字段或文件级原因，并给出可行动的修复提示。
5. 重试不能静默覆盖原任务；修复后创建新任务并保留来源关联。
6. 重复提交同一确认请求不得生成不可区分的重复执行。
7. 浏览器关闭或刷新不能把已创建任务伪装为丢失；Demo 必须诚实说明其持久化边界。
8. 部分成功终态必须同时展示成功与失败集合，不能只弹出成功提示。

## 7. 成功验证方向

- 使用者可正确判断“当前尚未写入”还是“任务已执行”；
- 使用者能在错误摘要、源行和字段之间定位并返回修复；
- 使用者能解释全量执行与仅执行通过项的差异；
- 任务刷新后状态与结果保持一致；
- 两类目标角色完成至少三次观察任务；不足时不声明业务价值改善。
