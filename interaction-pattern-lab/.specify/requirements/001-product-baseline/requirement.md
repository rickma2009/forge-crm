# 企业管理系统交互模式工作台需求草案

> 版本：0.2  
> 状态：approved-business-baseline  
> Business Gate：approved  
> 权威来源：`REQSRC-001`、`REQSRC-002`

## 1. 产品定位

面向需要设计、评审或实现企业管理系统页面的产品、设计、前端和方法论维护人员，本产品作为交互模式浏览与验证工作台，通过分类目录、可点击原型和结构化总结，降低重复设计和遗漏边界的风险；它不替代项目详细需求、业务系统、生产数据服务或人工 Gate。

### 2.2 首个纵向切片建议

Business Gate 已通过，首个纵向切片确定为：

```text
打开工作台
→ 在左侧看到分类和两个已验证模式
→ 选择“记录管理工作区”
→ 在右侧体验列表查询、新增和详情切换
→ 查看该模式的总结、边界、来源和验证状态
→ 一键重置 Demo
```

该范围已批准进入规格设计；具体行为和验收仍需通过 Specification Gate。

## 3. 角色与权限草案

首期只提供只读浏览者角色，不建设登录和在线编辑后台。模式内容通过仓库文件维护并经代码评审进入工作台。

| 角色 | 浏览模式 | 操作 Demo | 查看总结 | 在线修改/发布模式 |
|---|---:|---:|---:|---:|
| 浏览者 | 是 | 是 | 是 | 否 |
| 方法论维护者 | 是 | 是 | 是 | 首期通过 Git，不在 UI 内提供 |

该取舍已经 Business Gate 确认。

## 4. 业务规则草案

1. 左侧选择改变当前展示模式，但不改变方法论资产；
2. 切换模式或点击重置时，右侧恢复该案例预置状态；
3. 每个案例只能宣称其真实覆盖的交互，不以静态页面推断未实现行为；
4. `validated-once` 必须对应至少一个真实项目、浏览器证据和来源记录；
5. Open Design 案例、用户截图和外部系统默认是候选证据；
6. 用户提供源码时优先从源码、路由、样式、配置和测试萃取；
7. Demo 的样例对象必须去业务化，不携带参考系统敏感或组织专属数据。

## 5. 状态模型

### 5.1 模式资产状态

```text
idea → candidate → validated-once → validated-multiple
  └──────────────────────────────→ deprecated
```

任何晋升都必须记录证据；`deprecated` 保留为反例，不静默删除历史结论。

### 5.2 Demo 会话状态

```text
预置状态 → 用户交互后的临时状态 → 重置/重新打开 → 预置状态
```

首期允许 URL 定位当前模式，但不保存案例内部操作状态；具体路由方式留待 Architecture Gate。

## 6. 异常与边界草案

| 场景 | 期望行为草案 |
|---|---|
| 模式没有 Demo | 展示“说明已存在、交互案例待建设”，不得伪装可点击 |
| 模式资源加载失败 | 显示失败原因和重试入口，不影响目录浏览 |
| 分类无结果 | 保留筛选上下文并给出清空入口 |
| Demo 触发危险动作 | 只模拟影响与反馈，不调用真实外部服务 |
| 来源不可访问 | 标记证据缺失或待复核，不继续宣称已验证 |
| 案例与方法论冲突 | 并列记录差异，回到对应 Gate 或方法论评审 |
| 小屏显示 | 桌面优先；窄屏仍可恢复目录、原型与说明的访问，不要求完整移动端体验 |

## 9. 明确不做

- 首期不保存用户创建的业务对象；
- 首期不建设在线所见即所得编辑器；
- 首期不建设用户、角色、审批和发布后台；
- 不自动抓取或复制未经授权的外部案例；
- 不把参考系统的实现约束自动升级为通用规范；
- 前端框架、数据存储和部署平台留待 Architecture Gate 决策。
