# 需求 006：企业 UI 资产体系与主从单据首切片

> 状态：detailed-requirement-draft-awaiting-specification-gate
> 原始来源：`REQSRC-029`、`REQSRC-030`、`REQSRC-031`
> 上游业务边界：`REQSRC-014` 已批准的 `BUS-005`—`BUS-007`

## 1. 目标

把验证门户中分散在销售订单、客户、字典、工作台和主从工作区里的设计规则与组件行为，整理为同一登记册可追溯的基础规范、企业组件、页面模板和场景证据。首个纵向切片验证“主从单据 + SchemaForm + 可编辑行表 + 状态矩阵”，以销售订单为第一场景、BOM 为第二场景复核，避免把单一业务页面误当通用模板。

## 2. 已确认决策

- 产品形态：演示门户面向人，`_methodology/` 的 schema、tokens、模板、案例和检查面向 AI/工程复用。
- 推进方式：最小基础规范 → 企业组件 → 状态 → 页面模板 → 组合场景。
- 参考策略：`gscrm-sdd` 与 `gf_scm` 只做差量、定向、版本化萃取。
- AGENTS 边界：只保留事实源、路由、硬边界、暂停条件和验证入口。
- 技术策略：复用成熟基础控件和现有项目技术路线，先在 Lab 验证企业语义组件；真实项目采用前不拆独立包。

## 3. 范围

### In Scope

- 修复销售订单、工作台、主从工作区的来源与资产关联；
- 统一 `EPM-*`、`VAL-*`、Showcase 页面和 Demo 证据的投影关系；
- 当前切片所需语义色、排版、密度、间距、焦点、状态和文案；
- SchemaField、SchemaForm、EditableLineGrid、ValidationSummary、AsyncStateBoundary；
- 主从单据编辑模板；
- 销售订单交互验证；
- BOM 场景的跨场景适配复核；
- 自动检查、组件测试、浏览器验收和候选资产回流。

### Out of Scope

- 生产订单、BOM 或审批数据；
- 完整低代码设计器、完整 IAM、真实通知或工作流；
- 参考项目代码整仓复制；
- 发布独立 npm 包；
- 外部部署、Release Gate、真实项目采用或正式模式晋升。

## 4. 成功条件

1. 一个资产能从方法论登记册定位到来源、契约、门户页面、Demo、测试、成熟度和下一证据。
2. 销售订单可通过 schema 驱动表头与行表完成新增、修改、删除、撤销、校验、暂存和提交反馈演示。
3. BOM 场景复用相同核心契约；领域差异通过扩展点表达，不污染核心组件。
4. 基础规范、组件、页面模板与场景不是四套手工副本，而是同一资产关系的不同投影。
5. 所有结论只晋升到实际证据支持的成熟度。

## 5. 仍需 Gate 决策

- Specification Gate：可观察行为、失败边界、验收标准与测试设计。
- Architecture Gate：统一登记模型、组件目录边界、schema 解释策略、状态所有权和双场景适配方式。
- Release Gate：不在当前授权范围。
