# 企业工作台与主从工作区设计 Brief

> 状态：design-prototype；非项目 Spec，非 Gate 批准记录。

## 目标

让企业用户在一个连续上下文中完成两件事：先发现今天最重要的工作，再从任务队列选择对象、理解原因、查看业务摘要并执行下一动作。

## 推荐结构

1. **个人工作台**：问候与日期、四类可解释计数、我的待办、提醒与日程、快捷入口、异常关注。
2. **主从工作区**：左侧工作队列为“主”，中间对象详情为“从”，右侧行动上下文承载提醒、协作与关联任务。
3. **统一语义**：待办要求用户动作；提醒只改变注意力时机；预警表达规则异常；消息表达他人或系统的信息到达；审批是带业务状态机的特殊待办。

## 视觉基线

- 来源：`source-sales-order-and-shell.png`。
- 延续深色导航、浅灰画布、白色卡片、蓝色主操作、4—8px 圆角和高密度 10—13px 企业排版。
- 使用 Tabler 图标，不用 emoji、文本符号或自绘 SVG 代替功能图标。
- 1440×1024 为桌面验证视口；窄屏改为单栏顺序，不压缩到不可操作宽度。

## 核心交互

- 通过搜索、类型和优先级过滤工作队列；过滤无结果时给出可恢复空状态。
- 选择队列项后，详情、流程时间线和右侧关联上下文同步切换。
- “开始处理”“标记完成”“稍后提醒”提供即时、可撤销或可解释反馈。
- 新建个人待办需最小标题，成功后进入队列并成为当前项。
- 工作台的计数必须能由当前演示数据解释，不展示无来源 KPI。

## 左侧菜单抽象

| 菜单区 | 抽象资产 | 主要消费方 |
|---|---|---|
| 概览 | 应用/个人工作台 | 全角色入口 |
| 基础规范 | 令牌与可访问性基线 | 全部页面 |
| 基础组件 | 操作、输入、展示、反馈原语 | 全部模板 |
| 页面模板 | 列表、表单、详情、主从、工作台 | 业务模块 |
| 交互模式/状态/组合场景 | 行为契约与失败状态 | Spec、测试、原型 |
| 业务数据演示 | 模式组合后的领域适配器 | 实际项目候选 |
| 系统管理 | 树、关系、权限、审计和配置模板 | 平台管理场景 |

## 不纳入本原型

- 真实提醒调度、消息已读同步、工作流状态迁移、服务端权限和跨设备同步；
- 组织专属指标、审批规则、SLA 或业务对象字段；
- 将验证场结果直接声明为正式模板或最佳实践。
