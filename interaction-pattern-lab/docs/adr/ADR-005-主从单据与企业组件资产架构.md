# ADR-005：主从单据与企业组件资产架构

> 状态：accepted
> 日期：2026-09-05
> 关联：切片 `010-master-detail-document-assets`、`REQSRC-029`—`REQSRC-034`

## 背景

验证场已经有销售订单、工作台和主从工作区原型，但这些页面尚未形成可复用的企业组件契约；Showcase 页面引用也不能直接定位用户来源、EPM 资产、实现和 QA 状态。若直接从单一页面抽包，容易把销售订单或参考项目特性误当成通用能力，并形成方法论与门户两套登记事实。

## 决策

1. 继续采用验证场现有 `typescript-enterprise-web` v0.2，不新增 UI、表格、表单、状态库，不启用本切片不需要的服务端和数据库。
2. 采用“基础规范 → 原语适配 → 企业组件 → 页面模板 → 场景”五层架构，并禁止反向依赖。
3. SchemaForm、EditableLineGrid 和 MasterDetailDocument 使用受控 props、纯规则/reducer 与注入式 Scenario Adapter；React 视图不拥有不可观察的业务规则。
4. 场景 Adapter 为确定性纯内存实现；它可以模拟成功、校验失败、业务拒绝和部分成功，但不调用生产服务或持久化业务数据。
5. 先迁移销售订单，再以 BOM 的层级、匹配和差异能力做第二场景验证；BOM 专属行为只通过扩展点进入。
6. `_methodology/patterns/index.json` 保持唯一方法资产登记册；validation-slices manifest 记录验证覆盖，Showcase Registry 只记录页面装配及结构化追溯引用。
7. 当前不创建独立组件包，也不因本切片实现自动提升资产成熟度；包化和晋升等待双场景、浏览器 QA 与真实项目采用证据。
8. 采用渐进替换和可回指旧 Renderer 的回滚方式，避免重写既有销售订单原型。

## 备选方案

| 方案 | 结论 | 原因 |
|---|---|---|
| 继续维护三个独立原型 | 拒绝 | 无法证明组件契约复用，重复状态和失败语义会继续漂移 |
| 直接引入 Ant Design/AG Grid/Formily 等库 | 本切片拒绝 | 当前目标是验证中立契约，不是选择最终项目 UI 库；引入会扩大迁移和许可/适配边界 |
| 立即创建 workspace/npm 组件包 | 延后 | API 尚未经过 BOM 和真实项目采用，过早固化会增加兼容负担 |
| 把 Showcase Registry 变成完整资产登记册 | 拒绝 | 会与 `_methodology/patterns/index.json` 形成双源 |
| 用单一全局 store 管理表单与行表 | 拒绝 | 隐藏依赖和状态传播，不利于纯函数测试和场景替换 |
| 先做 BOM 再回改销售订单 | 拒绝 | 现有销售订单已有实现证据，更适合作为渐进迁移起点 |

## 后果

- 优点：组件行为可单测、页面装配可替换、场景规则隔离、追溯可自动检查，并保留技术栈中立的方法资产。
- 代价：同一能力需要维护中立模板、React 验证实现和投影校验三个层次；短期目录比单页原型更多。
- 限制：本轮不会证明生产服务事务、超大数据虚拟化、真实远程选择、并发编辑或第三方 UI 库兼容性。
- 复审条件：第三个差异显著场景、MCRM 真实采用、行数超过演示预算、接入真实 API 或需要发布组件包时重新评审。
