# ADR-004：数据库驱动导航与角色授权架构

> 状态：accepted（`REQSRC-020`）
> 日期：2026-09-03
> 关联：切片 `004-database-backed-navigation-rbac`、`REQSRC-017`—`REQSRC-019`

## 背景

历史切片 003 用前端 Registry 和内存身份验证了导航交互，但不能作为未来项目的权威授权实现。新边界要求菜单、页面操作、用户、角色、成员和权限进入数据库，并按目标系统由服务端执行授权，同时严格保持六类逻辑表和无数据权限范围。

## 决策

1. 采用 `typescript-enterprise-web` v0.2 的 React + NestJS + PostgreSQL + Prisma 模块化单体方向；以受控搬迁保留现有 Web，不运行覆盖式脚手架。
2. 六类权限表是唯一持久化授权模型；系统由配置白名单管理，本切片不增加 system/session/direct-grant 表。
3. 本地认证使用 Argon2id 密码哈希和短期 HMAC 签名 HttpOnly Cookie；服务端每次请求加载 ACTIVE 用户。
4. 使用集中式 `AuthorizationService` 计算 ALLOW 并集，PAGE 需要 MENU，ACTION 还需对应 ACTION grant；导航、直达路由和具体操作端点共用该服务。
5. 首片不缓存权限；导航在一致性事务中计算，并以有效结果稳定哈希作为 `permissionVersion`。
6. Prisma migration 是唯一 DDL 历史；数据库无法由 Prisma Schema 完整表达的约束进入同一 migration SQL，并由集成测试证明。
7. 服务故障默认拒绝，前端不得回退显示全量 Registry；历史 fixture 只用于测试和历史证据。

## 备选方案

| 方案 | 结论 | 原因 |
|---|---|---|
| 继续纯前端 Registry | 拒绝 | 无法形成服务端权威授权和数据库闭环 |
| 复制参考系统 IAM | 拒绝 | 会带入组织、租户、旧 Java 与账号旁路等非目标约束 |
| 增加 system/session/direct-grant 表 | 本切片拒绝 | 超出已批准六表和纯角色范围；有真实生命周期需求时重新开 Gate |
| JWT 存全部权限 | 拒绝 | 撤权不能在下一请求生效，且容易泄漏授权明细 |
| 通用 action execute API | 拒绝 | 弱化具体业务端点的输入和事务边界 |
| 权限应用缓存 | 首片拒绝 | 当前规模无需承担失效复杂度；先证明正确性与预算 |

## 后果

- 优点：授权链可审计、跨系统隔离明确、前后端契约可复用，管理员也没有账号旁路；
- 代价：需要把单包工程迁为 workspace，并用 raw migration 补充 Prisma 表达不足的数据库约束；
- 限制：签名 Cookie 无逐会话服务端撤销，系统白名单无数据库生命周期管理；二者在生产化前必须重新评审；
- 验证：空库迁移、种子约束、API 安全、撤权下一请求、前端回归与固定数据集性能测试全部通过后，才能进入 Release 评审。
