# ADR-003：认证式导航展示壳层架构

> 状态：accepted
> 日期：2026-09-03
> 关联功能：`003-authenticated-enterprise-navigation-shell`
> 决策 Gate：Architecture Gate approved（`REQSRC-016`）

## 1. 背景

切片 003 已批准用中性企业导航壳层演示主菜单、底部系统管理、`admin/viewer` 和菜单/路由/页面/操作四层权限。现有 Lab 已有稳定的 103 项分类目录、三个 Demo Adapter 和切片 002 的本地验证证据；直接替换根 App 会把新候选的风险扩散到已验证能力。来源系统实现包含其自身菜单接口、状态和品牌，不适合作为目标架构。

## 2. 决策驱动因素

- 保持切片 002 和 103 项目录入口、深链、测试与 Release 状态独立；
- 静态构建可直接打开门户链接，不依赖服务器重写；
- 菜单、路由、只读和操作必须共享单一 capability 语义；
- 刷新、退出和重置必须清除模拟身份和页面状态；
- Registry 必须可检查、可追溯、无来源项目文案；
- 当前只有一个 React 应用和两个固定角色，不应引入生产 IAM、插件平台或通用渲染器；
- 候选只在 Lab 验证，不能静默晋升方法论资产。

## 3. 备选方案

| 方案 | 优点 | 代价与风险 | 结论 |
|---|---|---|---|
| A. 直接替换现有 App 根壳层 | 最接近最终门户 | 回归面大；候选与已验证目录耦合；回滚困难 | 不采用 |
| B. 并行 Hash 入口 + 新壳层模块 | 静态直达、隔离清晰、无新依赖、回滚简单 | 暂时存在两个入口；后续成为默认入口需再评审 | 采用候选 |
| C. 引入 React Router 和全局状态库 | 路由与状态范式成熟 | 当前规模不需要；新增依赖和迁移风险 | 暂缓 |
| D. 复制来源项目菜单组件与权限体系 | 视觉接近、初期快 | 带入品牌、接口、缓存、组织 IAM 和旧实现约束 | 禁止 |
| E. Schema 驱动通用页面渲染器 | 长期配置能力强 | 超出首片范围；难以诚实表达复杂交互 | 暂缓 |

## 4. 决策

1. 新门户使用 `#/showcase/*` 并行入口；默认路径和现有 `?pattern=` 语义保持不变。
2. 门户身份状态使用切片内 React Context + reducer，仅驻留内存；不使用任何浏览器持久化或远端认证。
3. 建立 Lab 内 Registry v1，以 JSON + JSON Schema + Node 跨引用校验器登记菜单、页面、路由、capability、角色、renderer、icon key 和来源引用。
4. 建立无副作用 Access Resolver。`admin` 通过集中式 `all-registered` 角色绑定获得全部 Registry capability；`viewer` 只获得显式绑定。
5. 权限过滤顺序固定为 session gate → capability set → visible menu → search → route/page/action；身份切换销毁门户子树。
6. Hash Router 只服务 Showcase 子树，不引入路由库。页面 renderer 由静态 Adapter Map 解析，不执行 Registry 中的模块路径。
7. 图标使用本切片中性内联 SVG Registry；数据只持有稳定 key，未知 key 阻断校验。
8. 样式使用 `--showcase-nav-*` 和 `.showcase-*` 作用域，不覆盖既有 `--ipl-*` 或历史 Demo 样式。
9. 扩展现有隔离校验到 Showcase 源码，禁止网络、持久化、远端 URL 和凭据调用；验证继续使用 Vitest、Testing Library 和真实浏览器任务。
10. 本切片不创建方法论正式 UI 资产登记册；`UID-001` 保持候选，只有实现/交互证据形成后再单独评审回流。

## 5. 与既有 ADR 的关系

- ADR-001 的 React/Vite 静态单包、无后端、错误隔离和 Demo 不持久化原则继续有效；
- ADR-002 的方法论登记册、生成式目录投影、validation-slices manifest 与现有 Demo Registry 继续服务 103 项分类目录；
- ADR-003 不替代 ADR-001/002，只新增并行 Showcase 边界。若未来门户替换默认入口，必须复审三者的应用根和资产入口职责。

## 6. 后果

### 正面

- 新候选不会直接破坏已验证目录；
- 静态链接可直达且无需服务器配置；
- 权限语义集中、可做纯函数和契约测试；
- admin 新能力覆盖与 viewer 显式授权都能自动检查；
- Registry 可审查菜单完整性、禁用词、来源和 Adapter 映射；
- 无后端和数据迁移，回滚路径短。

### 代价

- 验证期存在默认目录与 Showcase 两个入口；
- 手写 Hash 路由仅适合当前有限范围；
- JSON Schema 之外仍需 Node 校验器处理跨引用和禁用词；
- Context、导航和页面 Adapter 需保持模块边界，避免重新长成单一 App 组件；
- 真正接入生产认证或远端菜单时不能直接复用模拟授权模块。

## 7. 复审条件

- Showcase 获准成为默认入口或替换现有根布局；
- 出现第二个应用消费 Registry；
- 页面超过当前说明页/固定 Adapter 模型，Hash 路由或静态映射成为维护瓶颈；
- 需要服务端渲染、浏览器 history path 或服务器重写；
- 接入真实账号、服务端权限、远端菜单、数据库、审计或多租户；
- `UID-001` 进入资产晋升评审；
- 新增运行时依赖或正式 UI 资产登记册。
