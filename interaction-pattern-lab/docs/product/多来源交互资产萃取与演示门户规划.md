# 多来源交互资产萃取与演示门户规划

> 状态：`database-backed-navigation-architecture-approved`
> 版本：0.5
> 日期：2026-09-03
> 来源：`REQSRC-013`、Q1—Q27 与 `REQSRC-017`；历史 Gate：`REQSRC-014/015/016`
> 适用范围：方法论 Review、多来源候选萃取、通用 UI 资产治理、演示门户规划

## 1. 目标

1. 建立一套从既有系统源码、页面原型和截图中萃取交互资产的方法、步骤、规范和证据模型。
2. 将验证后的主题、组件、页面模板和交互模式沉淀为可供新项目选择的资产；没有新增交互问题时优先复用既有资产。
3. 在现有验证场内提供可运行的演示门户；导航交互可先作为 Demo 验证，但被选为未来可直接采用的能力时，菜单、操作和角色授权需形成前后端与数据库闭环。
4. 保持来源证据与正式资产分离：来源层可记录真实项目名，正式资产名称、示例字段和用户可见文案必须去来源项目化。

## 3. 多来源萃取流程

```text
来源登记与版本固定
→ 为本次页面选择明确来源
→ 源码/路由/样式/测试取证
→ 截图视觉核对
→ 事实、推断、未知和冲突分离
→ 形成候选主题/组件/页面模板/交互模式
→ 验证场最小切片
→ implementation/interaction 证据
→ 人工评审后晋升正式资产
→ 新项目自主决定采用、调整或拒绝
```

每次页面生成前必须创建 `source-selection.md`，至少写明：目标页面、选择的来源、版本点、具体文件、保留内容、排除内容、冲突、授权范围和未选来源。没有选择记录时不得把多个来源静默拼接。

## 4. 资产模型

### 4.1 交互模式登记册

继续使用 `EPM-PAGE-*`、`EPM-ACT-*`、`EPM-VIEW-*`、`EPM-STATE-*`、`EPM-SPECIAL-*` 和 `EPM-SCENE-*` 描述用户任务与行为。

### 4.2 UI 资产登记册

待 Architecture Gate 和方法论变更评审后，独立建立：

- `UI-THEME-*`：语义颜色、排版、间距、密度和视觉状态；
- `UI-COMP-*`：组件行为、状态、可访问性和接入契约；
- `UI-TPL-*`：页面结构、字段槽位、动作、状态和权限能力组合。

UI 资产通过 `relatedEpmIds` 关联现有交互模式，不修改或手工扩充生成的 EPM 索引。

## 5. 演示门户目标结构

```text
企业页面模板展示
├── 概览
├── 基础规范
├── 基础组件
├── 页面模板
├── 交互模式
├── 页面状态
├── 组合场景
└── 系统管理（固定在导航底部）
    ├── 用户管理
    ├── 角色管理
    ├── 权限策略
    ├── 菜单管理
    ├── 操作日志
    └── 资源目录
```

左侧导航采用“上方业务/资产菜单 + 底部管理菜单”的稳定结构。品牌、菜单搜索、折叠、激活、展开、底部分隔和滚动边界属于壳层能力；菜单文字、路由和 capability 由演示门户配置提供。

## 6. 权限边界

- 原纯前端版本以 `admin/viewer` 的内存 capability 验证隐藏、禁用、只读和路由拒绝，证据保留；
- `REQSRC-017` 要求目标版本由数据库保存菜单、操作、用户、角色和角色权限，并由服务端按目标系统与当前用户角色返回；
- 权限只授予角色，禁止用户直授权；admin 必须加入系统管理角色，不得使用账号或用户级超级管理员旁路；
- 表级、行级、字段级和组织范围数据权限不在本轮；
- 新模型与目录约定见 `.specify/requirements/004-database-backed-navigation-rbac/`。

## 7. 首个候选切片

首个候选为“带底部管理分组的企业导航壳层”。原纯前端边界曾由 `REQSRC-014/015/016` 批准并完成 `TASK-401`—`TASK-406`；`REQSRC-017` 改变数据、认证与服务边界，`REQSRC-018/019/020` 已批准 Business、Specification 与 Architecture Gate。切片 004 当前可创建新 Tasks；旧 TASK-407/Release 继续暂停。

实现、工程检查和真实浏览器验收完成前，不宣称候选已通过实现或交互验证。

## 8. 成熟度与停止条件

候选遵循 `candidate → implementation-verified → interaction-verified → project-adopted → business-validated → released`。验证场最多独立提供实现和交互证据。

出现以下情况时停止晋升：来源冲突未说明、正式文案残留来源项目术语、字段或权限绑定旧系统、只有截图没有源码证据、未覆盖失败/无权状态，或相关 Gate 未批准。
