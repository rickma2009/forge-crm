# 参考资产复用指南

> 版本：v0.2  
> 更新：2026-08-29

## 1. 参考资产的定位

`_ref/` 中的内容都是证据和素材，不是规范源。参考项目可能正在建设，包含历史包袱、特定组织约束、未完成迁移或错误示范。

特别说明：`_ref/gf_scm/` 当前仍在建设，不是最佳实践项目。其 Java 遗留模板、旧前端技术栈、业务专用组件、CAS/数据库/部署约束不得默认进入新项目。

## 2. 复用分级

| 级别 | 方式 | 适用内容 |
|---|---|---|
| R0 阅读 | 只用于理解问题和方案 | 业务代码、事故记录、旧设计 |
| R1 抽象 | 提炼原则后重写 | 开发经验、流程、检查清单 |
| R2 改造 | 复制后清理和验证 | 小型工具、通用配置 |
| R3 直接复用 | 版本固定并有自动测试 | 已产品化共享包、稳定模板 |

`gf_scm` 默认按 R0 或 R1 处理。升级为 R2/R3 必须有明确评审证据。

## 3. 标准流程

```text
明确需求 → 定位候选资产 → 判断复用等级 → 识别依赖和风险
        → 去业务化改造 → 自动验证 → 记录来源 → 项目评审
```

复制前检查：

- 当前需求是否真的需要；
- 是否包含旧技术栈或旧项目名称；
- 是否依赖私有服务、组件、数据库或环境；
- 是否带入安全策略、授权假设或敏感配置；
- 许可证和维护责任是否明确；
- 新写一个小而清晰的实现是否成本更低。

## 4. 禁止直接复制

- `gf_scm/.specify/` 中的模板和提示词；
- `gf_scm/AGENTS.md` 和 constitution；
- Java、Spring、MobX、React 17 等历史模板片段；
- 业务模块、数据库 schema 和 API 契约；
- CAS、Apollo、ws-cli、特定 schema 等组织或项目约束；
- 带密钥、Token、真实数据或内部地址的配置和文档。

新项目的 SDD 模板只能来自 `_methodology/templates/`。

## 5. 复用记录模板

```markdown
## 复用记录：<资产>

- 来源：<路径 + commit/tag/日期>
- 复用等级：R0 / R1 / R2 / R3
- 解决的问题：<关联 REQ/ADR>
- 保留内容：<抽象后的能力>
- 删除内容：<业务、技术栈和环境耦合>
- 风险：<安全、依赖、维护、许可证>
- 验证证据：<命令、测试或评审>
- 负责人：<name>
```

## 6. 经验回流

经验进入 `_methodology/` 必须满足：

1. 已去除项目名称和特定业务语义；
2. 写清适用条件与不适用条件；
3. 至少经过一个实际切片验证；
4. 有来源和版本记录；
5. 不与现有通用原则冲突。

未经验证的经验只记录在项目 `_build-log/` 或项目 ADR 中。

## 7. 参考案例候选区

`reference-cases/` 用于保存“有证据、已去项目化、但尚未经过真实切片实现验证”的 R1 萃取报告。它属于方法论的参考区，不是模板、规范或可直接复制资产。

- `reference-cases/gf-scm-auth-permission-distillation.md`：从 `gf_scm` 认证与权限材料中提炼公共候选实践，同时记录不适合继承的策略和实现缺口。

候选实践只有在真实项目中通过 Spec、Architecture、实现和安全测试后，才可以迁入 `patterns/`。
