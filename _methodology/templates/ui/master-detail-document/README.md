# 主从单据候选模板

状态：`implementation-verified`（仅 interaction-pattern-lab 的销售订单与 BOM 确定性场景）；不是正式模式、真实项目采用、业务验收或 Release。

## 问题与不变量

适用于一个对象头与可编辑明细行需要共同校验、汇总、暂存和失败恢复的任务。头字段、行、选择、删除撤销、保存状态和错误定位必须是受控且可观察的；行身份稳定，已保存行删除与草稿删除语义不同，保存中不允许改变保存快照或重复提交。

不适用于独立低频表单、全屏复杂设计器、没有明确行语义的自由文本，或尚未由项目 Spec 定义事务、权限、并发和审计的真实业务写入。

| 分类 | 内容 |
|---|---|
| 来源事实 | `REQSRC-029` 要求销售订单表头/网格/BOM 候选；`REQSRC-030` 要求保留主从上下文。 |

| 已批准项目决定 | `ADR-005` 批准五层依赖、确定性内存 Adapter 和 sales-order 后 BOM 的验证顺序。 |
| 当前未知 | 真实服务端权限、事务/并发、审计、行业字段、金额口径及浏览器 QA。 |

可复用 core：语义令牌、受控字段、错误摘要、稳定行 reducer/grid、异步 outcome 与单据状态契约。场景专属：销售订单客户/税/交期，BOM 层级/物料候选/差异。组织角色、来源项目代码、数据库/API 与品牌样式均不复用；单一来源不是“最佳实践”。

## 接入与验证

1. 在目标项目 Spec 映射对象、行、权限、状态、失败和 `REQ/AC/TC`；替换示例字段与令牌。
2. 以项目 Adapter 接入服务端授权、事务、并发、审计与回滚；不要把验证场内存结果当生产结果。
3. 验证新增、候选、复制、草稿删除、标记删除/撤销、行/表头错误键盘定位、保存中锁定、校验失败、业务拒绝、部分成功和离开取消。
4. 演示必须使用固定 fixture/序号 ID、无网络/存储、可 reset；超出场景预算时拒绝操作并说明降级。
5. 回滚：保留旧项目页面/路由绿线，切换回旧实现而不删除契约测试；记录差异后才可考虑成熟度变更。

键盘焦点必须可见：Tab 进入控件，Enter 进入/提交编辑，Escape 取消，摘要能将焦点移至第一个可操作错误；查看、禁用和不可操作错误都要有真实可聚焦说明。
