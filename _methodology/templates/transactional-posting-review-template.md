# 单据过账采用与验证记录

状态：待填写。适用于库存、资金或其他由单据引起余额变化的流程；业务规则由目标项目确认。本模板不表示方案已批准或已通过测试。

| 项目 | 目标项目决定与证据 |
|---|---|
| 来源需求、业务对象与唯一写入模块 | 待填写；其他模块通过什么接口调用 |
| 余额唯一粒度 | 待填写；租户、法人、仓库、物料、批次等维度是否适用 |
| 批次/单位/币别 | 待填写；不适用的维度如何规范化，避免空值与空字符串形成不同粒度 |
| 审批与过账关系 | 待填写；审核即过账还是分别执行，谁可提交/审核/冲销 |
| 状态与版本前置条件 | 待填写；失效、重复、过期版本及跨作用域请求如何处理 |
| 原子写入范围 | 待填写；单据、余额、明细流水、来源履约和幂等结果是否同事务 |
| 幂等作用域与载荷比较 | 待填写；同键同请求、同键不同内容、不同操作者以及结果重放策略 |
| 并发冲突 | 待填写；锁/版本/条件更新/隔离级别、唯一约束，以及冲突后允许的重试方式 |
| 金额与舍入 | 待填写；定点精度、尾差归属、全量结清与零余额金额 |
| 来源追溯 | 待填写；来源单据、来源行 ID、行号、事务类型、操作者和时间 |
| 冲销语义 | 待填写；使用原成本还是重计价、全单/部分、反向流水、来源数量回写 |
| 对账公式 | 待填写；期初 + 有效事务净变动 = 当前余额，范围与期间必须一致 |
| 迁移与历史数据 | 待填写；旧单据缺行号/批次/流水的处理，不编造历史事实 |
| 采用/适配/排除 | 待填写；只复制已确认的不变量，不直接照搬来源表名与状态 |

## 最小验证矩阵

每项填写“未执行 / 通过 / 失败 / 不适用 + 原因”，附环境、命令和实际输出；mock、数据库事务、浏览器证据分开。

| 场景 | 要观察的结果 | 实际证据 |
|---|---|---|
| 正常过账 | 余额、流水、单据和来源履约一致 | 未执行 |
| 余额不足/非法批次/失效物料 | 无任何部分写入 | 未执行 |
| 同键同请求重复提交 | 无重复业务影响，响应语义明确 | 未执行 |
| 同键同请求同时提交 | 业务影响次数与响应成功/冲突分别检查；明确失败方能否安全重试 | 未执行 |
| 同键不同请求内容 | 明确拒绝或执行已批准规则 | 未执行 |
| 两笔竞争同一余额/订单余量 | 不超库存、不超来源余量，失败可解释 | 未执行 |
| 写完第一行后第二行失败 | 先证明第一行确实执行，再检查所有行和幂等结果均回滚；区别于输入校验阶段失败 | 未执行 |
| 写流水/更新来源时失败 | 余额及单据状态不发生半成功 | 未执行 |
| 冲销与重复冲销 | 对应原交易恢复一次，原流水仍保留 | 未执行 |
| 调整前后对账 | 按相同维度与币别核对数量及金额 | 未执行 |

不能用“调用了 transaction”代替事务回滚测试，也不能用一次顺序调用代替并发测试。优先在隔离数据库使用合成数据；将初始化、清理与验证结果分别记录，不为演示直接修改共享业务余额。
