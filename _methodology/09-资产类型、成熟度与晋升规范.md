# 资产类型、成熟度与晋升规范

> 版本：v1.1
> 更新：2026-10-03

## 1. 目的

本规范防止把“有想法、有 Demo、有代码”混称为可复用模板。每项资产必须同时声明类型、来源、适用边界、成熟度和证据；缺少任一项时不得晋升。

## 2. 五类资产

| 类型 | 主要内容 | 权威位置 | 不应承载 |
|---|---|---|---|
| 方法规则 | 生命周期、Gate、追溯、来源治理、检查规则 | `_methodology/*.md`、`scripts/` | 具体项目业务决策 |
| 项目起步包 | 技术栈中立治理骨架、可选技术 Profile、初始化器 | `_methodology/project-init/`、`profiles/` | 未批准的业务字段和架构默认值 |
| 交互模式 | 问题、行为、状态、边界、案例、接入与验收 | `_methodology/patterns/`、`templates/ui/`、`examples/` | 单纯截图、品牌专属样式 |
| 通用能力包 | 稳定接口、失败行为、测试契约与可安装实现 | 后续建立的能力包注册表 | 单项目复制代码、组织专属集成 |
| 参考案例 | 来源事实、支持推断、不可复用项和验证记录 | `_methodology/reference-cases/` | 未经验证的“最佳实践”结论 |

通用能力包在项目初始化器和资产回流闭环稳定前保持候选，不为凑目录提前建设。

## 3. 统一成熟度阶梯

| 状态 | 含义 | 最低证据 |
|---|---|---|
| `idea` | 尚未形成可评审资产 | 问题描述 |
| `candidate` | 已定义边界和验收，但尚未实现验证 | 来源、适用/不适用边界、验收草案 |
| `implementation-verified` | 在明确环境中实现并通过工程检查 | 代码位置、测试/构建结果、版本点 |
| `interaction-verified` | 关键交互在浏览器或等价真实界面中验证 | 场景、环境、交互结果和缺口 |
| `project-adopted` | 被至少一个独立真实项目显式采用 | 项目决策、接入记录、回归结果 |
| `business-validated` | 目标角色完成业务验收或指标验证 | 用户验收、业务反馈或指标证据 |
| `released` | 通过 Release Gate 并有可定位发布点 | 发布批准、版本、部署与回滚证据 |
| `deprecated` | 不再推荐采用但保留迁移与反例信息 | 原因、替代方案、影响范围 |

成熟度不是单向自动累计：边界变化、关键证据失效或验证范围被证明不足时，应降级或重新打开对应 Gate。历史证据保留，不改写成当前事实。

## 4. 晋升规则

1. 原型只能回答探索问题，不得直接标为 `implementation-verified`。
2. 验证场可以提供 `implementation-verified` 和 `interaction-verified` 证据，但不能独自证明 `project-adopted` 或 `business-validated`。
3. 真实项目采用必须记录采用了什么、排除了什么以及项目级决策，不能因引用模板自动晋升。
4. `released` 必须绑定真实 Release Gate 和版本点；本机预览不等于发布。
5. 任何晋升同时更新 pattern/reference、模板或案例、自动检查和资产索引；无法同步时保持原成熟度。

## 5. 证据卡最小字段

- `assetId`、类型、当前状态和更新时间；
- 问题、适用边界、不适用边界；
- 来源定位与不可复用项；
- 验证项目、切片、环境、版本点；
- 已通过项、未通过项、当前未知；
- 下一成熟度所需证据。

不得用单一 `validated-once` 覆盖实现、交互、项目采用和业务验收之间的差异。旧资产迁移时应拆成上述维度，并保留旧标签作为历史兼容信息。

## 6. 复用范围与规范迭代

“项目内可调用”说明当前工程存在公共源码、接口和实际调用，不等于“跨项目可直接复用”。资产对外展示复用能力时必须标明范围：仅本项目、候选跨项目采用、已有独立项目采用，或已发布能力包。截图、接入片段和单项目测试可以支持本地实现证据，却不能代替独立项目的采用记录。

准备跨项目采用时，使用采用记录区分 `adopt / adapt / reject`，记录依赖、权限、业务数据契约、回归命令及目标项目差异。技术规范变化时保留来源、影响范围、兼容/迁移说明、验证证据和复审条件；更新对应模板、示例和检查，再调整资产登记成熟度。原规范仍可作为历史版本查证，不把新规则追认到尚未验证的旧资产。

本次修订源于 Forge CRM 长期目标 `REQSRC-090` 与组件目录标注核对：组件可在本项目按源码调用，但目录尚无独立项目采用证据，故保持 `candidate`。v1.1 不改变既有资产的成熟度或发布状态。
