# 《企业工作区与可配置列表系统蒸馏萃取报告》

## 1. 系统总览

### 1.1 系统定位与核心目标

本轮聚焦登录后应用壳层和标准列表工作面：统一菜单、全局工具栏、路由多页签、系统/个人视图、数据字典与一个客户目录验证案例。目标是识别可跨项目复用的职责和不变量，而不是搬运来源业务页面。

### 1.2 解决的业务问题

它解决多页面系统中入口切换、并行任务、重复列表搭建、用户个性化查询和枚举口径分散的问题。系统视图给出受控基线，个人视图保存使用偏好，数据字典统一选项来源。

### 1.3 输入、输出与业务边界

输入包括已授权菜单、当前会话、路由、系统/个人视图、查询条件、字典项和业务记录；输出为可导航工作区和可持久化列表操作。本轮不包含数据范围权限、员工主数据、通知业务后台或生产部署。

### 1.4 材料范围与可信度

主证据为 `_ref/gf_scm/` 读取时源码与 Prisma Schema，提交基线 `3c8b6930...`，工作区存在未提交改动。在线客户页只确认可打开和标题，DOM 核验超时，因此没有把在线视觉作为事实。

## 2. 业务框架

### 2.1 业务域与能力模型

能力分为应用导航、工作区会话、列表呈现、视图偏好、基础字典和客户目录六部分。导航和页面操作受角色授权；视图控制呈现与查询偏好，不代替权限；字典提供稳定业务枚举。

### 2.2 端到端业务流程

`登录 → 按系统/角色取得菜单 → 点击菜单建立或激活页签 → 解析该页面可用系统/个人视图 → 装载查询栏与列 → 读取字典/远程选项 → 服务端分页查询 → 新增/编辑客户 → 返回列表并保持工作区状态`。

### 2.3 核心业务实体及关系

菜单页面拥有操作；角色拥有菜单与操作。列表页面拥有系统视图，角色获得可用系统视图，用户可从获授权基线派生个人视图和当前选择偏好。字典类型包含字典项；客户引用稳定字典值并保存销售选择快照。

### 2.4 规则、约束与例外

- 系统管理只是普通菜单组，不再拥有特殊布局或授权语义；
- 工具栏跨页常驻，页面切换不销毁其结构；
- URL 决定当前页签和页面，页签不能形成第二套路由事实；
- 个人视图不能扩大系统基线；每个列表必须有可解析的默认系统视图；
- 字典停用不等于删除历史含义；
- 客户首版没有删除和数据范围权限。

## 3. 系统应用架构

### 3.1 整体分层架构

候选分为壳层组合层、路由页签层、授权与视图解析层、列表页面层、基础数据服务层和业务验证层。通用层不依赖客户字段，客户模块只提供资源字段、查询和表单契约。

### 3.2 核心模块及职责

- `Layout.tsx`：来源顶栏、菜单与工作区组合；
- `TabBar.tsx` / `tab-store.ts`：路由派生页签；
- `ListPage/**` / `SearchForm/**`：标准列表和查询；
- `ResourceViewConfig.tsx`：系统视图管理；
- `AuthResourceView` / `AuthRoleViewAssignment` / `UserListView`：视图持久化；
- `settings/dict/**` / `modules/system/dict/**`：字典管理与消费；
- `opportunities/customers/**` / `modules/customer/**`：业务验证案例。

### 3.3 模块协作与调用关系

壳层从授权 API 得到菜单；路由同步器把路径映射为页签；列表页面从授权快照得到可用视图，再由视图解析器约束列和查询字段；字典与远程 Provider 提供选项；业务 API执行分页和写入。

### 3.4 数据流与控制流

菜单和操作权限先于页面呈现。视图解析失败时列表进入可恢复错误而非全字段降级。用户保存个人视图后刷新授权/视图快照；客户写入成功后刷新当前列表查询。

### 3.5 边界

来源的外部 IAM、字典平台、组织服务和 OMS/SCRM 均位于排除边界。目标验证场使用本地 PostgreSQL 和已有角色授权闭环，只抽取接口职责与失败语义。

## 4. 技术框架与技术栈

### 4.1 技术栈总览

来源和目标验证场均可由 React、NestJS、PostgreSQL 与 Prisma承载，但正式候选先以行为契约、数据不变量和验收条件表达，避免把技术选择误当成业务模式。

### 4.2 关键技术组件及作用

路由负责 URL 状态；页签 Store 保存派生会话；列表组件组合搜索、工具栏、网格和分页；JSON 保存列与过滤树；关系表控制角色可用系统视图；字典消费接口批量解析选项。

### 4.3 核心目录职责

目标项目的执行迁移仍只放 `packages/server/prisma/migrations/`，Schema 为当前模型，种子建立默认视图、字典和客户样本；方法论目录只保留候选证据，不能成为第二份可执行 SQL。

### 4.4 数据、集成与中间件

客户查询使用服务端分页/过滤/排序；销售选择通过可替换搜索 Provider 返回稳定键与显示名。首版 Provider 可由后端配置样本驱动，不建立员工表或伪造外键。

### 4.5 构建、部署与运行模式

本轮仅形成候选和 Business Gate 材料。后续分片将在现有 monorepo 中增量迁移、构建和测试；没有获得外部部署批准。

## 5. 核心设计思想与实现方法论

### 5.1 架构模式与设计原则

稳定壳层与可变页面分离；权限与视图分离；系统基线与个人偏好分离；字典管理与业务消费分离；通用列表与领域字段分离。

### 5.2 关键实现策略

先将来源事实转为中性契约，再用一个小客户域验证。默认视图、字典种子和客户样本都通过版本化迁移/种子建立；任何空权限、视图异常或字典失效都有显式失败行为。

### 5.3 核心架构决策候选

| 决策 | 收益 | 代价/风险 | 当前状态 |
|---|---|---|---|
| 普通菜单单树，不设管理专区 | 数据、渲染和授权模型统一 | 失去固定管理入口的空间提示 | 用户已提出，待 Business Gate |
| URL 驱动多页签 | 刷新、深链和浏览器历史一致 | 页签归并规则需严格测试 | 候选 |
| 系统视图为角色基线，个人视图只能收窄 | 兼顾治理与个性化 | 多三类数据关系和解析复杂度 | 候选 |
| 本地字典为事实源 | 可独立运行和复用 | 需要版本、引用和停用策略 | 候选 |
| 销售使用 Provider + 快照 | 不阻塞员工模块 | 暂无参照完整性 | 候选 |

### 5.4 可复用的方法论

每个新列表先声明资源字段、可查询性、默认系统视图和业务操作，再绑定字典/远程选项；不得先复制页面后补权限。来源实现中与外部平台耦合的部分标为排除证据。

## 6. AI/LLM 设计与落地思路

### 6.1 AI 定位

运行时不需要 AI。AI 只参与来源萃取、候选契约生成、字段映射建议和测试清单生成。

### 6.2 Agent 或模型执行链路

`选择来源 → 固定版本 → 读取源码/Schema/测试 → 区分事实/推断/未知 → 生成候选 → 建立需求 Gate → 实现与验证 → 决定是否晋升`。

### 6.3 Prompt、Skill 与上下文设计

每次生成列表页面前必须提供选用的来源记录、字段清单、角色操作、默认视图和字典映射；不得从来源业务字段自动扩展目标范围。

### 6.4 与业务代码的约束

权限、字典有效性、客户唯一性、视图收窄和数据库写入均由确定性服务端代码验证；AI 不参与运行时授权和数据写入决定。

### 6.5 容错、评测和边界

AI 无法访问真实数据库时必须说明，只能读取仓库中的 Schema/SQL。浏览器快照失败时不得宣称视觉一致。候选的跨项目价值需通过真实采用证据验证。

### 6.6 辅助设计证据

本报告由用户明确要求 AI 萃取和规划；这不是运行系统含 AI 功能的证据。

## 7. 现存局限、问题与演进建议

### 7.1 当前局限

在线页面未完成 DOM/视觉核验；工具栏通知数据源未定义；个人视图和字典尚未在验证场实现；004 双区模型与新目标冲突。

### 7.2 近期改进

先批准总业务包，随后依次实现壳层、多页签、字典、列表视图和客户目录，每片独立 Specification/Architecture/Release 验收。

### 7.3 中期演进

用第二个非客户列表验证默认视图复用，再决定把列表和字典候选晋升为正式模式或项目模板。

### 7.4 长期方向

接入真实通知、员工目录和数据范围权限；这些都必须作为独立需求，不得由 Demo 静默演化为生产承诺。

## 8. 附录

### 8.1 术语

- 系统视图：由管理员维护、作为角色可用列表基线的视图。
- 个人视图：用户基于获授权系统视图保存的收窄配置。
- 选择偏好：用户在一个列表范围内最近选择的视图。
- 销售 Provider：不要求员工表、可替换的远程搜索选项接口。

### 8.2 证据索引

详见同目录 `source-selection.md` 与 `evidence-matrix.md`。

### 8.3 可复用性结论

可复用的是职责分离、默认解析、收窄规则、失败行为和验收方式；不可复用的是来源品牌、外部平台、组织模型、客户字段全集、硬编码枚举和旧数据库命名。

### 8.4 2026-09-04 增量验证

客户目录切片进一步确认：查询栏不应由业务页面自行决定换行和折叠，而应由视图字段的 `queryVisible/queryCollapsed` 与统一的“首屏最多 3 项”规则生成；当前视图、设置、记录数和刷新属于列表功能区，不属于页面标题。来源的 `SearchForm`、`ListPage` 与 `ColumnViewSettings` 支持这一结论。验证场只复用交互契约和失败边界，未复制 Ant Design 组件、来源品牌或组织专属字段。
