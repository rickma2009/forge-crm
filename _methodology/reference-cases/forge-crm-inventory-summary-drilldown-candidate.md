# 汇总—维度明细—事务追溯候选案例

> 来源项目：Forge CRM，库存管理切片 024  
> 资产分类：参考案例；对应分类 `EPM-SCENE-007` 的一部分  
> 当前状态：`candidate`。当前项目实现和组件测试提供证据，但尚无独立项目采用或业务验收；不宣称行业最佳实践。  
> 来源要求：`.specify/sources/REQSRC-089-current-inventory-transaction-pages-20261003/source.md`

## 要解决的任务

库存使用者先看物料在当前筛选范围内的数量和金额，再定位该物料落在哪些法人、仓库和批次，最后通过出入库事务找到改变余额的来源单据与行。三层信息的粒度不同，不能把汇总行误当成一条可编辑的库存记录。

## 来源事实、推断和未知

| 类型 | 结论与定位 |
|---|---|
| 用户明确要求 | 七项条件同一查询行；上表按物料汇总，下表选中前为空、点击物料后联动；事务页独立查询并展示来源行号。见 `REQSRC-089`。 |
| 实现事实 | `InventoryService.inventorySummary` 按物料编码与币别汇总余额；`listBalances` 按所选物料、币别和原筛选条件返回法人/仓库/批次余额；`listTransactions` 查询事务。前端见 `InventoryStockPages.tsx`。 |
| 实现事实 | 七项条件与事务筛选均调用公共 `RecordQueryBar layout="singleRow"`；字段区横向滚动并保留查询操作可见。默认查询栏仍采用响应式换行。 |
| 实现事实 | 余额唯一维度为租户、法人、仓库、物料编码、批次；事务记录保存来源单据 ID、单据号、来源行 ID 和行号。见 `schema.prisma`、入库与销售出库过账代码。 |
| 可支持的推断 | 汇总与维度明细分开有利于用户逐层缩小核对范围；事务独立页面可保留完整时间序列，不受当前余额聚合掩盖。此为设计判断，尚未经过目标用户任务实验。 |
| 当前未知 | 数据量扩大后的查询时延、跨页导出的耗时与一致性、实际用户完成库存差异核对的效率、其他行业的成本计价和跨币别口径。 |

## 可复用的行为契约

1. 先定义**余额粒度**和**事务粒度**。余额是当前状态，事务是增减过程；两者都要明确租户/组织范围、计量单位、金额币别和时间口径。
2. 汇总行有稳定选择键。点击后明细必须沿用上表已提交的筛选条件，并附加所选键；筛选改变时清空旧选择，避免展示与上表不一致的明细。
3. 下表未选择时保持空，不用全量明细填充；加载、无记录和失败是不同状态。汇总与明细分别分页。
4. 不同币别金额不能直接相加。若对象的单位可能不同，数量也要先换算到同一基准单位，或按单位分别汇总。
5. 导出范围应与已提交的查询条件一致，说明导出的是汇总还是所选对象明细；权限、数据范围和金额口径与页面一致。
6. 事务至少关联来源单据和来源行；发生时间、事务类型、维度、数量与金额增减可用于与余额核对。过账和冲销规则由业务单据决定，不由列表组件推断。

## 适用边界与排除项

适用：多维度数量或金额余额、上层聚合与下层记录有稳定映射、需要从余额追溯到变更事件的企业查询场景。例如库存、应收余额、额度或配额，但各场景要重新定义维度和计价口径。

不适用：要求实时跨来源一致快照但没有读一致性设计；汇总键无法稳定对应明细；只需单表浏览；数据量大到必须由服务端异步生成导出文件的场景。

保留：查询条件继承、延迟加载明细、选择变化清空旧结果、粒度说明、币别隔离、来源行追溯、分层验收。

排除：Forge CRM 的物料分类、菜单编码、React 组件实现、Prisma 模型、当前权限角色、演示数据、仓库及批次字段的固定集合。

## 当前实现的限制与改进触发

- 汇总接口当前取得全部分组再切片分页；数据量增长时应改为数据库端分页或专用汇总投影，并验证总数与排序稳定性。
- CSV 当前由浏览器逐页获取后生成；大导出需要服务端任务、权限快照、进度和过期下载，并定义导出期间的数据一致性。
- 当前余额和事务分别查询，未提供同一时点的对账快照；正式核对须确定截止时间、过账完成状态以及调整或冲销的纳入规则。
- 当前页面测试验证前端联动与查询参数，不能单独证明大规模性能、对账正确性或目标用户效率。
- 入库输入与前端余额契约当前仅接受 CNY。查询服务的币别分组已用隔离库模拟美元余额验证，但不能据此声称跨币别单据或页面流程可用；人民币样本才由真实入库过账生成。见[数据库查询练习](../../docs/training/cases/inventory-summary-drilldown.md)。

## 接入与验收

目标项目先在自己的 Spec 中写出余额唯一维度、汇总键、币别与单位口径、事务来源关系和权限范围。然后提供三个只读接口：汇总、按选择键的维度明细、事务查询；导出使用同一过滤口径。前端复用查询和网格能力，但替换业务字段，不复制本项目的库存写入逻辑。

验收至少覆盖：未选中明细为空；选择后与汇总过滤一致；改筛选后旧明细消失；不同币别不混算；分页与导出范围一致；来源单据与行号可定位；无权、空结果、加载失败有明确反馈；大数据量下的分页和导出策略得到专项验证。
