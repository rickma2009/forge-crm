# 企业工作台与主从工作区候选萃取

> 资产：`EPM-PAGE-002` 工作台及其与对象详情、任务队列的组合候选
>
> 当前成熟度：`interaction-verified`（仅验证场）；不等于真实项目采用、业务验证或正式模式晋升
> 来源：`interaction-pattern-lab/.specify/sources/REQSRC-030-*`、验证场源码与浏览器截图

## 1. 要解决的问题

企业系统的菜单按模块组织，但用户每天的工作往往跨销售、采购、库存、生产、客户和系统管理。工作台需要回答“今天先做什么”，主从工作区需要回答“选中一个工作后，怎样在不丢队列上下文的情况下完成处理”。

## 2. 来源事实、推断与未知

| 类型 | 内容 |
|---|---|
| 来源事实 | 方法论已有工作台、任务中心、审批中心、列表、详情、时间线和提醒/催办等分类；验证门户登记 27 个页面入口。 |
| 实现支持的推断 | 个人工作台与主从工作区可以共享工作项投影，但应保持不同任务：前者用于发现与分流，后者用于集中处理。 |
| 当前未知 | 不同行业的优先级算法、SLA、跨系统身份、真实提醒渠道和审批状态机。 |
| 已采纳设计决定 | 使用确定性内存数据验证布局、选择同步、过滤、完成反馈、稍后提醒和个人待办。 |

## 3. 全菜单到页面族的抽象

| 已登记菜单 | 可复用页面族 | 组合关系 |
|---|---|---|
| 概览、工作台 | 角色化工作台 | 汇聚待办、提醒、预警、快捷入口和可解释指标 |
| 查询列表、高级筛选、客户列表、列表视图 | 记录工作区 | 搜索、筛选、视图、表格、批量动作 |
| 新增编辑、业务详情、销售订单 | 对象生命周期 | 表单、详情、主从明细、状态动作 |
| 主从工作区、数据字典、菜单管理 | 上下文保持型工作区 | 队列/树为主，详情/配置为从 |
| 用户、角色、权限策略 | 关系与授权工作区 | 主体、资源、动作、范围、继承 |
| 操作日志、页面状态 | 追溯与反馈 | 时间线、差异、错误和恢复 |
| 交互模式、组合场景 | 行为契约目录 | 为页面族补充操作、状态和特殊风险 |
| 基础规范、基础组件 | 设计系统层 | 令牌、输入、展示、反馈与可访问性基线 |

这张映射用于减少重复结构讨论，不表示每个菜单只能采用一个页面族，也不表示 27 个入口都已实现验证。

## 4. 必须保持的语义边界

- **待办**：明确要求当前用户执行动作，有完成状态和责任人。
- **提醒**：改变注意力时间，不直接改变业务对象或待办完成状态。
- **预警**：由规则或阈值产生的异常信号，需要确认、转任务或忽略策略。
- **消息**：信息到达，可已读但未必要求业务动作。
- **审批**：由业务状态机约束的特殊待办，动作必须由服务端校验。
- **快捷入口**：启动任务，不应伪装成已经生成的工作项。

## 5. 推荐结构

```text
个人工作台
├── 可解释工作计数
├── 我的工作队列
├── 日程与提醒
├── 快捷入口
└── 个人待办速记

主从任务工作区
├── 主区：可搜索/筛选的工作队列
├── 从区：对象摘要、检查点、流程与协作
└── 上下文区：负责人、截止、提醒、关联对象与动态
```

## 6. 适用与不适用

适用：跨模块高频工作、列表选择后需要快速处理、对象详情不应完全遮挡队列、个人行动与业务行动同时存在。

不适用：单一低频配置、需要全屏画布的复杂设计器、必须横向比较大量记录的分析报表、移动端深度录入、无法定义可靠优先级与数据来源的“假仪表盘”。

## 7. 复用与排除

保留：区域职责、语义区分、选择同步、过滤/空状态、即时反馈、可解释计数、响应式降级和验收清单。

排除：演示客户、订单、仓库、金额、人员、优先级、SLA、权限角色、路由地址、React 状态实现和具体图标库。
