# SDD Forge Workflow

## 开始前

1. 先读仓库根 `AGENTS.md`，再读目标项目自己的 `AGENTS.md`。
2. 将 `_methodology/` 视为唯一通用规范源，将 `_ref/` 视为只读证据。
3. 读取 `_methodology/00-搭建指南.md`，并按当前任务只加载直接相关的规范、模板和项目文件。
4. 检查未提交改动并保留用户资产；不要因为参考项目已有实现就默认复用。

## 判断当前阶段

- 新材料先归档到项目 `.specify/sources/`，保留原文与元数据，再做增量转换和冲突分析。
- 目标、范围、角色、指标或系统边界未批准时，停在 Business Gate 前。
- 切片业务语义、字段、校验或验收标准未批准时，停在 Specification Gate 前。
- 架构、数据、安全或重大技术决策未批准时，停在 Architecture Gate 前。
- 用户要求暂停等待详细需求时，标记暂停，不继续 Plan、Tasks 或实现。

## 推进切片

1. 从已批准业务需求选择一个最小纵向切片。
2. 依次形成 `spec → testcases → plan → tasks → implement → review`，保持稳定 ID 可追溯。
3. 先写失败行为、权限边界和验收证据，再实现主路径。
4. 执行项目校验与 `_methodology/scripts/check-sdd.sh`；没有真实执行的测试不得写成通过。
5. 完整实现评审至少覆盖需求追溯、代码安全和集成运行三个独立视角；问题修复后必须重新验证，不能把“可启动”等同于“可发布”。

## 使用参考项目

1. 记录材料明确事实、实现推断、未知项和目标项目批准决策。
2. 对每项候选复用记录来源、保留内容、排除内容、风险和验证状态。
3. 旧 Java、组织专属平台、历史兼容和在建未完成内容默认排除。
4. 复用优先级是：原则与不变量 → 验收与测试清单 → 去业务化稳定资产 → 代码。

## Skills 路由

读取 `_methodology/07-Skills初始化与使用规范.md`。工作台必需 Skill 由清单初始化；文档读取、需求分析、产品蓝图、浏览器验收、图示和 Skill 创建等能力只在对应阶段按条件调用。不要为了“可能有用”而复制或安装全部 Skills。

## 完成一次工作后的输出

至少报告：本次确认与未确认事项、可复用与不可复用内容、来源和验证证据、当前 Gate 状态，以及下一步允许和禁止的动作。
