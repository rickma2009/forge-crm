# 样式索引

样式不单独抽象设计系统，跟随 CRM 实际业务页。做新页面前，先查这张表找可参照的现有页面。

## 列表记录与操作列（全局强制规则）

规则编号：`UI-LIST-01`。适用于所有业务模块、公共系统管理页面及新建/修改/移植的列表表格。每次页面设计、编码与评审均需核对；下方历史页面只提供结构参考，不能覆盖本规则。

- **行操作用图标**：编辑、删除、审核等分别使用语义明确、全项目一致的图标按钮；不以常驻文字按钮展示。沿用当前图标库与现有样式，不为此引入新 UI 框架。
- **不设查看操作**：操作列不放“查看”文字按钮，也不放查看/眼睛图标；如果一行只有查看能力，省略空操作列。
- **业务标识即详情入口**：将本行的业务编码、业务名称或单号显示为链接，点击查看对应记录。优先采用稳定且便于识别的编码/单号；以名称作为主要识别字段的列表可用名称。页面规格必须明确具体字段，不能只约定“整行可点击”。
- **可识别、可访问**：图标按钮必须提供中文悬停提示及 `aria-label`，例如“编辑”“删除”“审核”；按钮与链接支持键盘操作和可见焦点。详情链接应有可识别的链接样式，不只绑定普通文本的点击事件。导航采用真实链接或路由 Link；按页面既有设计打开详情弹层时采用链接样式按钮。
- **权限与状态不改变**：图标化不新增操作权限；无查看权限的标识显示普通文本。操作的隐藏/禁用及提示按既有权限和状态规则执行；删除确认等既有交互继续保留。操作按钮不误触发详情跳转或行选择。

### 行操作语义图标（UI-ACTION-ICON-01）

表格行操作统一调用 `RowActionButton`，不得在业务页面自行挑选图标或用通用齿轮代替已定义动作。同一业务语义可使用同一图标；不同业务动作必须有可区分的图标、中文悬停提示和 `aria-label`。新增动作应先在公共组件中登记映射、补充测试和本表，再由业务页面调用。

| 业务动作 | Tabler 图标 | 组件语义码 | 交互约定 |
|---|---|---|---|
| 开始 / 启动 | `IconPlayerPlay` | `start` | 启动待处理任务 |
| 暂停 | `IconPlayerPause` | `pause` | 暂停可继续的执行过程 |
| 暂挂 | `IconClockPause` | `hold` | 等待条件或人工处理；区别于暂停 |
| 回复 / 等待回复 | `IconMessageReply` | `reply` | 回复或进入等待外部回复状态 |
| 完成 / 办结 | `IconCircleCheck` | `complete` | 完成业务闭环 |
| 备注 / 记录 | `IconNote` | `note` | 添加处理说明或记录 |
| 关注 / 收藏 | `IconStar`；选中后 `IconStarFilled` | `star` / `star-filled` | 作为操作放入操作列，选中态使用 `aria-pressed=true`，不另设“关注”列 |
| 忽略 | `IconEyeOff` | `ignore` | 忽略当前任务或提醒 |
| 恢复 / 继续 | `IconRefresh` | `resume` | 从暂停、暂挂或等待状态恢复 |
| 重新打开 / 重开 | `IconRotateClockwise` | `reopen` | 将已结束记录重新进入处理；区别于恢复 |
| 持续观察 / 观察 | `IconEye` | `observe` | 保持事件打开并进入观察状态 |
| 关闭事件 / 归档 | `IconArchive` | `archive` | 关闭已完成处置的事件；区别于删除 |
| 标记无关 | `IconUnlink` | `irrelevant` | 表示信息与监控主题无关 |
| 标记误报 | `IconFlagOff` | `false-positive` | 表示规则命中但经人工核验为误报 |
| 分派 / 转派 | `IconUserShare` | `assign` | 指派负责人或处理队列 |
| 编辑 / 修改 | `IconPencil` | `edit` | 修改记录 |
| 删除 | `IconTrash` | `delete` | 危险色并沿用删除确认规则 |
| 审核 / 通过 / 确认 | `IconCheck` | `approve` | 执行当前上下文的确认动作 |

动作的显示、禁用和可执行范围仍由页面权限与业务状态决定。图标只表达动作，不代替服务端鉴权；没有登记的动作暂用 `IconSettings` 时，必须在该功能交付前完成语义图标登记，不能长期保留无法区分的默认图标。

### 标准示例与验收

| 列表 | 点击查看的链接字段 | 操作列（图标按钮） |
|---|---|---|

| 报价列表 | 报价单号 | 编辑、审核、删除等符合状态的操作 |
| 商机列表 | 商机编号 | 编辑、删除等已授权操作 |

验收：① 操作列没有查看按钮/图标；② 编辑、删除、审核及任务状态动作为各自语义图标，且有中文提示与可访问名称；③ 不同动作不共用无区分度的默认图标；④ 点击标识查看正确记录；⑤ 无查看权限时不是链接；⑥ 图标点击不触发查看；⑦ 键盘可访问。查询、重置、新增、保存等页面级或表单级操作不受“行操作纯图标”约束。

## 邮件行操作排列（UI-ACTION-LAYOUT-01）

来源：2026-10-09 用户要求，`.specify/sources/UIRULE-20261009-mail-action-layout/source.md`。邮件处理记录与邮件任务闭环的操作列采用公共 `.row-actions-two-lines`：每行3个图标，6个动作呈两行，按DOM顺序从左到右、从上到下排列；键盘焦点顺序与视觉顺序一致。少量动作只占需要的行，不补空按钮。水平与垂直间距由紧凑行操作的4px缩小20%为3.2px，禁止叠加按钮相邻margin。桌面按钮仍为28×28px，图标16px，触控按钮44×44px；不得通过缩小按钮点击区域来压缩间距。操作单元格启用自动行高（DeclarativeDataGrid使用`data-wrap="true"`），第二行和焦点轮廓不得裁切。列宽需容纳3列按钮及单元格内边距，触控或窄列可横向滚动/调宽。保留中文提示、禁用状态、权限和删除确认。其他列表按业务需要采用，不自动全站更改。

验收：6个操作为3×2；按钮间距3.2px；无相邻margin叠加；第二行可点击且不裁切；Tab顺序从左到右逐行；少于6个动作与无权限场景不增加操作。

## 按钮样式与尺寸（全局强制规则）

规则编号：`UI-BUTTON-01`。适用于页面工具栏、查询区、表单、弹层及表格行操作。每次页面设计、编码和评审必须与 `UI-LIST-01` 一起核对；菜单项、页签和树节点虽可能使用 button 元素，但不按普通操作按钮设定尺寸。

### 默认大小与排布

| 场景 | 最小高度 / 点击区域 | 字号 | 水平内边距 | 图标尺寸 | 使用条件 |
|---|---|---|---|---|---|
| 默认文字按钮 | 32px | 全局 12px | 左右各 11px | 16px（有图标时） | 查询、重置、新增、保存、取消等，未说明尺寸时一律采用 |
| 紧凑文字按钮 | 28px | 全局 12px | 左右各 8px | 14px | 仅限明确标注的密集工具区，不作为普通表单默认值 |
| 表格行操作图标按钮 | 28 × 28px | 无可见文字 | 0 | 16px | 编辑、删除、审核等；与 UI-LIST-01 一致，不含查看 |
| 普通工具栏图标按钮 | 32 × 32px | 无可见文字 | 0 | 16px | 刷新、设置等非表格行操作 |
| 大按钮 | 40px | 全局 12px | 左右各 16px | 18px | 仅限明确需要突出或更易点击的场景，须在页面规格中说明 |

- 默认圆角 **5px**、边框 **1px**；文字按钮宽度随内容和内边距自适应，不固定成等宽大块，不使用胶囊形。
- 按钮内部图标与文字间距 **6px**，相邻按钮间距 **8px**；紧凑表格行操作可使用 **4px** 间距。同一工具栏/表单操作区使用同一尺寸，垂直居中。
- 字体沿用 `--ipl-font-family` 与 `--ipl-font-size`，默认字重 400，主要操作可用 500；不沿用历史局部 CSS 中被全局覆盖的 10.5px 字号。
- 表中高度为最小值；内容放大时允许增高，不裁切文字。触控场景的实际点击区域至少 **44 × 44px**，可以扩大按钮本身或命中区域，但不得与相邻点击区域重叠。

### 视觉类型与交互状态

| 类型 | 默认表现 | 用途 |
|---|---|---|
| 主要按钮 | 蓝色实底 `--ipl-primary`（当前 #2f6bff），白字，同色边框 | 当前操作区的主要提交或推进动作，如查询、保存；同一操作区通常只突出一个 |
| 次要按钮 | 白底，正文色 `--ipl-text`，边框 `--ipl-line-strong`（当前 #cbd3df） | 重置、取消、返回及普通辅助操作 |
| 轻量/图标按钮 | 透明底、透明边框，普通操作沿用正文色或主色 | 表格行操作、工具栏图标；不得省略可点击区域 |
| 危险按钮 | 红色文字/图标 #dc2626，默认轻量或描边；最终破坏性确认可用红底白字 | 删除等破坏性动作；编辑、审核不使用危险红色 |

- Hover：主要按钮使用 `--ipl-primary-dark`（当前 #2055d6）；次要按钮边框/文字突出主色；轻量按钮使用 `--ipl-primary-wash`（当前 #eaf0ff）；危险按钮使用浅红底 #fef2f2。图标保持语义颜色。
- Active：沿用当前类型并加深反馈，不改变尺寸、内边距或布局。Focus-visible：采用全局 **2px** 焦点描边、**2px** 偏移；不能移除键盘焦点提示。
- Disabled：使用原生 disabled 或等效可访问语义，文字/图标灰色 #9aa4b2、背景 #f1f3f5，轻量按钮可保持透明底；不响应点击/悬停，不继续展示可执行主操作的高亮样式。按既有权限策略决定隐藏还是禁用。
- Loading：原位置展示加载图标，保留按钮宽度和文字，阻止重复提交并提供 `aria-busy`；结束或失败后恢复可操作状态。
- 图标按钮必须提供中文提示和可访问名称（例如 `aria-label="编辑"`）；按钮默认使用 `type="button"`，明确提交表单时才使用 submit。删除确认、权限和业务状态规则不能因样式统一而取消。

### 来源、适用与验收

默认 32px 高度、11px 水平内边距、5px 圆角、1px 边框取自 `packages/web/src/showcase/showcase.css` 的 `.enterprise-page button` / `.enterprise-modal button`；字体 12px 与焦点样式取自 `packages/web/src/styles/index.css`。现有行操作曾使用约 27 × 26px，本规则将后续采用尺寸统一为 28 × 28px；其余尺寸变体与状态是本次补充的设计约定，不声称现有页面已全部实现。

验收：① 默认按钮尺寸和字体一致；② 同一区域对齐、间距统一；③ 主次与危险语义正确；④ hover/active/focus/disabled/loading 均有反馈且不导致布局跳动；⑤ 行操作只显示图标，详情由标识链接进入；⑥ 键盘和触控目标可用。沿用现有 React、原生 CSS 与图标库，不为此引入新的组件框架或独立设计系统。

## 业务列表工作区与视图设置（全局强制规则）

规则编号：`UI-LIST-VIEW-01`。报价单、销售订单等单据，以及商机管理、客户管理、产品管理等关键业务信息对象，从菜单进入时首先展示网格列表工作区。直接打开已授权记录详情链接仍进入该记录，不强制绕回列表。

### 页面结构

自上而下按以下顺序组织，参照客户管理页面的区域关系，不复制其业务字段或截图像素尺寸：

1. **查询条件区**：在表格上方独立展示字段标签、查询输入/下拉条件、查询和重置。条件来自当前业务对象及有效视图允许的字段；查询与重置行为在页面规格中明确，不能把未配置的业务字段凭经验补入。
2. **列表工具栏**：位于查询区下方、表格表头上方。左侧放新增按钮（有创建权限且对象支持新增时）；右侧按“当前视图、视图选择、设置、记录总数、刷新”排列。查询和新增属于不同操作区，可各自使用主要按钮，尺寸遵循 UI-BUTTON-01。
3. **网格表格与分页**：按有效视图展示该对象的列、顺序和已支持的排序等配置。行操作遵循 UI-LIST-01，编码/名称/单号链接打开详情；总数必须来自实际查询结果。

### 默认视图与个人引用优先级

- 首次进入或重新进入对象列表时，优先使用**当前用户针对当前对象已选用/引用、仍有权限且有效的个人视图**；没有个人设置或有效个人引用时，使用该用户角色可用的**对象系统默认视图**。
- “有个人视图”不等于“任意一个个人视图都可以自动成为默认”。仅创建或收藏其他视图不应替换已选用视图；设置页应明确展示当前使用/默认引用，切换并保存的行为须在规格中定义。
- 个人视图被删除、停用、撤销授权或引用失效时，回退至可访问的对象系统默认视图，并提示已回退。若连系统默认视图也不可用，展示明确的未配置/无可用视图状态，不擅自显示所有字段或扩大权限。
- 个人视图仅调整被授权的呈现配置，不能扩大字段、数据范围或操作权限；服务端仍校验权限。不同用户、租户/应用及业务对象之间不得混用个人引用。

### 按业务对象配置视图

- 每个对象使用稳定的视图对象标识，例如客户、产品、商机、报价单、销售订单各自独立；界面标题或某行记录 ID 不能作为对象视图的唯一标识。“按表的对象”指业务列表对象，不直接暴露或绑定物理数据库表名。
- 对象需登记系统默认视图、可配置业务字段、查询条件、列与排序等能力边界。具体允许调整哪些配置应在页面 Spec 中列明，不能因通用设置界面存在就自动支持任意字段。
- 有视图能力的页面提供视图切换和“设置”入口，设置目标始终绑定当前对象；复用公共列表视图能力，避免各业务模块另建一套。设置可采用既有设置页或弹层，入口必须清晰。

### 每次列表设计必须回答

| 设计项 | 必须明确的内容 |
|---|---|
| 是否需要视图设置 | 单据及关键业务对象列表默认需要；简单辅助表、只读明细子表等不需要时，在 Spec 中明确“不提供”及理由，不能遗漏判断 |
| 视图对象与作用域 | 对象标识、应用/租户范围、用户/角色边界 |
| 默认视图 | 系统默认来源、个人引用的保存和恢复方式、失效回退行为 |
| 设置入口 | 位于工具栏的“设置”入口，以及使用设置页还是弹层 |
| 配置范围 | 可调整的查询字段、显示列、列顺序、排序及权限约束 |
| 页面动作 | 新增权限、查询/重置/刷新行为、详情入口、行操作、分页与总数 |

验收：① 菜单进入首先出现列表；② 查询区、工具栏、网格顺序正确；③ 新增和视图设置入口遵循权限；④ 无个人引用时使用系统默认，有有效个人引用时恢复它；⑤ 个人引用失效可回退，无可用默认时失败关闭；⑥ 切换对象/账号不会串用视图；⑦ 设置后列表呈现与当前视图标识一致。来源：[本次用户要求与截图](../.specify/sources/UIRULE-20260923-list-workspace/source.md)。规则登记不代表所有业务对象已接入视图功能。

## 查询条件区（全局强制规则）

规则编号：`UI-QUERY-01`。所有带查询条件的列表页统一使用公共 `RecordQueryBar`，禁止业务页自行拼接不同高度、间距和按钮位置的查询栏。

- 默认一行展示 2—3 个最常用条件；其余条件通过“更多”展开为第二或第三行，具体数量由页面字段定义决定。
- 每个条件采用“上方标签 + 下方输入/下拉”的统一结构；控件高度、字体、边框和圆角沿用全局表单令牌。
- 操作区固定右对齐，顺序为“重置、查询、更多”；查询为主要按钮，重置为次要按钮，尺寸遵循 `UI-BUTTON-01`。
- 查询只在用户点击查询或提交表单时应用；重置同时清空当前输入和已应用条件，并重新加载第一页。
- 组件通过字段配置接收文本、下拉和日期等条件，不在组件中写入业务字段；页面负责权限、枚举来源和服务端参数映射。
- 窄屏允许条件换行，操作区仍保持完整可见；标签、控件和按钮必须支持键盘及可见焦点。
- 当业务明确要求所有条件同排（如当前库存、库存事务明细），调用 `RecordQueryBar layout="singleRow"`。字段区在窄屏内部横向滚动、不换行，重置与查询始终可见；字段宽度可通过 `--record-query-field-width` 调整，页面不得复制查询栏结构样式。

公共实现：`packages/web/src/common/RecordQueryBar.tsx`。验收：同一应用内查询区高度、标签、控件、按钮顺序、间距、展开/收起与重置行为一致。

## 可维护树节点（全局强制规则）

规则编号：`UI-TREE-01`。来源为角色管理左侧角色树的实际实现，适用于组织、字典、页面资源等具有节点维护能力的树。

- 每行保留左侧展开/收起、节点名称（无装饰图标/业务徽标）、选中反馈；节点右侧提供省略号图标按钮，带中文提示和可访问名称。
- 节点右键和右侧省略号打开**相同目标、相同权限、相同操作列表**。操作明确区分新建同级/根节点与新增子节点；编辑、删除/停用、移动仅在对象已支持且用户有权限时出现，不凭样式规范新增业务能力。
- 菜单定位在指针或按钮旁并限制在可视区域内，通过公共浮层展示，不能被树面板滚动区域裁切；点击外部、Escape、页面滚动或窗口改变时关闭。支持上下方向键、Home/End 与 Enter，Escape 恢复焦点。
- 删除沿用既有确认、引用检查和内置节点保护。菜单按钮不得触发节点选择、展开或拖动；右键非选中节点也必须作用于该节点，不沿用右侧当前详情的目标。
- 只读选择树、导航树、权限勾选树没有节点维护能力时，不展示维护菜单；在页面规格中登记用途与例外。组织无删除接口、字典仅软停用时，不虚构删除操作。

公共实现：`packages/web/src/common/useTreeNodeMenu.tsx`；左树右详情场景通过 TreeWorkspace 内置此 hook，页面只传入已授权 actions；专项树若登记例外，再自行绑定 open/button/menu。新项目保留交互与可访问约定，替换领域操作、权限和标识。验收覆盖双入口一致、目标节点、撤权、内置保护、边界定位、键盘与外部关闭。

### 左树 + 右详情工作区（全局强制规则）

规则编号：`UI-TREE-WORKSPACE-01`。适用于资源菜单、组织架构、数据字典及其他确实需要左侧树、右侧详情或多 Tab 内容的管理页面。商机阶段按已批准需求使用单表格管理，不得因本规则恢复成树工作区。

- 桌面布局保持左树、右详情/多 Tab 的明确分栏关系；左侧树面板提供整体向左收起与恢复展开入口，不能只提供节点级展开/收起。
- 收起后保留当前选中节点和右侧内容，显示可恢复展开的窄栏按钮；按钮必须提供中文 `aria-label`、`title`、键盘焦点和可见 focus 状态，恢复后焦点回到收起按钮或当前树节点。
- 左栏整体收起与树节点层级收起是两种独立状态；节点右键、右侧省略号、拖拽和选中行为不能被面板收起误触发。只读树可省略维护菜单，但仍需说明用途和收起例外。
- 右侧详情或多 Tab 必须在左栏收起后继续保持标题、当前对象上下文和主要操作可识别；不得因为左栏收起而丢失对象定位。
- 窄屏可将布局切换为上下结构，但必须保留树面板恢复入口、节点选择和详情内容，不得用隐藏代替可用的收起/展开。

验收：① 左栏可整体收起/恢复；② 收起后右侧内容不丢失；③ 当前选中对象和焦点可恢复；④ 节点菜单权限与目标不变；⑤ 桌面/窄屏均有可访问入口。

### 弹窗操作区（全局强制规则）

规则编号：`UI-MODAL-01`。适用于包含返回、取消、保存、确认、删除确认或其他提交动作的弹出框。

- 弹窗 footer 固定在右下角，使用 `display: flex`、右对齐和统一间距；次要/返回/取消动作在左，主要保存/确认动作保持最右。
- 弹窗 body 内容可滚动时，footer 仍保持可见且不随正文宽度漂移；按钮顺序、尺寸、主次和危险语义遵循 `UI-BUTTON-01`。
- 所有按钮必须支持键盘操作和可见焦点；提交按钮提供 loading/disabled 反馈，取消或返回不得误提交表单。

验收：① footer 位于右下角；② 次要动作在主要动作左侧；③ 主要按钮最右；④ 长内容滚动时 footer 仍可用；⑤ 键盘焦点和 loading/disabled 状态可见。


规则编号：`UI-TAB-01`。适用于系统顶部多页面路由页签，源项目 supply 只作为只读证据；不要求详情内部“基本信息/跟进”等内容切换页签提供关闭页面菜单。

- 使用公共 `packages/web/src/common/route-tabs/`，不在业务页面各建页签状态。每个可打开页面按稳定路由标识去重；当前项与内容一致，固定首页不可关闭。
- 页签标题与右键菜单的字体族、字号必须一致：共用 `--ipl-font-family` / `--ipl-font-size`（当前12px），菜单按钮继承菜单容器字体；Portal 挂载到 body 也显式应用同一令牌，不写死14px或继承浏览器默认字号。普通、禁用、悬停、焦点状态不改变字体族和字号；浏览器验收比较 computed fontFamily/fontSize。关闭叉号属于图标，不作为文字字号比较对象。
- 页签右键菜单统一提供刷新当前、关闭当前、关闭其他、关闭右侧、关闭全部、在新窗口打开；“当前”指右键命中的页签。不能执行的动作禁用，批量关闭保留固定页签，活动页被关闭后确定性选择相邻页或首页。
- 刷新重载目标页面；非活动页刷新状态在下次激活时生效。关闭/刷新/离开继续遵循页面已有未保存修改守卫，取消不得丢失编辑。新窗口使用真实路由且重新校验权限，不复制会话凭证。
- 菜单与树节点菜单一样需边界定位、外部关闭、Escape/方向键操作及焦点反馈；关闭按钮具有可访问名称，不误触发标签导航。

复用边界、接入方法和纯状态模型见该目录 README。验收覆盖六项动作、首页保护、去重、非活动目标、刷新与权限/脏数据守卫；不能仅验证菜单出现。

## 列表进入详情的统一工作区（全局强制规则）

规则编号：`UI-DETAIL-01`。适用于从业务列表进入的记录详情；来源是客户详情实现、商机详情差异与用户2026-09-24两张截图。页面仍须遵循 UI-BUTTON-01 和 UI-LIST-01。系统顶部路由页签仍遵循 UI-TAB-01，不与本规则的内容 Tab 混用。

1. **一个详情容器**：白底、1px外边框、8px圆角。标题、摘要、内容Tab和正文连成一体，不拆成多张悬浮卡片。
2. **第一行**：左侧统一返回箭头（32×32px、图标16px、中文提示和可访问名称）；右侧为对象名称或单号，字号沿用全局12px、加粗、行高1.5，状态可紧邻标题；页面级操作靠右。客户用简称，商机用名称，报价用单号。返回目标为对应列表，遵循已有未保存离开保护；不得用浏览器history猜测目标。
3. **第二行只读摘要**：对齐标题左边缘，统一“字段名：字段值”。行距8px、列距24px，允许自动换行；空值为“—”；保留授权后的真实关联链接，不显示无标签的拼接值。不扩大字段可见权限。
4. **内容Tab采用客户详情样式**：位于摘要下方，白底、底部通栏1px分隔线；Tab最小高度44px、内边距12px 16px、无独立圆角框，选中项蓝色字/600字重/2px下划线。不得使用商机旧record-tabs独立边框卡片。tablist/tab/tabpanel必须关联，支持左右/Home/End及可见键盘焦点；只渲染有权限的页签。
5. **Tab本身是大容器**：正文默认20px内边距，内部内容不再逐块套边框、圆角和阴影。需要区分内容时使用分区标题（例如“报价产品明细”）、24px留白或1px分隔线。表格行列线、输入框、错误提示、需要独立语义的弹窗可以保留边框；不能笼统移除所有后代边框。
6. **适配与例外**：700px以内内边距12px，摘要自然换行、操作另起一行，Tab横向滚动，表格在自身容器横向滚动；不可撑宽整页。触控返回命中区44px。无业务Tab的详情不强行增加Tab，沿用同一头部与平铺分区。树管理工作区、模态编辑器、仪表盘不机械套用。

组件：`packages/web/src/common/DetailWorkspace.tsx` 与 `detail-workspace.css`；提供 DetailWorkspace、DetailHeader、DetailTabs、DetailPanel、DetailSection。调用方负责对象身份、只读字段权限、操作权限、返回目标及离开保护；组件只承载一致呈现与页签键盘行为。Tab内容需要保留表单状态时由调用方保持挂载（客户即如此）。

验收：返回正确列表；标题/摘要两行；摘要全部带标签；Tab键盘/权限正确；一个外容器；分区无重复卡片；窄屏不溢出；原有保存/新增/关联行为不变。已接入客户、商机、报价，其他存量页面必须逐页登记，不能将规范发布等同全站迁移。来源：[原始需求](../.specify/sources/UIRULE-20260924-detail-workspace/source.md)。

## 列表视图组合控件（UI-VIEW-CONTROL-01）

“当前视图 / 下拉框 / 设置”统一调用 `ListViewSelector`，不得逐页复制。三段使用border-box，桌面外框高度/最小高度/最大高度均32px，边框1px，首尾圆角5px，中段无圆角；触控统一44px，不能只有一段增高。控件需覆盖全局输入框34px最小高度，禁止只设置height却遗漏min-height。三段上下边缘一致，加载/禁用/选中/聚焦时不改变尺寸；焦点轮廓允许超出但不能裁切。窄屏组合整体可换行，内部不拆行，select可收缩；记录数和刷新在组合外。

### 统一树形左右工作区组件（UI-TREE-WORKSPACE-01）

所有左树右详情/操作区域统一使用 `packages/web/src/common/TreeWorkspace.tsx`，禁止各页另写树面板。基准为角色管理，采用单一外框：左侧搜索框、工具展开按钮、右侧新增按钮；展开工具包含全部展开/全部收起/刷新。节点仅保留层级箭头、名称、省略号操作，不放装饰图标、内置/停用徽标，特殊属性在右侧呈现。行高桌面32px、触控44px，层级缩进16px；底部显示总节点数（不随搜索变化）、宽度滑条（默认320px、范围280–440px）。面板右边框中点箭头收放，收起保留24px操作条，不卸载右侧内容。700px以内树在上/内容在下，不使用宽度滑条，收起后仍可恢复。

已接入角色、组织、资源菜单、数据字典、物料分类。只读物料分类不提供分类维护；组织/字典仅暴露已有操作；资源拖放仍使用既有移动API。例外：角色权限勾选授权树、系统导航菜单、表格层级列、表单树选择器、ui-assets/scenarios/bom 只读层级差异预览不属于本左右工作区；商机阶段当前为表格，不改为树。未来新树形左右页面除明确记录例外外必须调用组件。

验收：首行对齐、节点紧凑无装饰、搜索保留祖先、菜单权限与危险提示、展开/收起/刷新、节点总数、拖动滑条、面板收放、右侧状态保持、键盘焦点与窄屏无整页溢出。复用的是布局和交互，不复用角色/组织/字典业务授权。实现来源与证据：角色旧实现及用户截图，`.specify/sources/2026-09-24-tree-workspace/request.md`、`TreeWorkspace.test.tsx`、`scripts/tree-workspace-browser-qa.mjs`。本规则是项目采用标准，不宣称跨项目已验证最佳实践。


### 内容 Tab 公共组件（UI-CONTENT-TABS-01）

组件：`DetailTabs` + `DetailPanel`，统一从 `packages/web/src/common/DetailWorkspace.tsx` 导入；样式在 `detail-workspace.css`。适用于记录详情和树右侧等内容切换，不要求外层一定是 DetailWorkspace，也不要求带返回箭头。系统顶部可关闭的路由页签仍使用 RouteTabs / UI-TAB-01。

以客户详情为唯一样式基准：白底，通栏1px下边线；未选中灰色文字（#64748b）、400字重、无独立方框/圆角；选中主题蓝文字、600字重和2px蓝色底线。统一全局字体/12px字号、1.5行高、最小高度44px、内边距12px 16px；焦点轮廓清晰可见。未选中项悬停不显示选中蓝线，组件须隔离通用按钮hover边框覆盖。禁止逐页覆盖为圆角按钮、卡片或另写 nav。内容默认20px内边距，窄屏12px，页签可横向滚动。

现有客户、商机详情复用此组件；本次将资源菜单右侧基本信息/子页面/按钮/页签/左菜单迁入。报价无内容Tab时不强加。后续新增/修改内容多Tab必须调用同一组件，专项例外在Spec登记。验收同时比较客户与接入页选中/未选中的计算样式，检查点击、键盘、计数、面板关联与窄屏滚动。可复用视觉和键盘行为，不复用业务权限与字段。来源 `.specify/sources/2026-09-24-content-tabs/original.md`。


## 单据详情与编辑（UI-DOCUMENT-01）

适用：入库单等主表/明细型业务单据。默认单页，不使用内容多Tab；有明确业务例外时在Spec中登记。此次实装入库单；其他既有单据不据此宣称完成迁移。

1. 顶部采用 `DetailHeader`：统一左返回箭头，右侧为单号（新建未生成时显示业务标题），必要的状态和“字段名：字段值”只读摘要，页面操作在右侧。
2. 上方主表字段、下方明细网格；主表沿用客户详情的标签在上、文本/输入/下拉在下，两列布局、窄屏一列，字段之间保持统一间距。用分区标题/留白/分隔线区分主表与明细，不再套多层圆角卡片。
3. 默认查看模式：主表只读，明细文字展示。明细上方不显示添加/维护按钮，明细网格不渲染操作列；不能仅把删除按钮禁用却保留空操作列。
4. 满足业务既有状态与编辑权限时，右上显示“编辑”。点击后进入页内编辑，按钮改为“保存”，可提供“取消编辑”；解锁允许维护的主表和明细字段，明细出现添加行与授权行操作，行操作遵循UI-LIST-01的图标按钮。只读身份/系统计算字段始终不可编辑。
5. 保存同时提交主表与明细并携带既有版本控制；成功使用服务器结果返回查看模式；失败保留输入/编辑状态并给出可恢复提示，禁止悄悄丢弃或刷新。保存期间防重复提交。返回/关闭/切换路由/刷新遵循未保存保护。审核/过账等生命周期操作只在查看模式按权限和状态出现，不与未保存编辑并行。
6. 入库单当前口径：草稿且有update权限可编辑；单号/状态/币别只读，其他既有维护字段按接口开放；已过账/冲销/作废只读。明细可直接行内编辑、新增/删除；调拨仍未启用；不新增状态转换或后台权限。

组件组合：`DocumentWorkspace`（common/DocumentWorkspace.tsx）提供统一头部与无Tab正文，内置DetailHeader；`DetailSection`划分主表/明细，主表form-grid/document-fields，明细document-grid。调用方持有查看/编辑/保存状态、字段权限、API/版本和离开守卫。头部保存用form属性连接真实form，按钮不能绕过校验。参考实装 `showcase/InboundOrderDetailPage.tsx`。

验收：默认只读且无内容Tab；上下结构；编辑权限与状态双重约束；编辑→保存→查看；新增/操作列仅编辑时显示；永久只读字段锁定；失败保留/版本冲突/取消/离开/重复点击；窄屏主表单列、网格只在自身横向滚动。来源 `.specify/sources/2026-09-24-document-detail/original.md`。

### 统一返回箭头（UI-BACK-01）

所有新增或调整的页面级返回入口统一调用 `DetailBackButton`（common/DetailWorkspace.tsx），DetailHeader已内置，客户详情与单据共用。使用Tabler IconArrowLeft 16px，按钮32×32px、圆角5px/1px边框遵循UI-BUTTON-01，触控44×44px，有明确中文aria-label/title和可见焦点；不得另写Unicode“←”或逐页自定义箭头。参数label/onBack/disabled；调用方指定正确的列表路由与未保存守卫，不能靠history猜测返回。此规则不把树收放/分页方向箭头当成页面返回，也不默认为所有存量返回入口已迁移。

### 详情浏览/编辑同构（UI-DETAIL-MODE-01）

适用于单据、主数据和其他信息对象的详情页。浏览态与编辑态必须复用同一个详情容器、头部、Tab、分区、字段顺序、表单网格及字段控件，不得在浏览态改成 `dl`/纯文本而在编辑态另换一套表单。浏览态将输入框、下拉框、日期、文本域等控件设为只读；原生不支持 `readOnly` 的控件使用 `disabled`，并保持清晰可读的文字、背景和标签。进入编辑、取消、保存成功或失败时不得因切换展示组件而造成字段位置跳动。

编辑态只解锁当前权限、状态和字段策略允许修改的控件；编码、单号、系统生成值等永久只读字段始终锁定。浏览态不得提交表单，不显示仅编辑所需的行新增/删除操作；页面级编辑、保存、取消及生命周期动作仍按业务权限和状态控制。隐藏字段、脱敏、关联名称、未保存离开保护及服务端授权不因同构展示而放宽。

验收：① 浏览与编辑的字段标签、顺序、控件类型和布局一致；② 浏览态所有业务字段不可修改且值清晰；③ 编辑态只解锁获准字段；④ 切换模式不更换页面骨架；⑤ 返回入口继续遵循 `UI-BACK-01`。来源：[2026-09-25 物料详情变更](../.specify/sources/REQSRC-074-item-detail-view-edit-parity-20260925/source.md)。物料详情为首个明确接入对象，其他存量页面仍需逐页登记和验证。

### 页面交互与过程反馈（UI-INTERACTION-BEHAVIOR-01）
统一业务模式：客户/商机/产品采用列表→详情；角色/组织/资源菜单采用公共左树→右详情；对象关联信息调用公共DetailTabs/DetailPanel；报价、入库等单据采用主表→明细表与默认查看；简单新增和选择使用有限弹窗；商机AI分析使用较大任务弹窗，提供真实任务状态、引用依据、人工审阅和明确确认保存。

查看与编辑遵循UI-DETAIL-MODE-01和UI-DOCUMENT-01，浏览态与编辑态同构。默认对象/单据查看，授权编辑后才开放字段和明细新增/删除；只读页面不显示维护操作，新增入口选择、关联选择、任务输入和独立行内录入的例外须在模板/需求中明确。列表查看通过编码、名称或单号链接，操作列使用语义图标。

默认手动保存；自动保存或提交后生效须明确需求，不得隐式开启。保存期间防重复提交；成功采用服务端结果；失败/冲突保留输入并提供恢复入口。离开、关闭或切换对象涉及未保存内容时提示保存、放弃或取消离开，未经明确放弃不能丢弃输入。纯查看/查询/选择未确认不写业务数据。

六种反馈须区分：加载（占位保结构）；处理中（动作/阶段明确、防重复）；成功（反馈并保持上下文）；失败（原因、保输入、可恢复）；空数据（区分无记录/无匹配/未配置）；权限不足（说明原因、按权限隐藏或禁用，服务端继续校验）。AI生成成功只表示结果待审阅，不等于业务已保存；任务关闭与取消分开，进度/重试/取消只展示真实支持能力。

阶段看板与指标仪表盘分开：前者按阶段分列卡片，拖动流转不是默认能力；后者展示指标、趋势和异常，支持同口径下钻。统一视觉仍为企业紧凑、清晰字段层级与适量留白，模板不另创视觉主题。

通用规则的可维护数据源是 `_methodology/templates/index.json` 的defaults/behaviorOverrides；正式详情显示解析后的三组规则。具体模板映射与例外见 `docs/design/interaction-template-library.md`。

### UI-BUSINESS-GRID-01 公共业务网格

新增或改造业务列表使用 `packages/web/src/common/data-grid/BusinessDataGrid.tsx`，保持顶部查询区、列表工具栏和网格分页区的项目布局。网格必须有横纵分隔线；统一表头、行高与状态反馈。单行文本的默认数据行高为 **32px**（从当前34px减少2px），文字、图标和控件均在单元格内上下居中；原生表格兜底行高由42px降为40px。多行文本或复杂单元格按实际内容自动增高，不强行压缩；增高后内容块仍相对整行上下居中，不单独顶端对齐。支持表头拖动列顺序、调整列宽、列隐藏、居左/居中/居右、左右固定、独立列筛选、表头排序、分页和每页自定义 1–200 条。

**记录列顺序与身份入口**：默认第1列为序号；有行级可操作能力时第2列为“操作”，没有则省略操作列；后面优先放对象身份字段。主数据优先编码（物料编码、客户编码等），单据优先单号（销售单号、报价单号等）。有详情页或明确的查看弹层且用户有权限时，身份值使用 `record-detail-link` / `customer-code-link` 同款蓝色加粗入口，悬停下划线、聚焦可见；点击/键盘进入本行记录。没有查看能力或权限时显示普通文本，不为遵守样式虚构跳转。列表视图配置允许在身份列之后调整其他业务列；选择器、授权矩阵、交叉分析及专用表单可在设计中记录必要例外。

**行操作图标**：统一使用 `RowActionButton`（下载等真实链接用同图标语义的 `RowActionLink`），按“修改（铅笔）→删除（垃圾桶）→审核/通过（对勾）→其他已授权操作”的顺序显示。删除使用危险色；各图标保持16px、按钮28×28px，提供中文 `aria-label` 与悬停提示，状态禁用和权限沿用业务规则；查看不占操作列。其他动作只在业务已支持时追加，禁止各表自造同义图标。

**文本溢出与多行**：单行列默认 `white-space: nowrap`，列宽不足显示省略号，悬停可读完整文字。不因列名包含“说明”“备注”“地址”就自动换行。页面明确要求完整显示的列以 `wrapText/autoHeight`（声明式表格用列头或单元格 `data-wrap="true"`）声明，行高随内容增长；同一格中有多个字段/附注时自动按复合内容处理，保留字段层次和自然换行，不截掉次字段。

**列宽与显示值**：建表时必须按信息密度设置初始列宽，不能让所有字段等宽。标题、主题、内容、摘要和长名称建议 **320–420px**；编码、单号、来源名称建议 **160–240px**；日期时间建议 **160–180px**；状态、数量、语言、类型等短字段建议 **90–140px**。长内容应优先获得宽度，短枚举不得挤占内容空间。列表显示用户可理解的字典名称和带单位的数量（如“3 条”“GDELT全球新闻”），内部编码只在明确的编码字段展示；导出内容遵循相同显示口径。详情展开不得在单元格内越界覆盖相邻列，应使用独立详情区、抽屉或弹层。

记录列表默认每页20条，网格下方显示真实总数、当前页/总页数、每页条数和首页/上一页/下一页/末页。公共表格是否分页由具体页面调用时通过 `paginationMode="paged" | "all"` 固定配置，不向用户显示分页模式选择框，也不放入个人视图设置。默认 `paged`；`all` 展示全部符合查询条件的记录，隐藏整个分页栏（不显示页数、条数或翻页按钮）。默认保持网格固定高度及滚动，少量明细可显式使用自动高度。服务端不分页列表必须提供完整结果加载，保留查询、排序和权限范围，校验数量与唯一行标识；失败显示错误并可重试，不得把当前一页当作全部，也不通过超大pageSize绕开接口限制。页面未接入全量加载时保持默认分页。使用服务端分页，查询、重置及每页条数变化回到第一页，序号跨页连续；可设置条数范围必须符合业务接口上限。员工管理与用户管理已按此规则接入公共分页。

普通网格内容区默认高度470px（比原520px缩短50px），窄屏390px；左树 + 网格的页面根据可用视口收缩数据区，为查询栏、工具栏和分页预留空间，分页不随数据区滚动。自动高度明细表保持随内容展开。

默认采用简洁网格：隐藏列设置、清除列筛选、导出范围、导出格式及导出按钮；表头仅显示字段名称，不显示独立筛选框、排序箭头或排序点击入口，表头高度40px。上述高级功能仅在具体页面需求明确说明后按项开启，禁止因为公共组件具备能力就默认展示。保留顶部业务查询、分页和既定列表视图选择/设置入口；未启用列筛选的页面不得应用历史视图中的隐藏列筛选条件。组件通过 showColumnSettings、enableColumnFilters、enableColumnSorting、enableExport 开关分别控制，默认均为false。

系统默认视图作为基线，布局/排序/列筛选/每页条数可保存到个人视图，下次进入恢复个人引用。列配置不得扩大授权字段或改变业务上下文范围。筛选、排序与导出须作用于服务端全部匹配且授权的记录，不能仅处理当前页；导出明确选择当前页或全部筛选结果，格式提供 Excel/CSV，按显示列顺序和显示值输出。

参考实现：客户管理 `/showcase/customers`、物料产品管理 `/showcase/items`。左树分类过滤与列筛选按 AND 组合，分页、排序与导出均保留分类范围。开源依赖仅使用 MIT 的 AG Grid Community，Excel 导出由项目 ExcelJS 适配器实现。

CSV 文件序列化统一使用 `common/data-grid/grid-export.ts` 的 `createCsvBlob`，公共网格的 gridExport('csv') 与库存导出共用该入口，不在页面复制 csvCell。函数处理 UTF-8 BOM、字段双引号、内嵌引号及 CRLF 行分隔，沿用公共 csvCell 对首字符 =、+、-、@、Tab、CR 的文本前缀策略；该策略不是所有电子表格软件的公式安全证明。授权字段、筛选/分页、数据快照、数量金额精度和下载文件名仍由业务调用方负责，序列化不负责补取数据或权限校验。

全系统表格统一：业务列表、详情明细、关联选择弹窗、授权矩阵、导入预览及交互模板演示都调用上述网格引擎。复杂旧页可经 `DeclarativeDataGrid` 声明式适配，不能另起表格实现；新页直接绑定类型化列和业务数据。迁移保留只读/编辑、选择、键盘、撤销、汇总、权限及原有分页协议，只有多行说明/校验提示等复杂内容才自适应增高。树、导航、模板缩略图画廊和时间线保持各自语义，不改成记录网格。`pnpm validate:data-grids` 已并入validate，防止新增独立原生表格；迁移清单见 `docs/design/shared-data-grid-adoption.md`。


## Agent任务与右侧抽屉

抽屉键盘事件遵循消费顺序：内嵌控件已 preventDefault 的事件不再次触发外层关闭；未消费的 Escape 才请求宿主关闭。Tab 循环候选排除 tabIndex 为负的元素，关闭后恢复仍存在的入口焦点。当前局部验证与未覆盖边界见[抽屉焦点回归](../docs/testing/drawer-focus-regression.md)，不能把 aria-modal 或单元测试通过等同于完整焦点隔离、背景滚动锁定或多层弹窗支持。

商机Agent小助手复用`DrawerWorkspace`与`AgentAssistantDrawer`，公共容器统一标题、固定操作栏、滚动内容、关闭和焦点行为。任务过程展示真实模型/工具步骤，关闭后后台继续，重新打开恢复；取消、依据查看与人工审阅按实际能力开放。结果不得自动写业务记录，沟通计划保存为明确待执行记录，权限/快照/幂等由服务端检查。其他业务Agent注册自己的上下文、只读工具、结果校验与保存适配器，复用公共执行循环。接入与验证见[Agent小助手](../docs/ai/agent-assistant.md)，模板TPL-08-04/08-05及TPL-05-03。

## 工作台指标卡

我的工作台采用公共 `MetricCard`、`DashboardModule`。普通文字沿用全局字号；指标主数字显式使用 `.ipl-type-metric` 和全局 `--ipl-font-size-metric`（40px），这是指标展示的统一字号，不改变表格和表单字体。上部指标卡、下部左待办与右预警/消息布局，参见 [工作台规范](../docs/features/my-workbench.md)。预览只截页面内容；真实敏感业务数据不得放入公开静态资产，使用明确标注的模拟数据效果图。

### 详情内只读关联列表（候选组件）

客户360的关联商机/报价/订单/出货采用[RelatedRecordList](../packages/web/src/common/RelatedRecordList.md)，复用现有网格和分页，详情入口为编码链接，无查看操作列。适用于详情Tab内的只读关联查询，不代替对象主列表个人视图；业务归属与权限留在源服务。本项目验证见[客户360 P1](../docs/testing/customer-360-p1.md)，尚无跨项目采用证据，不新增全站迁移要求。


## 阶段看板组件（本项目候选）

P2商机看板使用 [KanbanBoard](../packages/web/src/common/KanbanBoard.md)，继承列表查询区与视图工具栏。列头提供全量匹配数量/金额，卡片使用稳定业务标识链接；拖动手柄与详情链接分离，必须提供键盘等效入口。业务方在确认理由后提交受权限、版本和幂等保护的命令，禁止直接凭拖动修改状态。列独立加载，汇总不能取自已加载卡片。窄屏横向滚动，保留点击区域。

来源：[P2实施授权](../.specify/sources/REQSRC-094-opportunity-kanban-start-20261003/source.md)；边界与验证见[交付记录](../docs/testing/opportunity-kanban-p2.md)。当前只有商机采用，未晋升为跨项目强制标准。

## 活动时间轴组件（本项目候选）

客户、商机详情内的活动过程统一调用 [ActivityTimeline](../packages/web/src/common/ActivityTimeline.md)，继承详情Tab、字体及间距规范。时间轴属于过程语义，采用倒序时间列、类型、摘要、展开详情，使用“加载更多”游标分页；不改成业务网格或另套层层卡片。系统事件只读、作废标识保留、发生与录入时间分开。表单及附件复用现有公共组件。

组件只呈现已授权数据，业务适配层处理来源、筛选、旧请求隔离、分页失效及编辑；后端负责权限与审计。来源[REQSRC-095](../.specify/sources/REQSRC-095-activity-timeline-start-20261003/source.md)，证据[P3交付记录](../docs/testing/activity-timeline-p3.md)。当前同项目客户/商机采用，不自动扩展到其他模块或晋升跨项目标准。

## 销售建议、记录协作与评分组件（本项目候选）

客户/商机详情统一复用[SalesInteractionComponents](../packages/web/src/common/SalesInteractionComponents.md)中的建议列表、评论流、评分分项和操作弹窗。继续沿用公共详情及下划线Tab；Tab内使用留白、细分隔线，不另套多层卡片。评论为纯文本、一级回复，附件通过独立表单插槽组合；评分必须区分系统分与人工覆盖并展示理由，不标作成交概率。权限、幂等和业务规则由服务端负责。

来源REQSRC-096，验证见[P4—P6交付](../docs/testing/sales-enhancement-p4-p6.md)。客户和商机采用同一展示组件，现阶段不宣称跨项目成熟度，不要求其他无关模块迁移。


## 原单据工作流区域与可视化（UI-WORKFLOW-01）

- 保持原单据页面结构，在主表、明细及附件之后的页面最底部追加“工作流”区域，使用统一 DetailSection 标题与留白；不以新Tab、弹窗替代原单据。
- 展示流程版本、轮次、状态、当前承办人、流程图和审批记录；未发起显示明确空态，历史轮次只读。
- 设计器、审批执行页、原单据复用同一流程图组件和定义布局。保留节点、条件分支、并行汇合及未命中分支，运行态仅叠加进度和实际路径；时间轴不能替代流程图。
- 按实例绑定的发布版本及布局快照展示，不随新版本重新排图。节点可查看处理记录，支持缩放、适配、定位。查看和审批操作分别受权限控制。
- 当前原型 FlowDiagram 仅为固定模板路径演示；正式完整分支与布局快照要求见[审批方案](../docs/design/approval-workflow/solution.md)。

UI-WORKFLOW-01 正式组件候选：[ApprovalProgressDiagram](../packages/web/src/common/workflow/README.md)。定义与运行共享完整布局，运行状态仅作叠加；P2.1完成组件验证，P2.2已接入销售订单底部及审批中心；设置页、实例页保留同版本完整图，证据见040切片。
