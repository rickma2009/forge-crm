# 功能规格：线索评审工作流

> 功能编号：001  
> 状态：specified-example  
> Spec Gate：example-approved

## 1. 目标

- 关联目标：BUS-001，保证线索资格判定经过明确评审并可追溯。
- 用户故事 US-001：作为评审人，我希望按受控流程判定线索，以便避免越级和无依据决策。

## 2. 需求

| ID | 需求 | 优先级 |
|---|---|---|
| REQ-001 | 活动线索可以提交评审 | P0 |
| REQ-002 | 评审中的线索可以判定合格或拒绝 | P0 |
| REQ-003 | 非法状态迁移必须失败且不改变状态 | P0 |
| REQ-004 | 每次成功迁移必须记录来源、目标和时间 | P0 |

## 3. 验收标准

| ID | 需求 | Given | When | Then |
|---|---|---|---|---|
| AC-001 | REQ-001,REQ-004 | active 线索 | 提交评审 | 状态为 in_review，并记录历史 |
| AC-002 | REQ-002,REQ-004 | in_review 线索 | 判定合格 | 状态为 qualified，并记录历史 |
| AC-003 | REQ-002,REQ-004 | in_review 线索且有拒绝原因 | 判定拒绝 | 状态为 rejected，并记录原因 |
| AC-004 | REQ-003 | 状态不满足迁移前提 | 请求迁移 | 返回 INVALID_TRANSITION，状态和历史不变 |
| AC-005 | REQ-002 | 拒绝原因为空 | 请求拒绝 | 返回 VALIDATION_ERROR，状态和历史不变 |

## 4. 非功能需求

| ID | 维度 | 要求 |
|---|---|---|
| NFR-001 | 可验证性 | 核心状态机无需外部服务即可自动测试 |

## 5. 范围外

身份认证、审批人配置、通知、超时、重开、并发控制、数据库和 UI。
