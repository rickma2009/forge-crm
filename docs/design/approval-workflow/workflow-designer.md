# 受控审批工作流设计器（销售订单切片）

> 产品定位：满足常规业务单据的串行审批和排他条件分支，不建设通用低代码工作流平台。统一方案见 [solution.md](solution.md)。

## 已实现范围

系统管理中的“工作流设置”先显示查询列表，可按名称、编码和状态筛选。新增时从受控对象目录选择数据对象；当前目录只开放销售订单。创建后生成不可更换对象的 V1 草稿，初始只有开始和结束节点。

草稿详情可增加审批节点、排他分支和固定业务动作，维护连线、默认分支及 AND/OR 条件。条件字段只能来自销售订单字段目录，运算符、枚举值和数值类型由服务端校验。审批职责当前支持部门经理、二级部门负责人和财务负责人；人员按申请部门配置并在提交时冻结快照。

草稿允许保存未完成的中间设计。发布时才强制校验业务动作、完整路径、所有节点可达、唯一默认分支、非默认分支条件、组织职责和人员有效性。发布成功后版本不可修改或删除；“编辑为新版本”复制为同一工作流的新草稿。每个应用、每个业务对象同时只有一个启用版本，既有实例继续使用创建时的定义和图快照。

## 当前能力边界

- 支持开始、审批、排他条件、固定业务动作和结束节点。
- 支持串行审批；排他条件一次只选择一条路径，并必须配置默认路径。
- 支持同意、退回申请人、驳回终止和受控转交。
- 设置预览、审批详情和原单据底部显示完整流程图及运行状态。
- 不含字段/子表权限、会签或签、并行分支、加签、抄送、委托、催办、主动撤回、超时动作和子流程。
- 正式设计页使用自动布局的受控流程图：点击节点编辑属性，点击连接线可插入审批、条件或业务动作节点，也可维护连接和条件；不开放任意 BPMN/XML 或自由脚本。

## 安全边界

- 浏览器不能提交 BPMN XML、表达式、脚本、URL 或类名。
- NestJS 只接受结构化节点、连线和条件 AST，并按对象字段目录验证。
- Java 引擎再次验证节点、路径、字段、枚举、审批人变量和固定动作，然后编译 BPMN。
- Flowable 服务只访问独立工作流数据库；销售订单状态由 CRM 的 `sales.order.approve@1` 适配器在本地事务中更新。
- 列表、详情、配置、发布、删除、重试均受租户、应用、菜单动作、CSRF 和乐观版本约束。

## 主要接口

- `GET /api/systems/:systemCode/workflows/objects`：数据对象与字段目录。
- `GET/POST /api/systems/:systemCode/workflows/definitions`：工作流列表、新建草稿。
- `GET/PUT/DELETE /api/systems/:systemCode/workflows/definitions/:id`：详情、保存、删除草稿。
- `POST /definitions/:id/edit`：从发布版本建立下一草稿版本。
- `POST /definitions/:id/publish`：严格校验并异步发布到 Flowable。
- `POST /workflows/preview`：用同一安全编译器生成预览图。

## 业务对象扩展规则

新增业务对象时必须登记字段目录、可用业务动作、提交变量映射、状态适配器、授权和完整集成测试，不能仅在前端下拉框中增加对象。请假、报销、报价、付款和异常事件按这一方式分别接入。
