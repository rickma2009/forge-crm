# P2.1 引擎基础交付与P2.2接入边界

本阶段已进入正式代码开发，完成独立Flowable服务，不再是模拟状态机。运行端口8091只给服务端访问，审批中心页面目前仍为已确认原型；用户界面的正式替换待P2.2。

## 本阶段

- Flowable7.2.0 / Boot3.5.4 / JDK21 / PostgreSQL16；来源与commit锁定，完整上游源码独立检出。
- 串行、金额条件、固定完整分支图；发布版本不可变，实例保持版本。
- 同意、退回、拒绝、转交；任务版本、承办人校验、自审阻止。
- 持久命令账本、同scope命令串行化、重复重放、异载荷冲突。
- 显式业务等待节点与匹配结果，不把“人员同意”误认为“业务完成”。
- 服务令牌、scope隔离、强类型Nest客户端和公共流程图组件。

## 下一阶段的明确接入项

1. 部门职责与任职解析、二级部门口径配置；不得用默认演示人员填补缺失组织。
2. CRM审批定义/发布、申请快照、outbox/inbox及可靠调度。将当前基础的“启动时传入人员快照”升级为批准方案的节点解析策略，或显式选择冻结策略。
3. 销售订单提交同事务建申请与启动事件，业务审核动作同事务写结果账本；统一阻断旧审核API绕过。
4. 真实审批中心、消息、待办权限、审批执行页、原单据底部区域。入口不再使用预览模拟身份。
5. 业务动作异常队列、重试与补偿边界；一张真实订单闭环验收后才按对象启用。

不得在当前基础上直接开启全部销售订单审批开关：尚无CRM可靠业务适配层和组织解析。请假、报销、付款、事件依次按方案P3/P4推进，不在本阶段扩展。

## 数据治理

引擎独立数据库，Java服务唯一责任模块。自有表：sys_wf_scope_lock（并发锁）、sys_wf_command（防重）、sys_wf_definition（不可变定义）、sys_wf_instance（实例关联与结果）、sys_wf_audit（追加审计）。scope由租户UUID和应用UUID组合；关系按scope复合外键约束。跨库业务关联由后续CRM门面验证，没有伪造跨数据库FK。

Flowable ACT_*表按上游规则管理，是第三方独立库命名例外，不加入Prisma。当前开发初始化SQL不是生产迁移框架；上线前补足版本迁移、备份恢复、安全升级、保留策略及容量验证。没有删除或清空引擎数据的公开功能。
