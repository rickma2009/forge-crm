# Forge CRM 销售交互增强详细解决方案

版本：v1.4 · 2026-10-04。状态：P1—P6一期范围均已实现并完成针对性验证，未生产部署。最新交付见[P4—P6记录](../testing/sales-enhancement-p4-p6.md)，早期包证据保留在各自执行记录中。

来源：[REQSRC-092](../../.specify/sources/REQSRC-092-sales-interaction-plan-20261003/source.md)。用户已接受上一轮评估建议并要求整理详细方案。本文件为方案主入口；[当前态需求](../../.specify/requirements/012-sales-interaction-enhancement/requirement.md)登记范围与验收。新增的阈值、字段及接口是本方案推荐默认值，不冒称用户逐项批准。P1—P3依据各包后续开始指令执行；P4—P6依据REQSRC-096连续实施授权完成。下面的历史分包停止条件保留追溯，以本段当前状态及最终执行记录为准；长期目标继续暂停。

## 1. 目标、范围和决策

目标：让销售在同一工作区看清机会分布、关联客户业务、追溯跟进过程，并把规则建议转成可执行任务。复用现有 CRM 能力，新增公共组件只承担展示与交互，业务规则由服务端负责。

| 编号 | 决策 | 边界 |
|---|---|---|
| D01 | 六项能力分六个任务包交付 | 每包有停止条件，不连续扩展为长期建设 |
| D02 | 360 表示一个客户详情工作区 | Tab 按需加载，不将全部数据一次下载 |
| D03 | 看板阶段与商机业务状态分离 | 拖到某阶段不能直接产生赢单、丢单或订单 |
| D04 | 活动、待办、系统事件、评论分开建模 | 同一事实可多处展示，不多处保存 |
| D05 | 原“线索评分”调整为商机跟进优先级评分 | 不新增线索 CRUD、分配、转商机；未来线索另立规格 |
| D06 | 推荐一期采用规则 | 不调用现有大模型，不依赖 AI Key、向量库或黑盒预测 |
| D07 | 采纳建议产生待办和采纳事件 | 不能伪造已完成的拜访、电话或跟进 |
| D08 | 概率信息分别展示 | 阶段配置概率、销售把握度、历史统计赢率不混算 |
| D09 | 聚合不复制业务主数据 | 允许事件、评分计算保存必要历史快照 |

明确不含：邮件收发/同步、外部 IM、短信、实时聊天、复杂规则脚本编辑器、独立线索模块、合同/回款/工单模块、大模型预测、库存过账规则变更。本方案提及 CRM 品牌仅保留用户背景，不声称已验证其具体产品功能，也不将品牌做法直接作为本项目标准。

## 3. 页面与交互

### 3.1 客户360（REQ-SX-01）

布局：第一行统一返回箭头、客户简称、状态和授权操作；第二行只读“字段名：字段值”；下方客户同款下划线 Tab。默认保留“客户基本信息”，新增“概览”；既有用户入口不突然改变默认编辑行为。

推荐 Tab：基本信息、概览、联系人、地址、商机、报价单、销售订单、销售出货、活动、协作。未实施能力不显示空壳 Tab；协作随第5包开放。概览显示授权范围内的业务数量、最近有效跟进、待办摘要及建议入口。

- 关联列表固定 customerId 精确过滤；出货经销售订单或受约束客户外键关联，禁止按名称拼接。
- 单号/名称进入既有工作区详情；使用公共网格、分页和只读展示，不另外实现单据编辑器。
- 各 Tab 每页默认20行，允许已有规范范围内的页大小；切换客户清空旧查询和选择，过期请求不能覆盖新客户。
- 无权限的 Tab 与统计均不返回；“无权限”“无数据”“加载失败”是不同状态。单 Tab 失败可以单独重试，不拖垮基本信息。
- 数量与明细使用相同权限和过滤口径；金额分币别，不能将不同币别直接相加。没有明确币别的商机金额标记口径，不能擅自换汇。
- 客户时间轴中的商机活动按活动发生时保存的客户关联展示，说明源商机当前归属是否变化；历史跟进缺少该关联时只按当前关联展示并标注，禁止推造历史客户快照。

### 3.2 商机看板（REQ-SX-02）

查询区 → 新增/个人视图/表格-看板切换 → 看板。查询字段沿用商机列表；看板额外明确阶段模板。默认选择用户有效配置或现有默认模板，同一看板只呈现一个模板的阶段，不能按同名阶段合并不同模板。

列按阶段 sortNo 排序，显示名称、可见记录数量、预计金额、金额缺失数量；停用但仍有记录的历史阶段单列只读展示，不能静默丢弃卡片。默认展示启用且未关闭商机，允许筛选历史关闭记录，但关闭/停用记录只读。

卡片显示名称、编号、客户、金额、负责人、把握度、预计签约日期；名称/编号为真实详情链接，卡片空白区域可辅助打开。拖动手柄、菜单按钮不能误触详情。列独立滚动和加载更多，默认每列20张；列汇总针对所有授权匹配结果，不随加载张数变化。

阶段变更流程：拖动或菜单选择目标 → 展示当前/目标阶段、理由输入 → 提交 version 和 requestId → 服务端重新校验 → 成功后刷新相关列与汇总。默认所有阶段变更均要求简短理由；同阶段不写事件。不开放看板内自由卡片排序。

- 目标阶段必须属于同模板且启用；允许跨阶段推进/回退，但必须记录理由。已有更严格业务校验优先，不能绕过。
- SIGNED、LOST、VOID（作废）及停用商机禁止拖动，业务状态通过既有受控流程处理。
- 详情编辑、分析保存、看板拖动最终共用阶段变更服务；分析仍保存原分析内容，不制造空分析记录凑数。
- 版本冲突返回409，恢复卡片并提示刷新；无权限返回403；规则不符返回422或项目既有对应错误码。
- 同请求重试只生成一次事件；请求号重复但内容不同须拒绝。提交期间锁定该卡片，不能连续拖出重复命令。
- 键盘用户使用“变更阶段”菜单完成相同操作；窄屏横向滚动、不缩小点击区域，保持焦点和读屏反馈。

视图配置增加 schemaVersion、viewMode（TABLE/KANBAN）、kanban.templateId 与卡片显示配置。旧配置无 viewMode 时按 TABLE；切回表格保留列宽/分页设置。个人配置不得扩大系统视图字段权限；模板失效则提示并回退表格，不擅自切换到其他业务模板。持久化沿现有用户/应用/对象作用域。

### 3.3 活动时间轴（REQ-SX-03）

客户、商机详情复用 ActivityTimeline。记录分为已发生销售活动、计划任务、系统事件；评论留在协作 Tab，默认不计入销售跟进次数和活跃度。

销售活动：拜访、电话、人工邮件登记、跟进、备注；字段为标题、类型、发生时间、执行人、内容、结果、可选下一步、关联客户/商机、附件。发生时间不能晚于服务器当前时间；未来安排写入待办。按发生时间倒序、再按稳定事件键排序，显示录入时间以识别补录。

- 现有 SdOppFollowUp 继续作为跟进权威记录；统一查询通过适配器读取，新建商机跟进调用原服务，不另存一份相同活动。
- 新客户活动和其他类型使用新的销售活动模块；关联商机时由服务端校验客户归属。
- 普通活动创建者可在仍有记录写权限时修改/作废，管理员需相应管理权限；保留版本与修订审计，不硬删历史过程。
- 系统事件由原业务成功事务写入，包含操作者、时间、前后值、原因、来源类型/ID；浏览器不能提交 SYSTEM 类型。
- 旧事件按已有真实数据映射；没有证据的历史阶段变化不补造。
- 新增、筛选、详情、继续加载均保留上下文。来源记录无权限时不能透出内容或附件，也不能用事件快照绕开权限。
- 同源记录同时显示在客户、商机详情时使用统一 sourceType/sourceId 去重；游标带查询条件指纹和快照上限，筛选变更重置游标。

### 3.4 记录协作流（REQ-SX-04）

客户/商机详情“协作”Tab：评论编辑区、附件、成员提及、发送；列表按创建时间倒序，一级回复按正序展开。回复绑定根评论，暂不支持多层楼中楼。

正文建议上限4000字符；一期纯文本，链接安全展示，不执行 HTML。发送后由后端解析结构化 mentionUserIds，不依靠正文中的“@姓名”识别用户。成员联想仅返回同租户/应用且能访问该记录的启用成员；发送时再次检查，失效提及明确提示后修正。

作者可以编辑/撤回自己的评论，但仍需记录访问与评论权限；管理员只能凭单独管理权限隐藏违规内容。编辑留版本，撤回显示占位，有回复时保留结构，不级联删除历史。编辑仅通知新增提及者，去除提及不能抹掉已投递审计。

附件复用 SysAttachment 和现有上传组件；ownerType 增加白名单并验证所属评论/业务对象。推荐单文件20MB、单评论10个，具体类型复用现有安全白名单；先临时上传再绑定，发送失败可重试，孤立临时附件定期清理。下载重新校验对象权限、禁用状态和安全文件响应。

站内通知支持未读列表、数量、标记已读、全部已读；请求只能操作自己的通知。通知不是待办，读过通知不等于完成工作。评论和待投递事件同事务写入，投递幂等；被提及后不自动获得业务访问权。权限撤销后通知隐藏正文，打开提示无权访问，不泄露原对象摘要。暂不做实时聊天/WebSocket，可在可见页面按30秒刷新并在后台页停止轮询。

### 3.5 商机跟进优先级评分（REQ-SX-05）

本期明确从原线索评分调整为商机评分；界面名称“跟进优先级”，0—100分，不能叫成交概率。关闭商机停止新评分，保留历史结果供授权查看。缺失数据得0分并显示缺失原因，不将“未知”解释为差客户。

推荐默认规则（待业务样本校准，可版本化调整）：

| 维度 | 满分 | 计算方式 |
|---|---:|---|
| 信息完整度 | 30 | 有客户、有效联系人、明确需求、未来预计签约日期、有效负责人、有效产品行，各5分 |
| 来源质量 | 20 | 配置渠道得分映射，范围0—20；未配置0分并提示，不能凭渠道名称猜测 |
| 有效活跃度 | 20 | 距最近实际拜访/电话/邮件/跟进≤7天20分，8—14天10分，超过14天或无记录0分；备注、评论、系统事件、待办不计 |
| 金额潜力 | 30 | 同币别阈值T1/T2/T3分别10/20/30分，未达T1为0；币别或阈值未配置则0分并标记不可评估 |

总分为四项实际得分相加，限制0—100，避免“权重×已经加权的得分”重复计算。推荐分段：高≥70，中40—69，低<40。金额阈值不设置跨行业通用金额，按应用/币别配置后启用；活动中的未回复/负向结果一期不擅自推断为正向购买意向。

保存系统分、分项得分、规则版本、输入摘要/哈希、计算时间及数据版本。人工覆盖单独保存分数、理由、操作人、到期时间（默认30天）；系统分继续更新，生效分优先取未过期覆盖。可以主动恢复系统分，覆盖到期自动回退并留事件。覆盖权限与规则管理权限分离。

规则配置限定结构化参数，不执行任意脚本。草稿→发布→停用；发布版本不可修改，重算结果引用准确版本。对象/活动变化触发受控重算，另按应用时区每日补算时间衰减；同版本输入重算幂等，失败保留旧值并标记“待更新”，不伪装最新。

### 3.6 规则建议（REQ-SX-06）

详情提供“销售建议”区，显示标题、理由、依据时间、规则版本、建议负责人、操作。与已有 AI 分析入口区分，关闭 AI 服务后仍正常运行。

首批规则：

| 编码 | 触发条件（推荐默认） | 建议动作 |
|---|---|---|
| R01 | 启用未关闭商机距最后有效跟进超过7个自然日；无跟进则从创建时间起算 | 创建联系客户待办 |
| R02 | 未关闭商机预计签约日期早于应用当天 | 创建确认日期/风险待办，不自动改签约日期 |
| R03 | 未关闭商机缺联系人、需求或产品等关键资料 | 创建完善信息待办 |

客户级R01按直接客户活动和有权读取的关联商机有效活动取最近时间；结果明确“基于当前可见记录”，不能透露受限活动存在，也不能声称覆盖无权访问的全客户数据。

状态：ACTIVE → ADOPTED / IGNORED / SNOOZED / EXPIRED；稍后提醒到期且条件仍成立可重新 ACTIVE。忽略当前触发周期，默认7天冷却；源数据变化使条件消失即过期。每条建议绑定对象、接收人/可见范围、规则版本和触发周期，避免不同数据权限用户共用一条含敏感依据的建议。

采纳时重新验证权限、条件和输入版本；弹出待办编辑区，默认负责人为当前用户，指派他人需独立授权。确认后同事务创建待办、采纳记录和只读系统事件。唯一键约束建议只采纳一次，重复点击返回同一待办。待办完成时需实际结果，若同时创建跟进必须再次幂等。取消待办保留历史，不自动宣称建议已执行。

增强规则另设子任务：相似客户按已存在且授权的行业、区域、实际交易产品等可比字段匹配；至少两项有效维度才返回，显示命中项，不把缺失当相同，不强制产品线关联。默认最多5个参考客户，不推荐自身。

历史赢率若以后开放：按模板/阶段、明确时间窗和有权读取的样本计算，显示分母、时间范围和样本限制；建议最少30个已结束样本，否则显示不足。若缺历史阶段经历，只能展示“已关闭样本赢单占比”，不能冒充阶段转化率。阶段配置概率与人工把握度可立即并列展示，但不混合生成预测概率。

## 4. 服务端架构与接口契约

职责：customer-360 仅编排授权查询；opportunity 负责商机阶段命令；sales-activity 负责活动写入与时间轴适配；record-collaboration 负责评论；notification 负责投递/已读；sales-guidance 负责评分和建议；各模块不能直接改其他业务域表。

下列为候选相对路由，完整路径沿现有租户/应用/systemCode 路由约定；实施时先核查现有路由再确定名称。静态路由必须避免被 :id 捕获。

| 接口 | 输入要点 | 返回/副作用 |
|---|---|---|
| GET customers/:id/overview | 授权客户ID | 授权摘要，不包含无权Tab统计 |
| GET customers/:id/related/:kind | kind白名单、分页、排序 | 调用源业务服务，按customerId精确过滤 |
| GET opportunities/kanban | templateId、筛选 | 全量匹配列汇总、首批卡片、每列游标、asOf |
| GET opportunities/kanban/stages/:id | 相同筛选指纹、cursor | 单列下一批，客户端按ID去重 |
| POST opportunities/:id/stage-changes | targetStageId、reason、version、requestId | 原子更新和事件，返回新版本 |
| GET records/:type/:id/timeline | 类型过滤、cursor、limit | 标准事件封装，源对象标识及分页游标 |
| POST records/:type/:id/activities | 活动字段、requestId | 分发到权威活动服务 |
| PATCH activities/:id | 可修改字段、version | 修订/作废，保留审计 |
| GET/POST records/:type/:id/comments | 分页/正文、mentions、attachments、requestId | 授权评论和一级回复 |
| PATCH comments/:id | version、编辑/撤回 | 修订审计、新增提及通知 |
| GET notifications；POST notifications/read | 用户由登录身份获取、通知ID | 仅本人；可见范围内未读统计 |

所有写入身份来自登录态；禁止信任客户端传入 tenantId、操作者、ownerName。客户端校验只改善反馈，服务端承担最终权限、范围、状态、幂等和并发检查。错误返回沿现有统一结构，包含可展示原因和requestId，不回传内部SQL或隐私快照。

## 5. 数据设计候选与所有权

以下为架构候选，不是已建表清单；实施时登记表注册表、迁移和契约。所有新增物理名/字段小写snake_case且≤32字符，UUID主键、timestamptz时间、numeric金额，JSON只放受版本约束的证据快照。业务主表不得复制到聚合表。

| 候选对象 | 所有者/层级 | 关键字段和约束 |
|---|---|---|
| sd_sales_activity | sales-activity/业务 | customer_id必填、opportunity_id可空、type、occurred_at、actor_id、content、status、version；同时关联时校验同客户/作用域 |
| sd_opp_event | opportunity/业务事件 | opportunity_id、event_type、before/after、reason、actor_id、occurred_at、request_id；同作用域请求事件唯一；只追加 |
| sd_record_comment | collaboration/销售业务 | customer_id或opportunity_id恰一非空，root_comment_id同对象、body、state、version；一级回复，软撤回 |
| sd_comment_mention | collaboration/关联 | comment_id、user_id；同评论用户唯一 |
| sys_notification | notification/平台 | recipient_id、source_type/id、state、read_at；收件人+事件唯一；正文不充当长期权限快照 |
| sys_event_outbox | event-delivery/平台 | event_key唯一、payload_version、state、attempts、next_at；重试与失败可观察 |
| sd_score_rule_set | sales-guidance/规则 | scope、rule_version、status、effective_at、config；同应用当前生效版本受约束 |
| sd_opp_score | sales-guidance/计算结果 | opportunity_id、rule_version、input_hash、system_score、breakdown、calculated_at；计算键唯一 |
| sd_score_override | sales-guidance/人工记录 | opportunity_id、score、reason、operator_id、expires_at、state；每商机最多一条生效覆盖 |
| sd_sales_suggestion | sales-guidance/建议 | customer_id或opportunity_id、recipient_id、rule_code/version、cycle_key、status、version、evidence、todo_id；触发周期唯一 |
| SysPersonalTodo（扩展候选） | personal-todo/平台 | 复用现有待办，增加受控建议来源引用/幂等键，不重建待办表 |
| SysAttachment（扩展候选） | attachment/平台 | 增加受控owner类型，关联授权与临时绑定机制 |

作用域约束：新增表带tenant_id/application_id；子表通过同作用域复合外键绑定主表；用户引用校验应用成员资格；禁止 subject_id='*' 全局对象。多态读取接口只接受 CUSTOMER/OPPORTUNITY 白名单，持久化优先显式外键而非无约束type/id。

统一时间轴一期为查询投影：适配现有跟进、报价/销售事件与新增活动/阶段事件，不同步复制第二套业务事实。适配器提供可排序的稳定键，SQL联合投影在授权过滤后统一排序分页，禁止先各取一页再拼接冒充全量时间轴。规模需要异步读模型时另立设计，明确来源版本、幂等、延迟与重建方式。

索引候选：作用域+对象ID+发生时间+ID；通知作用域+收件人+状态+创建时间；待投递状态+next_at；评分对象+计算时间；评论对象+根评论+时间。使用查询计划验证，不因列多就为所有列加索引。

核心事务：阶段变更与事件同提交；评论、mentions与outbox同提交；采纳、待办和采纳事件同提交。通知异步投递采用至少一次+去重，失败重试不重复红点。所有删除默认Restrict，业务撤回不级联破坏审计。

## 6. 权限矩阵与数据保护

| 能力 | 基础要求 | 独立操作权限 |
|---|---|---|
| 360/看板/时间轴 | 对象读取、字段读取、关联业务读取 | 不因聚合自动扩权 |

评分/建议依据涉及不可见字段时，不能仅隐藏文字却继续泄漏分项值；一期只有具备该规则全部输入读取权限的用户可查看对应结果，其余显示“无权查看此分析”，避免把权限不足当得0分。缓存键包含租户、应用、对象、用户/授权版本；权限变化失效。日志保留关联ID与错误码，不记录完整评论/附件正文。

## 10. 迁移、启用、回退与风险

1. 先增加兼容契约与新增表/索引，旧视图无类型自动解释为表格；原数据不删、不重置。
2. 事件从启用日期起真实记录；历史适配来源可辨认，不重放出库/审核等业务操作来补历史。
3. 每项能力独立特性开关、菜单操作授权，小范围启用；规则默认草稿，参数完整后发布。
4. 新旧入口调用同一权威服务；如必须迁移跟进，另立去重/核对/恢复计划，本方案不直接迁移跟进表。
5. 回退优先关闭新入口和任务消费者，保留已创建活动、待办、评论及审计；不得删表丢数据。已采纳待办继续可用，待投递事件保留后续恢复。
6. 上线前备份与恢复演练覆盖新增关系、任务和规则版本；迁移SQL只追加，失败前滚修复。

风险重点：源业务行级权限覆盖程度需要实现前核对；现有商机币别口径不足时不能评分或汇总换汇；全量历史阶段经历可能不存在；活动补录不等于实时活跃；复杂通知/附件不能视为一个UI小组件。上述风险各归对应任务包处理，不自动展开为全系统整改。
