# 个人 CRM Web Agent 方案

> 状态：2026-09-30 用户明确要求开始开发；首版按本方案实施。  
> 日期：2026-09-30  
> 来源：`REQSRC-083`  
> 适用项目：Forge CRM Web 端；首版面向多个账号，各账号独立使用，不设计租户管理界面。

## 1. 目标与边界

建设独立的 Agent 工作台，让用户围绕已有客户、商机及其跟进、复盘和关联产品持续对话，获得有来源依据的跟进建议，并将确认后的行动建议转成正式待办。用户既能从独立菜单打开会话，也能从客户或商机页面带入当前对象。系统允许多个账号使用，但会话和待办按账号隔离；Agent 读取业务记录不得超出该账号在 CRM 中已有的查看权限。

“当前线索”在首版指未关闭的商机，不新增独立线索对象。首版聚焦个人使用体验，不建设跨账号共享会话、团队协作会话或可自主修改 CRM 的 Agent。现有商机详情“Agent 小助手”是单商机任务抽屉，保留现有能力；新工作台复用可用的 AI 运行底座，但采用独立的持久会话模型，不把历史任务伪装成聊天消息。

## 2. 现状与建设差距

| 当前能力 | 首版建设要求 |
|---|---|
| 商机抽屉支持跟进分析、沟通计划，任务按发起人保存 | 独立 Web 工作台、连续多轮会话和个人历史管理 |
| Agent 工具只读当前商机、跟进、产品和竞品 | 按授权范围检索客户、商机、跟进、复盘及关联产品，回答可追溯 |
| 工作台待处理事项由商机实时推导 | 新增可保存、可完成的个人待办，并在“我的工作台”呈现 |
| 尚无会话、消息、独立待办及业务标签/知识库模型 | 首版新增前三者；标签、知识库进入后续阶段 |

现有商机接口以功能权限为主，业务记录范围可能较宽。首版 Agent 以“当前账号在 CRM 页面可查看的记录”为一致性边界，不因 Agent 引入更宽的读取能力；实施时必须在服务端工具层逐次校验功能权限、记录可见性和账号状态。商机记录级权限收紧若涉及全 CRM 规则变化，应作为独立权限决策处理，不在本方案中暗改现有页面范围。

## 3. 首版用户场景

1. **从工作台开始**：授权用户进入“Agent 工作台”，新建通用会话，或选择一个有权查看的客户/商机作为主要对象。会话标题自动生成，允许改名、搜索、归档与删除；每个账号只能看到和管理自己的会话。
2. **从业务页面开始**：在客户或商机详情点击 Agent 入口，打开或新建携带该记录上下文的会话；界面明确展示当前绑定对象，用户能返回原业务页面。
3. **检索与问答**：用户询问客户现状、未关闭商机、跟进过程或商机复盘。Agent 只通过授权的只读工具获取资料；回答附可点击来源，区分记录事实、分析推断和建议。资料不足时明确说明，不补造客户事实。
4. **跟进辅助**：围绕当前商机生成沟通话术、跟进提示词、下一步建议和基于现有 CRM 资料的资料摘要。首版不上传文件，也不声称接入尚不存在的知识库。
5. **生成待办**：Agent 将建议整理成待办草稿。用户可修改内容、负责人及截止时间，确认后才保存。默认负责人为当前账号；没有可靠日期依据时截止时间留空。保存后可在会话和“我的工作台”找到对应待办及来源记录。
6. **失败恢复**：模型未配置、超时或调用失败时，保留用户输入与会话历史，明确显示错误和重试入口；真实模型失败不降级成未标识的模拟结果。

## 4. 页面与交互

- **独立入口**：新增“Agent 工作台”菜单和路由，按项目既有导航、顶部 Tab、按钮与工作区规范实现。推荐布局为左侧个人会话列表、右侧会话区；列表具搜索、新建及归档入口，会话区有当前对象、消息、来源链接、输入区和待办草稿确认区。
- **上下文入口**：客户、商机页面显示同一工作台的快捷入口，进入时携带稳定记录 ID，而非将整条业务资料放入 URL。会话只有一个主要客户或商机；可读取该对象的关联记录。通用会话不绑定对象。
- **回复反馈**：区分加载、生成中、成功、失败、无资料和无权限；长回复分段可读，来源链接直达有权查看的业务页。离开或刷新后仍可恢复已持久化的历史。
- **待办确认**：草稿与正式待办视觉上明确区分。保存按钮只在内容有效且用户有权创建时可用；保存失败保留草稿，不生成重复待办。
- **会话删除**：二次确认，仅影响本人会话及其消息；已经确认保存的正式待办不随会话删除而丢失，仍保留来源审计关联。归档可恢复。

## 5. 权限、安全与 AI 运行

- Agent 使用设独立角色权限；没有权限不显示入口，直达 API 仍返回拒绝。客户、商机等业务读取继续检查对应功能权限及适用的记录范围；会话/待办操作检查当前账号所有权。前端隐藏不是服务端授权替代。
- 服务端工具使用白名单，只读查询；查询条件、记录 ID、系统作用域由服务器验证，不接受模型自行扩大对象范围、执行任意 SQL/脚本或访问网络。业务文本是数据，不是工具授权指令。
- 延用现有模型配置与受控运行机制，设置请求时限、工具调用次数和用量限制；错误、取消与重试要有明确状态。用户输入、CRM 摘要和模型结果避免进入普通日志；审计记录调用者、动作、对象和写入结果，不记录密钥或不必要的完整业务文本。
- 回答中的来源引用应保存记录类型、稳定 ID、摘要和生成时点；点击时重新验证权限。后续记录更新或失效时，历史回答保持生成当时语义，并提示来源可能已变化。
- 产品首版不增加租户切换或租户管理，但底层继续遵守现有系统/应用作用域与数据库隔离约束。

## 6. 概念数据与模块分工

| 概念实体 | 核心职责 | 关键约束 |
|---|---|---|
| 会话 | 所属账号、标题、主要对象、归档状态、创建/更新时间 | 只能由本人读取和管理；主要对象类型、ID受控 |
| 消息 | 会话内顺序、角色、内容、生成状态、错误、来源引用 | 消息归属继承会话；失败输入保留；稳定分页 |
| 待办 | 标题/内容、负责人、截止日期、状态、来源对象/会话 | 草稿不算正式待办；确认写入幂等；本人工作台可见 |
| Agent 调用记录 | 模型运行状态、用量、工具步骤与可诊断错误 | 与会话消息关联；敏感内容最小化；遵守现有运行上限 |

会话与消息属于公共 Agent 服务，待办由独立待办服务负责，工作台通过该服务读取本人正式待办；客户和商机模块仍是其业务资料唯一责任方。物理表名、外键、同作用域约束、保留策略和迁移恢复方案在开发前的 Architecture Gate 定稿，遵守项目的 `sys_`/`sd_` 分层、`snake_case` 及 32 字符限制。不得以任意 JSON 字段替代核心可查询关系。

## 7. 首版交付与验收

首版交付包括：独立工作台与上下文入口、按账号隔离的持久会话、多轮问答、受权限约束的 CRM 检索与来源链接、跟进话术/提示词/资料摘要、待办草稿及确认保存、我的工作台待办展示、会话管理、模型错误与权限反馈。已有商机抽屉能力正常保留。

验收重点：两个账号互不可见会话和待办；无 Agent 权限或无业务查看权时不能通过接口越权读取；客户/商机入口绑定正确对象；来源链接与记录对应且失权后不可继续打开；未确认的待办不会落库，重复确认只生成一条；模型失败后输入可恢复；正式待办状态变化能在工作台同步显示。测试使用隔离数据和 mock 模型，不向真实模型发送现场 CRM 数据；真实网关兼容性另以非业务合成内容验证。

## 8. 后续阶段（不计入本次开发）

- **知识库与资料**：上传或接入受权限控制的文档，建立版本、引用和检索机制，再把知识依据并入 Agent 回复。
- **目标与营销**：目标/任务分解、营销方案和文案生成，审阅后保存；营销案例有来源、版本及可复用范围。
- **业务标签**：客户、商机标签的定义、人工维护与 Agent 建议；用户确认后落库，支持分类、筛选和分析。模板库自身的 `tags` 不是业务标签，不复用为客户/商机标签。

后续阶段另行形成需求、数据权限、验收和实施方案。当前只保留模块扩展边界，不预建空页面或不可用按钮。

## 11. 提炼后的 Agent 场景与开发衔接（2026-10-09）

新增候选聚焦已有客户/商机上下文及受控查询，沿用当前权限与正式动作确认：

- 客户会议/跟进文字→事实、诉求、问题、推断、缺失信息→多行动草稿→逐项确认→执行结果。首期不用录音/实时转写；不自动改商机关键字段。
- 产品 FAQ/SOP→按访问范围与有效版本检索→来源引用→解释或邮件草稿。先确认知识维护与数据责任，不默认已有知识库。
- 采购回签、质量 8D、经营分析→各场景只读适配器→结构化材料与行动草稿；待权威业务数据/API/指标口径就绪后择一。

Agent 不承载收件调度、邮件发送策略、采购状态机或质量放行；这些由数字员工场景和业务服务负责。行动草稿需要明确保存为个人待办还是商机跟进记录，不能隐式双写。正式任务所有权和数据权限继续服务端校验，引用失权时不可通过历史会话继续取数。

详情见[场景增强 Plan](../../.specify/specs/ai-scenario-enhancement/plan.md)及[任务清单](../../.specify/specs/ai-scenario-enhancement/tasks.md)。本节为待实施增量，不改变第 7 节首版交付范围，也不宣称知识、采购/质量工具已上线。

## 2026-10-09 首批场景增强交付

在既有工作区内补充商机会议多行动、执行结果、私有FAQ/SOP版本和邮件知识辅助草稿。范围、使用入口、验证与未完成条件见[阶段交付记录](../../.specify/specs/ai-scenario-enhancement/review.md)。私有资料不等同于企业知识库；发信仍通过原邮件策略，未新增自动AI发信。
