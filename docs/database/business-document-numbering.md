# 对象编码与业务单据编码规则

2026-10-04，来源：[REQSRC-097](../../.specify/sources/REQSRC-097-numbering-rules-20261004/source.md)。本版本替代新建对象使用的硬编码前缀和日期算法。历史业务编码及UUID不修改。

## 管理与默认规则

系统管理 → 编码规则。查询表格与分页；新增、编辑、编码链接查看均使用弹窗。规则包含显示序号、对象编码、对象名称、前缀开关/编码、日期开关/类型、流水位数、开始数和状态。开始数默认1，状态默认启用。对象编码是调用契约，创建后不允许改；显示名称可以改。

| 对象编码 | 对象名称 | 前缀 | 日期类型 | 流水位数 | 接入状态 |
|---|---|---|---|---|---|

## 取号不变量

- 格式为“启用的前缀 + 启用的日期 + 补零流水”；日期基于服务端取号时的 Asia/Shanghai 时间，类型YEAR/MONTH/DAY对应yyyy/yyyyMM/yyyyMMdd。回填单据日期不会重算编码。
- 日期流水按对应年、月或日重新开始；无日期持续递增。开始数是下限，不重置已用流水。修改位数不倒退；切回旧前缀和周期继续原命名空间计数。
- 前缀仅字母/数字，最多12位；流水1—12位，开始数为能容纳的正整数。最长编码32位，兼容现有单据字段。
- 规则在应用内唯一；流水和发号唯一性以租户+对象为界，兼容员工及出入库的租户级唯一约束。命名空间为前缀+周期，不含位数，避免改位数后倒退。
- 取号用独立短数据库事务、租户/对象advisory锁、持久计数与发号唯一账本。事务内读取精确同格式的既有编码最大值并避让；不是无锁“查最大值+1”。
- 分配成功即保留号码；后续业务保存失败或取消允许断号，号码不回收。同应用/对象/requestId重试返回同号。取号幂等不替代业务单据自身的幂等逻辑。
- 浏览新增表单不取号；点击确认/保存后由后端取号。更新对象不改号；普通新增不依赖用户拥有编码管理权限。
- 停用、缺失或流水耗尽时明确拒绝新增，不静默回退旧规则或截断流水。修正规则后可重试。已有编码的对象只能停用规则；未使用可删除并保留墓碑，再次初始化不恢复墓碑。
- 初始化只写首次默认值，重复执行不覆盖人工配置或授权。新增自定义规则不自动接入业务模块，不允许运行任意SQL、物理表配置或脚本。

## 调用方式

统一服务：[NumberingService](../../packages/server/src/numbering/numbering.service.ts)。业务模块先通过自身权限与输入校验，在开启业务写事务前调用，避免多个外层事务占满连接池等待内层取号。

```ts
const code = await numbering.allocate(systemCode, 'SALES_ORDER', requestId);
// code 已独立持久化；在业务事务中保存到不可编辑的单号字段。
```

未提供requestId时服务生成UUID。具有业务幂等键的报价直接传原requestKey；其他业务新建请求各取新号。已有业务未统一实现“同一提交请求只建一张单”的机制，本次不将发号幂等冒称为所有业务防重。

HTTP管理接口（登录会话、写请求CSRF与对应权限）：

| 方法与地址（前缀 `/api/systems/:systemCode/code-rules`） | 用途 |
|---|---|
| GET / | keyword/status/page/pageSize查询及格式预览，不耗号 |
| POST / | 新增，version=0 |
| PATCH /:id | 编辑，提供当前version；对象编码不可变 |
| DELETE /:id | 删除未使用规则，body包含version |
| POST /allocate | `{objectCode,requestId}` → `{code}`，真实分配并消耗流水 |

HTTP取号需独立`allocate`动作权限，仅用于受控接口集成，普通业务前端不要先调用取号再传回创建接口。现有创建接口均由服务端分配，不接受手填编码。HTTP预留号码不会自动绑定随后任意创建请求；新接入方必须在服务端正确保存其取得的号码，不能重复调用发号后丢弃第一次结果。

## 历史兼容与部署

历史客户C+年月、商机O+年月、报价Q+日期+8位全局序列、入库RK、销售出库XSCK保持原值。旧序列和counter表不删除，但新建业务已停止调用旧算法；旧格式纯函数保留用于历史测试，不是新业务取号入口。

迁移：`20261004100000_numbering_rules`，新增sys_code_rule/sys_code_counter/sys_code_issue；统一服务是唯一写入责任模块。先应用迁移，再运行 `pnpm --filter @forge-crm/server exec tsx scripts/initialize-numbering.ts`。脚本限制本地数据库，正式发布应按环境审批调用同一初始化函数。只给内置系统管理员新增菜单与动作；普通角色按需分配view/create/update/delete，接口集成另配allocate。

回退时停止新建操作并保留三表，不删除账本或恢复旧计数；通过前滚修复恢复。生产发布、跨系统外部发号服务与尚未实现的业务模块不在本次范围。

验证和使用入口见[交付记录](../testing/numbering-rules.md)。可复用候选为“规则配置+原子发号账本+静态业务适配器”；对象默认清单及历史字段映射属于本项目业务，不直接提升为跨项目标准。

## 2026-10-11 采购接入

供应商保存调用SUPPLIER，采购订单保存调用PURCHASE_ORDER，采购入库保存调用INBOUND；更新和状态动作不重新取号。INBOUND历史适配采用静态白名单联合scm_inbound_order与scm_purchase_receipt，SUPPLIER/PURCHASE_ORDER分别查询对应新表，避让同规则历史号码。没有改动已配置前缀、日期或开始数。取号与业务保存分开，失败允许断号，不回收。见[采购方案](../design/purchasing/solution.md)。
