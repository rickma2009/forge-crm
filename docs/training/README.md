# Forge CRM 团队 AI 开发案例

这里收录可复现的练习，帮助团队把需求、实现证据和复用边界连起来。案例用于学习和评审，不替代目标项目的业务需求、权限决策或 Gate。

第一次使用从[团队练习路径与评审方法](learning-path.md)开始。学员使用统一[交付记录模板](../../_methodology/templates/training-submission-template.md)，讲师按证据评审，不按页面数量或 AI 生成代码量评分。

| 案例 | 练习重点 | 资产状态 |
|---|---|---|
| [库存汇总、明细联动与事务追溯](cases/inventory-summary-drilldown.md) | 数据粒度、条件继承、来源行追溯、导出编码与完整性、契约与服务证据边界 | 12 项页面及 2 项隔离库查询测试通过；导出公共测试另 12 项，仅 CNY 业务契约，跨项目采用待补 |
| [GitHub Actions 工作流复用决策](cases/github-actions-reuse-decision.md) | 官方来源、组织模板与可复用工作流的区别、采用时机 | 候选；当前 CI 未拆分 |
| [从页面样式提炼公共查询栏](cases/query-bar-component-extraction.md) | 有限参数、兼容默认调用、业务边界、分层验证证据 | 隔离安装与交互已验证；独立业务项目采用待补 |
| [AI 分析草稿与人工确认保存](cases/ai-analysis-reviewed-save.md) | 资料快照、结果校验、确认幂等、权限与质量证据 | 8 项单元及 3 项隔离库测试通过；真实模型质量待验证 |
| [重复初始化与字段维护权](cases/catalog-seed-ownership.md) | 创建/更新分离、人工事实保护、作用域、回滚与并发时序 | 10 项单元及 3 项隔离库测试通过；其他并发时序与跨项目采用待补 |
| [React 状态归属与公共组件边界](cases/react-state-ownership.md) | 官方机制、草稿与已提交条件、受控值、重置反例 | 官方来源与源码已核对；5 项组件契约测试通过，团队练习未执行 |
| [组件通过而宿主仍裁切](cases/component-and-host-layout.md) | 可用宽度、容器责任、局部滚动、旧规则反例 | 实际窄屏缺陷与测量；验收范围见案例，非全站移动适配 |
| [销售出库的过账不变量](cases/inventory-posting-invariants.md) | 余额粒度、流水、原子回写、冲销成本、幂等与并发证据 | 11 项单元及 5 项隔离库测试通过；同键不同内容、异常断线等仍待验证 |

新增案例应给出原始来源、可复现任务、运行命令、预期与实际结果、失败场景、可复用内容、排除内容和采用记录入口。每次规范变化应复审相关练习；案例过期时标明版本和替代案例，不静默保留为“最佳实践”。

新增案例可从[培训案例模板](../../_methodology/templates/training-case-template.md)起步。实现型练习记录运行目录、预期和实际结果；设计型练习可提交源码核对或评审证据。统一将“已执行”“待验证”“不适用”写清楚。

## 维护入口与验证边界

从仓库根目录运行 `node _methodology/scripts/check-markdown-links.mjs`，检查根 README、方法论、培训案例、验收记录及 `_ref/README.md` 中的本地文件链接。该命令只读，不连接服务或数据库。2026-10-03 扩大扫描范围后，135 个 Markdown 文件通过；此前检查只覆盖 119 个文件，未包含培训和验收目录，不能把旧结果当作它们的链接证据。

检查器自身运行 `node --test _methodology/scripts/check-markdown-links.test.mjs`：4 项针对性测试通过，含两个新目录各自的失效引用反例；已接入现有 workbench 验证入口，本轮未运行完整 workbench。修改案例时使用与变化相关的最低验证等级，不因存在入口而自动运行全部测试。

当前仅检查普通 Markdown 内联文件链接的存在性，不验证标题锚点、远程地址、代码中提及的路径、图片、引用式链接、文档结论或历史测试是否仍有效。源码变化后的证据复审、真实目标项目采用和团队培训效果仍需分别取得证据。
