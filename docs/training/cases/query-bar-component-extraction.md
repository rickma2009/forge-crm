# AI 开发练习：从页面专用样式提炼公共查询栏能力

## 目标与准备

让开发者从明确的页面需求识别可复用的布局差异，用一个有限参数扩展已有组件，并保持业务查询由页面负责。预计 30—45 分钟，适合了解 React 与 CSS 的开发者。

练习使用本仓库依赖；命令均在仓库根目录执行。静态阅读不需要数据库，页面组件测试使用模拟网关。浏览器验收需要本地应用、登录权限及两个库存菜单。核对日期：2026-10-03。

来源：[原始库存需求](../../../.specify/sources/REQSRC-089-current-inventory-transaction-pages-20261003/source.md)、[查询区规范 UI-QUERY-01](../../../_methodology/style-index.md)、[公共组件](../../../packages/web/src/common/RecordQueryBar.tsx)、[组件样式](../../../packages/web/src/common/record-query-bar.css)、[库存页面](../../../packages/web/src/showcase/InventoryStockPages.tsx)。

本案例已有项目内实现、针对性测试、隔离宿主及实际库存页面浏览器证据；尚无独立业务项目采用证据。各次验收的日期和范围见下方记录。

## 事实与边界

| 分类 | 内容与证据 |
|---|---|
| 用户要求 | 当前库存的七个条件和事务页的六个条件均同排、不换行，见原始库存需求。 |
| 实现事实 | `RecordQueryBar` 接收 `layout="singleRow"`；默认布局仍响应式换行。单行模式仅字段区横向滚动，操作区不收缩。两个库存页面均使用此参数。 |
| 实现事实 | 法人/仓库联动、分类选项、表单输入、已提交查询条件、API 和权限由库存页面持有；组件只渲染布局并调用 `onQuery`、`onReset`。 |
| 设计判断 | 把重复布局放进公共组件，可以减少同类页面重复覆盖 CSS 的维护点；是否提高开发效率仍需团队采用数据。 |
| 未知 | 已检查 Chrome 桌面和窄屏的单行布局；系统缩放及其他浏览器仍待核对。项目内两个调用方及隔离宿主不能证明跨项目兼容性。 |

## 可复现任务

接入前可先运行 `node _methodology/scripts/inspect-component-dependencies.mjs CMP-01`，再对比 CMP-04。说明为何前者两个本地文件仍需宿主样式，而后者还包含网格、视图契约及导出依赖；工具限制见[依赖指南](../../../_methodology/components/dependency-guide.md)。该检查只辅助识别复制范围，不替代后续构建和交互演练。

需要源码副本时，使用 `node _methodology/scripts/export-component-source.mjs CMP-01 /absolute/new-output-directory`；在交付记录中保存 manifest 的文件哈希，并列出目标项目改了什么。尝试指向已有目录应失败，不能靠覆盖方式“更新”同学的适配成果。此步骤验证复制可追溯性，不替代下方独立宿主演练。

1. 写出验收条件：默认调用行为不变；库存两页条件不换行；窄屏查询/重置可见；键盘可到达每个字段；业务筛选仍由页面提交。
2. 阅读公共组件和两个调用方。列出组件可以负责的布局、按钮顺序，以及必须留在页面的业务状态和数据获取。说明为什么不需要新造一套查询组件。
3. 核对参数及样式：`layout` 默认值为 `default`，单行样式只影响修饰类；宽日期字段通过 `--record-query-field-width` 调整。检查[页面 CSS](../../../packages/web/src/showcase/inventory-stock.css)没有重写查询字段组和操作组布局。
4. 使用下表命令复现自动验证；把自己的日期和结果写进练习交付。指出静态规则与组件测试各自覆盖哪些验收项。
5. 在浏览器分别打开客户列表、当前库存、库存事务明细，按桌面与窄屏尺寸核对默认和单行布局。用 Tab 依次访问字段及操作按钮，确认聚焦字段可见、操作可提交。记录实际视口和结果，未执行则明确记“未执行”。
6. 假设第二个项目使用另一套字号和控件高度，填[采用记录](../../../_methodology/templates/ui/adoption-record-template.md)，说明需调整哪些令牌与依赖。此项是采用方案练习，不能标记为已跨项目采用。

接入操作可参考[组件依赖指南](../../../_methodology/components/dependency-guide.md)中的最小查询栏示例，重点核对全局表单样式、直接 label 结构、form 不嵌套，以及重置时提交的值。

可选动手练习：根目录执行 `node _methodology/scripts/rehearse-query-bar.mjs`，检查生成工程没有导入 CRM 页面样式，并按[隔离演练说明](../../../_methodology/examples/query-bar-adoption/README.md)核对浏览器行为。加 `--clean-install` 可在新目录独立安装依赖。2026-10-03 两种模式的构建和隔离宿主浏览器检查均已通过；源码哈希、实际版本与范围见各自记录，不能替代 CRM 业务页面视觉验收或真实业务项目采用。

可复用的 AI 任务提示：

> 请对照指定页面需求、公共组件及其调用方，先列出布局不变量和业务专属责任，再提出最小公共接口变更。保留默认调用行为，用两个实际调用点检查边界。验证结果分别标明静态、组件测试和浏览器证据；缺失证据写明未执行。不要把页面私有 CSS 原样复制到新组件，也不要引入未要求的筛选业务。

## 失败场景与评审

- 把所有查询栏改成 `nowrap`：可能破坏默认响应式布局。修正为显式选择的参数，并检查原调用方。
- 让整个查询栏滚动：窄屏可能把查询按钮推到视口外。修正为字段组滚动、操作组保持可见，并用浏览器验证。
- 把“查询后清空库存明细”放进公共组件：组件将依赖库存状态，其他对象难以复用。由调用方的 `onQuery` 管理该业务。
- 仅凭静态检查声称“所有分辨率已对齐”：检查没有渲染能力。应补浏览器证据或明确限制。
- 干净安装后构建超时就断言组件不可复用：先查进程状态、日志、实际依赖版本和运行架构。当前演练曾在60秒终止，同一工程重新构建约111秒后成功；脚本随后调整上限并复验。超时原因与复验结果都应保留，不把最初失败删除为“从未发生”。

学员交付一页采用说明：五条验收条件、责任边界、命令结果、浏览器记录或缺口、一个反例和一个独立项目采用决策。评审时检查结论是否超出了实际证据。

## 复用与维护

### 真实反例：依赖报告正常，但调用示例缺少 Hook

2026-10-03 对照 CMP-08 工作区页签目录与 README，发现示例调用 `useRouteTabs`，源码登记却没有公共 `route-tabs/index.ts`。原依赖扫描仅输出 RouteTabs.tsx、model.ts、CSS、README 四个文件，`unresolved: []`；从这些入口无法发现由宿主而非视图调用的 Hook。

在[导出测试](../../../_methodology/scripts/export-component-source.test.mjs)新增真实目录回归，首次执行 4 项通过、1 项失败，报缺少 index.ts。修正[组件目录](../../../_methodology/components/index.json)公共入口并在示例中写出 import 后，5 项通过，导出包含 index.ts、useRouteTabs.ts 等六个文件。临时消费工程 `/var/folders/hn/nhcrrs617l72_8rt97l8xgt00000gn/T/route-tabs-consumer-A5GO2q` 用实际快照导入 RouteTabs/useRouteTabs/applyTabAction，`tsc --noEmit` 退出 0；日志与快照在该临时目录，可能被系统清理。依赖链接本机现有安装，没有取得 CMP-08 干净安装或浏览器证据。

学员先回答：“零未解析依赖”为什么仍可能缺源码？然后从文档调用示例列出需要的值、类型、Hook、样式及公共入口，并逐一核对导出快照，最后编译一个最小调用方。评审不接受仅重复运行同一入口扫描。可复用的是**从使用方反查入口，再从入口遍历依赖**的双向检查；不要要求所有项目采用相同目录名或同一种 Hook。

复验入口：仓库根运行 `node --test _methodology/scripts/export-component-source.test.mjs`。它证明已登记示例所需文件被导出且字节一致，不自动编译所有目录示例；未来新增复合组件仍需各自补使用方验证。

### 把组件交给另一个 AI 任务

在系统“插件组件 → RecordQueryBar”中复制参考指令，另附目标列表的需求和可访问的源码快照。指令从[公共模板](../../../_methodology/templates/ui/component-adoption-prompt-template.md)生成，携带该组件的源码入口、依赖、步骤和配置，而不是只说“按这张图做一个查询栏”。若来源目录不在目标工程中，应提供快照或明确缺口，不能按文件名臆造接口。

练习时分别检查 AI 是否做到了：从真实 Props 确认调用；把查询参数和 API 留给业务；说明采用、适配与排除项；对目标宿主执行必要验证；把未执行项保留为未知。团队已有的 AGENTS 和技术约定优先，不把 Forge CRM 的业务规则和整套目录结构强加给目标项目。复制指令只是任务输入，不能证明接入质量；验收仍使用上面的实际证据。

可复用的是显式布局变体、默认行为兼容、字段与操作区的布局责任分离，以及按证据层次验收的方法。物料字段、库存权限、API、币别与过滤状态不能搬进通用组件。

代码级采用仍依赖 React、Tabler Icons 和目标项目的表单/颜色令牌，需适配后验证。接口、样式规范或库存调用方变化时，从[培训入口](../README.md)复审此案例；成熟度继续遵循[资产晋升规范](../../../_methodology/09-资产类型、成熟度与晋升规范.md)。
