# 公共组件通过，为什么真实页面仍然裁切

来源：Forge CRM 的 TreeWorkspace 独立接入演练与组织/资源菜单页面；2026-10-03。本案例来自实际项目排查，不宣称所有 Grid 布局都应采用同一种修复。

## 任务与可观察失败

树形组件在 390px 独立宿主中通过了搜索、菜单、选中和上下布局检查；放回 CRM 页面却出现右侧内容裁切。若仅引用组件演练通过记录，会遗漏真实宿主的问题。

只读浏览器测量显示：视口 390px、侧栏 64px、主工作区 326px；主工作区内部未显式声明列宽，计算出的列宽约 417.78px，顶部栏和正文随之超过容器。外层已经有 `overflow: hidden`，所以页面根元素没有水平滚动并不能证明内容没有被裁切。

排查入口：[工作区样式](../../../packages/web/src/showcase/showcase.css)、[浏览器回归脚本](../../../scripts/check-workspace-width-browser.mjs)、[树形组件独立演练](../../../_methodology/examples/tree-workspace-adoption/README.md)。

## 本项目修复与责任边界

在 `.showcase-main` 增加 `grid-template-columns: minmax(0, 1fr)`，明确让唯一内容列服从可用空间。复测同一场景时主工作区、顶部栏和正文宽度均为 326px，树形工作区为 298px（正文左右各 14px 内边距）。没有给树组件增加 CRM 侧栏宽度，也没有通过新增 `overflow: hidden` 掩盖问题。

| 责任 | 应验证的范围 |
|---|---|
| 公共组件 | 自身搜索、菜单、焦点、响应布局和内容容器 |
| 应用宿主 | 侧栏扣除后的真实可用空间、网格轨道、顶部栏与正文边界 |
| 业务内容 | 表格/内容页签的局部滚动、动作可达性、长文字 |

表格可以在自己的容器中横向滚动；不要把“所有节点 scrollWidth 都等于 clientWidth”设为全站断言。本案例只约束外框，并另检查树菜单保持在视口内。400px 宽的独立演示不能代替“400px 视口减去导航占用”的真实页面测试。

## 可复现练习

前置：本机 CRM Web/API 和演示库可用，`.env` 中存在本机演示账号配置；使用合成数据。脚本只读查看页面和打开/关闭菜单，不提交业务写入。运行于仓库根目录：

```sh
node scripts/check-workspace-width-browser.mjs
```

需要可导入 Playwright 以及 Chrome；可以用 `PLAYWRIGHT_MODULE_PATH` 指向已有模块。默认 `http://localhost:5173`，`QA_BASE_URL` 只接受本机 HTTP 地址。缺少演示账号配置则失败，不打印密码；不把生产凭证带入练习。

脚本覆盖资源菜单、组织架构、当前库存、库存事务明细，分别检查 1440px 和 390px。采集时统一关闭 CSS 动画，避免在外框的 180ms 切换动画中采样。对资源菜单 390px 场景临时注入旧列规则，断言能够重现越界，再移除规则；这能检验回归检查是否真的区分失败与成功。截图和结果存于新的临时目录。

学员先画容器宽度关系，再预测哪个元素可能越界，然后运行并解释结果。提交宿主/组件/业务责任表及自己的执行记录；可尝试长名称或不同视口，但不能把本案例历史结果当作自己的验证。未运行应明确写未运行。

## 复用与限制

实际结果（2026-10-03）：上述四页 × 两种宽度共 8 个场景通过，Chrome 154.0.8037.95。资源页旧规则反例重现越界，移除后恢复；登录后控制台与页面异常为空。详见[执行记录](../../testing/workspace-width-verification.json)。Browser plugin 未提供，使用已有 Playwright/Chrome。首次脚本沿用旧 `grid` 角色，库存页虽已显示仍定位超时；检查失败截图与源码后改为当前适配器的 `.ag-root`，再完成全部验证。登录前的会话探测 401 不作为已登录页面异常统计，登录后的错误仍会使检查失败。

可复用：分层取证、记录实际可用宽度、明确局部滚动责任，以及用旧规则反例验证检测器。具体 CSS 修复取决于目标布局，不应给所有 Grid 容器批量套用同一声明。

本例不证明所有页面、浏览器、缩放比例和屏幕阅读器均通过，也不验证业务 API。树形演练的历史独立安装记录仍有价值，但不覆盖宿主样式的后续变化；记录失效时保留历史，并新增相应范围的证据。目标项目采用时填写[采用记录](../../../_methodology/templates/ui/adoption-record-template.md)。
