# Forge CRM 本机一键启动

在工程根目录执行：

```bash
bash start.sh
```

脚本检查依赖、`.env` 和默认端口，必要时打开 OrbStack，等待 Docker 就绪，启动原 PostgreSQL 容器并等待其可接受连接，然后以前台方式启动前后端。Vite / Nest 成功启动后访问 http://localhost:5173/ 。终端需保持打开；按 `Ctrl+C` 停止前后端，数据库继续保留运行。

## 数据安全与适用边界

- 本入口用于已初始化的当前 Mac 开发环境，不是新电脑安装器或生产部署脚本。
- 2026-09-21 实际检查确认：容器 `interaction-pattern-lab-postgres-1` 使用数据卷 `interaction-pattern-lab_interaction-pattern-lab-postgres`。Forge CRM 改名只改变产品和代码身份，日常启动继续复用原数据库；这是显式兼容配置，不是遗留遗漏。
- 不执行 Compose 新建、迁移、seed、reset、删卷或强制结束占用端口的进程；容器缺失时停止，不猜测应使用哪个数据库。
- 首次使用需准备 Node（package.json 要求 >=22.12.0）、pnpm（>=9.15.0）、OrbStack/Docker、根目录 `.env`、已安装依赖及已初始化数据库。更新代码带来的依赖或数据库结构变更仍需单独处理，不因启动自动获得迁移授权。
- 默认前端 5173、后端 3000、数据库 55432；本入口按当前默认端口检查。改变 `.env` 端口或数据库目标时，也需相应调整启动入口，不应直接沿用。
- 重复启动若发现端口已占用，会给出提示并退出，不另开一套服务；不判断占用者一定属于本项目。
- `pg_isready` 仅证明数据库服务可接受连接，不证明业务表、登录配置和全部迁移正确。应用启动后可用 `curl --fail http://127.0.0.1:3000/api/health/ready` 检查应用与数据库连通。

## 回归验证

```bash
bash -n start.sh
node --test scripts/start.test.mjs
```

测试运行真实入口，替换 Docker/GUI/开发进程等外部命令，覆盖停止容器恢复、已运行容器、Docker 冷启动，以及容器缺失、启动失败、超时、缺少配置、端口占用。测试不操作真实数据库。

可复用原则：分层等待就绪、明确失败、复用既有数据、拒绝隐式重建。当前容器名、OrbStack 与端口为本机专属配置，不能直接作为跨项目模板。本次为启动缺陷修复，不改变业务规格，也不代表任何新 Gate、资产晋升或 Release 批准。
