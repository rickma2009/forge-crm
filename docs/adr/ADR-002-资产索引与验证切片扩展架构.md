# ADR-002：资产索引与验证切片扩展架构

> 状态：accepted
> 日期：2026-08-31  
> 关联功能：`002-bulk-assignment-partial-success`  
> 决策 Gate：Architecture Gate

## 1. 背景

历史 ADR-001 为两个具备 Demo 的种子模式建立了 React/Vite 静态工作台和显式 Demo Adapter。新业务基线要求浏览 103 个分类项，其中绝大多数没有 Demo；同时必须把成熟度、覆盖关系、项目验证切片和方法论资产分开管理。现有 `demoId` 两值联合类型、固定注册表和“目录必须正好两项”的检查已经触发 ADR-001 复审条件。

## 2. 决策驱动因素

- `_methodology/` 必须是通用资产唯一权威来源；
- 103 项需要机器可检查，但不能被误称为 103 个成熟 pattern；
- Lab 需要展示无 Demo 条目，并把 `maturity` 与 `coveredBy` 分离；
- 第三个及后续验证案例不应修改 App 主流程或扩大字面量类型；
- React Demo 与未来 HTML Example 应能共享行为证据，而不是复制 UI 代码；
- 当前只有一种运行时和一个消费应用，不应过早建设 CMS、插件系统或通用渲染器。

## 3. 备选方案

| 方案 | 优点 | 代价与风险 | 结论 |
|---|---|---|---|
| A. 扩大现有手写 `patterns.data.json` | 改动最少 | 在 Lab 形成第二规范源；103 项易漂移；项目覆盖与成熟度混层 | 不采用 |
| B. 运行时解析 08 Markdown | 无额外登记册 | Markdown 结构脆弱；资产状态、证据和下一证据难表达；浏览器构建跨目录复杂 | 不采用 |
| C. 方法论机器登记册 + 生成式 Lab 投影 + Lab 切片 manifest | 权威边界清晰；可检查 103 项；项目事实与资产事实分离 | 首次需要 Schema、录入和生成检查 | 采用候选 |
| D. 在线资产 CMS/通用 Schema 渲染器 | 长期编辑与自动渲染能力强 | 当前没有第二消费者或真实编辑需求，复杂度和治理风险过高 | 暂缓 |

## 4. 决策

1. 在 `_methodology/patterns/` 建立经 Schema 校验的机器资产登记册；08 保留分类语义，登记册持有 ID、类型、成熟度、证据和资产链接。两者通过双向检查防止名称与数量漂移。
2. Lab 只消费生成式只读投影；生成器支持写入和 `--check`，CI/verify 使用后者阻止人工修改。
3. Lab 单独维护 validation-slices manifest，记录 `VAL-*`、覆盖资产、Demo ID 和 Spec 引用。覆盖关系不得推导成熟度。
4. 保留显式懒加载 React Adapter，但把 `demoId` 改为开放字符串，`getDemo` 允许返回 null，并用契约测试验证 manifest 与注册表一致；不建设动态插件加载。
5. 场景契约使用版本化 JSON + Schema，作为测试 oracle 约束 fixture、动作、可观察结果、失败代码和键盘路径；不驱动 UI 渲染。候选契约留在 Lab，资产晋升后再决定是否进入方法论 Example。
6. 沿用 React 19、TypeScript 5.7、Vite 5、Vitest、Testing Library、原生 CSS和现有 pnpm 锁文件；不新增运行时依赖。

## 5. 与 ADR-001 的关系

ADR-001 的静态单包、无后端、目录 Module、显式 Demo Adapter、错误隔离、懒加载和生命周期重置继续有效。以下内容由 ADR-002 替代：

- “每个目录条目必须有 Demo”；
- `demoId` 仅允许两个值；
- 投影检查要求目录正好两个条目；
- App 内手写投影承担完整资产清单；
- “新增第三模式只新增投影、Adapter 和测试”的不完整扩展步骤。

## 6. 后果

### 正面

- 103 项目录可查且不虚构成熟度；
- 方法论资产、Lab 投影和项目验证证据各有唯一职责；
- 无 Demo 条目成为正常状态；
- 新验证切片通过 manifest 与 Adapter 扩展，不修改主流程；
- 行为契约可被不同技术实现复用。

### 代价

- 需要首次录入并人工抽查 103 项；
- 生成文件需要同步提交并由检查器防漂移；
- 显式 Adapter 表仍需为每个可运行 Demo 增加一行映射；
- 场景契约和 React 行为仍需契约测试维持一致。

## 7. 复审条件

- 出现第二个独立应用消费机器登记册；
- 需要在线编辑、多人协作或内容发布；
- 出现 React 以外的第二种真实运行时并需要动态装载；
- 可运行 Demo 达到 10 个且显式注册成为主要维护瓶颈；
- Markdown 与 JSON 双向检查持续脆弱，需要迁移分类权威格式；
- 引入真实后端、权限、事务或业务数据。
