# 销售出库隔离数据库验证

2026-10-03，L2 针对性测试补充。未改业务运行逻辑，没有在演示库新增单据或修改库存。

## 运行与环境

仓库根目录：`node scripts/test-sales-posting-integration.mjs`。需要已安装工程依赖和本机 PostgreSQL，连接用户可创建/删除临时测试库。脚本只接受本机地址，随机创建 `sdd_sales_<12位十六进制>` 数据库；测试还检查环境开关与数据库名称。直接运行普通 Jest 时该套测试默认跳过。

测试库从当前 Prisma schema 执行 db push、基础 Seed，再加载销售迁移文件末尾的部分唯一索引与检查约束。**这不是完整历史迁移演练**。使用 Node v24.16.0、Prisma 7.9.1、本机 PostgreSQL 127.0.0.1:55432；没有启动 HTTP 应用、AI Worker 或调用外部模型。

所有库存增量由真实入库服务创建并过账。测试物料从隔离库 Seed 的合成物料复制，采用新的物料编码和测试批次；不同案例使用不同批次。销售单据经真实服务创建、提交、审核；并发案例仅添加等待屏障以协调两笔调用，库存写入仍执行原服务和真实数据库事务。

## 实际结果

首次执行：1 个测试文件、3 项通过，Jest 总耗时 5.414s。后续补齐两类反例后，同一入口 **5 项通过**，Jest 总耗时 5.464s。源码：[隔离运行器](../../scripts/test-sales-posting-integration.mjs)、[数据库测试](../../packages/server/src/sales/sales-posting.integration.spec.ts)。

| 场景 | 安排与断言 | 结果 |
|---|---|---|
| 第二行失败整单回滚 | 先通过另一笔真实出库消耗第二批次；观察目标第一行过账调用已成功，然后第二行库存不足。比较审核前后余额、目标单据、订单、目标流水和事件完整快照 | 一致；无部分写入 |
| 两笔竞争库存 | 同批次库存 3，两笔各出库 2，屏障确保两笔都进入过账阶段。一笔提交，一笔并发失败；余量 1、金额 10，只有一条负向流水，订单已出货 2，失败请求无操作事件且单据仍待审核 | 通过；补入 2 后显式重试原失败请求可提交，累计出货 4、余额 1 |
| 重复审核/冲销与对账 | 相同请求键顺序重试审核与冲销，分别比较完整快照。原负向流水和反向流水都保留，订单回到未出货；按相同法人/仓库/物料/批次汇总全部测试流水 | 余额数量 3、金额 30，与净流水一致 |
| 流水插入失败 | 在隔离库增加仅拒绝本例批次 OUTBOUND 流水的真实 CHECK 约束，观察包含该约束名的数据库拒绝；比较过账前后完整快照，finally 删除临时约束 | 余额扣减回滚，单据、订单、流水和事件均无部分写入 |
| 同键同时审核 | 屏障确保同一单据、动作、操作者、请求键的两笔调用均进入过账；一笔提交、一笔并发冲突。余额 1/10、订单已出货 2 且行状态 PARTIAL，负向流水和对应事件各一次；随后原键重试并比较快照 | 只产生一次业务影响；冲突后的重试返回当前已提交单据，不再写入 |

第一次运行因测试夹具漏填必填“所属区域”而失败，尚未进入过账；补齐夹具后上述测试通过。这不是业务修复，不将第一次失败计作过账回滚证据。

两次测试库 `sdd_sales_30ad84dd9c7f`（夹具失败）、`sdd_sales_09f46b02aadf`（通过）均由 finally 删除，并另外只读查询 `pg_database` 确认不存在。脚本只删除自己本轮成功创建的随机库。进程被强制杀死/机器断电时 finally 不保证执行，应按输出的确切测试库名核对，不批量删除类似命名数据库。

后续五项测试使用 `sdd_sales_5a0cc702a7a7`，同样由 finally 删除并另查 `pg_database` 确认不存在。故障约束仅存在于此隔离数据库，不新增到生产 schema 或迁移。SQL 标识符与批次字符串由测试内 UUID 生成，不接受用户输入。

## 证明范围与剩余缺口

运行入口后续增加 `inventory-summary.integration.spec.ts`，因此当前命令共运行 7 项（本文件描述的 5 项过账 + 2 项查询）。新增查询验证及夹具币别边界见[当前库存验收](current-inventory-acceptance.md)，不计为新增过账场景。

结果补足了模拟事务无法证明的真实回滚、受控并发竞争、同键同时审核和显式重试场景；不等于负载测试，也不等于所有隔离异常已覆盖。同键同时审核的一笔请求会收到并发冲突，不承诺两个请求都立即成功；“业务影响一次”和“每次响应都成功”是两个不同的验收条件。

未验证：HTTP/RBAC/CSRF、同键不同完整请求内容的比较、自动重试、提交成功但客户端断线、跨法人/跨租户攻击、全套迁移升级及历史坏账恢复。当前服务幂等仍按单据/动作比较并返回当前单据，不承诺重放原始响应；本轮没有修改这一语义。

复用价值：用真实入库建立余额、构造第二行失败、用等待屏障协调竞争、按对象和维度比较完整快照，并独立确认清理。目标项目应照其业务与数据库重新设计夹具，不能直接复制本项目客户/账号/表名或把本次通过计入自己的验收。
