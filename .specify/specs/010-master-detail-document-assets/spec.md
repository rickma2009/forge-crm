# Feature Specification：主从单据与企业组件资产化

| 项目 | 内容 |
|---|---|
| Feature ID | `010-master-detail-document-assets` |
| 来源 | `REQSRC-014`、`REQSRC-029`—`REQSRC-032` |
| 状态 | `specification-approved-awaiting-architecture-gate` |

## 1. 用户故事

- `US-1001`：作为产品或设计人员，我希望从分类资产定位到基础规范、组件、页面模板和场景，以判断能否在新项目采用。
- `US-1002`：作为前端开发人员，我希望查看主从单据组件的状态、失败行为和可交互案例，而不是从单一销售页面反推契约。
- `US-1003`：作为方法论维护者，我希望每项资产能定位来源、实现、测试、成熟度和下一证据，避免门户与方法论产生两套事实。

## 2. 功能需求

### 资产与追溯

- `REQ-1001`：销售订单、工作台和主从工作区必须分别引用其直接用户来源，并保留所采用的 UI 萃取来源。
- `REQ-1002`：分类资产、Showcase 页面、Demo、模板和证据必须通过稳定 ID 建立可检查关系；无关联项必须被自动检查报告。
- `REQ-1003`：门户概览必须分别表达交互页面与说明页面数量，不得以总登记数暗示全部实现。

### 最小基础规范

- `REQ-1004`：本切片必须展示所使用的语义色、排版层级、密度/间距、图标语义、焦点和状态令牌，并能定位其来源与使用资产。
- `REQ-1005`：基础规范只覆盖当前切片所需范围；未定义项必须显式缺失，不得补造完整设计系统。

### SchemaForm

- `REQ-1006`：schema 字段至少支持文本、数字、日期、单选、远程选择的展示/编辑状态，以及分组、必填、只读、禁用、帮助和错误信息。
- `REQ-1007`：条件显隐、条件必填和条件只读产生可预测结果；隐藏区域中的错误必须能被定位或清除，不能静默阻断提交。
- `REQ-1008`：远程选择字段在只有已保存 ID 时仍显示可读名称；加载或回显失败必须提供安全反馈。

### 可编辑行表

- `REQ-1009`：用户可以新增空行、从候选项新增行、复制行、删除草稿行和标记删除已保存行。
- `REQ-1010`：删除已保存行后提供可感知撤销；撤销恢复同一行身份、字段值和原位置。
- `REQ-1011`：行表支持行级编辑、行选择、固定操作入口、金额/数量汇总和未保存变更提示。
- `REQ-1012`：行级校验必须标识行与字段；表单级校验摘要可以把焦点移动到首个可操作错误。
- `REQ-1013`：批量或保存结果存在部分成功时，必须分别显示成功、失败和未处理数量，并保留失败原因。

### 主从单据模板

- `REQ-1014`：模板至少包含对象头、表头字段区、行表、校验摘要、汇总、关联/日志入口和底部动作区。
- `REQ-1015`：模板支持新建、查看和编辑三种模式；只读与禁用在视觉、语义和行为上有区别。
- `REQ-1016`：保存中禁止重复提交；校验失败或模拟业务拒绝后保留用户输入；成功反馈与业务状态变化分别表达。
- `REQ-1017`：离开含未保存修改的对象前必须提供可取消的提醒，取消后保留原上下文。

### 双场景验证

- `REQ-1018`：销售订单场景验证表头、产品行、数量/价格/税率/交期、汇总、删除撤销、暂存和提交反馈。
- `REQ-1019`：BOM 场景必须复用同一核心表单与行表契约，并通过扩展点表达层级、匹配候选和差异高亮；不得把 BOM 专属规则写入核心组件。
- `REQ-1020`：所有场景操作只修改确定性 Demo 状态，不调用生产服务或写真实业务交易数据。

## 3. 非功能需求

- `NFR-1001`：核心搜索、字段、行操作、错误定位、保存和取消路径可使用键盘完成，焦点可见且状态可感知。
- `NFR-1002`：1440px 与 1024px 保持完整操作；窄屏按查看和轻量动作降级，不发生关键文本逐字挤压或不可恢复裁切。
- `NFR-1003`：技术栈中立 schema、状态矩阵和验收不依赖 React、Ant Design、AG Grid 或任何来源项目组件名。
- `NFR-1004`：新增资产、页面或 Demo 后，Registry、来源、成熟度和投影一致性可由自动检查验证。
- `NFR-1005`：验证场实现通过 lint、typecheck、自动测试、构建和真实浏览器 QA 后才可记录相应工程证据。

## 4. 验收标准

- `AC-1001`：销售订单、工作台和主从工作区均能从门户页面定位到直接 REQSRC、EPM 资产、实现和 QA 证据。
- `AC-1002`：门户概览准确显示交互/说明页面计数；孤立引用会使自动检查失败。
- `AC-1003`：基础规范页面只展示本切片实际使用的令牌，并列出消费者与未覆盖项。
- `AC-1004`：SchemaForm 完成字段类型、分组、显隐、必填、只读、禁用、帮助、错误和远程回显测试。
- `AC-1005`：行表完成新增、选品新增、复制、删除、撤销、选择、编辑、汇总和未保存提示。
- `AC-1006`：字段/行错误可从摘要定位；隐藏错误和远程回显失败均有明确结果。
- `AC-1007`：保存中防重复；验证失败、业务拒绝和部分成功保留必要上下文且反馈互不混淆。
- `AC-1008`：新建、查看和编辑模式中，只读与禁用行为符合定义；未保存离开可以取消。
- `AC-1009`：销售订单使用核心契约完成主路径与失败路径演示。
- `AC-1010`：BOM 通过扩展接口完成层级/匹配/差异验证，核心组件不出现组织或 BOM 专属字段。
- `AC-1011`：桌面、窄桌面、窄屏和键盘浏览器验收无 P0/P1/P2 阻断项，控制台无错误。
- `AC-1012`：方法论检查、Lab `pnpm verify` 和工作台 `verify-all.sh` 真实通过；成熟度不超过证据。

## 5. 明确边界

本 Spec 已由 `REQSRC-032` 批准可观察行为、验收标准和测试设计。该批准不包含技术目录、React API、状态库、数据模型、数据库、API、独立组件包、方法论正式晋升、外部部署或 Release。
