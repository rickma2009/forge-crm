# 联系人项目角色字典增量

来源：REQSRC-048，2026-09-22 用户明确要求的字段与初始化调整。仅复用现有字典、联系人存储和权限架构；不宣称新的 Architecture / Release Gate，不做资产晋升。

## 行为与验收

- AC-818 / TC-818：新增、修改联系人不显示所属客户 ID；仍由当前客户路径关联，不能通过表单切换归属。
- AC-819 / TC-819：原“决策角色”在表格及表单统一展示为“项目角色”，从当前系统有效的 `contact_project_role` 字典取值，不硬编码 UI 选项。
- AC-820 / TC-820：初始化决策人、技术选型人、使用者、预算审批人、其他，按此顺序展示；对应稳定值为 `decision_maker`、`technical_selector`、`user`、`budget_approver`、`other`。
- AC-821 / TC-821：保留原可空行为；新增或更换角色必须由服务端校验当前系统的有效字典值。已有历史值不自动改写；未改角色时允许保存其他字段，改角色只能选有效值或清空。
- AC-822 / TC-822：增量初始化可重复执行，仅补缺失项；不覆盖已有名称、停用状态或联系人。失败后可重试，不执行全量 seed 或 DDL。

## 数据与实现计划

| 项目 | 决策与边界 |
|---|---|
| 层级 / 所有权 | 系统配置，现有 `sys_dictionary` / `sys_dictionary_item`，唯一写入口为 DictionaryService / 已授权 API；客户服务仅调用字典校验 |
| 作用域 / 主外键 | 保持现有 systemCode、字典 UUID、字典项 dictionaryId 与作用域唯一键，不扩展多租户模型 |
| 联系人存储 | 保留兼容字段 decisionRole / decision_role，显示改名；不重命名物理列，不新增表，不伪造外键迁移 |
| 状态 / 审计 | 沿用字典 ACTIVE / DISABLED、创建修改人及 version；角色分类不承载状态机，不新增有效期 |
| 并发 / 权限 | 沿用客户/系统归属校验、RBAC、CSRF、联系人 version；历史值豁免只对同一版本且值未变的记录有效 |
| 恢复 | 无 DDL；初始化记录创建结果，重复执行仅补缺失。需要撤销时通过字典维护停用该字典，不删除已被使用的值 |
| 验证 | UI 隐藏归属、动态选项与中文回显；服务拒绝非法值、作用域校验、旧值未改兼容、版本冲突；初始化两次结果不重复；真实浏览器查看与选择，不新增业务联系人 |

任务：先补失败测试 → 前后端调整 → 增量字典初始化 → 单元测试、页面验证及记录证据。禁止为本次初始化运行涉及用户、角色或客户数据的全量 seed。

## 本地实施与验证记录（2026-09-22）

- 新增和修改联系人均隐藏客户 ID，仍从当前客户路径传给接口；地址弹窗未改动。联系人表格和表单统一显示“项目角色”，从当前系统字典加载选项并将编码回显为名称。
- CustomerService 新增时校验有效字典值；修改时先核对客户、系统和 version，再对变更的角色值校验。未变更历史值不被强制覆盖。
- 通过字典所属模块的 RBAC / CSRF API 初始化 `contact_project_role`：第一次创建 1 个字典和 5 个 ACTIVE 项；第二次创建 0 个字典、0 个项。未执行全量 seed、DDL、联系人写入或权限调整。
- 可复用的增量命令：在根目录运行 `pnpm --filter @interaction-pattern-lab/server exec tsx scripts/init-contact-project-role.ts`。固定使用本机 localhost:5173 和 demo-portal，其他环境不能未经评审直接复制执行。未来全量演示 seed 引用同一份默认值定义，但本次未运行全量 seed。
- 失败回归先捕捉旧字段名称、任意角色写入及缺少版本化历史值判断，再完成实现；UI 与服务定向回归、变更文件 lint、前端 typecheck、服务运行代码 noEmit 检查及初始化脚本单独类型检查通过。
- Chrome / Playwright：1440×1000 与 390×844 查看新增联系人，确认客户 ID 不显示、五个选项顺序正确、选择“技术选型人”后取消不改变联系人数量；无页面 JS 异常、无框架错误覆盖层。登录前 session 的 401 是预期未登录响应。未在真实库创建测试联系人。
- 原切片 `check-sdd.sh ... spec` 通过，仅说明既有规格结构检查通过，不代表新增人工 Gate 或 Release 批准。
