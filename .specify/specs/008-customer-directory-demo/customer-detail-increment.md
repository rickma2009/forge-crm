## 规格与验收

- AC-813：新增客户仍为弹窗；成功后打开新客户详情并刷新列表。查看、修改均进入容器客户页签，同一客户只打开一次，不同客户独立；按系统隔离。
- AC-814：对象头显示简称、编码、负责人；内部依次为客户基本信息、联系人、地址。查看只读，修改进入基本信息编辑，保存/取消在页内执行。
- AC-815：联系人按姓名、部门、职位、决策角色、手机、电话、邮件、状态、备注列展示为表格；地址按用途、收件人、电话、地区详细地址、默认标记、状态和备注展示。所属客户 ID 自动关联且不可改写。
- AC-816：子记录逐条新增、修改使用局部弹窗，失败保留内容，成功刷新；继续使用已有契约与并发版本，不扩大发票、OMS、删除或多用途地址业务。
- AC-817：返回列表保留查询分页；内部页签切换保留主记录草稿；关闭、刷新、离开未保存页面前确认，取消离开时保留输入。只读用户无写入口，服务端仍独立授权。

## 技术执行边界

复用 React/Vite、现有 RouteTabs、客户菜单权限、HTTP gateway、现有客户主子表及接口。不安装框架、不新增数据库迁移、不改 API 语义、不运行 seed、不回写 supply。

前端修复动态页签登记与菜单能力映射，按客户身份隔离编辑状态；拆出客户详情组件；补齐现有 gateway 中未接通的联系人地址方法。维护局部草稿与离开守卫，主记录和子记录独立保存。现有默认标记不升级为新的唯一性规则。
