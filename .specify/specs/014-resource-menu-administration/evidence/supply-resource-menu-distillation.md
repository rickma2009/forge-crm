# 《Supply 资源菜单系统蒸馏萃取报告》

## 1. 系统总览

### 1.1 系统定位与核心目标

该功能是“页面资源目录 + 导航挂载”的管理工作台：统一登记系统、模块、页面、子页面和组件，并维护页面按钮、关联页签及左侧菜单。

### 1.2 解决的业务问题

解决页面资源散落、菜单结构难以配置、按钮权限点无法统一发布的问题。树节点右键支持新建子节点、编辑、删除，工具栏支持新增和 SQL 导出；证据见 `MenuTree.tsx:79-139`。

### 1.3 输入、输出与业务边界

输入是页面资源、按钮、页签和导航挂载配置；输出是可授权资源目录及用户可见导航。字段级目录、数据权限表达式和个人视图虽已出现在 supply 新版页面中（`index.tsx:10-19,43-49`），但不属于本切片，继续由本工程既有 RBAC、list-view 模块负责。

### 1.4 材料范围与分析可信度

已核对 supply 前端、Hook、NestJS Controller/Service、Prisma Schema、建表 SQL 和 HTML 原型。线上链接在当前会话重定向到统一登录页，无法在未登录状态直接核对生产数据，因此视觉与行为结论以源码为主要证据，可信度高；线上实际数据量与组织专属配置未知。

## 2. 业务框架

### 2.1 业务域与能力模型

能力分为页面资源树、按钮资源、页签关联、导航挂载、导出和角色授权六部分。页面类型明确为系统、模块、页面、子页面、组件（`MenuTree.tsx:6-29`）。

### 2.2 端到端业务流程

管理员选择系统后加载资源树；选中节点并行加载按钮、页签与导航数据；编辑保存后刷新对应资源并通知导航更新。Supply 的并行加载和菜单刷新证据见 `index.tsx:101-166`。

### 2.3 核心业务实体及关系

`sys_page_resource` 形成单父级树；`sys_page_button` 从属于页面；`sys_page_tab` 连接同一应用内两个页面；`sys_menu.page_resource_id` 表达资源向真实导航的挂载。Supply 对应证据为 `iam_page_resource`、`iam_page_button`、`iam_page_tab`、`iam_page_left_menu`，见 `create-local-iam-tables.sql:197-286`。

### 2.4 业务规则、约束与例外

系统根不可删除或移动；移动不得形成环；页面/子页面必须有站内路径；编码在应用内唯一；页签不得关联自身且来源、目标必须属于同一应用；删除采用停用；写操作要求管理权限并记录审计。

## 3. 系统应用架构

### 3.1 整体分层架构

实现遵循 Contracts Zod 契约 → NestJS Controller/Service → Prisma/PostgreSQL → React Gateway/Page 的既有分层。

### 3.2 核心模块及职责

`rbac/resource-menu` 负责目录、权限发布和导航挂载；既有 `authorization` 负责运行时校验；Web 的 `ResourceMenuPage` 负责交互；Registry 只登记页面适配器与操作能力。

### 3.3 模块协作与调用关系

页面按钮发布时同步 `sys_permission` 与 `sys_menu_action`；新资源选择自动挂载时同步导航访问权限；系统角色获得新发布权限，普通角色仍需显式授权。

### 3.4 数据流与控制流

所有请求先验证会话，再按系统编码解析应用作用域，再校验 `access.resource-menu.*` 权限；写入通过事务同时完成资源、权限、导航和审计更新。

### 3.5 领域边界及外部系统边界

本工程不调用 supply 运行时接口，也不复用其 `iam_*` 表；supply 仅作为只读实现证据。线上页面需要组织 SSO，当前材料未提供可复用凭据。

## 4. 技术框架与技术栈

### 4.1 技术栈总览

当前实现采用 React 19、Vite、NestJS 10、Prisma 7、PostgreSQL 16 和 Zod。

### 4.2 关键技术组件及作用

Zod 固化请求/响应；Prisma 承担应用作用域关系；数据库复合外键阻止页签跨应用；Nest Guard 承担会话、CSRF 和权限验证。

### 4.3 核心目录职责

服务端位于 `packages/server/src/rbac/`，数据库位于 `packages/server/prisma/`，前端位于 `packages/web/src/showcase/`，共享契约位于 `packages/contracts/src/`。

### 4.4 数据、集成与中间件

页面目录和导航挂载分别持久化，避免将“可授权资源”与“当前菜单布局”混为一表；通过事务同步两者。无新增外部中间件。

### 4.5 构建、部署与运行模式

使用 pnpm workspace；迁移采用不可变增量目录；Seed 可重复执行并初始化 admin 的完整访问权限，viewer 不获得资源菜单权限。

## 5. 核心设计思想与实现方法论

### 5.1 架构模式与设计原则

参考项目是证据而非直接复制目标。保留业务不变量和交互模式，去除 SCS 编码过滤（`MenuTree.tsx:63-70`）、旧 IAM 命名及组织专属 SSO 逻辑。

### 5.2 关键实现策略

资源目录作为授权事实，`sys_menu` 作为展示挂载；按钮保存后发布稳定权限点；所有树写入使用版本号和循环检测；删除统一停用并级联停用展示挂载。

### 5.3 核心架构决策

| 决策 | 背景 | 当前选择 | 证据 | 收益 | 代价与风险 | 置信度 |
|---|---|---|---|---|---|---|
| 资源与挂载分离 | 一个页面可存在但不进入导航 | `sys_page_resource` + `sys_menu` | supply 同时存在 page resource 与 menu mount | 权限目录稳定、布局可变 | 同步逻辑更复杂 | 高 |
| 使用 `sys_` 平台表 | 本工程数据库治理要求 | 新表全部 `sys_` | `_methodology/11-数据库设计与数据分层规范.md` | 可跨业务系统复用 | 不直接兼容 supply 表名 | 高 |
| 不纳入字段级 ABAC | 本工程已有独立权限/视图模块 | 本切片只做页面、按钮、页签、导航 | `index.tsx:10-19` 显示这是后续扩展 | 边界清晰 | 与 supply 最新全量页面存在功能差异 | 高 |

### 5.4 可复用的方法论

跨项目可复用“资源登记 → 权限发布 → 导航挂载 → 角色授权 → 运行时过滤”的链路；前提是目标系统支持稳定的应用作用域、权限编码和事务写入。

## 7. 现存局限、问题与演进建议

### 7.1 当前局限与问题

页面资源支持树拖拽，按钮、页签和导航挂载支持新增、编辑、停用/删除；导航挂载当前采用上下移动排序，没有复刻 supply 的拖拽手势。字段目录和视图配置按边界未纳入。

### 7.2 近期改进

完成已登录浏览器视觉核验和左菜单拖拽细节；补充失败态和键盘操作。

### 7.3 中期演进

将权限发布做成显式预览/确认流程，并为导航变更提供差异比较与回滚包。

### 7.4 长期方向

在多个真实系统验证后，再把资源目录晋升为正式跨项目模式；当前只作为已验证候选实现。

| 优先级 | 问题或机会 | 证据 | 建议 | 预期收益 | 成本/前置条件 |
|---|---|---|---|---|---|
| P1 | UI 编辑覆盖仍不完整 | 与 supply modal 行为对比 | 补齐按钮/页签编辑与菜单拖拽 | 达到完整迁移目标 | 浏览器回归 |
| P1 | 生产页面未登录核对 | 线上只返回登录页 | 由用户提供已登录会话后复核 | 降低视觉偏差 | 合法会话 |
| P2 | 权限同步耦合事务 | 当前 Service 实现 | 增加发布预览与恢复测试 | 变更更可控 | 产品规则确认 |

## 8. 萃取总结

Supply 资源菜单最值得复用的是将页面资源树、按钮、页签与实际导航挂载统一管理，同时保持资源目录和展示菜单的职责分离。本工程保留了树形维护、右键操作、拖拽排序、SQL 导出及权限发布链路，并改造为 `sys_` 平台表、应用作用域复合约束、角色授权和审计事务。SCS 专属过滤、旧 IAM 表名、组织 SSO 与字段级 ABAC 未直接复用。该能力适合具备统一认证与稳定权限编码的企业管理系统，仍需经浏览器核验后进入 Release Gate。
