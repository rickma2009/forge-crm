# 数字员工与 Agent 场景增强开发 Plan

版本：2026-10-09 v0.2  
状态：首批近期三个有限代码切片已实施，业务试点及条件场景待验收；不是生产发布结论。  
本次授权更新：用户要求“请按推荐，按顺序进行任务实施”；按顺序落实 WP-01、WP-02 及私有资料范围 WP-03。新接口/企业共享与条件场景仍受原依赖限制。  
来源：[用户要求](../../sources/20261009-ai-scenario-enhancement-plan/source.md)。

## 1. 目标与本轮取舍

以已开发邮件、CRM Agent 为起点，把“信息获取和建议”提升为可核验的业务交付，逐步支持知识、采购、质量及经营分析。沿用企业蓝图的证据、权限、接管及净提效原则。

本计划选定三个近期场景与三个依赖就绪后才启动的场景，并安排一个配套的场景准备度/运行度量工作包。完成一个有限切片后独立交付，不自动续跑全部计划。

| 编号 | 场景 | 承载位置 | 现状证据/差距 | 顺序 |
|---|---|---|---|---|
| AE-MAIL | 邮件/售后处理结果闭环 | 现有邮件场景 | 已有同步、规则、任务动作；需核查结论、发送与关闭证据及重开一致性 | 近期 |
| AE-SALES | 客户会议到商机跟进 | 商机抽屉、个人 Agent | 已有分析、会话和确认待办；需明确会议输入、多行动项、执行反馈和事实区分 | 近期 |
| AE-KNOW | 受控产品/SOP 知识辅助 | 个人 Agent；邮件草稿选择来源 | 原 Agent 文档将知识库列后续；不能假设已经具备文档权限与版本 | 近期，先小范围资料 |
| AE-PO | 供应商回签与交期差异 | 现有采购订单执行场景 SCN-PO | 有场景登记，采购单/回签连接与运行闭环待核实 | 条件场景 |
| AE-QUALITY | 客诉/质量事件证据包与 8D | 现有客诉及质量事件 SCN-RMA | 有场景登记，QMS/追溯来源待接入 | 条件场景 |
| AE-BI | 销售或库存经营异常解释 | 现有业务详情与 Agent，上下文绑定 | 业务表可用；统一指标服务、授权聚合与解释需核查 | 条件场景，先选一个主题 |
| AE-OPS | 场景准备度、验收与价值记录 | 现有场景配置/审计/运行记录 | 已有管理壳和部分日志；不可用评分替代关键条件 | 配套、随首批建设 |

采购、质量、BI 三者由数据就绪和业务责任人决定择一先启动。软件研发/测试工具在企业侧评估，不在 CRM 中重建；财务支付、HR 事务、现场设备、自动排程、通用电脑操作不在此 plan。RFQ 独立菜单继续保持原暂缓决定，可在邮件/商机中提取询价缺失项，但不得顺带恢复菜单。舆情仍手工触发，行情继续遵守现有月度源规则。

## 2. 产品与技术责任分界

- 数字员工：事件/计划触发、队列、分派、业务处理、预警、执行记录及接管。
- Agent：用户主动提问、授权查询、来源解释、行动草稿。不会替代场景状态机。
- Skill/模板：会议提取、邮件草稿、回签检查、8D、经营解释的方法和输出要求；不承载凭据、权限和调度。
- 业务服务：客户、商机、订单、库存和未来采购/质量对象的权威记录及合法动作。
- 公共能力：身份、作用域、连接、来源引用、模型调用、运行限额与审计按已有契约复用。

不进行全系统运行引擎合并，不新建另一套审批、邮箱连接或通用任务中心。共性接口只提炼实际出现的重复需求，保留各场景的任务、状态及来源语义。

## 3. 分阶段工作包及开发内容

### WP-00 现有能力盘点与基线（前置）

**工作**：逐项核查邮件及 Agent 的实现/配置/测试状态；登记业务完成标准、责任人、接管人、数据范围、真实样例与基线；核对历史未完成验收，不以旧 tasks 勾选代替本次运行证据。

**输出**：差距矩阵，每项标为已有复用、需要开发、需要配置或待验证；必要的有限 spec。已有合格功能不重复开发。

**验收**：两条现有链路可以被描述和复现；未知项明确；不向未授权模型发送真实资料；没有跨部门配置就不宣称企业可用。

**验证**：文档 L1；仅在授权后使用真实环境做只读运行核查。后续逻辑等级分别选择。

### WP-01 邮件结果闭环增强（AE-MAIL）

**复用**：MailAutomationCenter、邮箱连接、同步去重、分派/关注/备注/暂挂/完成动作、回复模板与执行日志。

**拟开发缺口**：

- 完成结论与结果证据显示：人工结论、已执行邮件动作、关联业务及仍待执行事项。
- 回复草稿、提交发送、SMTP 接受、发送失败、收到外部反馈与业务处理完成分别解释；不把“发送成功”写成“已送达/问题已解决”。
- 暂挂/等待条件、责任人和恢复时点明确；到期提醒不自动完成。
- 失败可重试/接管，成功状态及时刷新；重开保留原结论与历史。
- 关联真实售后对象前，仅支持关联已有业务对象或明确的外部来源；不伪造售后单。

**验收**：重复确认不重复发送/关闭；失败不标成功；完成/重开/分派刷新一致；关键动作保存操作者、时间及来源；不同账号/连接不能越权；没有发送授权只能生成草稿。已有实现满足的项直接登记复用。

**验证**：L3（外部动作、权限及跨状态），隔离数据、模拟 SMTP/IMAP 验证主路径与失败；真实发信需独立明确授权，不用现场邮箱做隐式回归。

### WP-02 客户会议与跟进行动（AE-SALES）

**复用**：当前商机取数、个人 Agent 会话、来源、待办确认及商机跟进记录服务。

**拟开发**：

- 用户粘贴/输入会议纪要，绑定可访问商机并说明来源；首期不接录音/视频、附件或实时转写。
- 事实、客户诉求、问题、推断、待核实信息分组，未知日期/负责人不补造。
- 提取多个行动草稿，允许逐条修改、确认及舍弃；每条确认幂等，未确认不落正式任务。
- 划清“个人待办”和“商机正式跟进记录”两个保存目标，默认沿用已有待办路径，正式跟进需额外操作权；不能静默双写制造两份任务。
- 回显已确认任务的执行状态及来源；会议讨论不能自动改商机阶段、金额或把握度。

**验收**：正确对象/作用域；新输入与旧 CRM 事实标明；多个行动部分确认正确；重复确认不重复；失权后不能取数/保存；已完成任务可追踪，模型失败保留输入。

**验证**：L3（共享 Agent 契约、权限和持久化），模型模拟、隔离数据库与现有商机/待办回归。

### WP-03 小范围知识与 SOP 辅助（AE-KNOW）

**首期范围**：维护经审核的文本资料/链接及版本摘要，选产品 FAQ 或 SOP 一类；独立授权后才让 Agent 和邮件草稿引用。不先导入全公司文件，也不默认解析任意附件。

**拟开发**：资料维护人、版本/有效期、适用产品/业务、访问范围、启停；受控检索与稳定引用；没有证据时拒答/提示缺失；知识变更后的历史引用保留生成时版本；将方法模板与产品事实分开管理。

**接入**：优先沿用现有系统文档服务，若无服务先确定唯一知识责任模块。向量检索和文档解析待检索效果证明需要后再比较方案；不先引入 Dify/RAGFlow。

**验收**：版本适用正确、撤销权限立即生效；过期/冲突资料提示；引用可查；恶意资料不能改变工具授权；邮件引用只形成草稿，不绕过发送策略。

**验证**：L3（新知识权限、持久化、跨模块接入）；正负样例与多账号隔离，最小化保留敏感内容。

### WP-04 条件场景：采购回签（AE-PO）

**启动条件**：权威采购对象/API、订单行标识、供应商邮件授权、币税单位口径、采购负责人明确。

**拟开发**：外部订单只读映射；回签文本抽取；按行核对料号、数量、分批交期及价税；人工确认匹配关系；差异队列和催办草稿；回复/等待/确认/关闭结果。

**验收**：多行/部分回签可识别；未知订单不猜配；金额和日期由确定性规则核对；不自动改订单或承诺；重复邮件防重；发送仍走邮箱授权。

**边界**：不自动定标、修改采购单、更新库存/工单或外发商业承诺。接口未就绪保持等待配置，不生成假订单。验证 L3。

### WP-05 条件场景：质量证据与 8D（AE-QUALITY）

**启动条件**：质量事件责任服务、检验/返修/版本/批次来源及可见范围明确；质量工程师提供样例。

**拟开发**：只读证据关联、时间线与缺失清单、已确认事实/根因假设分离、8D 模板草稿及人工修订记录；问题责任事项和验证结论可追溯。

**验收**：不把相关性当根因；每项事实可回来源；没有批次谱系不生成追溯结论；原始证据不能被模型覆盖；关闭由合法业务状态与工程师结论决定。

**边界**：首期不做 QMS 重建、视觉算法、自动放行/冻结/赔付/召回。验证 L3。

### WP-06 条件场景：经营指标解释（AE-BI）

**启动条件**：选择销售订单或当前库存一个主题，确认法人/仓库/期间/币种/单位/状态口径与数据可见范围。

**拟开发**：固定指标定义及只读聚合服务；Agent 按白名单查询解释差异；数字附过滤范围和生成时点；证据不足明确列未知原因；行动草稿复用确认流程。

**验收**：聚合可与原列表核对；失权记录不进入总数；金额币种不混加；库存数量遵循法人/仓库/批次逻辑；出入库流水不被改写；解释不能生成任意 SQL 或将假设写为根因。

**边界**：不接全 BI 平台、不默认浏览器操作、不预测现金/利润，不自动更改单据。验证 L3（聚合授权与业务口径）。

### WP-OPS 最小运营配套（AE-OPS）

随 WP-01/02 分段建设：显示未配置/待验证/试点/可运行等真实准备状态；关联责任人/接管人；记录输入版本、运行结果、失败、复核和使用反馈；统计净处理时间及单个合格任务成本。

关键条件（授权、连接、必要评测、接管）是阻断项；原 80 分评估可继续辅助排序，不能单独决定启用。变更后历史配置要兼容，不能靠新增字段默认值把旧场景自动上线。

首期不建专用全企业观测平台，已有审计/运行记录能满足的直接复用。文案配置 L1、局部统计 L2；公共授权/启用逻辑/新增持久化按 L3。

## 4. 数据、接口和迁移设计约束

本文件是实施前计划，不提前承诺具体表名、字段或 DDL。每个切片实施前须输出数据设计与契约，符合数据库规范；共享能力只设一个权威责任模块。

| 资产 | 唯一责任与候选处理 | 需核查 |
|---|---|---|
| 原邮件/执行/处理状态 | 数字员工邮件模块，复用现有模型 | 完成结论是否已有，保留期/外部标识/幂等 |
| 会话、会议输入、来源和行动草稿 | Agent 服务 | 多行动兼容旧单草稿；归档/删除后的引用和隐私 |
| 正式任务/跟进 | 个人待办/商机服务分别负责 | 保存目标、防重、负责人合法性、关闭结果 |
| 文档及知识版本 | 明确的知识责任模块，优先复用文档服务 | 访问范围、有效版本、撤销、历史引用 |
| 外部订单/质量来源映射 | 集成层 `int_`，不得代替权威业务记录 | 游标、映射、防重、错误/重放 |
| 指标与运行统计 | 指标责任服务/审计运行数据 | 行级过滤、聚合口径、统计时间窗 |

新增模型应登记层级、应用/租户/账号/业务范围、同作用域关系、稳定引用、唯一约束、状态机、审计、索引、保留期和删除规则。兼容迁移默认不删除原内容；回填仅影响明确范围；新功能可停用，旧场景仍可运行。迁移方案验证旧数据和恢复，不用重置数据库代替升级。

外部连接继续服务端加密凭据；前端和 Skill 不持有密钥。工具只读/草稿/执行分级，授权在每次取数及写入时校验，不依赖菜单隐藏。模型/外部文本不能授予权限。

## 5. 页面与组件复用

- 运行在现有主框架工作区，不新增独立应用；场景从各自菜单进入。
- DetailWorkspace/DetailHeader/DetailTabs、RecordQueryBar、DeclarativeDataGrid、视图与分页按样式规范复用；场景页面保留各自语义。
- 表格来源/单据编号为详情入口；操作列使用已登记不同语义图标、提示与权限状态；长内容列留足宽度，字典显示名称。
- Agent 保留当前对象抽屉与持续会话工作台，新增任务输入/引用/确认区复用共有组件。
- 知识配置仅需要时新增管理入口；未接入场景不添加伪造数据或可点击的空功能。

组件复用不等于完成跨项目通用性验证；业务闭环先在本项目验收，再登记候选资产。

## 6. 执行顺序、依赖和交付检查点

```text
WP-00 差距与基线
  → WP-01 邮件闭环 + 最小 WP-OPS
  → WP-02 会议行动 + 最小 WP-OPS
  → WP-03 知识/SOP（数据维护人和授权就绪）
  → WP-04 / WP-05 / WP-06 中择一（外部数据/口径就绪）
```

知识不阻塞基于现有 CRM 记录的邮件/会议试点；外部连接不阻塞前两项。任何切片验收后单独报告缺口和结果，不以“已开发”代替实际配置或业务试点。

每次开始一个切片：限定输入、输出、授权和停止条件；完成对应 spec/testcases/plan 的必要细化；选择最低有效验证等级；实现与验证后交付。关键权限、外部写入、数据迁移采用 L3。普通纯显示调整不因此被迫做全量测试。

本计划不承诺工期和人日，因接口、责任人及团队资源未确认。建议业务负责人先按 WP-00 提供样例，再估算有限切片，避免全清单排成连续无人确认的开发目标。

## 8. 风险与停止条件

- 没有业务/知识责任人，不启动对应场景正式运行。
- 没有可靠来源或授权，不用模拟结果填充生产页面。
- Agent 多行动与旧契约冲突时先设计兼容，不直接替换旧结构。
- 结论显示、发送结果和业务完成有歧义时保留未完成状态并人工处理，不能自动闭环。
- 指标不同口径或质量数据不足时不生成肯定结论。
- 任何越权或未授权执行阻断上线；净提效不足时收缩场景，不持续堆功能。

**本轮停止条件**：首批有限切片实现、L3针对性验证及兼容迁移完成后停止。等待真实样例和运行验收；不自动扩展到采购、质量、BI或新增外部接入。实现范围、接口与迁移见 [implementation-design.md](implementation-design.md)，完成证据见 [review.md](review.md)。

## 2026-10-09 后续场景页面实施授权（当前态覆盖）
