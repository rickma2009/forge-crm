# 功能规格

BUS-APV-01：在现有框架内连续评审审批操作，不重复显示原型外壳。

|需求|验收|
|---|---|
|REQ-APV-01 首页旁增加审批中心入口及模拟待办数|AC-APV-01 本机开发时已登录用户可打开；非本机/正式构建不提供预览入口|
|REQ-APV-02 复用主框架页签打开首页/任务/配置，保留其他页签|AC-APV-02 重复点击任务不重复开页签；切回列表查询分页保留；没有嵌套页签或侧栏|
|REQ-APV-03 预览导航、待办和未保存状态双向同步|AC-APV-03 修改草稿后离开/关闭/刷新可取消，原数据保留；同意更新模拟待办数|
|NFR-APV-01 原型源码与真实程序隔离，严格消息校验|AC-APV-04 拒绝错误origin/source/路径/消息格式，不传身份令牌，无真实业务写入|
|NFR-APV-02 预览服务不可用时可恢复|AC-APV-05 超时提示启动命令及重试；原有框架仍可导航，构建与针对性测试通过|

预览入口不是生产审批权限。正式接入须替换预览承载并建立服务端授权/待办接口。本次不修改数据库、现有业务审核和通知存储。


## 原单据工作流区域与流程图统一规则（2026-10-05补充）

1. 原单据保留现有主表、明细、附件、按钮及浏览/编辑行为。工作流以独立区域追加在整个原页面最下方（附件之后），采用统一分区标题和留白，不替换原单据、不新增单据多Tab、不默认弹窗。未发起时显示“尚未发起审批”。
2. 区域显示流程名称、定义版本、轮次、状态、当前节点及承办人，提供流程图与审批记录。多次提交可选择历史轮次，历史记录只读；原单据权限和审批动作权限分别校验。审批操作不因能查看该区域而获得授权。
3. 设计器、审批执行页和单据底部使用同一个流程图组件及同一份定义布局；节点类型、名称、位置、条件分支、并行与汇合连线保持一致。运行态只叠加当前、完成、未执行、跳过、退回、终止、失败等状态和实际流转路径，不将完整设计图重新排列为时间轴或简化链条。
4. 运行图绑定实例启动时的已发布定义版本和布局快照；后续发布不改变历史实例。未命中分支保留并弱化，不删除。转交、加签等运行态变化以标识和记录解释，不能冒充原始设计配置。
5. 点击节点查看处理人、时间、意见及动作执行结果；支持缩放、适配、定位当前节点。审批记录另按时间展示，不能替代流程图。无权限字段、附件和意见遵循后端权限过滤。
6. 原型已在模拟原单据底部追加工作流区域，并复用设计页的 FlowDiagram。当前固定模板图仅展示计算后的路径；完整分支布局、未命中分支保留及定义布局快照列为正式设计器验收项，不能将当前模拟图视为这部分已实现。
