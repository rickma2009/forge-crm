# 销售订单与销售出库方案

状态：**已确认业务方向的实施提案，Architecture Gate 与 Release Gate 均未执行**  
日期：2026-10-01  
来源：本轮用户需求及四轮设计决策；“一个小时”为笔误，不构成工期限制。本文件是方案，不表示功能已实现。

## 1. 目标与边界

建立可追溯的“商机/报价 → 销售订单 → 多次销售出库 → 库存流水”链路。销售订单也允许手工新建。首版完成订单和出库单的创建、修改、提交、审核、驳回/撤回、订单取消/剩余量关闭、出库冲销，以及批次、金额、成本、权限与审计。

首版**不做**客户退货、发票、应收、库存预留、单位换算、第三方同步和自动批次分配。已有部分出货的订单不能取消，只能关闭未履约剩余量；客户退货后续另立单据，不能用“冲销”代替真实退货。报价只允许已接受且仍有效的记录作为来源；商机只允许未关闭记录作为来源。

## 2. 已有能力与需新增的事实

- `md_item` 已是销售产品和库存物项的唯一权威，报价与商机产品行现已引用它；旧 `md_product` 是遗留表。销售订单不新建产品映射表。每个交易行保存 `item_id`，并保留产品编码、名称和单位快照。
- 报价已有客户、可选商机、产品价格/折扣、有效期和状态；商机已有客户、负责人和产品行。来源只读引用与交易快照并存，订单修改不回写来源。
- 库存已有按租户、法人、仓库、物项编码和批次分组的数量/金额余额，以及入库流水；尚无销售出库、库存预留或 FIFO 成本层。首版使用该余额的移动平均成本。
- 销售区域尚无权威主数据，新增受控的 `sales_region` 字典项，订单保存字典项 ID 与名称快照；不能由地址推断区域。税率由受控的 `sales_tax_rate` 字典项提供，不硬编码法定税率。
- 销售员引用真实用户/员工，所属组织引用有效组织单元。来源有负责人时预填；手工单默认当前用户及其有效组织。保存和审核都校验人员、组织及其关系。

## 3. 单据与页面

### 3.1 销售订单列表与创建向导

菜单进入 `sales-order-directory` 列表，复用 `BusinessDirectory`、`RecordQueryBar`、`ListViewSelector`、分页及个人视图。订单号是详情链接；行操作采用带中文提示和可访问名称的图标，按权限和状态禁用。默认视图显示单号、订单日期、客户、订单类型、来源、销售员、组织、含税折后总额、审核状态、履约状态、更新时间；查询支持单号、客户、来源、状态及日期范围。

“新增销售订单”打开向导：

1. 选择来源：**手工新建 / 商机 / 报价单**；默认手工新建。确认来源后点“下一步”。
2. 商机来源搜索未关闭商机；报价来源搜索已接受、未过期且尚未生成有效订单的报价。选中后预览客户和产品行；手工新建选择客户。来源不可在订单保存后更换。
3. 进入订单编辑页，带入全部来源产品行、数量、价格与折扣。草稿中允许增删改产品行与其他可编辑字段；来源单据的客户不可修改，手工单客户可修改。保存时才由服务端事务生成单号和草稿，关闭未保存向导不产生空单据。

同一商机允许多张订单；一张报价最多对应一张**非取消/非作废**订单，由数据库部分唯一约束与服务端事务共同保证。若报价关联商机，订单直接来源仍记报价，并保存商机追溯 ID。向导对同一商机已有其他有效订单给出提示，但不直接阻止商机来源多次成单。

### 3.2 销售订单详情

复用 `DocumentWorkspace`：第一行客户同款返回箭头、订单号、状态和操作；第二行按“字段名：字段值”显示客户、来源、来源单号、创建人/时间等只读摘要；主表字段在上，订单行表格在下，不设内容 Tab。浏览态不显示添加行、行操作列或可执行编辑按钮；从列表“修改”入口进入且单据仍为草稿时直接编辑。提交后字段、来源、行不再编辑。

主表字段：订单号、制单日期、订单日期、客户 ID/编码/名称快照、销售员、所属组织、所属区域、来源类型/ID/单号、订单类型、币种（首版仅 CNY）、销售原金额、表头折扣、折后含税总额、税额、备注、审核状态、履约状态、创建/审核信息、版本号。订单行字段：稳定行 ID、行号、显示序号、来源行 ID、物项 ID/编码/名称/单位快照、订单数量、含税单价、原金额、行折扣、行折后单价/金额、分摊的表头折扣、最终成交金额、税率/税额、已出货数量、履约行状态、行备注。已出货数量及履约状态只由有效出库记录计算，不接受客户端写入。

订单类型首版为**普通销售、样品、补发**，由受控配置展示；样品及补发允许零售价，仍须走审核并实际扣库。订单类型不隐式改变税率，提交前逐行明确选择可用税率。产品数量必须大于零，单位固定为物项基本单位；首版不做单位换算。

### 3.3 销售出库列表与详情

菜单进入 `sales-outbound-directory` 列表，使用同一列表/视图组件。出库单号是详情链接；支持从已审核且未完成/未关闭的销售订单发起，也可在出库列表点击新增后选订单；**不能脱离销售订单创建**。

一张销售出库单只对应一张订单和一个仓库。跨仓库出货应创建多张出库单。主表继承订单客户、销售员、组织、区域、订单类型、币种及订单金额口径的只读快照；**订单折后总额**与**本次出库销售金额**分列，不能把部分出库显示成整单销售额。另含出库单号、来源订单 ID/单号、出货日期、出货仓库、出货人、本次出库成本合计、审核状态、创建/审核信息和备注。出库行关联订单行与物项，显示来源行号、物项编码/名称、批次、本次出货数量、累计已出货/剩余量、成交单价、本次含税销售金额、本次出货成本、随单据派生的行状态和行备注。

操作人从选定仓库的可用余额中**明确选择批次**；一条订单行可拆成多条出库行覆盖多个批次。批次管理物项必须选批次，非批次管理物项不得填批次。出库草稿显示估算成本；审核时重算并锁定实际成本快照。出库单不允许改订单成交价。行选择器仅显示可出货物项和该仓库的可用批次/数量，并清楚提示库存不足。

## 4. 状态与业务不变量

### 4.1 销售订单

`DRAFT → SUBMITTED → APPROVED`；提交后可撤回到草稿，审核人可驳回到草稿，均记原因和事件。已审核且**从未发生已审核出库**可取消为 `CANCELLED`；即使历史出库已冲销，也不把它当作“从未出库”。已部分出货的订单可把剩余量标记为“关闭剩余”，并记录操作者、原因和时间；已出货事实保留，不再允许新出库。草稿“删除”采用作废/归档，不物理删除有引用或事件的交易单据。

审批状态与履约状态分开：`NOT_SHIPPED / PARTIAL / FULL / REMAINDER_CLOSED`。各订单行也由有效出库行派生未出货、部分出货、全部出货；不可手工改状态。审核订单**不预留库存**，出库审核时才检查实时余额。

### 4.2 销售出库

`DRAFT → SUBMITTED → APPROVED`；撤回/驳回回草稿并记原因。只有已审核出库单记库存扣减和订单已出货数量。已审核出库不能直接改删；操作错误走**全单冲销**至 `REVERSED`，按原数量、批次和成本写不可变反向流水，再重新开单。冲销后订单剩余量回升；若订单先前已关闭剩余量，仍保持关闭，恢复可出货必须走明确的重开审批动作或新订单，首版不隐式重开。

订单和出库分别设置 `view/create/update/submit/withdraw/approve/reject/cancel-or-close/reverse` 等动作权限。审核人不得审核自己提交的单据；记录提交人、审核人、时间、意见及权限校验结果。紧急代审需单独授权设计，首版不设置管理员自动绕过。服务端再次校验状态、版本和来源，页面禁用不能替代后端权限。

## 5. 数量、金额、税和成本口径

全部计算使用十进制定点数，数量最多 4 位小数、含税单价最多 6 位、金额和成本金额 2 位；折扣存 `0～1` 系数并在界面显示百分比。服务端是计算权威，客户端仅用于实时预览。订单每次保存/审核重算，不信任客户端传入的汇总数。

对每行：`原金额 = round2(订单数量 × 含税单价)`；`行折后单价 = 含税单价 × 行折扣系数`（保留高精度计算，展示可按 6 位）；`行折后金额 = round2(订单数量 × 含税单价 × 行折扣系数)`。`订单原金额 = Σ行原金额`；`表头折前金额 = Σ行折后金额`；`订单折后含税总额 = round2(表头折前金额 × 表头折扣系数)`。表头折扣金额按各行行折后金额比例分摊，以“最大余数法”分配到分，保证行最终成交金额之和严格等于订单总额。行税额按该行最终含税成交金额和该行税率反算并四舍五入到分；订单税额为行税额之和。零售价行允许配置的零税率，但不能由零售价自动推断税率。

部分出库的销售金额按订单行最终成交金额和本次出货数量比例分配；同一订单行的最后一次出货吸收舍入尾差，确保全量出货后各出库行销售金额之和等于订单行最终成交金额。出库金额、税额与成本分别记录，不把出货成本当作销售收入。

审核出库时，对每个仓库/物项/批次余额：`移动平均单位成本 = 当前余额金额 ÷ 当前余额数量`，`本次成本 = round2(单位成本 × 本次出货数量)`，剩余数量与金额在同一事务中扣减；全批次出清时本次成本吸收余额金额尾差，使剩余金额归零。零金额库存可形成零成本，但负数、缺失或数量/金额不一致的余额应拒绝过账并提示修复。冲销严格使用原出库行保存的成本金额和数量回加，不按冲销时的新平均成本重算。

## 6. 来源、有效性与并发

- 创建和提交订单时分别校验来源状态/有效期、客户启用、物项可用；报价来源还检查“仅一张有效订单”。来源变化不会自动重写已提交订单快照。商机直接来源使用商机行预计价格；报价来源优先使用报价行已确认价格与折扣。手工单选物项并录入价格。
- 订单来源三元组 `source_type/source_id/source_no_snapshot` 创建后不可更换；来源行关联 ID 可追溯，但行快照可在草稿修改，且不回写来源。订单引用报价时保留其商机 ID 供追溯。
- 出库审核时重新查已审核且可履约订单、有效库存物项、订单行剩余量、仓库批次可用量及权限。对订单行与库存余额行加锁并按固定顺序处理；状态/版本采用 CAS，事务包含单据审核、余额扣减、库存流水、订单履约聚合和幂等事件。并发两张出库单不能使订单超发或库存变负。
- 提交、审核、冲销和关闭剩余量使用请求幂等键；相同键/相同内容回放同结果，相同键/不同内容报冲突。失败时整事务回滚，不出现已审核单据但未扣库、已扣库但无流水的中间状态。

## 7. 数据与 API 责任边界

销售模块负责 `sd_sales_order`、`sd_sales_order_line`、`sd_sales_order_event`、`sd_sales_outbound`、`sd_sales_outbound_line`、`sd_sales_outbound_event`。这些名称为**拟登记的物理表名**，实现前需经数据库表注册和 Architecture Gate；交易事实保留，关系默认限制删除。字段包含 `tenant_id`、必要的 `application_id`、版本、创建/更新/审核人和时间，物理名 `snake_case` 且不超过 32 字符。区域与税率使用受控字典，不另外复制权威主数据；订单行保留税率快照。库存模块唯一写入 `scm_inventory_balance`、`scm_inventory_txn`、`scm_inventory_event`，须扩展 `OUTBOUND/OUTBOUND_REVERSAL` 流水类型，销售模块通过库存过账服务完成同事务业务操作，禁止页面或销售代码直接更新余额。

建议 API：`/sales-orders` 列表、来源候选、详情、创建、草稿更新和提交/撤回/审核/驳回/取消/关闭剩余命令；`/sales-outbounds` 列表、可出货订单/行/批次候选、详情、创建、草稿更新和提交/撤回/审核/驳回/冲销命令。所有写 API 使用现有会话、CSRF、`AuthorizationService.assertAction`、租户/应用作用域与版本校验；列表视图仍是呈现设置，不能扩大数据或动作权限。出库行的销售金额和成本由服务端返回计算结果，不接受客户端信任值。

拟登记单号前缀：销售订单 `SO`、销售出库 `XSCK`。最终实施前写入 `docs/database/business-document-numbering.md`；沿用“前缀 + 上海业务日期 yyyyMMdd + 5 位日流水”，数据库事务内原子生成，不回收断号，客户端不能改号。

## 8. 分阶段实施与验收

1. **规格与 Gate**：补齐正式需求、状态图、字段字典、权限矩阵、表登记、编号登记、数据迁移与恢复方案；检查报价、商机、库存引用的真实字段与约束；经项目要求的 Architecture Gate 再改 Schema。此文件不能替代 Gate 通过记录。
2. **销售订单核心**：contracts、数据库迁移、区域/税率配置、服务端订单聚合与金额计算、来源导入/唯一约束、RBAC；前端列表/视图/向导/详情和商机、报价的创建入口。
3. **销售出库与库存**：出库聚合、仓库/批次选择、移动平均成本、事务过账/冲销、已出货聚合、订单关闭剩余量；前端出库列表/详情及订单出库入口。
4. **验证与上线准备**：数据库迁移与 Seed 幂等、权限/跨租户、并发超发与重复提交、金额尾差、批次/零成本/冲销、撤回驳回、来源失效、窄屏/键盘/视图回退；灰度前备份与恢复演练。只有独立的 Release Gate 通过后才部署。

关键验收：报价不能重复生成有效订单；非草稿不能修改；来源客户不可改而手工单客户可在草稿改；已审核订单可多次、分仓分批出货但累计不超订单量；不同仓库/批次余额不串账、永不负库存；审核人与提交人不同；库存扣减、流水、成本和履约数量原子一致；冲销恢复原批次数量及原成本；金额逐行与总额在分级舍入后对账；用户个人列表视图不会扩大权限。

## 9. 当前结论与适用边界

已确认的项目级规则：三个订单来源、客户锁定、报价唯一有效订单、订单与出库审核、无预留的分批履约、手选批次、移动平均成本、两级折扣、按行税率、职责分离及首版排除项。跨项目可复用的是“来源快照、审核状态与履约状态分离、库存不可变流水与原价冲销、汇总金额对账”这些原则；**不可直接复用**本项目的状态码、字段名、CNY 限定、`md_item` 归属、数据库前缀和当前权限结构。证据来自本轮用户确认及现有 Prisma/报价/库存代码；方案未经过迁移、接口或浏览器验证，Architecture Gate 尚未执行。
