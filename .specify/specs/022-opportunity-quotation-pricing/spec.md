# 切片 022：商机报价与销售定价

## 业务与验收

US-022-001：定价维护人员为已有产品配置带有效日期的标准含税价或连续阶梯，销售按报价日期和单行数量获取可追溯建议价并可调整成交价。
US-022-002：销售建立客户报价草稿，编辑表头与稳定明细行，提交后商业内容冻结；登记接受/拒绝、复制重报、导出 PDF。
US-022-003：商机查看关联报价，获授权人员明确选择已接受报价替换预签金额，而非自动同步商品行/阶段。

约束与推荐答案采用 Q-QUO-001—010：两位金额、四位数量、百分数折扣、逐行 HALF_UP 后求和、阶梯覆盖正数域、Asia/Shanghai 截止日含当天、内部登记反馈、择一替换回写。

字段限制：标题 200；条款 8000；备注 2000；交付说明 200；最多 200 行；最多 100 阶梯；查询页长上限 100。金额最大 16 位整数两位小数；数量最多 14 位整数四位小数。错误不丢输入，弹窗错误在弹窗内。

权限默认拒绝：价格查看/维护独立，报价查看/创建/修改/提交/反馈/复制/导出/回写独立。新报价默认本人负责；普通用户仅访问自己负责的报价及关联商机，应用受保护管理员可访问应用内全部，后续组织范围需显式策略，不默认为全量。客户引用继续执行现有客户授权。无跨租户或跨应用引用。

未配置 PDF 出具方时用中性“报价单”标题，不伪造企业名称或法律条款；条款由用户显式填写。PDF 不含内部备注、建议价/权限/内部身份。不自动发送客户。

需求/验收追溯采用需求同号映射；测试见 testcases.md，所有验证在实际执行前均为未完成。

## 报价创建与详情当前规则（2026-09-24）

来源：REQSRC-QUO-CREATE-20260924。本次明确要求替代“先填表后保存创建”“草稿可换客户/商机”“不导入商机产品”。

- REQ-QUO-013 / AC-QUO-013：新增弹窗默认“关联商机报价”，下拉选择商机；切换“独立报价”后选择客户，可输入编码/名称检索并翻页。取消不创建；确认事务成功后已落库并打开详情，失败保留弹窗与输入，重复确认幂等。
- REQ-QUO-014 / AC-QUO-014：只允许当前未关闭且有权访问的商机。当前模型状态为 ACTIVE/ DISABLED，按 ACTIVE 可用、DISABLED 不可用执行，不按阶段概率猜测关闭。创建事务重验状态、客户权限与作用域，从商机读取客户及产品行；一行对应一行，不合并同品。保留数量、成交单价、需求备注，折扣初始 0；有有效定价时形成建议价快照，无有效定价时保存空价格版本、`0.00` 建议价和 `UNPRICED` 来源并保留可编辑成交单价，不因缺售价整单失败。不存在、停用或越权产品仍阻止创建。零产品商机可建立空明细草稿。

- REQ-QUO-023 / AC-QUO-023：报价明细选择同租户启用产品时，无销售定价也可加入；页面不显示阻断性错误，成交单价默认 `0.00` 且可修改。保存、提交允许价格版本为空，后端以成交单价计算金额；显式重新取价无匹配版本时保留成交单价并提示，不删除明细、不伪造价格主数据。

- REQ-QUO-024 / AC-QUO-024：报价界面将“成交单价”改为“单价”。新增行调用公共产品选择弹窗的多选模式，支持查询、分页、多选、当前页全选、取消/确认，展示产品编码/名称/中类/小类；确认后批量生成数量 1、折扣 1 的独立明细并按既有有价/无价规则初始化单价。组件另支持单选模式且只返回一个产品。原优惠百分比决定被 REQ-QUO-025 替代。
- REQ-QUO-025 / AC-QUO-025：折扣为 `0–1`、最多两位小数的折扣系数，默认1；前端与服务端按 `round(数量 × 单价 × 折扣, 2)` 计算。迁移将旧百分比转换为等价系数并收紧默认值和数据库检查。产品选择公共组件的表头和数据行桌面高36px、单行省略显示，完整文本可通过title查看；查询、分页和选择语义不变。
- REQ-QUO-026 / AC-QUO-026：当前产品引用以 `md_item` 为唯一权威来源。迁移删除 `sd_quotation_line`、`sd_opp_product`、`sd_product_price` 指向 `md_product` 的遗留外键，不删除旧表或业务数据，不改变既有 `md_item` 编码外键。选择仅存在于 `md_item` 的启用产品后，报价草稿保存必须成功；未知服务端异常记录 requestId、错误类型、错误代码和堆栈，但 API 仅返回脱敏的 503。
- REQ-QUO-015 / AC-QUO-015：确认后生成 UUID、系统单号、草稿状态、创建时间、创建人和默认报价人（当前创建人）。客户、报价方式、是否关联商机、商机 ID 永久锁定，草稿 PATCH 也不能改变。报价方式由持久化且不可变的 opportunityId 是否为空唯一表达，不新增可能矛盾的冗余字段。标题初始“新报价单”可修改；报价日期当天、有效期默认 30 天（沿用复制报价默认），条款和备注空白。
- REQ-QUO-016 / AC-QUO-016：顶部主标题为单号，下一行客户名称、可导航且只读的商机名称（独立报价完全隐藏）、状态、创建日期、创建人。下面按标题；报价日期/有效期；报价合计/币别；客户联系人/报价人；条款；备注排布。客户只读、报价方式不展示；报价人沿用既有负责人默认创建人且只读。合计只读，来自明细折扣后金额，客户端即时预览、服务端重算。
- NFR-QUO-013：沿用对象权限、CSRF、版本并发、请求幂等、同事务快照与审计。历史报价不批量导入、不回填客户关系；创建后商机变化不自动同步报价。

未决边界：如果业务“关闭”需要独立于当前 ACTIVE/DISABLED 的生命周期字段，需另增需求；当前不发明关闭状态。多币别与报价人转交不在本次范围；无定价产品报价已由 REQSRC-075 纳入当前范围。

## 商机发起报价当前规则（REQSRC-QUO-ENTRY-20260924）

三轮 grilling 建议已由用户依次“本轮按推荐 / 按建议 / 按建议”确认。以下细化既有报价规则，替代商机入口仅预选但可换方式/商机的行为。

- REQ-QUO-017 / AC-QUO-017：商机详情顶部提供“新增报价单”，以报价 create 权限判断，不要求商机 update；商机内报价列表入口保留。ACTIVE 可创建，DISABLED 按钮禁用并解释原因，历史报价仍可看。编辑弹窗有未保存内容时不得发起顶部创建。
- REQ-QUO-018 / AC-QUO-018：来自商机的创建弹窗锁定关联商机报价及当前商机，显示对应客户；加载失败/未完成不能创建并可重试。报价管理的普通入口仍允许选择模式/商机/客户。成功关闭弹窗并打开新报价详情页签，原商机页签保留，取消不落库。
- REQ-QUO-019 / AC-QUO-019：提交客户端核对过的商机 version，事务锁商机后比对。版本变化不创建，提示“商机信息已更新，请重新核对后创建”；刷新弹窗客户及产品数量/价格供核对后需再次确认。不自动重试创建、不导入未保存内容，状态与权限仍再次校验。
