# 数字员工正式功能规格

## 范围

在 Forge CRM 主框架内提供数字员工工作台、任务、数字员工、场景中心、启用评估、规则、连接和审计页面。任务与配置持久化；尚无适配器或凭据的连接显示等待配置并阻止正式执行。

## 关键规则

- `REQ-DE-01` 顶部入口为纯机器人图标，页面运行在主框架内容区，不依赖原型服务。
- `REQ-DE-02` 列表查询、表格和分页使用 `RecordQueryBar`、`DeclarativeDataGrid` 等公共组件。
- `REQ-DE-03` 场景卡展示触发、输入证据、交付物、控制点和指标；启用评估达到 80 分方可提交。
- `REQ-DE-04` 数字员工配置包含目标、责任人、接管人、数据范围、运行级别及动作权限；正式写入和对外发送默认需人工确认。
- `REQ-DE-05` 邮件连接支持 `INTERNAL_API`、`MICROSOFT_GRAPH`、`GMAIL_API`、`IMAP_SMTP`。前端不回显密钥；服务端只有配置了加密密钥时才接受凭据。
- `REQ-DE-06` 连接未配置、密钥缺失、健康检查未通过时状态为 `WAITING_CONFIG`，不得自动拉取或发送邮件。通用 IMAP 连接通过健康检查后，可以只读方式增量同步收件箱。
- `REQ-DE-07` 所有变更受登录态、页面动作权限、租户与应用作用域约束，并写审计记录。
- `REQ-DE-08` 邮件同步使用 UID 游标和证据键去重；对新邮件生成内部分类、摘要和待办，同步不改变已读状态，不删除、归档或发送邮件。
- `REQ-DE-09` 邮件数字员工可按分钟间隔、星期和每日生效时段自动拉取；每次运行保存触发方式、读取数、新增数、动作数、结果和错误。
- `REQ-DE-10` 邮件规则按优先级匹配发件人、主题、正文和分类，可组合创建待办、标记已处理、生成回复草稿、受控自动回复、确认删除和延迟移至回收站。
- `REQ-DE-11` 回复模板支持受限变量替换。对外自动发送默认关闭；启用后仍受域名白名单、地址黑名单、no-reply 拦截及分钟/小时限流约束。
- `REQ-DE-12` 邮件处理状态独立持久化为待处理、待确认、处理中、已处理、失败、已忽略、待删除、已删除；页面提供人工处理和动作确认入口。
- `REQ-DE-13` “删除”只将邮件移动到配置的邮箱回收站，不永久删除。回复和删除动作以幂等键防重，失败按配置次数重试，并保留执行错误。

## 当前切片边界

本次实现正式管理与配置闭环、可追溯任务状态、通用 IMAP 增量同步，以及 IMAP/SMTP 邮箱的计划、规则、模板、处理状态和执行记录闭环。已初始化邮箱保持“自动收取开启、对外自动发送关闭”；只有显式配置规则和安全范围后，动作才会进入人工确认或自动队列。具体 ERP、MES、WMS、电商、行情以及 Graph/Gmail API 调用由后续适配器接入；未接入前保持等待配置。

## 分类导航与场景工作区增量（2026-10-08）

- `BUS-DE-NAV-01` 用户需要从左侧按业务领域直达数字员工具体场景，并在不同类型场景中使用各自适合的工作区。
- `REQ-DE-14` 左侧一级“数字员工”作为目录，二级分组为公共、营销、供应链、研发、财务及其他必要业务类别，三级菜单进入具体数字化场景；菜单只显示当前用户有权访问的场景。
- `REQ-DE-15` 保留 `/showcase/digital-employee` 现有页面及顶部机器人图标跳转行为。目录本身不占用现有页面路由，现有工作台可作为目录下单独页面入口。
- `REQ-DE-16` 每个场景页面使用场景自己的内容和页面内 Tab；不得要求各场景共用同一数据结构或处理流程。路由级页签继续使用公共 RouteTabs，场景内容页签使用 DetailTabs。
- `REQ-DE-17` 邮件处理场景首个内容页显示实际收集的待处理邮件；配置页展示现有运行计划、处理规则、模板和连接状态。邮箱连接缺失时明确提示等待配置，不显示虚构邮件。
- `REQ-DE-18` 信息获取场景按来源显示实际采集结果及可用的分析内容；适配器或来源未配置时显示等待配置/无数据状态，不生成虚构采集记录或分析结论。
- `REQ-DE-19` 其他已登记场景可先提供场景上下文和适配器状态；菜单可见不代表场景已有数据源或可执行能力。
- `REQ-DE-20` 用户登录后，左侧数字员工目录及已授权的二级分类默认展开，展示对应的三级场景；分类与场景仍由服务端授权导航返回，不绕过 RBAC。
- `REQ-DE-21` 当前导航使用名称：舆情监控、电商评论、采购订单执行、生产工单执行、库存管理、研发过程执行、大宗商品监控、质量过程执行、客诉及质量事件；RFQ 解析、SMT 换线准备、序列号批次追溯暂不出现在菜单，底层场景定义保留。
- `REQ-DE-22` 在公共分类下提供“邮件处理”菜单，进入邮件待处理列表及其规则、接口和运行配置工作区；无已连接邮箱时显示等待配置。
- `REQ-DE-23` 数字员工独立菜单页面不显示页面内返回按钮；工作台内部打开的邮件集成页保留返回集成列表操作。
- `REQ-DE-24` 邮件工作区中可编辑、修改、保存的运行配置、规则和模板使用项目统一 DetailWorkspace、DetailTabs、企业表单控件和 SalesActionDialog；详情正文不重复嵌套卡片外框。

## 大宗商品监控方案增量（2026-10-08）

- `REQ-DE-MARKET-01` 大宗商品监控提供接口设置、监控商品、获取列表、价格走势图四个内容 Tab，位于“数字员工 → 财务 → 大宗商品监控”。
- `REQ-DE-MARKET-02` 接口设置展示 World Bank Pink Sheet 免费月度商品来源及 Frankfurter 无 Key 汇率来源，维护时区和每月获取时间；不要求或保存外部 API Key，并显示连接/运行状态、错误摘要和上次成功获取时间。
- `REQ-DE-MARKET-03` 商品设置预置铜、铝、金、银，可维护启用状态、来源商品代码、市场基准和报价单位。仅获取并保存世界银行来源中的月度基准价，不生成日价/周价。
- `REQ-DE-MARKET-04` 首次启用可回补最近 12 个可用月份；之后每月获取并按商品行情月份及独立汇率进度续取。只有成功持久化的范围推进进度；部分成功按商品独立推进，失败可重试且不得跳过失败区间。
- `REQ-DE-MARKET-05` 每条月行情保存月份、美元月度基准价、USD/CNY 汇率、汇率生效日期、人民币换算价、报价单位、数据来源和实际获取时间。按月内最近可用汇率换算并保存其生效日期。缺行情/汇率不得以零或未标记的其他日期数据填充。
- `REQ-DE-MARKET-06` 获取列表支持按商品、日期、币种查询，默认按行情日期倒序，并显示实际获取时间和数据状态。
- `REQ-DE-MARKET-07` 走势图仅展示月度数据，支持美元/人民币切换；明确标注月度基准价，单位清晰且不同单位不混合。
- `REQ-DE-MARKET-08` 每次运行和每商品游标分别记录触发方式、请求日期范围、开始/结束、成功时间、状态和错误摘要。“最近运行时间”与“上次成功获取时间”分开。重复获取幂等去重；保存当前来源原始返回值和最近获取时间，来源对既有日期更正时更新当前快照。
- `REQ-DE-MARKET-09` 行情文件来源固定为世界银行官方目录 HTTPS 链接并验证主机，避免 SSRF；来源价格口径及单位必须显示，不得把月度基准价称为每日成交或交易所结算价。

详细页面、进度规则、候选接口及待定业务口径见[大宗商品监控方案](commodity-monitoring-solution.md)。

### 验收标准

- `AC-DE-NAV-01` 左侧结构为“数字员工 → 业务分类 → 具体场景”；分类至少包括公共、营销、供应链、研发、财务，并按已登记场景提供生产与质量分类。
- `AC-DE-NAV-02` 现有顶部机器人图标仍打开 `/showcase/digital-employee`，原工作台组件及初始页面内容保持不变。
- `AC-DE-NAV-03` RFQ 邮件场景在连接就绪时默认进入真实待处理邮件列表；未连接时只显示等待配置，规则和连接信息可在专属工作区查看。
- `AC-DE-NAV-04` 信息获取场景仅展示实际接入的数据；无采集结果时显示等待配置/无数据，不展示模拟成功结果。
- `AC-DE-NAV-05` 路由页签和场景页面内 Tab 独立，其他未接入场景显式显示适配器状态。
- `AC-DE-NAV-06` 当前用户登录后可在系统侧栏看到数字员工下级分类和已授权场景；展开状态默认可见，且未授权场景仍不显示。
- `AC-DE-NAV-07` 菜单显示用户指定的九个更新名称及公共分类下的“邮件处理”；RFQ、SMT、序列号追溯菜单项停用，场景数据和定义保留。
- `AC-DE-NAV-08` 点击“邮件处理”进入邮件工作区；连接就绪时首个 Tab 为待处理邮件，邮箱未连接时显示等待配置，不显示虚构邮件。
- `AC-DE-NAV-09` 邮件处理及所有数字员工场景独立菜单页面均无页面内返回按钮；工作台集成内嵌邮件页仍可返回集成列表。
- `AC-DE-NAV-10` 邮件计划配置中的输入框、下拉框、时间控件、复选框、保存按钮以及规则/模板弹窗符合项目统一表单与按钮规范，明细区域不出现重复卡片边框。
