# 数字员工分类导航与场景工作区实现计划

## 决策

1. 复用 `sys_menu` / `sys_page_resource` 树、现有导航授权和详情工作区 Tab，不新增物理表，也不引入通用的 JSON 页面配置引擎。
2. 将现有 `digital-employee` PAGE 调整为目录 GROUP；新增子页面 `digital-employee-home` 继续使用 `/showcase/digital-employee`，保持顶部机器人快捷入口、路由和工作台组件不变。
3. 按既有场景清单 Seed 三级场景 PAGE。二级分类为公共、营销、供应链、研发、财务、生产与质量；新菜单均使用稳定 `menuCode` 和场景编码路由。
4. 场景路由通过现有 `gateway.assertPage` 进行服务端授权。场景内容根据场景编码分发；不把场景名作为权限或关系键，不为当前菜单增添另一个授权层。
5. 邮件场景复用真实邮件中心 API 和 `MailAutomationCenter`，默认打开待处理邮件，未连接时展示等待配置。信息获取场景首批使用风险雷达，显示已登记来源状态；目前没有实际采集数据/适配器时必须为空状态，不伪造结果。
6. 其他场景当前只提供场景说明及等待配置状态。目录登记不等于外部系统集成完成。

## Architecture Gate 数据登记

| 项目 | 决策 |
|---|---|
| 数据层级/所有者 | 复用公共系统层 `sys_menu` 与页面资源目录；唯一写入责任仍为 RBAC/资源菜单 Seed。业务邮件数据继续由数字员工模块及 `int_de_*` 邮件模型负责。 |
| 新增持久化 | 无新物理表/字段/索引/迁移；仅修改受版本控制的 Seed 菜单树。 |
| 作用域 | 菜单沿用当前 `systemCode`、应用和租户约束；本次新页面仅注册于 `demo-portal`。授权由现有菜单访问权限检查。 |
| 主外键/业务键 | 复用 `sys_menu.parent_id` 和 `sys_page_resource.parent_id`；菜单 `menuCode` 与场景 `SCN-*` 编码稳定。邮件数据仍以连接及 IMAP UID 去重。 |
| 状态/有效期 | 菜单启停沿用 ACTIVE/DISABLED；连接和消息状态沿用既有状态模型。 |
| 删除/审计 | Seed 通过既有幂等 Upsert 和失效菜单禁用处理；场景读取不新增写审计。邮件配置和操作仍走原 API 审计。 |
| 查询/安全 | 场景路由先调用页面权限 API；页面使用授权连接 API，不接受前端伪造的数据或凭据。凭据永不回显；连接未就绪/来源适配器缺失时 fail closed。 |
| 恢复 | 回退 Seed 变更并再次运行 Seed 可恢复旧菜单树；无数据回填或数据丢失风险。 |
| 验证 | 静态检查确认场景路由、菜单码、权限动作和场景码一一对应；代码测试/浏览器验收待本切片后续验证。数据库 migration 和数据库集成测试不适用，因为无 DDL 或新增持久化模型。 |

## 兼容与视觉

- 根菜单继续为“数字员工”，原工作台作为其子页面；顶部机器人入口仍定位同一路径。
- 场景页使用 DetailHeader/DetailTabs 和 DeclarativeDataGrid；顶部 RouteTabs 维持全局状态，不和页面内 Tab 混用。
- 菜单图标沿用现有 Tabler 图标映射；不新增 UI 框架。
- 页面返回回到既有工作台。快捷入口页面的默认视图和原内容不变。

## 风险与边界

- Seed 会将当前 `digital-employee` 从页面改成目录，已有 `/showcase/digital-employee` 页面资源迁移到新子项；须验证旧权限授予向新工作台子页的兼容。
- 既有角色权限可能只授权旧菜单码。Seed 默认系统管理员授权完整；受限角色不会自动获得数字员工场景权限，需保持原受限策略。
- 场景菜单若后续按业务授权，应为各场景建立独立访问授权；本次不隐式扩大既有受限角色权限。
- 风险雷达/行情及 ERP、MES、WMS 等场景接口并未因此实现。

## 回滚

恢复旧 Seed：将 `digital-employee` 还原为 PAGE 并停用新分类/场景菜单，恢复其 `manage`/`execute` 动作；运行 Seed 后核对页面资源路径和菜单授权。由于不改数据库结构，回滚不需要迁移或业务数据回填。
