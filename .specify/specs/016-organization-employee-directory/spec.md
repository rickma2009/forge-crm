# 规格：组织与员工目录

## 目标

- `BUS-021`：建立组织—岗位—员工—账号一致的公共主数据闭环。
- `US-1601`：管理员通过组织树查看和维护组织基本信息。
- `US-1602`：管理员查询、新增和编辑员工，员工必须有主职部门、岗位和可登录账号。

## 需求

- `REQ-1601`：组织 API 只返回公开契约字段，不泄露租户和审计内部字段。
- `REQ-1602`：组织页面左树右详情，父级收起时后代隐藏，右侧只显示基本信息。
- `REQ-1603`：员工列表支持关键词、部门、状态查询；新增/编辑使用弹窗。
- `REQ-1604`：员工字段包括工号、姓名、账号、部门、岗位、用工类型、联系方式、状态、生效时间和备注。
- `REQ-1605`：所属部门、岗位、工号、姓名、账号必填；工号和账号租户内唯一。
- `REQ-1606`：员工主体、雇佣、岗位、任职和账号分别持久化；账号通过 `employee_id` 可选一对一绑定。
- `REQ-1607`：新增员工同时获得受限演示角色；服务端对列表和维护操作分别鉴权。
- `REQ-1608`：列表联系方式脱敏，写操作记录结构化审计并使用版本冲突检查。
- `REQ-1609`：Seed 初始化批准组织树、岗位及各部门员工账号，并保持幂等。

## 验收标准

- `AC-1601`：组织页面不再出现 `unrecognized_keys`，显示左树右基本信息。
- `AC-1602`：组织树包含部件BG及指定八个下级组织，收起父级隐藏全部后代。
- `AC-1603`：员工管理位于组织架构下方，列表可查询，新增/编辑均弹窗完成。
- `AC-1604`：不选所属部门或岗位不能新增；越权写请求返回 403。
- `AC-1605`：Seed 重跑不重复组织、岗位、员工、账号、任职和角色成员。
- `AC-1606`：初始化员工可使用初始化密码登录，但只拥有受限演示角色能力。
