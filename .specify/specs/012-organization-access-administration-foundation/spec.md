# Feature Specification：组织与访问管理基础

| 项目 | 内容 |
|---|---|
| Feature ID | `012-organization-access-administration-foundation` |
| 业务目标 | `BUS-018`、`BUS-019` |
| 来源 | `REQSRC-043`—`REQSRC-045` |
| 状态 | `specification-gate-approved-REQSRC-046` |

## 1. 目标与范围

本切片把现有数据库导航授权升级为可管理、可审计的平台访问管理闭环：保留数据迁移平台表，建立稳定权限目录，并让系统管理员在统一页面查询账号、维护普通角色、维护角色成员和保存角色权限矩阵。

范围包含本地验证环境的数据迁移、默认租户与演示门户应用、用户管理、角色管理、角色成员、只读权限目录、权限矩阵、系统管理员保护、服务端授权和审计。范围不包含组织员工、数据权限、外部身份源、租户运营、菜单管理页、审计查询页、生产迁移和 Release。

## 2. 用户故事

- `US-1201`：作为系统管理员，我希望查询账号并维护账号状态和角色，以便通过统一入口控制谁能访问当前应用。
- `US-1202`：作为系统管理员，我希望创建和维护普通角色，以便用稳定角色表达岗位或职责所需的功能权限。
- `US-1203`：作为系统管理员，我希望在分组权限矩阵中复核差异并原子保存，以免形成不可解释的部分授权。
- `US-1204`：作为只读查看者，我希望查看脱敏后的用户、角色和权限目录，以便支持核对而不能改变授权。
- `US-1205`：作为现有应用使用者，我希望迁移后保留原账号、菜单和列表视图能力，以免平台治理整改破坏既有演示流程。

## 3. 功能需求

### 作用域、迁移与初始化

- `REQ-1201`：所有用户、角色、权限和菜单授权决策必须处于明确租户与应用上下文；请求缺少上下文、上下文无权访问或关联跨作用域时拒绝。
- `REQ-1202`：现有用户、角色、角色成员、菜单、菜单操作、列表视图和偏好迁移后必须保留原记录 ID、稳定编码、有效关系和可解释记录计数，不允许以删除重建冒充迁移。
- `REQ-1203`：首轮初始化一个默认租户和演示门户应用；`admin` 与 `viewer` 均通过角色成员关系获得权限，不存在账号名特例。
- `REQ-1204`：迁移完成后，运行时只使用新的平台事实源；旧表不再被业务读写，也不保持长期双写。
- `REQ-1205`：迁移后原有数据库驱动导航、菜单操作和已保存列表视图继续可用；不因改名或作用域补齐而改变既有用户的已批准能力。

### 权限目录与系统管理员

- `REQ-1206`：权限点具有稳定编码、显示名称、资源、动作、状态、系统来源和应用作用域；编码发布后不能通过本切片页面修改。
- `REQ-1207`：权限目录支持关键词、资源和状态筛选、稳定分页与详情查看；首轮不提供新增、删除、修改编码或停用操作。
- `REQ-1208`：每个有效应用恰好存在一个受保护的系统管理员角色；系统发布新的有效权限点时，发布结果必须保证该角色拥有显式授权，否则整个发布不成立。
- `REQ-1209`：系统管理员角色的编码、类型、状态和权限集合不能通过普通角色页面修改，且不能被删除或停用。

### 用户管理

- `REQ-1210`：用户列表支持按账号/显示名称关键词和状态查询，使用稳定分页，并展示账号、显示名称、账号类型、状态、当前有效角色和更新时间。
- `REQ-1211`：用户详情展示账号基本信息、当前有效角色、未来生效或已到期的角色成员记录及最近的管理变更摘要；不展示员工档案或未批准的个人敏感信息。
- `REQ-1212`：获授权管理员可将 `ACTIVE` 用户停用或将 `DISABLED` 用户重新启用；`LOCKED` 状态只读，不得由本页面直接解除。
- `REQ-1213`：当前会话操作者不能停用自己；停用其他用户后，该用户下一次受保护请求必须被拒绝，已有页面不得继续成功执行写操作。

### 角色与成员管理

- `REQ-1214`：角色列表支持按编码/名称关键词、角色组和状态查询，展示编码、名称、角色组、类型、状态、有效成员数、权限数和更新时间。
- `REQ-1215`：管理员可创建普通角色，必填角色编码和名称；同一租户与应用中的规范化编码不得重复。
- `REQ-1216`：普通角色创建后编码不可修改；名称、说明和角色组可修改。角色不使用父子层级，也不产生权限继承。
- `REQ-1217`：有引用的普通角色不物理删除；管理员可停用或重新启用。停用后，其成员在新的授权计算中不再从该角色获得权限。
- `REQ-1218`：管理员可为角色增加或结束用户成员关系；成员关系默认立即生效、无结束时间，也可指定未来结束时间，有效期采用 `[effective_at, expires_at)`。
- `REQ-1219`：角色成员必须与角色处于同一租户；重复且有效期重叠的同一用户—角色关系被拒绝，失败不得留下部分记录。
- `REQ-1220`：不得结束或移除会导致当前租户与应用没有有效系统管理员成员的关系；当前操作者移除自身管理角色时必须被拒绝并给出可行动提示。

### 角色权限矩阵

- `REQ-1221`：普通角色权限矩阵按资源分组，展示权限名称、稳定编码、动作、状态和当前选中状态，并支持关键词过滤而不丢失未显示选择。
- `REQ-1222`：保存前展示新增和移除权限的差异摘要；取消不产生变更，确认后以角色完整显式权限集合原子保存。
- `REQ-1223`：已停用权限不可新选；角色原有的已停用权限以异常状态显示，并允许在本次保存中移除。
- `REQ-1224`：多人编辑同一角色权限时，过期版本不得覆盖较新结果；界面提示重新载入并展示当前实际权限。

### 授权、只读边界与审计

- `REQ-1225`：页面、菜单和按钮可根据权限改善体验，但用户、角色、成员和权限相关写操作必须由服务端使用同一权限点重新授权。
- `REQ-1226`：权限或角色成员变更成功后，下一次受保护请求和下一次导航刷新使用新结果；不要求向已打开页面实时推送。
- `REQ-1227`：viewer 可读取脱敏后的用户、角色和权限目录，但不能改变账号状态、角色、成员或权限；直接发起写请求同样被拒绝。
- `REQ-1228`：用户状态、普通角色、角色成员和角色权限变更必须记录租户、应用、操作者、动作、目标、变更摘要、结果、关联 ID 和时间；不得记录密码、Token、Cookie 或完整敏感请求体。
- `REQ-1229`：授权数据不可用、作用域不匹配、权限未知或状态无效时默认拒绝，不得回退为显示全部或允许写入。
- `REQ-1230`：系统管理页面沿用现有客户管理页的全局字体、紧凑查询区、功能工具栏、表格、状态标签、分页和弹窗/抽屉反馈；不引入第二套独立视觉体系。

## 4. 业务状态与不变量

### 4.1 状态

```text
用户：ACTIVE ⇄ DISABLED
      LOCKED（本切片只读）

普通角色：ACTIVE ⇄ INACTIVE
系统管理员角色：ACTIVE（受保护）

角色成员：scheduled → effective → expired
                  └────→ ended

权限：ACTIVE | INACTIVE（本切片只读）
```

### 4.2 不变量

- 用户权限仅来自当前时间有效的角色成员、有效角色和有效权限的交集；多角色权限取并集，没有显式拒绝和角色优先级。
- 权限点是安全事实，菜单和按钮不承担唯一安全语义。
- 系统管理员角色必须保持唯一、有效且至少有一个有效成员。
- 角色权限保存要么整体成功，要么完全不改变；角色成员与账号状态变更同样不能产生部分结果。
- 跨租户或跨应用引用被拒绝；客户端提交的作用域不能覆盖服务端已认证上下文。
- 角色或权限失效不删除历史审计事实。

## 5. 验收标准

- `AC-1201`：迁移前后各类记录 ID、稳定编码、关系和计数可逐类对账；迁移后原账号登录、数据库导航、菜单操作和已保存列表视图仍按原批准能力工作。
- `AC-1202`：默认租户、演示门户应用、admin、viewer、系统管理员角色和稳定权限目录初始化可重复执行且不产生重复事实；admin 不依赖用户名特例。
- `AC-1203`：缺少/越权应用上下文、跨租户成员、跨应用权限或未知权限请求均被拒绝，且不产生部分写入。
- `AC-1204`：管理员可按关键词和状态查询用户、稳定翻页并查看角色有效期；列表和详情不泄露未批准个人信息。
- `AC-1205`：管理员可停用和启用其他用户；不能停用自己，不能从用户页面解除 `LOCKED`；停用用户的下一受保护请求被拒绝。
- `AC-1206`：管理员可查询、创建、修改和停用普通角色；重复编码、修改编码、物理删除有引用角色和修改系统角色均被明确拒绝。
- `AC-1207`：管理员可增加、定时结束或提前结束角色成员；重复重叠、跨租户和最后一个系统管理员移除被拒绝且无部分结果。
- `AC-1208`：权限目录支持规定筛选和详情，只读用户和管理员均不能通过页面或直接请求新增、删除或改码。
- `AC-1209`：普通角色权限矩阵按资源分组，过滤不丢失选择；保存前显示差异，取消无变化，确认后完整权限集合原子生效。
- `AC-1210`：已停用权限不能新选，已有异常授权可见且可移除；过期版本保存被拒绝并要求重载，不覆盖最新授权。
- `AC-1211`：系统管理员角色唯一、不可停用/删除/普通编辑，并在权限发布完成时显式拥有全部有效权限；不满足时发布整体失败。
- `AC-1212`：viewer 能读取允许的用户、角色和权限信息，但所有写入口不可用且直接写请求被服务端拒绝；管理员只有拥有对应能力才可操作。
- `AC-1213`：每次成功管理变更和权限拒绝均形成可关联审计事件，包含规定上下文但不包含凭据或完整敏感请求体。
- `AC-1214`：授权数据不可用、作用域错误、状态无效时系统默认拒绝，并向用户提供不泄露内部安全细节的可行动反馈。
- `AC-1215`：1440px 与 1024px 下支持完整管理流程；窄屏保持列表和详情可读，并明确复杂矩阵的桌面编辑边界。
- `AC-1216`：用户、角色、权限页面使用项目全局字体和客户管理页既有查询、工具栏、表格、状态、分页及反馈模式；键盘可完成查询、详情和主要管理流程。
- `AC-1217`：所有展示和验证使用本地中性数据，不连接或修改 `supply`、`gf_scm`、MCRM 或生产数据库；BUS、REQ/NFR、US、AC、TC 追溯完整。

## 6. 非功能需求

- `NFR-SEC-1201`：所有写操作在服务端执行认证、租户/应用作用域校验和权限校验；失败默认拒绝，错误响应不暴露表结构、凭据或内部堆栈。
- `NFR-DATA-1201`：迁移、角色成员和权限集合变更具备事务一致性、幂等或重复请求保护、并发冲突检测与可验证恢复路径。
- `NFR-AUD-1201`：安全与管理变更具备结构化审计；敏感信息遵循最小返回、最小记录和默认脱敏。
- `NFR-PERF-1201`：在受控测试数据规模下，用户/角色/权限列表使用稳定分页和确定性排序；性能基线、数据量和测量环境必须一并记录，不以空数据结果声明容量。
- `NFR-A11Y-1201`：查询、分页、状态操作、成员维护和权限矩阵具备键盘路径、可见焦点、可感知错误与状态反馈。
- `NFR-UI-1201`：页面使用项目级全局字体和既有企业页面密度；桌面宽度不出现关键操作或文字不可恢复裁切。
- `NFR-OBS-1201`：迁移与授权失败具有稳定错误类别和关联 ID，可区分校验冲突、权限拒绝、作用域错误和系统不可用。
- `NFR-TRACE-1201`：来源、BUS、REQ/NFR、US、AC 与 TC 具有稳定可检查追溯；参考项目事实与目标批准决策保持区分。

## 7. 边界与异常行为

| 场景 | 预期行为 |
|---|---|
| 关键词为空或无结果 | 返回稳定分页的全部或空态，不显示错误态 |
| 快速重复提交同一状态或成员变更 | 返回同一结果或明确已完成，不产生重复关系和重复副作用 |
| 角色权限保存期间权限点被停用 | 保存按最新状态校验并整体拒绝过期选择，要求重新载入 |
| 被管理用户已被其他管理员停用 | 展示最新状态，不用旧版本覆盖；重复停用不伪装新的变更 |
| 角色已有未来生效成员 | 详情区分 scheduled/effective/expired/ended，不计入当前有效成员数 |
| 系统管理员只剩一名成员 | 任何导致零有效管理员的操作被拒绝，即使操作者拥有普通写权限 |
| 应用上下文切换 | 查询和写入重新按新上下文授权，不能携带上一应用的角色或权限选择 |
| 审计写入无法满足安全要求 | 高风险授权变更整体失败，不出现“授权成功但无审计”的结果 |
| 迁移校验不一致 | 停止进入应用验证，输出不一致类别；不得把缺失记录自动当成废弃数据 |

## 8. Specification Gate 边界

Specification Gate 已由 `REQSRC-046` 批准可观察行为、状态、不变量、异常、验收标准和测试设计。该批准不包含物理表、字段类型、SQL、迁移步骤、API、并发机制、审计存储、组件结构或部署方案，也不批准 Architecture、Tasks、实现、生产迁移或 Release。
