## 3. 系统应用架构

F：supply 路由 `/settings/roles` → 页面组件 → `packages/scs-web/src/hooks/useRoleManage.ts` → `packages/scs-server/src/modules/system/role/role.service.ts` → `LocalIamService`。统一数据权限另走 authorization 服务；RoleService 注释明确当前不调用天舟云 RBAC，不能将旧参数名当作外部依赖事实。

F：目标现有角色页面在 `packages/web/src/showcase/AccessAdminPages.tsx`，支持新建、用户绑定/结束授权、权限集合保存。另有 `packages/server/src/role-management/` 树与 CRUD 服务；需要整合责任而不是再生成第三套角色模型。目标切片 014 正在实施资源菜单，必须共用其资源/操作 ID 和权限目录，避免重复注册。

I：此次不是纯 UI 换皮。组织/群组授予、数据条件、字段安全、资产授权均超出当前页面两页签能力；仅移植 React 组件无法闭环。

## 4. 技术框架与技术栈

沿用目标 React/Vite、NestJS、Prisma/PostgreSQL 与 contracts。源 UI 使用 Ant Design、LESS、NavTree。外观采用源页面的左树右面板、8px 外框间距/圆角、14×16px 头部留白、40px 角色图标、紧凑页签和表格；最终需线上或本地可运行参考截图核对。源 `roles.less` 的 `.st`、`.tbl` 等全局类必须限定页面作用域，避免污染客户页面。

### 数据映射建议（不是迁移脚本或已批准建表清单）

| supply 物理模型 | 目标现状/建议 |
| --- | --- |
| `iam_role` | 保留现有 `sys_role`；已有树、简称、排序、日期、版本；`isSystem` 不是 `isSuperAdmin`，不可互相映射 |
| `iam_role_binding` | 目标 `sys_role_user` 有 FK、有效期和审计；用户授权保留，组织/群组绑定需设计新的 `sys_` 扩展，不能丢掉原授权历史 |
| 功能授权 | 复用 `sys_role_permission` 及资源菜单公共目录，保留应用作用域和原子集合更新 |
| `auth_policy` / `auth_policy_field_rule` | 候选 `sys_auth_policy` / `sys_auth_policy_field_rule`；首先确定规则语法、拒绝优先级、默认拒绝及实际查询执行方式 |
| `auth_role_field_permission` | 候选 `sys_role_field_permission`；定义读取过滤、编辑拒绝与导出三条链路 |
| `auth_role_view_assignment` | 先与现有 `sys_role_list_view` 比较语义再决定复用或扩展，视图展示不等于数据安全 |
| `auth_policy_publish_log` | 候选 `sys_auth_policy_publish_log`；不可变版本、发布人、前后差异及回滚来源 |
| `iam_role_asset_grant` / `iam_role_managed_org` | 候选 `sys_role_asset_grant` 等；必须有真实资产目录和唯一责任服务，不复制 supply 业务资产实例 |

本增量 Architecture Plan 必须补齐：公共系统层责任模块、tenant/application 隔离、复合主外键/唯一键、状态与时区有效期、删除限制及审计、现有数据备份/加法迁移/回填校验/切换/恢复演练、数据库测试。不得整库复制、reset、全量 seed 覆盖或新建 iam_/auth_ 表。当前没有执行数据库修改。

## 5. 核心设计思想与实现方法论

候选可复用：树与详情工作区、上下文内授权、配置与实际授权执行分离、不可变策略版本及可审计回滚。适用条件：资源目录稳定、后台强制鉴权、有真实消费端和回归样例。当前仅参考萃取，不晋升为正式模式。

不可直接复用：scs 根节点过滤、CVTE 身份入口、legacyTzcId、gongfu schema、供服专属资产与成员数据、无限制管理员开关、无操作按钮和吞错返回空数组的行为。

## 8. 萃取总结

本次确认业务角色页是树与七类授权配置组合的工作区，而非简单角色列表。已有功能、旧兼容配置和未接线按钮并存。可借鉴上下文授权、紧凑主从布局和版本回滚，但组织专属过滤、超管绕过和旧授权数据不可直接搬入。目标应保留 sys_ 公共模型及授权历史，以真实 API 执行验证每项权限。当前只完成首轮证据和差异草案，需完成增量范围及架构评审后实施，不代表 Release 或资产晋升。
