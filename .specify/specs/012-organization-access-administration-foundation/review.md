# 实施自审：012 组织与访问管理基础

> 评审日期：2026-09-22  
> 性质：AI 实施后自审与自动检查汇总，不冒充独立人工 Gate。  
> 结论：核心实现可继续本地演示；Release Gate 暂不批准。

## 需求与权限视角

- 用户、角色、成员、只读权限目录和权限矩阵已形成前后端闭环。
- viewer 与规格一致：能读取允许的三类管理信息，但没有页面写入口，直接写请求仍由稳定权限断言拒绝。
- admin 没有账号名旁路；授权来自系统管理员角色。自停用、自移除和最后管理员保护均在服务端。
- 用户详情“最近管理变更摘要”、角色组筛选、矩阵差异确认展示仍较简化，属于已知体验缺口，不能视为完整业务验收。

## 架构与数据库视角

- 物理表遵循 `sys_` 平台层；`sys_dictionary` 与 `crm_*` 保持本切片边界。
- 稳定权限目录成为导航、动作与 API 的共同授权事实；菜单不再是 API 授权依据的唯一表达。
- PostgreSQL 复合外键、唯一键、检查约束和排斥约束覆盖关键跨作用域和重叠风险。
- 代码层仍保留 `Iam*`/`Ui*` Prisma 模型名以及部分 `system_code` 兼容字段；它们是迁移期代码兼容，不是新增物理表命名先例。后续清理必须另做切片，避免静默扩大迁移。

## 安全与质量视角

- 读取不返回 password hash；写请求继续使用 Session、same-origin CSRF 和服务端权限断言。
- 审计仅写动作级白名单摘要，不记录密码、Cookie、Token 或完整请求体。
- `pnpm verify`、本地数据库 migration/seed 和 15 项 DB integration 均实际通过。
- 当前没有发现未处理的已知 P0/P1 代码缺陷；但恢复、规定规模性能、浏览器全流程与独立评审尚无证据，因此不能批准 Release。

## 可复用与不可复用

可跨项目复用：平台 tenant/application 作用域、稳定权限编码、角色-only 授权、成员有效期、最后管理员保护、原子权限矩阵、同事务审计、只读受限账号验收清单。

不能直接复用：演示门户菜单与种子数据、默认租户登录假设、当前 `system_code` 兼容层、CRM Showcase 路由/样式、当前本地密码和任何参考项目组织字段。
