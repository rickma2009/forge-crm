# Specification 澄清：组织与访问管理基础

> Specification 澄清状态：`approved-REQSRC-046`

| ID | 问题 | 推荐答案 | 影响 |
|---|---|---|---|
| `Q-SPEC-1201` | 用户列表首轮展示哪些信息？ | 账号、显示名称、账号类型、状态、有效角色、更新时间；不展示员工档案和联系方式 | 避免在员工切片前建立重复个人信息 |
| `Q-SPEC-1202` | 用户状态如何维护？ | 只允许 `ACTIVE ↔ DISABLED`；`LOCKED` 只读并提示通过后续认证恢复流程处理 | 明确本切片不是完整认证运营台 |
| `Q-SPEC-1203` | 管理员是否能停用自己或移除自己的当前管理角色？ | 不允许当前会话操作者停用自己；不得移除导致当前租户/应用无有效系统管理员的成员关系 | 防止误操作锁死管理入口 |
| `Q-SPEC-1204` | 普通角色编码能否修改或删除？ | 创建后编码不可修改；有引用的角色只能停用，首轮不提供物理删除 | 保持安全契约和审计链稳定 |
| `Q-SPEC-1205` | 角色成员有效期如何输入？ | 默认立即生效、永不过期；可选结束时间，统一为左闭右开有效期 | 支持临时授权且口径明确 |
| `Q-SPEC-1206` | 权限矩阵如何保存？ | 保存角色的完整显式权限集合；移除权限时展示差异摘要，整体原子提交 | 避免逐项操作产生部分授权状态 |
| `Q-SPEC-1207` | 多人同时编辑角色权限如何处理？ | 后保存者发现版本过期时拒绝覆盖，并要求重新载入差异 | 防止静默覆盖他人授权变更 |
| `Q-SPEC-1208` | 权限目录首轮可做什么？ | 可按关键词、资源、状态查询和查看来源；不可新增、删除或修改编码 | 权限点由系统发布，不是普通字典 |
| `Q-SPEC-1209` | viewer 的读取范围如何定义？ | 可查看脱敏后的用户、角色和权限目录；无任何写操作能力 | 形成可验证的只读角色 |
| `Q-SPEC-1210` | 窄屏如何处理复杂授权矩阵？ | 列表和详情保持可读；矩阵允许分组纵向展开，但复杂批量编辑提示使用桌面宽度 | 保持桌面优先，不伪造完整移动端效率 |
| `Q-SPEC-1211` | 授权变更何时生效？ | 成功提交后，下一次受保护请求和下一次导航刷新使用新权限；不要求实时推送到已打开页面 | 明确“立即”是服务端决策生效而非 WebSocket 推送 |
| `Q-SPEC-1212` | 失败写操作是否记录？ | 业务校验冲突记录可追踪结果；权限拒绝记录安全事件，但不保存敏感请求体 | 支持审计又避免日志泄密 |

## Architecture 推荐决策

> 状态：`recommended-awaiting-approval`

| ID | 问题 | 推荐答案 | 影响 |
|---|---|---|---|
| `Q-ARCH-1201` | 平台表迁移采用双写还是协调切换？ | B：停写窗口内保留数据迁移并协调切换，不长期双写 | 当前是本地验证环境，双写会制造两个授权事实源 |
| `Q-ARCH-1202` | `systemCode` 如何进入正式模型？ | B：外部路由继续使用应用编码，服务端解析为默认租户下的 `application_id` | 保持现有 URL，同时让数据库关系使用 UUID 作用域 |
| `Q-ARCH-1203` | 权限点是否直接等同菜单或按钮？ | B：权限点独立；菜单和操作引用权限点，API 直接校验稳定权限编码 | 前后端共享安全事实，菜单仍只是投影 |
| `Q-ARCH-1204` | 既有菜单/操作 grant 如何迁移？ | B：每条 grant 一对一映射到新权限点并保留 grant ID；未知目标阻断迁移 | 保留审计身份并避免静默丢授权 |
| `Q-ARCH-1205` | 角色成员历史如何保存？ | B：关联改为独立 UUID，保留多段有效期，并用数据库排斥约束阻止重叠 | 支持到期和重新授权，不覆盖历史 |
| `Q-ARCH-1206` | 角色权限移除如何处理？ | B：停用关联并记录撤销人/时间，不物理删除；重新选择时复用关联 | 保留授权历史和稳定 ID |
| `Q-ARCH-1207` | 并发编辑权限矩阵如何实现？ | B：角色 `version` 乐观锁 + 串行化事务，过期版本整体拒绝 | 防止后保存静默覆盖 |
| `Q-ARCH-1208` | 审计数据如何存储？ | B：同库 `sys_audit_log`，只保存白名单化摘要；高风险成功变更与审计同事务 | 保证授权成功必有审计，不记录凭据 |
| `Q-ARCH-1209` | 是否启用 PostgreSQL RLS？ | B：本切片不启用；使用复合外键和服务层作用域校验 | 单应用验证阶段避免引入连接身份复杂度 |
| `Q-ARCH-1210` | API 如何组织？ | B：应用上下文下的专用 access 管理资源，不提供任意 action execute API | 权限和业务语义可审查 |
| `Q-ARCH-1211` | 页面是否引入新组件库？ | B：不引入；复用现有企业页面 CSS 和受控组件 | 保持客户管理页风格与包体稳定 |
| `Q-ARCH-1212` | 迁移失败如何恢复？ | B：停写前备份与对账，失败可恢复快照；共享环境应用后只做前滚修复 | 不改写已应用 migration，不伪造无损回滚 |
