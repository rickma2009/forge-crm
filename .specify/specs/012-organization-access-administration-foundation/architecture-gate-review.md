# Architecture Gate 评审：切片 012

> 评审对象：`plan.md`、`clarification.md` 的 `Q-ARCH-1201`—`Q-ARCH-1212`、`docs/adr/ADR-006-平台访问管理与无损迁移架构.md`  
> 状态：`approved-REQSRC-047`  
> Specification Gate：approved（`REQSRC-046`）

## 1. 建议批准的核心方案

- `sys_` 平台分层、唯一 access-admin 写入口和默认 tenant/application；
- 协调停写的保留数据 migration，不改历史、不删除重建、不长期双写；
- 现有用户、角色、菜单、操作、grant 和列表视图 ID/关系对账；
- 稳定权限目录，菜单/操作引用权限，API 直接校验权限编码；
- 角色成员多段有效期、数据库排斥约束和最后管理员事务保护；
- 角色权限停用保留历史、role version 并发控制和完整集合原子保存；
- 复合外键作用域、默认拒绝、无权限缓存、无 RLS；
- 同事务白名单审计、受控错误码、恢复演练和性能基线；
- 专用 access API 与沿用客户管理页风格的三个系统管理页面。

## 3. 明确不批准

- Tasks、代码、migration SQL、测试结果已经完成；
- 组织员工、数据权限、用户直授权、DENY、角色继承、审批流；
- SSO、MFA、租户运营、RLS、权限缓存或微服务拆分；
- 菜单管理页、审计日志查询页、生产零停机迁移；
- 修改参考项目、连接生产数据库、部署、Release 或资产晋升。

## 4. 必须接受的限制

- 当前只初始化一个默认租户，登录不提供租户选择；
- 本迁移需要协调停写窗口，不支持旧服务和新 Schema 长期并行；
- `sys_dictionary` 和 `crm_*` 的 `system_code` 留待独立切片，本次不静默扩大迁移；
- GiST 排斥约束和复合外键采用 PostgreSQL 特性，降低数据库可移植性；
- 性能预算只适用于 Plan 固定的本地/CI 数据规模，不代表生产 SLA；
- 审计查询页面不在本期，但审计写入和数据库验证是本期阻断要求。

## 5. 风险与停止条件

- 任一旧 grant 无法一对一映射、任一主键/关系对账不一致，停止切换；
- 无法证明系统管理员完整授权和至少一名有效成员，禁止启动新服务；
- 复合作用域、区间重叠、过期版本或 viewer 直接写请求测试失败，禁止进入 Release；
- 迁移恢复未在独立测试库演练，不得声称可交付数据库变更。
