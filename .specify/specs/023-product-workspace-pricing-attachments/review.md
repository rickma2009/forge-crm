# 实施自审：023 产品工作区、有效期定价与通用附件

> 评审日期：2026-09-23  
> 性质：AI 实施后自审与自动检查汇总，不冒充独立人工 Gate。  
> 结论：`verified-awaiting-release-gate`。

## 需求与体验视角

- 产品新增保留弹窗，查看/编辑进入统一三页签工作区，满足用户对客户式详情交互的要求。
- 产品删除将报价、定价、商机与附件引用校验放在服务端提交事务内；前端只负责解释冲突明细。
- 定价字段覆盖标准/阶梯、有效期、币别、区间和备注；报价按业务日期解析并保存快照。
- 通用附件组件通过归属类型/ID/权限参数接入，首个产品场景已完整验证上传、下载、编辑说明与删除。
- `REQSRC-069` 已消除产品详情与客户详情之间的视觉/交互分叉：两者现在共用相同的对象页头、下划线页签、双列字段和图标操作语言；没有改变产品数据模型或权限边界。

## 架构与安全视角

- `sd_product_price` 属于销售域，`sys_attachment` 属于公共系统层；没有新增按应用名机械分表的前缀。
- 有效期冲突同时有服务校验与 PostgreSQL 排斥约束；删除引用校验与实际删除位于同一 Serializable 事务。
- 文件名被净化，落盘路径验证仍位于配置根目录内，下载不暴露物理路径；写操作继续执行会话、同源与动作权限校验。
- admin 没有账号特判，viewer 的只读行为来自角色授权；浏览器已验证前端按钮隐藏，服务端仍是最终授权点。

## QA 与交付视角

- migration、seed、contracts/server/web 测试、完整 `pnpm verify`、数据库治理和真实浏览器双账号验收均通过。
- 测试附件已清理；演示数据库未保留为验收而创建的临时附件数据。
- 已知限制为对象存储/病毒扫描/备份恢复/规模性能/独立人工评审未完成，以及仓库既有根上下文文件冲突阻断 `verify-all.sh`。
- 因上述交付边界，当前只能提交 Release Gate 评审，不能宣称已发布到生产或外部环境。

## 方法论回流判断

可作为后续候选萃取的是：业务日期有效定价、引用保护删除、参数化附件归属和角色动作验收清单。当前只有产品切片验证，尚不足以直接宣布为跨项目正式模式；至少再由第二个业务实体接入附件后，才能评审是否晋升。
