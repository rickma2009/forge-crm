# 规格：组织架构层级管理

## 业务目标与用户故事

- `BUS-020`：以企业共享组织树作为用户、岗位、负责人和数据权限的后续唯一组织基础。
- `US-1301`：系统管理员可按层级查看并维护组织单元，未授权用户不能进入或写入。

## 功能需求

- `REQ-1301`：系统管理显示“组织架构”菜单，菜单和操作权限从数据库授权投影。
- `REQ-1302`：页面按父子层级展示组织，支持展开、收起、搜索、类型和状态筛选。
- `REQ-1303`：有维护权限的角色可新增根组织、新增下级和编辑组织。
- `REQ-1304`：组织包含编码、名称、类型、上级、排序、状态、半开有效期和备注。
- `REQ-1305`：编码租户内唯一且不可修改；父子必须同租户；禁止自引用和循环。
- `REQ-1306`：层级深度只在读取时计算，不作为权威持久字段。
- `REQ-1307`：新增和编辑必须写安全审计并使用版本冲突检测。
- `REQ-1308`：用户、角色、权限页面查询区与场景清单的按钮对齐样式一致，重置立即执行无条件查询。

## 非功能与边界

- 数据责任模块：`packages/server/src/organization`；其他模块只通过 API 使用。
- 不含员工、岗位、标签、负责人、数据权限和物理删除。
- 桌面优先；窄屏保证可滚动和操作可达。

## 验收标准

- `AC-1301`：admin 登录后可从系统管理进入组织架构，并看到数据库 Seed 的四级树。
- `AC-1302`：收起父级时所有后代隐藏，展开后恢复。
- `AC-1303`：新增下级默认选中对应父级，保存后数据库和页面同步。
- `AC-1304`：移动到自身或后代、跨租户父级、重复编码和过期版本均受控拒绝。
- `AC-1305`：访问管理三页查询/重置按钮右对齐，重置请求不带旧关键词。
