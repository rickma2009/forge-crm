# 技术计划：业务角色工作区

> 当前范围以 REQSRC-057 和 `two-tab-refinement.md` 为准：仅用户管理及功能与数据权限两个页签。旧计划后续模块不再属于本次完成条件，数据权限仅保留入口；不删除既有授权数据或服务端策略。

> 目标纠正（REQSRC-054）：仅针对根 CRM 的 `#/showcase/system/roles` 菜单和 `access-roles` renderer；不在已废弃的分类目录/App/Demo 中开发。旧 `?pattern=...` 入口已经安排删除，不作为任何实现或验收地址。

来源：REQSRC-053 连续本地实施授权；不是虚构用户逐份人工审阅。本计划采用原推荐边界，安全语义以spec.md为准。

## 决策与阶段

沿用 React/Vite + 原生CSS、NestJS、Prisma/PostgreSQL，不引入源UI组件库。按纵向闭环顺序实施，不用空按钮声明完成；每段完成后更新tasks和验证证据。参考源保持只读，现有账号、权限、成员及用户未提交变更保留。

1. 角色树与表单：修复现有树API的作用域、字段白名单、不可改编码、系统保护、树防环、版本及审计；前端主从工作区接入。
2. 成员/功能授权：复用AccessService，与新树同一sys_role事实源；用户候选分页、多选、批量原子操作、差异复核，权限委派上限。
3. 资源及数据权限：统一目录，条件编辑与发布、字段保护、视图分配、版本差异/回滚，真实消费端验证。
4. 组织/群组、仪表盘、组件/页签、分类：核实目标事实源，补必要中性目录和消费链路；不扩张为供服业务系统，不把配置存储等同安全执行。
5. 全面测试、浏览器验收、性能/恢复、三视角自查与Release评审包。不自动声明Release。

## API与责任边界

API-1501：现有 /api/systems/:systemCode/roles 承担角色树/基础属性/移动/归档，统一引用AccessService的应用上下文、sys_role及sys_audit_log。旧access/roles入口需保持兼容但不能旁路安全不变量。
API-1502：既有access角色成员和权限接口扩展批量行为，所有写入重验当前权限及委派范围；前端canManage不是安全边界。
API-1503：资源策略配置/历史/发布/回滚由公共授权责任服务负责；业务域消费策略，不直接写策略表。
API-1504：候选对象/资产及分配使用带作用域接口；不得调用supply写接口。

## 数据层与迁移检查

公共安全实体使用sys_前缀；组织事实仍由org_层负责。主键UUID，时间timestamptz，稳定编码同应用唯一。sys_role、sys_role_user、sys_role_permission、sys_role_list_view不重建、不换ID。角色父子在同应用，结构无权限继承；这对数据库治理“不用无继承父角色模拟分组”形成窄范围偏离：仅为用户明确要求的参考树导航，roleGroup仍独立，授权求值完全忽略parentId，必须回归验证。

新可查询核心实体应关系建模（策略、字段权限、角色绑定、资产授权）；条件树和不可变版本快照允许JSON，不用单一JSON包替代整个权限模型。每个具体新增模型必须在写DDL前补入本计划和新迁移，并登记同作用域FK、状态/索引/恢复。

角色可变属性采用version乐观锁，树移动采用Serializable事务检查防环及排序；授权集合替换和审计同事务提交。有效期半开区间，停用/过期在下一请求撤权。保护系统角色与最后有效管理员；不得新增任意超管绕过。

迁移仅增量：先确认连接为本机验证库并备份；新migration加入约束/必要列；生成客户端；迁移前后对账ID/角色/成员/授权计数。禁止reset、全量seed覆盖。失败优先回滚事务/新迁移前滚；需恢复时先在隔离本地临时库演练，不盲目覆盖运行库。

## 测试边界与证据

### 组织与群组来源的最小补齐

当前组织表只有组织节点，没有用户任职映射；群组也无既有事实源，因此不能用组织 ID 冒充用户 ID。新增 `org_user_assignment` 由组织责任层管理合法账号与组织的有效期关系；新增 `sys_user_group`、`sys_user_group_member` 作为当前应用的非嵌套群组事实；新增 `sys_role_subject_binding` 保留角色对组织/群组的动态绑定，禁止物化复制为 sys_role_user。

主外键采用 UUID；组织映射以 tenant + org + user 约束，群组以 application + tenant 约束，角色绑定以 role + application + tenant 约束。组织、群组二选一 CHECK，包含后代只能用于组织；成员/绑定使用 ACTIVE/DISABLED、半开有效期、version，结束关系保留审计及历史。重复且重叠的生效区间在 Serializable 事务拒绝。停用账号、节点、群组或关系在下一次授权查询失效。

“有应用访问资格”本次取可验证的最小定义：账号在当前应用至少有一个有效的直接角色成员关系；组织/群组不会自己给未获应用准入的账号创建访问资格。已有空业务角色可承担基础准入，此条件必须在选择器说明并显示资格结果。系统角色只允许直接用户维护，不允许组织/群组批量扩张系统管理员。组织成员/群组来源维护要求现有组织维护/资源维护权限并限制到当前应用受保护管理员；角色绑定另需成员管理权限及可委派范围。

统一有效角色解析同时供导航、权限断言、列表视图、数据策略和委派校验消费；角色树 parentId 不参与权限继承。新增表仍增量迁移，不改写原 direct memberships、grant 或用户 ID；恢复先隔离测试并比较原始主键集合。

按用户免重复确认指示，测试边界确定为：公开契约、HTTP角色/授权接口、面向用户的React组件及真实浏览器；策略求值作为公共纯函数接口测试。数据库边界可使用隔离测试库；不mock内部算法，不把未执行测试记为通过。

每个闭环先失败测试，再实现与重跑。安全至少覆盖错误作用域、系统角色、循环、重复编码、版本冲突、日期边界、批量原子、撤权即时性和不回归原显式授权。当前运行服务期间避免会删除dist的构建；优先noEmit和定向测试。

## 完成与恢复界限

### 数据策略纵向闭环的具体模型决策（REQSRC-053 授权下的实施决策）

公共授权模块唯一负责 `sys_authorization_resource`（应用下受支持消费绑定）、`sys_authorization_field`（资源字段元数据）、`sys_role_data_policy`（角色/资源/操作策略头）、`sys_role_data_rule`（规则及条件 AST）、`sys_role_field_rule`（字段限制）、`sys_policy_revision`（不可变发布快照）。核心关系不打包成单个 JSON：资源归属 application，策略以 role+resource+action 唯一，规则/字段行归属策略；仅条件 AST、字段值来源及历史快照为 JSON。所有新表使用 UUID、timestamptz，跨作用域关系用复合外键，状态和 version 乐观锁；删除资源/字段前检查当前策略及发布历史引用，不硬删历史。

首个真实消费绑定为既有客户模块（读取、新建、修改），字段必须映射代码内注册的安全查询能力；不能注册任意 SQL、URL 或对象路径。资源接入状态默认关闭，明确启用后默认拒绝，既有未接入应用保持旧行为。客户列表、详情、写入和关联子表入口都执行父客户策略；关联子表响应以整体字段权限限制，不伪造暂不存在的独立子表细粒度字段能力。保留客户 id/version 等协议控制字段为系统只读，不能利用隐藏身份字段破坏并发校验。

数据发布 Serializable 原子替换规则、字段、适用视图及追加版本；回滚重跑相同验证并生成新版本。策略求值不绕过原有功能权限，规则 ALLOW 并集、DENY 优先、无匹配默认拒绝；所有字段限制按显式限制优先合并。资源目录维护权限与角色授权权限分离，管理界面不得创建无真实执行端的操作。采用同应用预登记字典/选项服务，不发起任意地址请求。

角色视图单独编辑暂复用 `sys_role_list_view`，保留原 id 和历史状态；使用 role.version 并与角色权限事务隔离一致。适用视图在策略发布时同事务更新，不能提升功能或字段权限。上述数据库扩展仅在本地已备份验证库增量迁移，恢复先在隔离数据库演练。

第一段具体DDL：仅在既有sys_role增加nullable archived_at，区分停用与归档；加父角色同application复合外键、自父禁止、有效期顺序CHECK。现有id/application复合唯一键复用，无新实体表。责任模块role-management；应用上下文带tenant交叉校验；父子防环在Serializable事务内校验。查询按application+状态/归档过滤，暂复用原索引，小规模测量后再评审额外索引。归档禁止子节点/有效成员/有效功能或视图授权引用，审计同事务。恢复旧代码前保留新增列和约束，不删除任何数据；代码回退期间禁用新写入口，数据恢复仅使用已演练备份。

完成要求22项功能及4项NFR有真实对应证据；未完成项保持unchecked并说明原因。浏览器测三档尺寸及只读/管理身份。需求、安全、运行三个视角分别记录审查，单代理自查不冒称外部独立审查。Release状态独立，未完成测试或恢复不能宣称发布。
