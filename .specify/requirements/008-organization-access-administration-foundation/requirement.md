# 组织与访问管理基础业务需求

> 版本：v0.1  
> 状态：`business-gate-approved`  
> 来源：`REQSRC-043`、`REQSRC-044`、`REQSRC-045`

## 1. 业务问题

当前演示门户已经能够按数据库角色读取导航，但平台表仍使用 `iam_*`、`ui_*` 等历史命名，权限事实同时依赖菜单和操作记录；系统管理中的用户、角色、权限和菜单页面仍是说明页。管理员无法在统一工作台中查询用户、维护角色成员、分配稳定权限点并复核变更。

## 2. 目标

| ID | 目标 | 当前基线 | 成功方向 |
|---|---|---|---|
| `BUS-018` | 建立可复用的平台访问管理底座 | 已有数据库导航授权，但没有稳定权限目录和可操作管理页 | 平台表符合批准的数据规范，现有数据无损迁移，管理员可通过角色完成用户和功能权限管理 |
| `BUS-019` | 建立一致的系统管理交互 | 用户、角色、权限页面为说明页 | 页面沿用客户管理页的查询、工具栏、表格和弹窗/抽屉风格，且所有操作受服务端权限控制 |

## 3. 目标角色

| 角色 | 核心任务 | 权限边界 |
|---|---|---|
| 系统管理员 | 查询账号、维护普通角色、分配角色成员和功能权限 | 通过系统管理员角色获权；不能删除系统管理员角色或绕过审计 |
| 只读查看者 | 查看用户、角色和权限目录 | 不可新增、修改、停用、分配成员或保存权限矩阵 |
| 应用使用者 | 登录后使用获授权的菜单和操作 | 不能进入未授权系统或通过隐藏 URL 绕过服务端权限 |

## 4. 首个切片业务流程

```text
正式迁移并校验现有平台数据
→ 初始化默认租户、演示门户应用和稳定权限点
→ admin 通过系统管理员角色获得全部已发布权限
→ 管理员查询用户并维护其角色成员关系
→ 管理员查询/维护普通角色
→ 管理员打开角色权限矩阵并保存显式授权
→ 服务端按相同权限点控制页面、菜单、按钮和 API
→ 变更写入结构化审计记录
```

## 5. In Scope

- 将现有 `iam_*`、`ui_*` 平台表收敛到已批准的 `sys_*` 模型，保留已有 ID、数据和关系；
- 建立默认租户、应用、稳定权限点和角色分组所需的最小平台表；
- 迁移现有用户、角色、角色成员、菜单、菜单操作、列表视图及偏好；
- 用户列表：关键词/状态查询、账号详情、启用/停用、角色成员维护；
- 角色列表：关键词/状态查询、普通角色新增/修改/停用、成员维护、权限矩阵；
- 权限目录：按资源/关键词查询，展示权限编码、动作、状态及来源；首轮不允许任意新增或改码；
- 系统管理员角色保护、admin 和 viewer 演示账号；
- 服务端授权、审计日志、数据库集成测试和页面权限测试；
- 页面视觉与交互沿用现有客户管理页面；`supply` 只作为信息结构与交互证据。

## 6. Out of Scope

- 组织单元、员工、雇佣、任职、岗位和负责人页面及表；
- 行级或列级数据权限、显式拒绝、角色继承和审批流；
- 外部身份源接入、SSO、MFA、密码找回和完整会话运营；
- 租户/应用管理页面、生产多租户运营和跨企业委派；
- 复制 `supply` 的 Ant Design 视觉、customer/supplier 域或手工 DDL 流程；
- 生产数据库执行、外部部署或 Release。

## 7. 业务不变量

1. 用户只能通过角色获得权限，不支持个人直接授权。
2. 权限点是服务端授权事实，菜单和按钮只是投影；隐藏界面元素不能替代 API 授权。
3. 系统管理员角色不可删除，且不能因普通页面操作失去管理底座所需权限。
4. `admin` 不通过账号名特例绕过权限，而是通过系统管理员角色获权。
5. 权限编码发布后稳定；首轮权限目录由 migration/seed 初始化，不开放任意新增和改码。
6. 停用用户、角色或权限后，新的授权计算必须立即拒绝其失效能力。
7. 平台表迁移必须保留已有 ID、关联和演示数据；禁止删除重建冒充迁移。
8. 授权数据库不可用或作用域不匹配时默认拒绝。
9. 角色成员和权限变更必须记录操作者、目标、前后摘要、时间和关联 ID。
10. viewer 只能读取已授权信息，不能通过直接请求执行写操作。

## 8. 成功验证方向

- 迁移前后用户、角色、菜单、操作和列表视图记录可通过自动校验逐类对账；
- admin 能完成“创建普通角色—分配 viewer—选择权限—viewer 重新登录验证”的闭环；
- viewer 的页面操作和直接 API 写请求均被拒绝；
- 系统管理员角色保护、跨应用关联、重复关联和无效权限均有数据库或服务端失败测试；
- 用户、角色、权限页面在桌面宽度下与客户管理页保持相同字体、查询区、工具栏、表格密度和反馈模式。

## 9. Gate 边界

Business Gate 已由用户通过 `REQSRC-045` 批准业务目标、角色、范围、不变量、切片顺序与 `Q-1201`—`Q-1210` 推荐答案。它不批准字段 Schema、迁移 SQL、API、组件设计、测试实现、Architecture、Tasks、代码、部署或 Release。
