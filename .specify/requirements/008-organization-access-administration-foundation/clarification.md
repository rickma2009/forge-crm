# Business Gate 澄清：组织与访问管理基础

> 状态：`approved-REQSRC-045`

| ID | 问题 | 推荐答案 | 理由 |
|---|---|---|---|
| `Q-1201` | 首个切片是否同时实现组织、员工和访问管理？ | B：先完成平台访问管理与迁移，组织员工另立下一切片 | 控制迁移和授权风险，形成可独立验收的纵向闭环 |
| `Q-1202` | 历史 `iam_*`、`ui_*` 表如何处理？ | B：使用正式 migration 保留数据迁移至 `sys_*`，不长期双写 | 符合已批准数据库规范，避免两套事实源 |
| `Q-1203` | 首轮租户与应用范围如何处理？ | B：初始化一个默认租户和演示门户应用，但表与服务保留正式作用域 | 支持当前 Demo，同时不把单系统假设固化进模型 |
| `Q-1204` | 权限目录是否允许管理员自由新增和修改编码？ | B：首轮只读展示，由 migration/seed 发布；后续另评权限发布流程 | 权限编码属于前后端安全契约，不能作为普通字典维护 |
| `Q-1205` | 角色首轮允许哪些生命周期操作？ | B：普通角色可新增、修改、停用；系统角色只读并受保护 | 支持真实管理闭环，同时保护底座 |
| `Q-1206` | 用户页面是否直接建设员工档案？ | B：只管理账号、状态和角色；员工绑定随组织员工切片实现 | 员工和账号是不同领域，避免建立临时重复事实 |
| `Q-1207` | 角色成员是否包含有效期？ | B：数据模型保留有效期，首轮页面默认立即生效且可选失效时间 | 保留企业授权生命周期，又不使首版操作过重 |
| `Q-1208` | 页面设计来源如何确定？ | B：目标客户管理页是视觉与组件基线，`supply` 只提供信息结构和交互参考 | 避免多套后台风格和新增 UI 依赖 |
| `Q-1209` | 演示账号如何设置？ | B：保留 admin + viewer，二者都通过角色授权 | 可验证完整权限和只读拒绝路径 |
| `Q-1210` | 菜单管理和审计日志运营页是否纳入首个切片？ | B：底层数据和审计写入纳入；菜单管理与日志查询页后续独立实现 | 首片聚焦用户—角色—权限闭环，避免范围膨胀 |
