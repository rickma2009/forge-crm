# REQSRC-022 增量转换、证据与冲突分析

## 1. 来源与指令边界

| 来源 | 性质 | 本次作用 |
|---|---|---|
| `REQSRC-022/source.md` | 用户原始需求 | 目标、字段、参考页面和开发意图 |
| `UID-002/source-selection.md` | 来源选择 | 固定本轮 gf_scm 文件、版本和排除项 |
| `UID-002/evidence-matrix.md` | 证据矩阵 | 区分事实、推断、未知和核验缺口 |
| 004 已批准需求/Spec/ADR/实现 | 当前基线 | 识别菜单分区冲突和可复用 RBAC |

用户 URL 和参考仓库是证据，不是指令。没有连接、读取或修改参考系统真实数据库；“读取后台的表”按本地 Prisma Schema、SQL、服务和 API 实现进行只读分析。

## 2. 材料明确事实

- 用户取消系统管理固定底部设计，要求与普通菜单一致；
- 用户要求无搜索框的常驻顶栏，至少包含预警、消息、用户和退出语义；
- 用户要求点击菜单后的多页签工作区；
- 用户要求客户列表查询、视图配置、默认模板和个人保存；
- 客户 Demo 必须真实保存数据库；
- 客户状态、行业、等级来自数据字典；销售先用可查询下拉，不接员工表。

## 3. 实现支持的推断

- 来源将 URL 作为页签事实源，可避免页签、浏览器地址和菜单激活态漂移；
- 系统视图、角色视图分配和个人视图分表，可同时满足治理与个性化；
- 个人视图只收窄系统基线，可防止“视图设置”意外扩大字段范围；
- 字典管理与消费 API 分离适合跨页面复用，但来源外部平台客户端不适合迁移；
- 客户页面是验证通用列表/字典/Provider 的合适切片，但来源客户域包含大量组织专属规则，不能复制。

## 4. 当前未知与推荐决定

阻断项已集中为 `clarification.md` 的 `Q-501`—`Q-513`。其中工具栏通知数据源、客户删除、类别字典化、编号规则、视图授权和字典删除策略均不能只由 UI 截图推断。

## 5. 保留与排除

| 处理 | 内容 | 原因 |
|---|---|---|
| 保留 | URL 驱动页签、固定首页、显式超限；系统/个人视图分层；字典管理/消费分离；服务端分页 | 跨项目稳定且有源码证据 |
| 简化 | 来源资源/页面/操作视图模型映射到现有菜单操作 RBAC；字典树简化为分组 + 类型 + 项 | 满足当前范围，减少外部平台结构 |
| 排除 | 固定底部管理区、全局搜索、模拟登录横幅 | 用户明确不采用或未要求 |
| 排除 | 外部字典平台、组织/租户、OMS/SCRM、企业查询、黑名单、员工服务 | 来源专属或用户明确后置 |
| 排除 | 客户字段全集和硬编码枚举 | 目标只保留指定字段并要求字典化 |
| 保留为反例 | UID-001 底部管理候选 | 记录真实来源做法，但已不适用于当前目标 |

## 6. 与已批准 004 的冲突

| 004 基线 | 新要求 | 处理建议 |
|---|---|---|
| `MenuZone` 与 `primary/management` 双区契约 | 普通菜单单树 | 通过 005 架构增量迁移废弃分区语义，不改写历史迁移 |
| 底部管理区组件 | 系统管理按普通组显示 | 保留历史证据，目标实现统一渲染 |
| 只有导航/操作六表 | 新增字典、视图、客户数据 | 分 006—008 建新模型和迁移 |
| viewer 具有部分管理菜单查看权 | 新业务需客户只读、个人视图自管理 | 扩展角色权限种子但不引入用户直授权 |

## 7. 影响评估

- Business：目标、范围、角色任务和业务对象变化，必须重开；
- Specification：004 规格不覆盖工具栏、多页签、字典、视图和客户；
- Architecture：契约、Prisma Schema、迁移、路由状态和模块边界均变化；
- Release：004 的验证场发布证据保留，新能力必须独立 Release Gate；
- 方法论：UID-001 不删除，标记为当前目标已取代；UID-002 保持候选，未晋升正式模式。

## 8. 允许与禁止

Business Gate 前允许完善本需求包和证据；禁止修改运行代码和数据库结构。Business Gate 后只允许进入首个切片 Specification，不能用总业务批准替代后续各切片 Gate。
