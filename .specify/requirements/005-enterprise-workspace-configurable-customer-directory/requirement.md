# 企业工作区与可配置客户目录业务需求

> 版本：1.0
> 状态：`business-gate-approved`
> 权威来源：`REQSRC-022`；批准证据：`REQSRC-023`

## 1. 痛点与目标

| 痛点 | 目标 | 备注 |
|---|---|---|
| 004 将系统管理建成特殊底部菜单区，增加了数据、接口和渲染的分支 | 所有菜单采用同一树模型，系统管理只是按排序出现的普通菜单组 | 需要增量修改 004 已批准模型 |
| 当前页面切换缺少稳定的全局工具区和多任务工作面 | 常驻顶栏提供通用工具，菜单页面以多页签并行打开 | 顶栏不包含全局搜索 |
| 列表页的查询、列配置和个人偏好容易在新项目中重复开发 | 建立系统视图基线、角色可用视图和个人视图的可复用闭环 | 视图不代替字段或操作权限 |
| 枚举散落在前端常量中，难以统一维护 | 建立本地数据库字典管理与业务消费能力 | 不依赖来源系统的外部字典平台 |
| 现有 Demo 缺少可操作的真实业务数据切片 | 用客户目录验证查询、视图、字典、远程选择和数据库 CRUD | 不接员工表，不做数据范围权限 |

## 3. 角色与主流程

| 角色 | 本期行为 | 权限边界 |
|---|---|---|
| `admin` / 系统管理员角色 | 访问全部菜单与操作；管理字典和系统视图；维护客户 | 仍通过角色授权，不设账号旁路 |
| `viewer` / 受限演示角色 | 访问获授权菜单；查询客户；保存和管理自己的个人视图 | 不管理系统视图/字典，不新增或编辑客户 |

```text
登录并选择系统
→ 服务端返回角色授权后的单棵菜单树
→ 点击左侧菜单创建或激活路由页签
→ 页面解析角色可用系统视图和用户个人视图
→ 查询栏、列、默认过滤和分页按当前视图呈现
→ 字典和销售 Provider 提供选项
→ 服务端分页读取客户
→ admin 新增/编辑，viewer 只读
→ 数据库保存并刷新列表
```

## 4. 页面与功能

### PAGE-501 应用工作区

#### FR-501｜【修改】【P0】统一菜单树

- 删除“应用菜单/系统管理菜单”两区展示语义；所有分组和页面节点使用相同层级、搜索、展开、排序和角色授权逻辑。
- “系统管理”保留为普通菜单组，通过 `sort_no` 决定位置，不再固定在底部，也不因名称获得特殊权限。
- 无权页面先移除，只保留仍有可见后代的祖先；成功返回空菜单时不得显示全量回退。

#### FR-502｜【新增】【P0】常驻工具栏

- 位于菜单右侧内容区顶部，所有业务页面和页签切换期间保持存在；不显示来源系统的全局搜索框。
- 首期稳定槽位为预警/待办、消息、当前用户和退出；工具用稳定 `tool_key` 注册，以便不同系统启停或替换实现。
- 当前用户来自真实会话，退出调用现有会话注销接口；预警/消息未接数据源时显示明确空态和零计数，不伪造消息。

#### FR-503｜【新增】【P0】多页签工作区

- 本文将原文“点击昨天菜单”按语境作为待确认项 `Q-502`，推荐解释为“点击左边菜单”。
- 点击页面菜单创建或激活对应页签；URL 是当前页面事实源，刷新和深链后仍能定位页面。
- 首页固定不可关闭；其他页签支持关闭、刷新、关闭其他、关闭右侧、关闭全部；关闭当前页签后激活相邻页签。
- 首期最多 12 个页签；超限阻止新开并提示，不自动关闭潜在含未保存状态的页面。
- 页签切换保留已打开页面的会话内状态；浏览器重启后的跨会话恢复不在首期。

### PAGE-502 数据字典管理

#### FR-504｜【新增】【P0】本地数据字典

- 字典类型和字典项持久化在验证场 PostgreSQL，由 admin 管理；viewer 只能通过业务页面消费已启用项。
- 字典类型至少包含系统、编码、名称、分组、状态、排序和说明；字典项至少包含稳定编码、值、名称、颜色/标签语义、状态、排序和说明。
- 支持字典类型和字典项的查询、新增、编辑、启停与排序；首期不做物理删除，避免破坏历史引用。
- 提供按编码单查和批量查询接口。停用项不再出现在新录入选项中，但已有客户记录仍能解析名称。
- 记录创建人、修改人和时间；运维缓存清理、外部同步、SQL 导出不属于标准业务模板首期。

### PAGE-503 系统视图配置 / PAGE-504 通用查询列表

#### FR-505｜【新增】【P0】系统视图与角色可用视图

- 每个列表页面和读取操作至少存在一个启用的系统默认视图；没有可用系统视图时页面显示配置错误，不回退全字段。
- 系统视图绑定系统、页面和读取操作，可配置列顺序、显隐、宽度、固定、查询栏显隐/折叠、默认过滤条件、默认排序和每页条数。
- admin 维护系统视图，并把视图分配给角色；同一角色可有多个可用系统视图。
- 系统视图只决定页面展示/查询基线，不授予菜单、页面操作或数据权限。

#### FR-506｜【新增】【P0】个人视图

- admin 和 viewer 都可以基于自己当前可用的系统视图创建、修改、删除自己的个人视图；管理员只能只读查看他人的个人视图目录。
- 个人视图可保存列布局、查询栏布局、过滤条件、排序和页大小，但不能新增系统基线未开放的字段或能力。
- 默认解析顺序为：当前对象有效的最近个人引用 → 有效的用户默认个人视图 → 角色可用的对象系统默认视图。最近选择记录只有指向有效个人视图时才作为优先个人引用；普通系统视图的最近选择不覆盖个人引用优先规则。个人引用失效提示回退，无可用系统默认时明确显示配置错误，不再任取首个系统视图。（来源：UIRULE-20260923-list-workspace，替代早期解析顺序。）
- 一个用户在同一列表范围内最多保存 30 个个人视图；选择视图时持久化最近选择偏好。

#### FR-507｜【新增】【P0】通用查询列表模板

- 单据（报价单、销售订单等）及关键业务对象（商机、客户等）从菜单进入首先展示列表：顶部查询条件与查询/重置，其下工具栏左侧新增、右侧当前视图/选择/设置/总数/刷新，下面是网格与分页。动作受已有权限约束；按稳定业务对象标识隔离视图，不能以物理表名或单条记录 ID 代替视图对象。
- 每个列表设计时必须确认是否提供视图设置、设置页或弹层入口、可配置字段、对象/用户/应用边界和失效回退；单据与关键对象默认提供，不提供的辅助表需在 Spec 中说明理由。布局遵循 UI-LIST-VIEW-01，按钮与行操作同时遵循 UI-BUTTON-01 / UI-LIST-01。

- 固定组合为查询栏、查询/重置/更多条件、页面工具栏、当前视图及设置、数据表格、行操作和服务端分页。
- 查询字段由系统视图控制首屏/折叠和可用性；切换视图时查询栏、列、默认过滤、排序和页大小一致切换。
- 应用临时设置只影响当前会话；保存或另存为才写入个人视图。
- 页大小限 10、20、50、100；至少保留一列可见字段；无效/重复/已移除字段导致保存失败并给出明确提示。

### PAGE-505 客户目录

#### FR-508｜【新增】【P0】客户列表、查询与详情

- 列表字段：客户类别、客户编码、客户名称、客户简称、客户地址、当前状态、所属行业、客户等级、负责销售、备注。
- 查询字段首期为关键词（编码/名称/简称）、客户类别、状态、行业、等级和负责销售；支持重置、更多条件和服务端分页。
- 客户类别、状态、行业和等级均从本地数据字典读取；列表保存稳定字典值并显示字典名称。
- admin 和 viewer 均可查看列表与详情；数据范围为全部演示客户，并明确不代表已实现生产数据权限。

#### FR-509｜【新增】【P0】客户新增与编辑

- admin 可新增和编辑上述字段；viewer 看不到可执行入口，直接调用写接口也返回 403 且不改数据。
- 客户编码由服务端生成且唯一，格式推荐 `CYYYYMM####`；客户名称唯一，简称不要求唯一。
- 客户名称、简称、类别、状态为必填；地址、行业、等级、负责销售和备注可选。长度与并发更新规则进入切片 008 Specification。
- 保存前校验字典项属于正确字典且可用于新录入；保存销售 Provider 返回的稳定键和显示名快照。

#### FR-510｜【新增】【P1】销售可查询下拉

- 表单输入关键词后调用后端 Provider 返回演示销售选项，支持防抖、加载、空态和选择回显。
- 首版 Provider 由受控种子/配置提供，不创建员工表；接口与字段保持可替换，未来接员工目录时不修改客户页面交互契约。

## 6. 公共约束

- 所有新增表、API、菜单、文案和正式候选使用中性命名，不出现来源项目名称；来源名称只留在 `REQSRC-022`、`UID-002/source-selection.md` 和证据定位。
- 菜单访问、字典管理、系统视图管理和客户写操作均继续由角色授权，不能新增用户直授权。
- 真实数据库仅指验证场自己的 PostgreSQL；不得连接或修改参考项目数据库。
- 可执行 SQL 只存在于 `packages/server/prisma/migrations/`；方法论和需求文档不保存第二份可执行 SQL。

## 7. 验收方向

全局列表行操作规则（来源 `UIRULE-20260923-list-record-actions`，2026-09-23 当前有效）：编辑、删除、审核等已有行操作使用带中文提示和可访问名称的图标按钮；不新增业务操作权限。操作列不得提供查看按钮或查看图标，改以本行编码、名称或单号链接查看详情，客户列表具体采用客户编码。无查看权限时显示普通文本；只有查看能力时省略空操作列。此规则替代早期“操作列提供查看图标”的呈现要求，页面级查询/新增/保存按钮不受影响；对应 REQ-810、AC-810、TC-810，页面适配待核查。

| ID | 验收条件 |
|---|---|
| `AC-501` | 菜单 API 和 UI 只返回/呈现一棵授权树；“系统管理”与其他普通分组使用同一逻辑且不固定底部 |
| `AC-502` | 任意菜单页和页签切换时工具栏保持存在，搜索框不存在；用户信息和退出使用真实会话 |
| `AC-503` | 打开、切换、刷新和批量关闭页签符合规则；第 13 个页签被阻止且已有状态不丢失 |
| `AC-504` | admin 可维护本地字典；viewer 写接口 403；停用项不供新录入但历史客户仍可读 |
| `AC-505` | 每个列表有默认系统视图；角色只能取得已分配系统视图；无视图时显式失败 |
| `AC-506` | 用户能保存和切换个人视图，不能突破系统基线，最近选择和默认顺序可复核 |
| `AC-507` | 客户查询、分页、新增、编辑和详情均读写 PostgreSQL；服务重启后数据仍在 |
| `AC-508` | 客户类别/状态/行业/等级全部来自字典；负责销售来自可查询 Provider 且无员工表 |
| `AC-509` | admin 可维护客户，viewer 只读；绕过前端写入仍被服务端拒绝 |
