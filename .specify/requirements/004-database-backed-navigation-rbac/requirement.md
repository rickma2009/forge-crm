# 数据库驱动的导航与角色授权业务需求

> 版本：0.1
> 状态：`business-gate-approved`
> 权威来源：`REQSRC-017`；批准证据：`REQSRC-018`

## 1. 目标与结果

将已验证的企业左侧导航从“前端内存 Demo”升级为可供后续项目采用的最小全栈候选：菜单、页面操作、用户、角色和授权关系保存在数据库；登录用户选择/传入目标系统后，服务端只返回该系统内经其角色授权的菜单与页面操作。

| ID | 业务结果 | 验收方向 |
|---|---|---|
| `BUS-009` | 一套数据模型承载多个系统的导航，不为每个项目复制一套权限表 | 同一数据库可登记至少两个 `system_code`，查询结果严格隔离 |
| `BUS-010` | 菜单访问与页面操作全部经角色授权 | 数据结构和接口均不存在用户直授权路径 |
| `BUS-011` | 演示门户具备可替换的前后端与数据库闭环 | 菜单和操作不再以打包 JSON 作为运行时唯一事实源 |
| `BUS-012` | 默认管理员也遵循角色模型 | `admin` 通过系统管理角色获得权限，不使用用户级超级管理员旁路 |

## 2. 角色与核心流程

| 角色 | 任务 | 责任边界 |
|---|---|---|
| 登录用户 | 选择一个目标系统并查看被授权菜单、进入页面和执行被授权操作 | 不能传入其他用户身份或获得用户直授权 |
| 系统管理角色成员 | 管理该系统全部菜单与操作 | 管理能力仍来自角色权限，不是账号硬编码 |
| 权限管理员 | 维护角色、角色成员和角色权限 | 本次不配置行级/字段级数据权限 |
| 开发人员 | 新增系统菜单与页面操作，执行受控迁移和种子数据 | 不从参考项目复制组织、租户或遗留兼容规则 |

```text
用户完成认证
→ 客户端提交目标 system_code
→ 服务端从会话取得当前用户
→ 查询该用户在目标系统内的有效角色
→ 汇总角色拥有的菜单和菜单操作
→ 先按系统、启用状态和角色权限过滤
→ 返回应用菜单树、系统管理菜单树和允许的操作编码
→ 前端渲染；后端在操作接口再次鉴权
```

## 3. 功能需求

| ID | 需求 | 优先级 | 验收方向 |
|---|---|---|---|
| `REQ-401` | 【修改】菜单与页面操作必须由数据库持久化并由后端提供，前端 Registry 只可作为迁移/种子输入或失败降级候选，不能继续作为运行时授权事实源 | P0 | 修改数据库后，无需重新构建前端即可反映授权菜单变化 |
| `REQ-402` | 【新增】菜单必须带 `system_code`；服务端按客户端选择的系统过滤，且不得返回其他系统菜单、操作或角色信息 | P0 | 两系统同名菜单互不泄漏 |
| `REQ-403` | 【新增】菜单分为 `APPLICATION` 与 `SYSTEM_MANAGEMENT` 两个区域；应用菜单显示在上部，管理菜单显示在底部系统管理区 | P0 | 两区顺序、层级与当前壳层一致 |
| `REQ-404` | 【新增】菜单支持分组和页面节点、父子层级、路由、图标语义、排序、启停；无权叶子先移除，仅保留仍有可见后代的祖先 | P0 | 不泄漏隐藏菜单名称、数量和关键词 |
| `REQ-405` | 【新增】每个页面菜单可登记零到多个操作，操作具有稳定编码、名称、类型、排序与启停状态 | P0 | 同一页面操作编码唯一，禁用操作不返回 |
| `REQ-406` | 【修改】用户只能通过角色获得菜单和操作权限；禁止用户—菜单、用户—操作直授权和账号代码特判 | P0 | 权限数据与 API 不提供个人直授权入口 |
| `REQ-407` | 【新增】角色属于一个系统；一个用户可加入多个角色，同一系统内多角色权限采用允许集合并集，未授权默认拒绝 | P0 | 角色禁用或绑定失效后权限立即不再生效 |
| `REQ-408` | 【新增】每个系统初始化一个不可删除的系统管理角色；`admin` 用户通过角色用户关系加入该角色，该角色显式获得该系统全部菜单和操作 | P0 | 新增菜单/操作后的管理员授权策略须在 Specification Gate 明确 |
| `REQ-409` | 【新增】服务端返回当前用户在目标系统的两区菜单树和操作权限；受限路由返回 403，未知路由返回 404 | P0 | 菜单、路由和页面操作使用同一服务端授权结果 |
| `REQ-410` | 【新增】页面操作接口必须在服务端再次校验角色权限；仅在前端隐藏或禁用不能视为授权控制 | P0 | 绕过前端直接调用未授权操作仍返回 403 且无数据变更 |
| `REQ-411` | 【不变】本次不实现表级、行级、字段级或组织范围数据权限 | P0 | 数据模型与页面不得暗示已具备数据范围控制 |
| `REQ-412` | 【修改】现有前端内存 `admin/viewer` 方案保留为历史验证/测试 fixture；新版完成前不得删除，但也不得继续标为目标架构 | P1 | 历史证据与新版目标分别标记 |

## 4. 六类逻辑表要求

以下名称是中性设计候选，供 Architecture Gate 转换为 PostgreSQL/Prisma DDL；当前不是已批准 SQL。

### 4.1 `ui_menu`：功能菜单表

| 字段 | 业务含义 | 约束 |
|---|---|---|
| `id` | 菜单稳定标识 | 主键 |
| `system_code` | 所属系统 | 必填；与 `menu_code` 联合唯一 |
| `menu_code` / `menu_name` | 稳定编码与显示名称 | 必填 |
| `menu_zone` | `APPLICATION` 或 `SYSTEM_MANAGEMENT` | 必填；决定上下区域 |
| `node_type` | `GROUP` 或 `PAGE` | 必填；PAGE 才可配置路由和操作 |
| `parent_id` | 同系统父菜单 | 可空；禁止跨系统父子关系与环 |
| `route_path` / `icon_key` | 页面路由与中性图标键 | PAGE 路由必填且系统内唯一 |
| `sort_no` / `status` | 顺序与启停 | 同父级稳定排序；仅 ACTIVE 可返回 |
| `version` / 时间字段 | 并发与审计基础 | 必填 |

### 4.2 `ui_menu_action`：菜单拥有的页面操作表

| 字段 | 业务含义 | 约束 |
|---|---|---|
| `id` / `menu_id` | 操作及所属页面菜单 | 主键；菜单外键 |
| `action_code` / `action_name` | 稳定操作编码与名称 | 同菜单唯一 |
| `action_type` | 例如 VIEW、CREATE、UPDATE、DELETE、EXPORT 或自定义动作 | 枚举策略待 Spec 确认 |
| `sort_no` / `status` | 顺序与启停 | 仅 ACTIVE 可授权/返回 |
| `version` / 时间字段 | 并发与审计基础 | 必填 |

### 4.3 `iam_user`：用户表

| 字段 | 业务含义 | 约束 |
|---|---|---|
| `id` / `account` / `display_name` | 用户主键、登录标识、显示名 | account 唯一 |
| `auth_source` / `external_subject` | 认证来源与外部主体 | 认证方案待 Architecture Gate；不得存明文密码 |
| `status` | ACTIVE、DISABLED、LOCKED | 非 ACTIVE 不得获取权限 |
| `version` / 时间字段 | 并发与审计基础 | 不设置 `is_super_admin` |

### 4.4 `iam_role`：角色表

| 字段 | 业务含义 | 约束 |
|---|---|---|
| `id` / `system_code` | 角色与所属系统 | 必填 |
| `role_code` / `role_name` | 稳定编码与名称 | 系统内唯一 |
| `role_type` / `is_system` | SYSTEM 或 BUSINESS；系统内置标识 | 系统管理角色为 SYSTEM + true |
| `status` / `description` | 状态与说明 | 系统角色不可删除，只可按批准规则维护 |
| `version` / 时间字段 | 并发与审计基础 | 不以用户字段代替角色权限 |

### 4.5 `iam_role_user`：角色用户表

| 字段 | 业务含义 | 约束 |
|---|---|---|
| `role_id` / `user_id` | 角色与用户关系 | 联合唯一；双外键 |
| `status` | ACTIVE、DISABLED | 仅 ACTIVE 生效 |
| `effective_at` / `expires_at` | 可选有效期 | 开始必须早于结束 |
| 时间字段 | 建立与变更时间 | 不承载权限字段 |

### 4.6 `iam_role_permission`：角色权限表

| 字段 | 业务含义 | 约束 |
|---|---|---|
| `id` / `role_id` / `menu_id` | 角色对菜单的授权 | 必填；三者必须属于同一系统 |
| `permission_type` | `MENU` 或 `ACTION` | MENU 时 `menu_action_id` 为空；ACTION 时必填 |
| `menu_action_id` | 页面操作授权 | 可空；若存在必须属于 `menu_id` |
| `status` | ACTIVE、DISABLED | 仅 ACTIVE 生效 |
| `version` / 时间字段 | 并发与审计基础 | 同角色、菜单、权限类型、操作不可重复 |

核心不变量：ACTION 权限不能单独赋予页面访问；只有角色同时拥有有效 MENU 权限时，ACTION 才生效。数据库约束与服务层均需验证同系统关系。

## 5. 非功能与安全要求

| ID | 要求 | 验证方向 |
|---|---|---|
| `NFR-401` | 认证主体只能来自服务端验证后的会话，客户端只提交 `system_code`，不得提交可信 `user_id` | 篡改 userId 不改变授权主体 |
| `NFR-402` | 系统隔离、角色状态、用户状态、绑定有效期、菜单/操作状态必须在服务端统一计算 | 契约与集成测试覆盖失效组合 |
| `NFR-403` | 权限查询和拒绝不得泄漏其他系统或未授权菜单/操作元数据 | 403 响应不含隐藏对象名称和 fixture |
| `NFR-404` | 数据库变更必须通过版本化迁移，具备唯一约束、外键、检查约束、索引、种子验证和回滚说明 | 空库创建、重复执行策略、异常回滚测试 |
| `NFR-405` | 运行文案、表名、API 和代码使用中性术语；来源项目名称只留在证据与转换层 | 正式实现扫描无来源专属名称 |
| `NFR-406` | 菜单读取失败时不得退化为“显示全部”；前端呈现可恢复错误，写操作默认拒绝 | 数据库/API 不可用测试 |

## 6. 范围边界

### In Scope

- 上述六类逻辑表及系统维度；
- 每系统菜单分区、层级和页面操作目录；
- 用户—角色—权限链；
- 默认系统管理角色与 admin 角色成员种子；
- 登录后按目标系统返回授权导航与操作；
- 服务端菜单/操作权限校验；
- PostgreSQL 迁移、Prisma 模型、种子和前后端契约（需后续 Gate）。

### Out of Scope

- 表级、行级、字段级、组织级数据权限；
- 用户直接授权；
- 复制参考项目的租户、组织、外部平台、兼容字段和超级管理员旁路；
- 完整权限管理 UI、审批流、SSO、MFA、密码找回和生产部署；
- 自动把候选晋升为 `_methodology/` 正式模板。

## 7. SQL 目录约定候选

若 Architecture Gate 选择工作台的 `typescript-enterprise-web` Profile（React + NestJS + PostgreSQL + Prisma），SQL 唯一迁移源建议放在：

```text
interaction-pattern-lab/
└── packages/server/
    └── prisma/
        ├── schema.prisma
        ├── migrations/
        │   └── <timestamp>_create_navigation_rbac/
        │       └── migration.sql
        └── seed.ts
```

- `schema.prisma`：当前数据模型；
- `migrations/**/migration.sql`：有序、不可改写的 DDL；
- `seed.ts`：系统管理角色、admin 用户、角色成员及演示门户菜单种子；
- 不在 `docs/scripts/`、前端目录或 `_methodology/` 再保存一份可执行 SQL，避免双事实源；
- 当前 Lab 仍是单包 React/Vite，以上目录只有在新版 Architecture Gate 批准工程升级后才创建。

## 8. 验收条件

| ID | 验收条件 |
|---|---|
| `AC-401` | 两个系统登记同名/同编码局部菜单后，用户选择系统 A 只收到 A 的授权树与操作 |
| `AC-402` | 用户只有角色 R1；新增/删除 R1 的菜单或操作权限后，重新请求即可反映，且没有个人授权记录 |
| `AC-403` | admin 通过系统管理角色获得菜单和操作；移除角色成员关系后不再具有权限，不存在账号旁路 |
| `AC-404` | 应用菜单与系统管理菜单分区返回；无权叶子和无可见后代分组不会泄漏 |
| `AC-405` | viewer 可访问资源页面但直接调用未授权维护/导出接口得到 403，数据不变 |
| `AC-406` | 数据库或权限服务不可用时页面显示可恢复错误，系统不会显示全部菜单或放行操作 |
| `AC-407` | 迁移在空 PostgreSQL 实例创建六类表、约束和索引；种子产生系统管理角色、admin 与显式角色权限 |
