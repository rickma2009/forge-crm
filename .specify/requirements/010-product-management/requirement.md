# 产品管理工作区需求说明书

> v1.1-rc1 · 2026-09-23 · 来源 REQSRC-058、REQSRC-062、REQSRC-066、REQSRC-069  
> 状态：推荐设计已获确认，Specification 待审阅；本文是产品管理当前完整需求，不是 Release 批准。

## 1. 目标与边界

产品是企业公共主数据，沿用既有 `md_product` 身份，不建立 CRM、商机或报价专属的第二套产品表。目标是在既有列表基础上形成可维护、可审计、可被报价稳定引用的产品工作区，并把附件沉淀为跨业务复用能力。

本期包含：产品列表和查询、弹窗新增、详情/编辑工作区、受控删除、产品定价、产品附件。产品审批、产品版本工程管理、汇率换算、价目表审批、对象存储云服务和附件在线预览不在本期。

## 2. 页面与导航

### PAGE-PROD-001 产品列表

- 继续位于“基本信息 / 产品管理”，保持客户列表同类的查询区、视图区、功能区和表格风格。
- 查询、分页和列配置沿用现有列表公共能力。
- 新增产品使用弹窗；保存成功后可直接打开新产品详情。
- 产品编码作为详情链接；查看和编辑均进入产品详情工作区，不再使用列表内编辑弹窗。
- 操作列采用与客户列表一致的图标按钮：查看使用眼睛图标、编辑使用铅笔图标；图标按钮必须保留可访问名称和悬浮说明，不显示“查看/修改”文字。
- 有权限时显示查看、编辑、删除操作；无权限时不显示对应操作，直接 API 仍必须拒绝。

### PAGE-PROD-002 产品详情

产品详情在应用工作区中打开，页签标题为“产品详情”，不在标题重复显示产品名称。内部固定三个页签：

1. 产品信息：展示既有产品编码、名称、型号、单位、产品线、状态和备注等字段；查看态可切换编辑态，保存/取消行为与客户详情一致。
2. 产品定价：展示及维护该产品的价格版本与阶梯明细。
3. 附件：嵌入通用附件组件，归属类型为 `PRODUCT`、归属 ID 为产品 ID。

详情内容区必须与现有客户详情使用同一交互语言：

- 顶部左侧是仅显示返回箭头的按钮；其右侧第一行显示产品名称和状态标签，第二行至少显示“产品编码”，并可并列显示型号、产品线等识别信息。
- 右侧集中显示编辑、删除等当前角色获权操作；编辑态的取消和保存也位于该动作区。
- 三个页签采用客户详情同款无外框、选中项蓝色下划线的样式，并提供 `tablist/tab/tabpanel` 语义及键盘左右切换。
- 产品信息查看态使用客户基本信息同款双列字段表单：标签在上、只读值位于浅色禁用输入框内；备注跨两列。进入编辑态后保持字段位置不跳动。

路由直接刷新时必须能根据产品 ID 恢复详情；无权或不存在对象分别返回明确的 403/404 页面状态。

## 3. 功能需求

### FR-PROD-001｜产品基础信息

- 复用既有产品主数据和租户内唯一产品编码；新增时由弹窗维护，编码创建后不可随意变更。
- 产品名称必填；单位、产品线等可报价条件沿用报价需求约束。
- 停用不等于删除：停用产品保留历史引用但不能加入新商机商品或新报价。
- 编辑使用乐观并发版本；冲突时拒绝覆盖并要求重新加载。

### FR-PROD-002｜受控删除

- 删除是独立权限和显式确认操作，不能由“编辑/维护”权限隐含获得。
- 服务端在提交删除的同一事务中执行最终引用校验，至少检查：商机商品、报价单明细和产品定价。前端预检查只能用于提示，不能替代服务端校验。
- 存在任一引用时返回业务冲突，响应包含引用类型和数量，不泄露用户无权查看的业务明细；产品不删除、关联数据不改变。
- 产品尚有附件时也拒绝删除，提示先删除附件，避免元数据或文件成为孤儿。
- 只有完全无引用、无附件且版本未冲突时才物理删除产品。删除不得级联删除商机、报价、价格历史或其他业务记录。
- 并发新增引用和产品删除必须由数据库事务及外键/约束共同保证，不能发生先检查后被引用仍删除的竞态。

### FR-PROD-003｜产品定价模型

- 每条价格记录属于一个产品，记录定价类型、币别、生效日期、失效日期、备注、创建/修改审计和不可变价格版本。
- 定价类型只有：`STANDARD`（标准）和 `TIERED`（阶梯）。同一价格版本只能选择一种类型。
- 标准定价保存一个非负单价，不保存阶梯行；阶梯定价保存一组数量下界、可空上界和非负单价，头部单价为空。
- 阶梯数量支持最多四位小数，采用左闭右开区间，第一段从 0 开始、相邻段连续不重叠、最后一段无上限；实际报价数量必须大于 0。
- 币别使用 ISO 4217 三字母代码；首期只初始化并允许 `CNY`，不做汇率换算。
- 生效日期必填；失效日期可空且不得早于生效日期。同一产品、币别的有效价格区间不得重叠。
- `当前是否有效`是只读派生状态：记录未作废，且业务日期位于生效/失效区间内。不能由客户端直接修改独立布尔值。
- 调价新增版本，不覆盖已被报价引用的历史版本；修正未被引用且尚未生效的草稿价格是否允许，留到 Architecture Plan 明确定义，默认仍新增版本。

### FR-PROD-004｜报价取价契约

- 报价取价以报价单的`报价日期`为业务日期，而不是浏览器时间、服务器当前时间或简单的最新版本。
- 匹配条件为：同产品、同币别、已发布/可用、生效日期不晚于报价日期，且失效日期为空或不早于报价日期。
- 标准定价直接返回单价；阶梯定价再按该报价行自身数量匹配区间，同产品多行不合并数量。
- 无有效价格、存在重叠有效价格或阶梯无命中均为配置错误，阻止自动取价和报价提交，不静默使用最新价或零价。
- 报价行保存产品快照、价格记录 ID、命中阶梯、建议单价和成交单价；后续调价不改变历史报价。显式重新取价时仍使用报价日期并展示差异后确认。

### FR-PROD-005｜通用附件能力

- 公共附件能力由统一服务和组件提供，业务页面传入归属类型、归属 ID 及授权动作，不为产品另写一套上传页面。
- 通用表格至少展示：文件名、附件类型、文件版本、附件说明、文件大小、首次上传时间/人、最后修改时间/人和操作。
- 统一支持上传、下载、修改附件说明和文件版本、删除。上传和编辑使用弹窗；删除必须确认。
- 后端同时校验附件动作权限和归属对象访问权，不能仅依赖前端传入的权限布尔值。
- 附件元数据至少包含：ID、租户、应用、归属类型、归属 ID、原始文件名、附件类型、MIME 类型、文件大小、内部存储键、首次上传时间/人、最后修改时间/人、附件说明、可空文件版本。
- 归属类型使用受控枚举/登记册，首个值为 `PRODUCT`；服务端按归属类型验证对象存在和可访问，禁止任意字符串形成不可追溯弱引用。

### FR-PROD-006｜文件存储与安全

- 文件不存数据库，不放在 Vite/Nest 可直接公开的静态目录。存储根目录通过环境变量配置，本地默认使用项目运行数据目录下的 `var/attachments`，并加入 Git 忽略。
- 存储键格式：`<owner-type>/<yyyy>/<mm>/<owner-id>/<attachment-id>/<safe-file-name>`。业务类型形成子目录，同时用附件 ID 防止重名覆盖。
- 数据库保存相对存储键，不保存开发机绝对路径；下载地址由鉴权 API 动态生成，例如 `/api/systems/:systemCode/attachments/:id/download`。
- 上传校验文件名、扩展名、MIME、大小和路径穿越；文件名必须安全化但保留原始显示名。初始大小上限作为配置项，Plan 推荐默认 20 MiB。
- 元数据与文件写入失败必须补偿清理；删除先进行权限/版本校验，再删除元数据和物理文件，部分失败须可重试并留下可诊断记录。

## 4. 权限与审计

至少区分：产品查看、新增、编辑、删除，价格查看、价格维护，附件查看、上传、编辑说明、删除、下载。管理员按角色获得权限，不按用户名特判。

价格新增/失效、产品删除尝试、附件上传/编辑/删除/下载记录主体、时间、对象和结果；日志不记录文件正文、Token 或服务器绝对路径。

| ID | 关联需求 | 可观察通过条件 |
|---|---|---|
| AC-PROD-001 | FR-PROD-001 | 新增仍为弹窗；列表查看/编辑为图标按钮；编码链接打开可刷新恢复的三页签详情；顶部、页签和双列字段与客户详情一致；编辑冲突不覆盖 |

## 6. 未决但不阻断 Specification 的技术项

- 物理表、索引、日期排他约束和存量价格迁移策略在 Architecture Plan 确认。
- 附件默认 20 MiB、允许类型白名单和本地文件存储为首期推荐配置；未来可替换为对象存储，但不改变组件与业务 API 契约。
- 本需求不批准直接修改既有报价数据；迁移必须可回滚并验证历史建议价及报价快照不变。
