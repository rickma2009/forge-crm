# 商机管理需求说明书——报价与商品定价增量

> v1.1-rc1 · 2026-09-23 · 来源 REQSRC-062、REQSRC-066  
> 状态更新：后续 REQSRC-063 已委托按推荐连续开发与测试；本稿作为切片 022 业务基线，实施证据见该切片 review.md。不是独立 Release 批准，原文事实和项目推荐仍区分记录。
> 既有商机基线继续见 [原需求](../requirement.md)。本增量将“报价”从后置范围提入本次实施范围，不包含合同、订单、审批。
> 2026-09-23 产品工作区增量重新打开定价相关 Specification：有效价格改为按报价日期匹配，不再简单取最新版本；完整产品侧规则见 [产品管理工作区需求](../../010-product-management/requirement.md)。

## 1. 痛点与目标

最新页面行为修订（REQSRC-QUO-UI-001）：报价查询仅展示“单号/标题、状态”，查询和重置按钮桌面同行；明细新增/编辑统一弹窗，确认才应用、取消不影响原行。覆盖下文初稿中冲突的多条件查询/行内编辑描述，其他商业规则不变。实现与验证见切片 022 的 query-line-dialog-increment.md。

| 痛点 | 本次目标 | 不改变的边界 |
|---|---|---|
| 商机商品行用于销售预测，缺少正式对客报价单及流转历史 | 商品取价 → 主从报价单 → 提交 → 客户反馈 → PDF 的闭环 | 商机商品行不变成报价行、不自动互相同步 |
| 产品无标准价与阶梯价，出价依据难以追溯 | 按单行数量给出建议价，保留人工覆盖及价格来源 | 不做渠道价、多币种、折扣审批 |
| 报价接受与商机预测金额脱节 | 明确选择一份已接受报价，审计回写预签金额 | 不自动改变商机阶段、赢率、把握度、状态或赢丢单结果 |

成功验收以第 7 节可观察结果为准；效率、采用率等业务目标值尚无来源，不虚构数值。

## 3. 对象与定位

“产品”和原文“商品”在本项目统一指现有产品主数据。**推荐复用现有产品清单，不建立第二套同义商品库**；这是相对原文“独立商品库”的显式适配选择，见 Q-QUO-001。

```text
既有产品 ── 定价配置（标准价、阶梯价）
    └─────────── 报价行（保存快照）
既有客户 ── 报价单 ── 多条报价行
    └── 既有联系人 ↗
既有商机 ── 可选关联报价单 ── 已接受后显式回写预签金额
    └── 原商机商品行保持独立
```

报价单归销售报价业务所有，可独立归属客户，无商机也能创建；在商机入口创建时必须关联该商机。商机只是业务入口和关联对象，不是所有报价单的必选父对象。

## 4. 系统功能

### PAGE-QUO-001 产品及定价维护

入口：既有产品管理中的“销售定价”操作/页签；使用角色为具备产品维护、价格维护权限的内部人员，权限分别判定。

#### FR-QUO-001｜【修改】【P0】可报价产品

- 复用现有产品 ID、编码、名称、型号、单位、产品线和启停状态；ID/编码不因本增量重建。产品名称必填，型号可空。
- 当前有效规则（REQSRC-QUO-NO-LINE-20260924）：引用产品只检查同租户内产品存在且启用，不以单位、产品线是否填写作为引用门槛；报价有效价格校验另行保留。此前要求补齐启用产品线的规则已废弃。
- 报价引用产品与产品线字典无关联约束；不查产品线字典，不要求补齐/映射产品线。既有产品线仅作可选历史快照，不新增关联关系。
- 产品停用不可新选，已提交历史报价继续显示快照。草稿提交时再校验产品可报价条件；原报价复制的新草稿若含失效产品，标识待替换并阻止提交。

#### FR-QUO-002｜【修改】【P0】带有效期的标准价与阶梯价

- 每条产品价格版本必须选择标准或阶梯一种定价类型，保存币别、生效日期、可空失效日期和备注。首期只允许人民币 `CNY`，含税、非负、两位小数；不实现汇率换算。
- 标准定价保存一个单价且无阶梯；阶梯定价由数量下界、可空数量上界和含税单价构成，头部单价为空。保存一整组配置时检查区间合法性，失败全部不生效。
- 不重叠、不留缝及数量精度按 Q-QUO-002 推荐：数量支持最多四位小数；启用阶梯时覆盖全部正数量，内部使用左闭右开区间，首段下界为 0（实际数量仍必须 >0），末段无上限。如 `[0,10)`、`[10,50)`、`[50,+∞)`，避免“1–9”对 9.5 数量无定义。
- 阶梯配置出现无命中视为配置错误并阻止提交，不默默回退其他版本或零价。若业务希望只对部分数量区间优惠，应另立需求，不放宽连续覆盖规则。
- 生效日期必填，失效日期不得早于生效日期；同产品、币别的有效日期区间不得重叠。“当前是否有效”按记录状态和业务日期派生，不接受客户端写入独立布尔值。
- 价格修改保留操作者、时间及不可变版本；支持当前和未来生效日期，不改写已被报价引用的历史版本。本期仍不做定价审批或客户专属价目表。

#### FR-QUO-003｜【新增】【P0】建议价与人工覆盖

- 选商品、修改报价日期或改变本行数量时，先按报价日期匹配唯一有效价格版本，再计算标准价或命中阶梯价；同商品两行独立匹配，不合并数量。
- 建议单价只读展示，标记“标准价/阶梯价”，可查看命中范围和取价版本；成交单价初始等于建议价，销售可手改，二者分开保存。
- 推荐数量变化时重算建议价：成交价仍为自动跟随状态则一起更新；已经人工覆盖则保留并提示差异，不静默覆盖用户输入。更换商品时重新取价。
- 报价行保存价格版本 ID、命中阶梯及建议/成交价快照。保存、提交、重开草稿不会因后台改价而悄悄重算；显式“重新取价”仍按该报价的报价日期计算，展示前后差异并确认。提交前发现价格版本失效或配置冲突时阻止提交。
- 建议价与来源必须由系统可信计算；不能信任客户端传入的只读值。用户可编辑的是成交单价，而不是伪造取价来源。

### PAGE-QUO-002 报价列表与主从详情

入口：“商机管理 / 报价管理”以及商机详情内的关联报价入口；客户详情不提供关联报价入口或内嵌报价列表。报价详情打开工作区 Tab；短表头新建可用弹窗，主从编辑在详情页完成。

#### FR-QUO-004｜【新增】【P0】查询、新建与单号

- 查询报价单号/标题、状态；列表分页，详情和导出沿用同一可见范围。
- 报价 ID、单号系统生成，只读；单号按原文全局唯一，不能仅凭当前列表最大号生成或从浏览器生成。格式待 Q-QUO-009，唯一性不得降为仅应用内唯一。
- 从客户进入预填客户；从商机进入必须写入商机关联且客户保持一致，客户/商机关联不可因隐藏字段而省略。
- 创建弹窗确认即落库：客户由所选商机或客户确定，标题、日期、有效期由系统初始化后可编辑，允许暂时无行；提交必须至少一条完整有效报价行。

表头信息：

| 字段 | 规则 |
|---|---|
| 单号、ID | 系统生成；ID 不必展示 |
| 标题 | 必填 |
| 客户 | 必填，引用当前客户，不另造客户档案 |
| 关联商机 | 独立报价可空；商机入口必填；客户必须匹配 |
| 联系人 | 可空，必须属于客户；创建后客户与商机关联不可更改 |
| 报价日期 | 必填，默认业务时区的当天 |
| 有效期至 | 必填、不早于报价日期；规则见 Q-QUO-006 |
| 币种、税口径 | 人民币、含税单价；不新增单独税率计算 |
| 负责人 | 推荐默认创建人，用于独立报价的数据范围；授权规则见 Q-QUO-008 |
| 报价总金额 | 各行小计之和，只读 |
| 备注、报价条款 | 可空；条款进入对客快照，内部备注是否导出按 Q-QUO-010 |
| 状态、创建/更新时间、版本 | 系统维护，不允许通用编辑直接改状态 |

#### FR-QUO-005｜【新增】【P0】报价行网格与金额

- 支持从启用且可报价产品选择新增行、追加同商品多行、编辑、选中删除、排序；删除仅作用于草稿，明确确认，不连带删除产品。
- 每行保存稳定身份和展示行号；插入/删除后可重排行号，但不能用当前序号当记录身份。
- 行字段：商品引用、产品编码/名称/型号/单位快照、数量、建议单价、取价来源、成交单价、折扣率、行小计、交付时间、行备注；数量 >0，成交单价 ≥0。
- 推荐折扣率界面按“优惠百分比”输入，空值为 0，范围 0%～100%、最多两位小数；10% 表示优惠 10%，不是支付一折。具体精度、零金额规则见 Q-QUO-003。
- `行小计 = round(数量 × 成交单价 × (1 − 折扣百分比 ÷ 100), 2)`；`总金额 = 已逐行舍入的小计之和`。推荐十进制四舍五入 HALF_UP；金额不能以二进制浮点近似值作为权威结果。
- 后端重新校验和计算，客户端篡改总额不生效。错误定位到具体行/字段，保留未保存内容；弹窗发起的错误按公共弹窗规则在弹窗内展示。

#### FR-QUO-006｜【新增】【P0】快照及冻结

- 选商品时保存名称/型号快照（原文要求）；推荐扩展为编码、单位、产品线、价格配置版本、命中范围、建议价、成交价、折扣等完整报价依据。
- 客户/联系人抬头、报价条款、日期等对客信息也保存快照，避免改名后旧 PDF 内容漂移；内部 ID 继续用于关联和授权。
- 已提交后报价行不可改；推荐同时冻结所有商业表头字段，状态、操作日志和回写记录通过受控操作追加，不覆盖已提交内容。该扩展见 Q-QUO-005。
- 不沿用当前商机商品“整体删除后重建、重新取产品名称”的保存逻辑；报价须保留行身份和历史报价依据。

#### FR-QUO-007｜【新增】【P0】状态及失效

| 当前状态 | 允许操作 | 目标状态与条件 |
|---|---|---|
| 草稿 | 编辑、提交 | 提交校验完整行、可报价产品、归属、权限和有效期后变为已提交 |
| 已提交 | 记录客户接受 | 未超过有效截止点，变为已接受 |
| 已提交 | 记录客户拒绝 | 未超过有效截止点，变为已拒绝 |
| 已提交 | 自动失效 | 超过有效截止点，变为已失效 |
| 已接受/已拒绝/已失效 | 查看、导出、复制新报价 | 原单保持终态；已接受且有关联商机可发起受控回写 |

- “客户接受/拒绝”是业务事实；推荐本期由被授权内部人员登记反馈时间、记录人及说明，不假设已存在客户门户或客户本人认证。
- 原文“过期未接受均失效”与流程图“仅已提交失效”不完全一致。推荐只有已提交自动失效；过期草稿仍是草稿，但必须调整有效期后才能提交（Q-QUO-006）。
- 推荐 Asia/Shanghai 时区，有效期至当日全天有效，次日 00:00 起不可接受。接受与失效同时发生时以服务端当前时间和原子状态判定裁决；后台任务延迟不得允许过期接受。
- 后台任务可重试，重启后补扫；重复请求不能产生多次转换或重复审计。不存在撤回、取消、重开终态等未定义状态。

#### FR-QUO-008｜【新增】【P0】复制新版本

- 已提交需修改，以及任一终态需要重报时，生成新的报价 ID/单号和草稿，保存“来源报价”及版本链；原单不修改。
- 推荐先复制原内容及价格作为待检查草稿；日期、有效期重新确认，停用产品/失效联系人突出标记，用户可显式重新取价。新单未校验完整不得提交。
- 不因新单创建或接受，自动使旧单失效或替换旧单客户决定；同一商机多个已接受报价如何选择回写见 Q-QUO-007。

#### FR-QUO-009｜【新增】【P0】PDF

- 对客 PDF 至少含正式单号、标题、客户/联系人快照、日期/有效期、产品及单位数量、成交单价、折扣、行小计、总额和报价条款；实际版式与出具主体信息见 Q-QUO-010。
- 草稿导出推荐明确“草稿”水印；失效、拒绝单据不得伪装成有效报价。导出不隐含发送给客户、客户接受或审批。
- 输出依据报价快照，不重新读取产品当前价计算；不输出内部用户 ID、权限信息、内部备注等未批准对客字段。
- PDF 与页面同权限；中文字体、多页表格重复表头、页码、长备注和金额对齐必须验收。生成失败不修改单据状态，提示后可重试。

### PAGE-QUO-003 商机关联报价

#### FR-QUO-010｜【修改】【P1】关联入口

- 推荐在商机详情增加第 4 个一级 Tab“报价单”，保留现有“商机信息、跟进记录、商机分析记录”及商品行；这是对旧“固定三个 Tab”的显式增量，不偷换原页签内容。
- 展示该商机关联且用户可见的报价，支持“新建报价”“打开报价”；不以查看商机权限替代报价权限。
- 客户详情不提供“关联报价”入口或内嵌报价列表，保留基本信息、联系人、地址操作。此项依据 2026-09-23 用户变更，替代原客户关联区入口要求；独立报价管理和报价数据不受影响。来源：`.specify/sources/customer-detail-remove-quotation/source.md`。
- 创建关联报价时一次性导入商机产品，后续原商机商品和报价行不互相覆盖或自动同步；报价单可独立进入列表/详情。

#### FR-QUO-011｜【新增】【P1】手动回写预签金额

- 仅已接受、有关联商机、客户一致且双方记录均有权操作时可用；独立报价不能凭任意商机 ID 直接回写。
- 确认界面展示报价单号、报价总额、当前预签金额、差额、此前金额来源；确认后只替换预签金额，不自动累加多份报价。
- 保持商机商品行、客户预算、阶段、阶段赢率、把握度、状态、分析记录及赢丢单结果不变。
- 同时校验报价和商机版本；回写金额、商机版本及回写来源记录原子成功，冲突则全部不改并提示重新加载。
- 同一请求重试幂等。若商机金额后来被其他操作修改，不因旧请求重试再次覆盖；重新回写需要新的确认和当前版本。
- 推荐多个已接受报价由用户选择一份替换；后续手动修改预签金额要保留修改记录并显示当前来源，不继续把旧报价标签当当前来源（Q-QUO-007）。

#### FR-QUO-012｜【新增】【P0】权限、审计与异常

- 动作至少区分：价格查看/维护，报价查看/新建/编辑草稿/提交/记录反馈/复制/导出/回写；复用当前 RBAC，不把“有菜单”当全部按钮授权。
- 推荐独立报价按负责人及角色批准范围可见；关联商机报价取“报价范围 ∩ 商机范围”。列表、详情、客户/商机关联列表、导出和直接 API 一致，拒绝跨租户/应用及越权 ID。
- 价格维护人员可不具备报价接受权限；查看产品不自动获得价格维护权限。超级管理员身份不在业务页面通过账号字符串特判。
- 审计保留定价变更、人工改价、提交/反馈/失效、复制、PDF 导出及金额回写的主体、时间、对象与必要差异，不写密码/Token或完整敏感请求体。
- 草稿保存、提交、反馈、回写支持乐观并发和可重试失败；任何失败不得留下半张报价、错总额或“已接受但写回记录丢失”。普通页面不物理删除有审计价值的历史报价。
