# 商机报价增量：决策与澄清

日期：2026-09-23。状态更新：REQSRC-063 已委托按推荐继续实施，Q-QUO-001—010 纳入切片 022；初稿时为待批准建议。外部原文“已确认”“待确认：无”不等于本项目批准；本次依据是独立的用户持续实施指令。

## 保留的来源要求

不做渠道价、不做报价审批、不按同商品多行合并数量匹配阶梯；必须导出 PDF；商机内创建报价必须关联该商机；接受报价不自动推进商机阶段。这些要求纳入本次评审基线。

## 推荐决策

| 编号 | 原文及现状问题 | 本项目推荐答案 | 影响与批准点 |
|---|---|---|---|
| Q-QUO-001 | 原文基于“无商品主数据”；当前已有 md_product，单位和产品线可空 | 复用产品主数据，不再新建商品库。销售定价独立负责；产品线接数据字典，报价可用产品要求单位、产品线完整。存量空值保留并列为待完善，不伪造补值 | FR-QUO-001/002；Business 批准复用边界，Spec 明确字典和兼容规则 |
| Q-QUO-002 | 1–9、10–49 的整数样例不能覆盖当前允许的小数数量 | 数量最多四位小数；阶梯可不配置，使用标准价；配置时覆盖全部正数量，采用连续左闭右开区间，如 [0,10)、[10,50)、[50,+∞)。零仅为边界，购买数量必须大于零；最后一段无上限 | FR-QUO-002/003；Business 批准计价边界；不默认支持部分区间回落标准价 |
| Q-QUO-003 | 折扣单位、舍入与数量精度未定义 | 折扣用百分数 0–100，最多两位小数，空值为 0；金额两位，数量四位；逐行 HALF_UP 后求和。允许零价/100% 折扣，但明确显示，保留改价审计；服务端 Decimal 计算 | FR-QUO-003/005；Business 批准零价和折扣语义，Spec 定义上限/溢出 |
| Q-QUO-004 | 修改数量、价格调整、手工成交价之间缺少优先级 | 建议价始终展示来源及版本；数量改变重算建议价，手工成交价不被静默覆盖。主动重新定价需确认。提交时若参考定价版本已变更，明确选择保留原价或刷新，并留痕 | FR-QUO-003/006；Business 批准历史价格保留策略；Spec 定义来源校验 |
| Q-QUO-005 | 原文只明确提交后明细不可改，未定义头部与草稿完整性 | 草稿可无明细，但满足最小表头；提交至少一行且字段全部有效。提交后客户、联系人、日期、条款等商业内容一起冻结，只允许专用状态操作。变更复制为新单据，不覆盖旧版本；停用商品在新单提交前必须替换 | FR-QUO-004/005/006/008；Business 批准冻结边界；Spec 定义字段长度、必填与复制清单 |
| Q-QUO-006 | 文本“过期未接受”与状态图“已提交→过期”不完全一致 | 仅已提交自动过期，草稿不转过期，但不能以过期有效期提交。Asia/Shanghai 有效截止日含当天，次日 00:00 截止；接受操作实时判断时间，不能依赖定时任务是否已运行 | FR-QUO-007；Business 批准日期口径 |
| Q-QUO-007 | 一个商机多份已接受报价如何回写未定义 | 用户明确选择一份，以总额替换预签金额，不累加；显示旧值/新值并确认。报价与商机版本校验、金额更新、回写事件在同一事务完成，幂等重试不再次覆盖。阶段、结果、预算和商品行不变 | FR-QUO-011；Business 批准替换语义；Architecture 明确跨模块事务责任 |
| Q-QUO-008 | 接受者身份和对象级权限未定义 | 本期由获授权内部用户登记客户接受/拒绝，不建设客户门户。报价默认负责人为创建人；关联商机需同时满足报价与商机的可见/操作范围。查看价格、维护价格、提交、反馈、导出、回写分别授权 | FR-QUO-012；Business 明确角色责任，Spec 给出角色×动作×对象范围矩阵 |
| Q-QUO-009 | “全局唯一”无编号格式；当前产品编码实际仍手输 | 报价编号服务端分配，建议 Q+日期+递增流水；采用数据库唯一约束及并发安全分配，不用 max+1。产品内部 ID 与业务编码分开；现有产品编码自动化属于既有商机缺口，报价不重复实现一套 | FR-QUO-004；Business 接受编号方向，Spec 明确流水容量、跨日与失败重试 |
| Q-QUO-010 | PDF 出具方、品牌、内部备注及法律性文字未定义 | 本期单一模板，客户可见字段白名单，排除内部成本/建议价来源/内部备注；草稿水印，历史报价按商业快照生成，状态另外标示。出具方名称、联系方式、条款文本使用经确认的项目配置，不编造企业信息 | FR-QUO-009；Business 确认对外内容范围，Specification Gate 前确认模板样例和配置来源 |
