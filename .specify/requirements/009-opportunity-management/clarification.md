# 澄清与推荐决策

> 状态：`recommendations-awaiting-business-decision`

| ID | 决策主题 | 推荐答案 | 影响 |
|---|---|---|---|
| `Q-1701` | “公共”模板阶段 | 沿用旧基线六阶段：初始线索、客户需求确认、技术认可、报价、商务谈判、合同签订 | 阶段名称有来源，可直接形成候选 Seed |
| `Q-1702` | 阶段赢率及招投标阶段 | 公共阶段建议 10/25/40/60/80/100；招投标建议“项目发现、资格预审、报名立项、投标文件、开标评标、中标/合同”及 10/25/40/60/80/100 | 百分比和招投标阶段在现有材料中没有事实依据；批准前只作为推荐值 |
| `Q-1703` | 产品编码 | 服务端生成 `PYYYYMM####`，页面只读；产品名称不强制唯一，编码租户内唯一 | 与客户编码体验一致，避免名称相同型号不同导致冲突 |
| `Q-1704` | 产品线来源 | 首期复用当前数据字典 `product_line`，产品线可空；不额外建设产品线管理表 | 控制首批范围，后续需要属性时再升级主数据 |
| `Q-1705` | 分析记录修改/删除 | 分析记录追加后不可编辑和删除；纠错通过新增一条分析说明 | 保留分析会判断过程，避免静默改写历史 |
| `Q-1706` | 商机数据范围 | 负责人本人可见；部门负责人按角色数据策略看本组织及批准下级；系统管理员全部可见 | 复用现有角色数据策略，不把范围固化在前端 |
| `Q-1707` | 已创建商机切换模板 | 允许切换，但必须在同次保存中选择新模板的有效阶段并二次确认；不自动猜测阶段 | 避免旧阶段与新模板不一致 |
| `Q-1708` | 同一商品重复行 | 允许同一产品出现多行，每行可有不同价格、数量和需求说明 | 延续旧基线，适应分批/不同配置报价 |
| `Q-1709` | 把握度 | 0～100 整数，快速新建默认 0，可在详情和分析中修改 | 0 表示尚未形成主观把握，不与阶段赢率联动 |
| `Q-1710` | 阶段维护页面顺序 | 首先完成专用表、Seed 和只读选择；核心商机闭环后再交付维护 UI | 降低首个纵向切片范围，不妨碍后续灵活配置 |
| `Q-1711` | 旧基线赢丢单与批量转交 | 保留为后续 P1，不进入本次三个详情 Tab 的首批开发 | 避免把未再次明确要求的旧范围静默并入当前交付 |
| `Q-1712` | 商机物理表缩写 | 商机聚合内所有表统一使用 `sd_opp*`：`sd_opp`、`sd_opp_template`、`sd_opp_stage`、`sd_opp_product`、`sd_opp_follow_up`、`sd_opp_analysis`、`sd_opp_analysis_competitor` | 用户要求统一使用 `opp`；独立产品和竞争对象仍为 `md_product`、`sd_competitor` |

`REQSRC-060` 已批准 `Q-1701`—`Q-1712` 的推荐答案并授权连续本地实现；阶段 Seed 使用上述推荐值，真实验证完成前不得声明 Release。
