# 全量演示数据重建当前需求

来源：`REQSRC-106`。本需求只管理测试系统演示数据，不改变生产数据、权限模型或业务状态机。

- `REQ-DEMO-01`：执行清理前生成可恢复的 PostgreSQL 自定义格式备份，记录备份位置和重建批次。
- `REQ-DEMO-02`：保留并使用最新组织、员工账号关联、物料分类、001 产品、004 物料和规范 BOM；删除其他旧业务演示数据，以及引用旧业务对象的助手会话、活动、协作、建议和待办数据。
- `REQ-DEMO-03`：产品物料只接受正式编码；临时编码、临时物料及其 BOM 不导入。物料产品名称唯一、包含关键配置且不超过 30 个字符。
- `REQ-DEMO-04`：按当前规则生成客户、员工、商机、报价、销售订单、入库和销售出库编码，并同步持久化计数器。
- `REQ-DEMO-05`：客户类别与状态组合、商机业务状态与阶段、报价状态、订单状态、入库状态与类型、出库状态各至少 5 条。
- `REQ-DEMO-06`：报价和订单主从金额一致；BOM 只引用启用物料；库存余额等于库存流水净额；员工均具有有效雇佣和主职任职关系。
- `REQ-DEMO-07`：重建脚本、来源 Excel、结果报告和只读验证 SQL 统一保存在 `demo_data/`。

## 验收标准

- `AC-DEMO-01`：备份可被 `pg_restore` 读取；重建失败时可恢复重建前关键表数量。
- `AC-DEMO-02`：客户、员工和全部业务单据编码正则检查无异常，计数器等于本次最大流水。
- `AC-DEMO-03`：70 条产品、444 条物料全部启用且分类完整，名称重复数和超过 30 字符数均为 0；24 个 BOM 引用有效。
- `AC-DEMO-04`：各要求状态、类型和阶段的最小数据量不低于 5。
- `AC-DEMO-05`：员工关系缺口、报价金额差、订单金额差、库存余额差均为 0。

验证等级：L3。原因是本次包含跨模块批量删除、数据迁移、数据库约束和恢复操作。用户已明确授权执行，无新增产品 Gate；验证证据以重建报告和数据库只读检查为准。
