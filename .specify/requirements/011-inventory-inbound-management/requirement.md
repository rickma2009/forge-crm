# 库存与入库管理完整需求

状态：已批准进入切片实现  
来源：REQSRC-070

## 1. 目标与范围

建立可审计的库存增加最小闭环：维护法人、仓库和统一物项；创建入库单；一次性过账时原子更新库存余额并生成库存流水；通过只读库存明细查询当前库存；错误过账通过整单冲销纠正。

本期包含：

1. `org_legal_entity` 法人主数据；
2. `scm_warehouse` 仓库主数据；
3. `md_item` 统一物项主数据，并迁移现有产品数据及引用；
4. 入库单列表、详情、表头和明细维护、过账、冲销、作废；
5. `scm_inventory_balance` 库存余额；
6. `scm_inventory_txn` 库存流水写入；
7. 库存明细只读查询、分页、视图配置和导出；
8. 菜单、角色动作权限和演示初始化数据。

本期不包含：出库、调拨出库、部分入库、多单位换算、库存占用/冻结、移动平均成本、审批工作流、库存流水查询页面。

## 2. 角色与权限

| 角色 | 权限 |
| --- | --- |
| admin / 系统管理角色 | 法人、仓库、物项维护；入库单查询、新建、修改、作废、过账、冲销；库存查询与导出 |
| viewer | 法人、仓库、物项、入库单和库存明细只读 |

权限必须由角色授权，不对个人直接授权。页面和按钮均以服务端授权结果为准。

## 3. 主数据

### 3.1 法人

法人归属一个管理组织，一个管理组织可以拥有多个法人。字段：法人ID、租户、管理组织ID、法人代码、法人名称、本位币、状态、显示序号、备注、版本及创建/修改审计字段。法人代码在租户内唯一、创建后不可修改。

### 3.2 仓库

一个仓库只属于一个法人。字段：仓库ID、租户、法人ID、仓库代码、仓库名称、仓库类型、仓库性质、状态、显示序号、备注、版本及审计字段。仓库代码租户内唯一、创建后不可修改。仓库类型、性质来自数据字典。

### 3.3 统一物项

`md_item` 取代 `md_product` 作为产品与物料的统一权威主数据。页面统一称“物料产品管理”，表单统一称“物料”。字段：`item_id`、租户、`item_code`、物料名称、物料类型、物料大类、物料中类、物料小类、型号、产品线、基本单位、是否批次管理、状态、备注、版本和审计字段。

物料大/中/小类来自数据字典“物料类别”的三级树并保持级联约束。管理页采用左类别树、右列表；左侧直接从大类开始显示，选择任一级均过滤该节点及其下级物料。新增仍使用弹窗，批次管理使用 Y/N 下拉；浏览和编辑通过物料编码进入三 Tab 详情：物料基本信息、物料定价、物料附件。

`item_code`：租户内唯一，仅允许大写字母、数字、`-`、`_`，最长32字符，创建后不可修改。业务接口可使用 `item_code` 作为稳定的用户可识别编码，但依赖表必须保存 `item_id` 外键；交易记录同时保留物料编码和名称快照。产品页面改为物料产品页面的产品过滤视图；旧产品、定价、报价和商机引用必须完整迁移并验证。

## 4. 单据编码

统一规则：`单据前缀 + yyyyMMdd + 5位日流水`。流水按租户、单据类型、业务日期每日归零；数据库保证租户内单号唯一。入库单前缀为 `RK`，示例：`RK2026092400001`。编号由服务端生成，不允许用户修改。

## 5. 入库单

### 5.1 表头

字段：内部ID、租户、应用、入库单号、制单日期、制单人、入库类型、单据状态、过账时间、过账人、冲销时间、冲销人、入库仓库、入库法人、工厂代码（可空受控预留）、入库原因、币种、备注、版本及审计字段。

入库类型：生产入库、成品入库、调拨入库、盘盈入库。调拨入库在完整调拨链路上线前不可选择。

状态：`DRAFT` 草稿、`POSTED` 已过账、`REVERSED` 已冲销、`VOIDED` 已作废。

### 5.2 明细

字段：内部ID、入库单ID、行序号、`item_id`、`item_code`、物料名称快照、批次、原单数量、实际入库数量、实际入库单位快照、入库金额、备注和审计字段。`item_id` 用于强关联，页面只展示物料编码与名称。

草稿允许新增、修改、删除行；其他状态只读。同一单据内相同物项和同一规范化批次不得重复。

## 6. 校验规则

- 法人、仓库和物项必须启用，仓库必须属于所选法人；
- 单据至少一行；实际数量大于0，金额大于等于0；零金额必须填写原因；
- 批次管理物项必须填写批次；非批次物项批次为空；
- 单据币种必须等于法人本位币；
- 原单数量可空；若与实际数量不同，必须填写入库原因或行备注；
- 单据只允许一个仓库和一次整体过账，不允许部分或多次入库；
- 停用主数据不能用于新单或过账，但历史单据仍可查看。

## 7. 过账、余额与流水

过账必须在单个 Serializable 数据库事务内完成：锁定并校验草稿和明细；把状态改为已过账；按租户、法人、仓库、`item_code`、批次原子新增或累加库存数量和金额；为每一行生成一条正数量、正金额流水；写入审计与幂等事件。

库存余额唯一键为：`tenant_id + legal_entity_id + warehouse_id + item_code + batch_no`。空批次采用数据库“NULLS NOT DISTINCT”等价约束，保证只有一条余额。

库存流水保存：来源类型、来源名称、来源单据ID、单号、来源行ID、行号、物项编码、物项名称快照、数量、金额、批次、仓库、法人、币种、备注、发生时间、操作者。入库为正，冲销为负。来源单据行和动作组合必须唯一，重复请求不能重复记账。

## 8. 冲销与作废

草稿“删除”实际变更为已作废并保留审计。已过账单据不可编辑或删除，只允许整单冲销一次。冲销生成逐行反向流水并原子扣减余额；库存不足时拒绝冲销。冲销完成后原单状态为已冲销。

## 9. 页面与交互

菜单：基本信息下提供“物料产品管理”；库存管理下提供“入库单、库存明细”；系统管理下提供“法人管理、仓库管理”。库存流水页面本期不显示。

引用展示遵循数据库治理规范：入库单虽然保存法人、仓库和物料引用 ID/编码，页面列表、详情和选择回显必须展示法人名称、仓库名称、物料编码与名称，不得直接显示 UUID。

列表页面遵守 `UI-LIST-01`、`UI-LIST-VIEW-01`、`UI-BUTTON-01`。入库单号、物项编码、法人代码和仓库代码作为详情入口；操作列不提供查看按钮，编辑/作废/过账/冲销使用图标按钮和中文提示。

入库单详情采用统一详情工作区：顶部返回按钮、单号和状态；Tab 为“基本信息、入库明细”。行维护使用弹窗。库存明细只读，支持法人、仓库、物项编码、名称、类型、批次筛选、分页、视图配置和导出，并支持明细与汇总视图。

## 10. 精度、审计和非功能规则

- 数量 `numeric(18,4)`、单价 `numeric(18,6)`、金额 `numeric(18,2)`；API 使用十进制字符串；
- 时间戳使用 `timestamptz`，业务日期使用 `date`；
- 所有写操作采用版本号乐观锁；过账/冲销同时使用事务锁和幂等键；
- 所有物理表、字段为不超过32字符的小写 `snake_case`；
- 多租户请求不得跨租户读取或写入；
- 余额只能由库存记账服务修改，禁止普通 CRUD 直接编辑。

## 11. 验收标准

1. 重复或并发过账只产生一次余额变化和一组流水；
2. 事务任一步失败时状态、余额和流水全部回滚；
3. 相同物项不同批次分别计存，空批次只存在一条余额；
4. 冲销生成反向流水并恢复余额，且只能执行一次；
5. 停用法人、仓库或物项不能过账；
6. 迁移前后产品、定价、报价、商机引用数量一致且无孤儿数据；
7. viewer 不能看到写操作，服务端也拒绝越权调用；
8. 库存明细页面不存在新增、修改、删除库存入口；
9. 所有列表详情入口、图标操作、视图配置和按钮尺寸符合全局样式规范。

## 12. 物料详情动态路由（2026-09-24 当前有效补充）

来源：`REQSRC-072`。物料编码进入 `/showcase/items/{itemId}` 详情地址；浏览和编辑共享同一详情工作区，不把记录 ID 当成独立菜单资源。页面访问权限继承“物料产品管理”菜单 `/showcase/items` 的查看及操作权限，记录 ID 仅用于加载业务数据。合法且有权访问的详情地址不得因未逐条登记菜单而返回门户 404。

详情必须保持“物料基本信息、物料定价、附件”三页签。默认进入查看态；具有修改权限时在详情内切换编辑态，不另建编辑路由。
