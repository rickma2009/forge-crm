# 视图组合控件统一实施

来源：UIRULE-20260924-view-selector。明确要求三段对齐、所有相同设置统一、可传参组件化；没有待确认业务规则。

原因：旧view-controls子项32px与全局select最小34px冲突，客户和通用业务列表还重复维护相同结构。公共ListViewSelector统一border-box、height/min-height/max-height、边框/圆角；桌面32px，触控44px。参数控制选项、选中值、回调和禁用状态，数据/权限仍由页面负责。

两处重复实现全部替换：客户目录和BusinessDirectory，使用后者的商机/报价/产品/竞争对象列表自动复用。不强行给无视图配置的计数/刷新工具栏增加功能。规范UI-VIEW-CONTROL-01已进入总样式索引、项目模板、工作区模板、金标准说明及静态接入检查。

验证：12项测试通过（组件2、公共列表3、客户等页面7），修改文件ESLint与前端typecheck通过，规范引用/两处组件接入检查通过。Chrome客户/商机/报价三页1440px和390px逐一测量三段y与height相等、高度32px；截图和结果见evidence/view-selector-20260924。旧产品路由实际404，未计为浏览器通过，也未为测试修改权限或路由。

可复用：组合控件统一盒模型与参数化的权限/加载接口；产品对象名、视图权限和默认引用仍是业务配置，不能写死到组件。Specification按用户明确指令更新实施，无数据库/架构变化，未发布生产；全仓库既有CONTEXT布局问题不在本次修复范围。
