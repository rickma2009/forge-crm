# 库存与入库单 需求方案

> 状态：可开发
> 范围：法人组织、仓库、库存表、入库单（主子表 + 过账）、库存明细表查询。
> 本期不做：出库单、库存流水查询页（库存明细完成后再开发）、审批工作流。
> 入库单一次只入一个仓库（仓库在主表，不在行表）。

---

## 1. 对象与数据表设计

### 1.1 法人表 `legal_entity`

| 字段 | 说明 |
|---|---|
| id | 主键 |
| entity_code | 法人代码，唯一 |
| entity_name | 法人名称 |
| status | 启用 / 停用 |
| display_order | 显示序号 |
| created_at | 创建时间 |

- 一个管理组织下可有多个法人。停用法人不可再被新单据选用，历史单据保留。

### 1.2 仓库表 `warehouse`

| 字段 | 说明 |
|---|---|
| id | 主键 |
| warehouse_code | 仓库代码，唯一 |
| warehouse_name | 仓库名称 |
| warehouse_type | 仓库类型（固定枚举，先保留值） |
| warehouse_nature | 仓库性质（固定枚举，先保留值） |
| status | 启用 / 停用 |

- 停用仓库不可新选，历史保留。

### 1.3 库存表 `stock`（当前结存）

| 字段 | 说明 |
|---|---|
| id | 主键 |
| legal_entity_id | 法人 |
| warehouse_id | 仓库 |
| product_code | 产品/物料代码 |
| batch | 批次，可为空 |
| quantity | 库存数量，默认 0 |
| amount | 库存金额，默认 0 |

**聚合键**（决定是否新增一行还是累加）：
- 批次非空：`(法人, 仓库, 产品代码, 批次)`
- 批次为空：`(法人, 仓库, 产品代码)`

> 同一聚合键只允许一行；过账时按此键 upsert。

### 1.4 入库单主表 `inbound_order`

| 字段 | 说明 |
|---|---|
| id | 主键 |
| order_no | 入库单号，系统生成、唯一、只读 |
| order_date | 制单日期 |
| created_by | 制单人 |
| inbound_type | 入库类型：生产入库 / 成品入库 / 调拨入库 / 盘盈入库 |
| status | 单据状态：草稿 / 已过账 |
| posted_at | 过账日期（草稿为空） |
| posted_by | 过账人（草稿为空） |
| legal_entity_id | 入库法人 |
| warehouse_id | 入库仓库（单头唯一，整张单入一个仓库） |
| factory_code | 工厂代码，可空 |
| inbound_reason | 入库原因，可空（不同入库类型含义不同，先保留） |
| remark | 备注 |

### 1.5 入库单子表 `inbound_order_line`

| 字段 | 说明 |
|---|---|
| id | 入库行 ID，主键 |
| order_no | 所属入库单号 |
| line_no | 行序号 |
| product_code | 产品/物料代码 |
| product_name | 产品/物料名称（快照） |
| batch | 批次，可空 |
| order_quantity | 原单数量 |
| actual_quantity | 实际入库数量 |
| unit | 实际入库单位 |
| amount | 入库金额 |
| remark | 备注 |

### 1.6 库存流水表 `stock_ledger`

| 字段 | 说明 |
|---|---|
| id | 主键 |
| source_object_code | 来源对象编码，如 INBOUND / OUTBOUND / STOCK_GAIN / SCRAP |
| source_object_name | 来源对象名称，如 入库单 / 出库单 / 盘盈单 / 报废单 |
| order_no | 单号 |
| line_no | 行号 |
| product_code | 产品/物料编码 |
| quantity | 数量：入库为正，出库/消耗为负 |
| amount | 金额：与数量同号 |
| batch | 批次，可空 |
| warehouse_id | 仓库 |
| legal_entity_id | 法人 |
| remark | 备注 |

> 任何库存增减都必须写一条流水；流水只增不改不删。本期入库单产生正数量流水。

## 2. 入库单功能

### 2.1 状态机

```
草稿 ──审核过账──▶ 已过账（终态）
```

- **草稿**：可新建、修改、**物理删除**。
- **已过账**：只读，不可修改、不可删除。（如需冲销，以后做红冲/出库单，本期不做。）
- 没有审批工作流；点"审核过账"即直接置为已过账。

### 2.2 过账逻辑（必须在一个数据库事务内）

点击"审核过账"时：

1. 校验当前状态为草稿、至少有一行明细。
2. 更新主表：`status=已过账`、`posted_at=当前时间`、`posted_by=当前用户`。
3. 逐行处理入库行：
   - 在 `stock` 按聚合键（1.3）查找：
     - **存在**：`quantity += actual_quantity`，`amount += 行金额`；
     - **不存在**：插入新库存行（法人、仓库、产品、批次、数量=实际入库数量、金额=行金额）。
   - 同时写一条 `stock_ledger`：来源=入库单，单号、行号、产品、`quantity=+实际入库数量`、`amount=+行金额`、批次、仓库、法人。
4. 事务提交；任一步失败整体回滚，库存与流水保持一致。

> 关键不变量：库存表的数量/金额 与 流水表按同一聚合键的累计结果必须一致。

## 3. 页面

| 页面 | 功能 |
|---|---|
| 入库单列表/新建/编辑 | 新建、修改、物理删除草稿；点"审核过账"触发 2.2 |
| 库存明细表 | **只读查询**：按仓库、法人、物料（产品代码）筛选，**按 法人+仓库+物料 汇总**，不展开批次，显示当前结存数量与金额。不允许增改删——库存只能由出入库单驱动。 |
| 库存流水查询页 | **本期不开发**，等库存明细表完成后再做。 |

---

## 4. 验收要点

1. 草稿入库单可增改删（物理删除）；已过账后不可改不可删。
2. 过账后按 法人+仓库+产品(+批次) 正确累加库存；无记录则新建库存行。
3. 每一行入库都生成一条正数量、正金额的库存流水。
4. 重复过账被拦截（已过账单据不能再点过账）。
5. 库存明细表可按仓库/法人/物料查出当前结存，按物料汇总、不展开批次。
6. 过账失败时不产生半更新（事务回滚）。

---

## 5. 已确认决策

- 已过账单据不可改不可删；不做红冲。
- 入库类型固定枚举：生产入库、成品入库、调拨入库、盘盈入库。
- 库存金额按入库行金额累加，不另算成本价。
- 批次为空时按 法人+仓库+产品 聚合，不强制每笔都有批次。
- 草稿删除为物理删除。
- 库存明细查询按 法人+仓库+物料 汇总，不展开批次。
